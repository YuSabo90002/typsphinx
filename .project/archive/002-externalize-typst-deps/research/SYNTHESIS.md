## Decisions

### Single version source: module location and shape

- **Decision**: Add one new leaf module `typsphinx/typst_deps.py` that imports nothing from `writer`, `template_engine`, `builder`, or `translator`. It holds, as literal strings, the five default specs in a tuple of frozen dataclasses (fields: full `spec` such as `"@preview/codly:1.3.0"` and the import `items` such as `"*"` or `"mi, mitex"`, with `name` / `version` derived from `spec`), plus the constants `DEPS_OUTPUT_DIR = "_typsphinx"`, `DEPS_FILENAME = "deps.typ"`, `DEPS_IMPORT_PATH = "/_typsphinx/deps.typ"`, `INIT_FUNCTION_NAME = "typsphinx-init"`, and pure functions: `render_default_deps() -> str` (the default file text: generated-file header comment, five `#import` lines in today's order, and the `#let typsphinx-init(body) = { show: codly-init.with(); codly(languages: codly-languages); body }` definition), `deps_preamble_lines() -> list[str]` (the two-line `#import "/_typsphinx/deps.typ": *` + `#show: typsphinx-init` preamble), `strip_typst_comments(text) -> str`, and `extract_preview_versions(text) -> dict[str, set[str]]` (comment-stripped, five packages only). The `codly-init` / `codly(languages:` text exists only here. This is the only file under `typsphinx/` that the SC1 grep may match.
- **Runner-up**: Keeping the constants inside `template_engine.py` (already imported by `writer.py`, writer.py:16-21) — lost because SC1 requires `writer.py` and `template_engine.py` to contain no `@preview/` literal and no codly init line. A bundled `typsphinx/templates/deps.typ` data file — lost because SC1's grep covers `.typ` files under `typsphinx/` and names a single Python module. Storing name and version separately and formatting the spec at runtime — lost because the SC1 grep would then match no file at all, leaving the "single source" unprovable by the stated check.
- **Evidence**: INTENT.md SC1, Scope in bullet 1; evidence-codebase.md § The `@preview` package versions are triplicated and test-gated; writer.py:254-274; template_engine.py:695-712; base.typ:8-29.
- **Confidence**: high

### Preamble emission in content files and wrappers

- **Decision**: `TypstWriter.translate()` (writer.py:264-277) replaces its eleven-line import/init block with `deps_preamble_lines()` followed by one blank line, then the body. `TemplateEngine.render()` (template_engine.py:686-726) emits, in this order: the optional `generate_package_import()` line (unchanged), then `deps_preamble_lines()` on every route, then the template import or inline template, then `#show: FUNC.with(...)`. This keeps the existing relative order (package import, then shared imports and codly init, then template, then template show rule), so codly-init still wraps the template function as today. The inline-default-template route (only reachable from direct unit-test callers; writer.py:507-512 always passes a `template_file` unless package-alone) emits the preamble too; the inlined `base.typ` then repeats `#import "/_typsphinx/deps.typ": *`, which is a harmless re-import of identical bindings, and the old CR-01 "exactly one emission site" rule is restated in its test as "`#show: typsphinx-init` appears exactly once".
- **Runner-up**: Keeping the CR-01 skip (no preamble on the inline route) and emitting `#show: typsphinx-init` after the inlined template — lost because it reorders `typsphinx-init` relative to `base.typ`'s top-level rules on that one route, adds a third branch to keep in sync, and buys nothing for production output, which never takes that route.
- **Evidence**: template_engine.py:695-726 (CR-01 comment and `will_inline_default_template`); writer.py:507-518; INTENT.md SC2, N1; INTENT Current state "Measured Typst facts".
- **Confidence**: medium — Typst accepting a duplicate `*` import of the same module on the inline route is inferred, not measured; verify in wave 1 with one compile of the inline route.

### Writing deps.typ in the builder lifecycle, and stale files

- **Decision**: Add `TypstBuilder._write_dependencies_file()`, called first in `TypstBuilder.finish()` (before `copy_image_files()` and `_copy_used_template_bundles()`; builder.py:2462-2479), so `TypstPDFBuilder.finish()` (builder.py:2505, which calls `super().finish()` before compiling) always compiles against it. It runs on every build regardless of the write set and always writes the same path, `OUTDIR/_typsphinx/deps.typ`: when `typst_dependencies` is `None`, `Path.write_bytes(render_default_deps().encode("utf-8"))` (no platform newline translation, identical bytes every rebuild); when set, `shutil.copyfile(resolved, dest)` (bytes, no re-encoding, no metadata promise). Because both modes write the one fixed path on every build, switching modes between builds always leaves the newly effective file (E2); nothing else under `_typsphinx/` is created or deleted. The method re-checks the resolved path itself (the write-time validator below is the primary gate), mirroring the CONF-17 hoist-plus-finish-guard precedent, because tests drive `finish()` directly.
- **Runner-up**: Writing `deps.typ` at the top of `write()` before the per-docname loop — lost because tests that drive `write_doc()` / `finish()` directly bypass `write()` (builder.py:1302-1320 D-06 note), and the drift scan, which needs the effective file, already runs in `finish()`. Writing only when content differs — lost: extra code for no observable gain; E2 asks for identical bytes, not an unchanged mtime.
- **Evidence**: builder.py:1654-1775 (`write()` validation order), :2462-2479 (`finish()`), :2505-2520 (`TypstPDFBuilder.finish()` calls `super().finish()` first), :1594-1604 (`get_outdated_docs` yields every doc, so every build rewrites every content file); INTENT.md SC2, SC3, E2, E6, N3.
- **Confidence**: high

### typst_dependencies validation: timing and rules

- **Decision**: Add `TypstBuilder._validate_typst_dependencies()`, called at the top of `write()` next to `_validate_output_path_collisions()`, `_validate_registry_key_references()` and `_validate_used_template_paths()` (builder.py:1683-1718), so a bad value leaves zero `.typ` files on disk. Rules: `None` → default, no check; any other non-`str` value (Sphinx only warns on wrong types) or `""` → `ExtensionError`; otherwise resolve as `os.path.join(srcdir, value)` and require `os.path.isfile()` on the result, else `ExtensionError`. Messages start `typst_dependencies:` and name the configured value and the resolved path through `quote_path()` (for example: `typst_dependencies: file not found: 'deps/my-deps.typ' (resolved to '/abs/src/deps/my-deps.typ')`). Content of the user's file is never validated, parsed for errors, or modified.
- **Runner-up**: Validating in a `config-inited` handler like `removed_config.check_config_at_init` — lost because the codebase reserves that hook for removed names (__init__.py:62-73), and builder methods are where every other config-shape error is raised before writing. Falling back to the default file with a warning (as `typst_template` does at template_engine.py:366-375) — lost because SC3 and E4 require the build to stop.
- **Evidence**: evidence-codebase.md § Config-shape validation is concentrated in the builder, with one deliberate event-hook exception; builder.py:1683-1718, :1586-1592; INTENT.md SC3, E4, E6.
- **Confidence**: high

### Reserve the _typsphinx output directory

- **Decision**: Extend the OUT-07 reservation in `_validate_output_path_collisions()` (builder.py:1155-1222) so a content file or wrapper whose first output-path segment folds to `_typsphinx` is a build-stopping failure in the same aggregated `ExtensionError`, exactly as `_template` is today. Generalise `_reserves_template_prefix()` (builder.py:1017-1066) to check a small tuple of reserved directory names (`TEMPLATE_OUTPUT_DIR`, `DEPS_OUTPUT_DIR`) through `_collision_key()`, and name the matching directory in the message.
- **Runner-up**: No reservation — lost because a docname `_typsphinx/deps` would write a content file to the very path `_write_dependencies_file()` overwrites in `finish()`, silently breaking every file that imports it; the codebase already treats this class of clash as fatal for `_template`.
- **Evidence**: builder.py:1017-1066, :1155-1222 (OUT-07 for `_template`); INTENT.md SC2 (the file every content file imports must be the generated or copied one).
- **Confidence**: high

### Drift scan: which files, how comments are stripped, how warnings are emitted

- **Decision**: After `_copy_used_template_bundles()` in `finish()`, call `_warn_template_dependency_drift()`. Files: every `.typ` file actually copied into `OUTDIR/_template/KEY/` by `_copy_bundle_directory()` (have it return the copied relative paths so the scan reads exactly the used-bundle set after `_is_excluded_bundle_entry` filtering); package-alone keys have no bundle and are skipped. Effective versions: when `typst_dependencies` is unset, the specs in `typst_deps.py`; when set, `extract_preview_versions()` over the copied `deps.typ` decoded as UTF-8 with `errors="replace"`. Stripping: `strip_typst_comments()` is a single left-to-right character scanner that (a) copies double-quoted string literals through unchanged, honouring backslash escapes and ending a string at an unescaped `"` or at end of line, so `"https://…"` is never read as a `//` comment; (b) removes `/* … */` block comments with nesting depth counting, as Typst nests them; (c) removes `//` to end of line. Matching: regex `@preview/(codly-languages|codly|mitex|gentle-clues|diagraph):(\d+\.\d+\.\d+)` requiring the `:` right after the name, so `codly` never matches `codly-languages:` and `@local/…` is ignored. Per (file, package), if any found version differs from the effective version, emit one `logger.warning` naming the file as its outdir-relative path (`_template/KEY/REL.typ`, quoted with `quote_path()`), the package, the template's differing version(s) (sorted, comma-joined), and the `deps.typ` version; iterate sorted by (path, package). Plain `logger.warning` with no `type`/`subtype`, matching every existing warning in builder.py.
- **Runner-up**: Regex-only stripping (`//[^\n]*` and non-greedy `/\*.*?\*/`) — lost because it truncates any line containing a `"https://…"` string and mis-ends nested block comments, both of which can hide a real pin or expose a commented one. Reporting the source path instead of the outdir-relative copy — lost because the default bundle lives in site-packages and srcdir paths differ per machine, making the message and its tests nondeterministic; the outdir-relative path already names the key. Adding a warning `subtype` for `suppress_warnings` — lost on convention (no `subtype=` anywhere in typsphinx/) and not requested.
- **Evidence**: INTENT.md SC4, E7, E8, E9, E10, Corrections C1, Risks bullet 4; builder.py:2195-2270 (`_copy_bundle_directory`, `shutil.copy2` keeps bytes identical), :2272-2460; tests/test_preview_version_sync.py:44-48 (existing `#import` regex, which this scan generalises).
- **Confidence**: medium — the scanner treats `"` as a string delimiter even in Typst markup mode, where it is literal text; an odd number of prose quotes on one line can hide a later comment on that line. Accepted under INTENT Risks bullet 4 (best-effort aid); wave-1 unit tests must pin E10 and the URL case.
