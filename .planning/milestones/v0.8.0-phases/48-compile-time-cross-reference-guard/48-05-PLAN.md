<task type="checkpoint:decision" gate="blocking">
  <decision>What should a Sphinx-generated page reference that has no Typst counterpart (`genindex`, `py-modindex`, `search`) render as in the PDF?</decision>
  <context>
Task 1 measured two sub-populations of dead links. Sub-population A — references that resolve onto a
real document — is closed by this gap's fix unconditionally: those get a per-document self-anchor to
target and route through the existing compile-time guard. Sub-population B is different in kind:
`genindex`, `py-modindex` and `search` are pages Sphinx generates for HTML builders. The Typst output
never produces them, so there is nothing to link to and nothing to guard against. They exist in
`docs/source/index.rst`'s "Indices and tables" list.

Both options below are implementable inside this phase's locked decisions: neither adds a second
degrade mechanism, neither adds a second guard-string derivation point (D-07), and neither adds a
second label helper (D-13). The difference is one predicate's body at ONE call site, and one number
in the post-fix assertion.

Measured discriminator available to both: `sphinx.util.nodes.make_refnode` sets `internal=True` on
every reference it builds, so a Sphinx-resolved page reference is distinguishable from a hand-written
relative rST link to a real `.pdf` asset (which carries no `internal` flag). Both options preserve
such asset links untouched.
  </context>
  <options>
    <option id="option-a">
      <name>Leave them as they are — guard only references that resolve onto a real document</name>
      <pros>Smallest change; the policy predicate is a plain `found_docs` membership test; nothing that is not a real document changes behaviour at all; zero risk to any relative link to a genuine file asset.</pros>
      <cons>Sub-population B's annotations stay in the PDF as dead file links — clicking "Index", "Module Index" or "Search Page" still produces the owner's original ERR_FILE_NOT_FOUND. The gap is closed for every real document but not for these.</cons>
    </option>
    <option id="option-b">
      <name>Degrade them to plain text through the SAME guard — every Sphinx-internal whole-document reference is guarded</name>
      <pros>Post-fix the PDF carries zero dead file links. No new code path and no hardcoded page list: the reference is guarded against `&lt;genindex:{self-anchor}&gt;`, a label no compile can ever contain, so the existing guard's else branch renders plain text — the same mechanism, the same helper, one predicate body changed from a `found_docs` test to an `internal`-flag test. The reader sees the same words, just not clickable, which is D-02's own rule.</pros>
      <cons>Any OTHER Sphinx-internal reference to a page with no Typst counterpart also silently stops being a link — including, if the project ever uses one, a `:download:` reference whose target path happens to end in the builder's `out_suffix`. Slightly wider blast radius than option-a, all of it in the same direction (dead link becomes plain text).</cons>
    </option>
  </options>
  <resume-signal>Select: option-a or option-b</resume-signal>
</task>
