## Flagged planner assumptions

- **The per-build include-dedup ledger makes a single shared content file unusable for SC#1 on this
  tree.** `typsphinx/builder.py:750` resets `_included_docnames` once per build, not once per
  master, so a document toctree'd by two masters is `#include()`d into only one of them (defect A,
  owned by Phase 49). The SC#1 fixture therefore proves per-master divergence with two content
  files carrying a byte-identical reference line, and asserts that byte-identity explicitly, rather
  than with one shared file. This is recorded as a backstop truth above.

- **CORRECTED after review — the pre-fix behaviour of the SC#1 fixture.** An earlier draft of this
  plan claimed the build-time mechanism "suppresses the link for bravo and emits it for index", so
  the two content files disagreed at write time. That is **wrong**, and the planner re-verified it:
  `_compute_master_included_docnames()` seeds its BFS from *every* master docname and returns "the
  set of docnames included in **some** compiled master" — a union. `target` enters that union through
  alpha's toctree, so bravo's byte-identical `:ref:` also sees `xref[0] in master_included`, takes
  `degrade_xref_to_text = False`, and emits the same real `link(<target:…>, …)`. The two content
  files **agree** pre-fix; what fails is bravo's *wrapper compile*, which does not `#include()`
  `target.typ`. Consequences carried through this plan: failure mode 1 is a direct build fatal
  (stronger evidence, less machinery), and no test in this plan may assume the fixture builds
  green today.

- **The bravo-side "no link" assertion is destination-based, not count-based.**
  `typsphinx/templates/base.typ` calls `outline(...)` unconditionally, and Typst emits a GoTo `/Link`
  annotation per outline entry, so any heading anywhere in bravo's wrapper produces link annotations
  unrelated to the guard. Every bravo assertion in this phase therefore reads link **destinations**
  and asserts the target's namespaced label is absent from them.
