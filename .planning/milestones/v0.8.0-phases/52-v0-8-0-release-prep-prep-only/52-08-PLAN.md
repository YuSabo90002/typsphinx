## The three defects, as measured

**Defect A — locale-dependent warning baseline (test-side).**
`tests/test_state_guard_shapes_gate.py::TestNoLostDiagnostics::test_warning_baseline_preserved`
compares captured Sphinx output against fragments parsed out of
`49-SHAPES-RED-EVIDENCE.md` by `_parse_warning_baselines()` (defined around line 716). Those
baseline bullets were captured on this machine under a Japanese locale, so they contain Japanese
Sphinx warning text such as `toctree で重複したエントリが見つかりました`. CI runners are
English-locale, Sphinx emits `duplicated entry found in toctree`, and the substring check fails.
Affects the 2 parametrized cases `state_guard_self_and_url_gate` and `state_guard_selfref_gate`,
which is what turned all six OS/Python lanes and Code Coverage red.

Reproduces locally — this is your RED:

```bash
LC_ALL=C LANG=C LANGUAGE=C uv run python -m pytest \
  "tests/test_state_guard_shapes_gate.py::TestNoLostDiagnostics" \
  -q --tb=line -p no:randomly
```

Origin: Phase 49. Never caught because `ci.yml`'s push trigger covers only `main` and `develop`,
so this branch's CI runs exclusively via `workflow_dispatch` and had not been dispatched since.

**Defect B — `repr()` escaping in a test assertion (test-side).**
`tests/test_builder.py::test_post_process_images_rehome_escape_relocates_with_warning` builds
`abs_uri = os.path.join(os.sep, "typsphinx_test_50_03_escape_root", "chart.png")` and then asserts
`abs_uri in message`. The product emits that message at `typsphinx/builder.py` with

```python
f"could not rehome image URI {resolved_uri!r} relative "
f"to the doctree directory -- relocated to {key!r}"
```

`!r` is `repr()`, and that is deliberate and correct — the message quotes the path. On POSIX
`os.sep` is `/`, `repr()` escapes nothing, and the raw string is a substring of the message, so the
test passes. On Windows `os.sep` is `\`, `repr()` doubles every backslash to `\\`, and the raw
string is no longer a substring. **The product is right and the assertion is naive.** Fails on the
two Windows lanes only — confirmed absent from the ubuntu lane's failure list.

Origin: Phase 50 (`7dd50ecd test(50-03)`).

**Defect C — `ruff I001` unsorted import block (test-side, lint).**
`tests/test_builder.py:569`, inside
`test_post_process_images_rehome_cross_drive_value_error_relocates`. CI reports:

```
I001 [*] Import block is un-sorted or un-formatted
 --> tests/test_builder.py:569:5
569 |     import typsphinx.builder as builder_module
```

Origin: Phase 50 (`7dd50ecd test(50-03)`). Never caught locally because `.venv/bin/ruff` is a
generic-linux ELF the NixOS stub loader rejects — the standing environment defect filed at
`.planning/todos/pending/2026-08-11-ruff-generic-linux-elf-unrunnable-on-nixos.md`. **You cannot
run `ruff` on this machine. Do not claim you did.** The second CI run is the only authority for
this defect's fix.
