## The defect, measured

CPython 3.13 changed `ntpath.isabs()`: a driveless path beginning with a single separator is no
longer absolute on Windows. Measured on this machine (Python 3.13.13):

```
ntpath.isabs('\typsphinx_test_50_03_escape_root\chart.png') = False
ntpath.isabs('C:\typsphinx_test\chart.png')                 = True
```

`tests/test_builder.py::test_post_process_images_rehome_escape_relocates_with_warning` builds its
fixture as `os.path.join(os.sep, "typsphinx_test_50_03_escape_root", "chart.png")`. On Windows
that is driveless. `TypstBuilder._track_image()` gates its whole rehome branch on
`path.isabs(resolved_uri)` at `typsphinx/builder.py:910`, which on Windows resolves to
`ntpath.isabs`. Under 3.13 that returns `False`, the rehome branch never runs, `img["uri"]` is
never rewritten, and the test fails at `tests/test_builder.py:547`:

```
E  AssertionError: assert '\\typsphinx_...ot\\chart.png' == '_typst_converted/chart.png'
E    - _typst_converted/chart.png
E    + \typsphinx_test_50_03_escape_root\chart.png
tests\test_builder.py:547: AssertionError
============ 1 failed, 1169 passed, 5 skipped in 296.62s (0:04:56) ============
```

Windows + 3.12 passes on the identical commit, which is what pins this to the interpreter version
rather than to the OS alone.

## The product-side inconsistency — do NOT fix it here, but DO record it

The same module already knows about this trap. Around `typsphinx/builder.py:105-112`:

```python
# posixpath.isabs(), not path.isabs(): this function's own contract is
# ... count as absolute (e.g. ntpath.isabs("/abs/manual") is False, since
return ".." in segments or posixpath.isabs(stem) or _is_drive_qualified(stem)
```

That sibling deliberately avoids `ntpath.isabs()` and pairs `posixpath.isabs()` with
`_is_drive_qualified()`. `_track_image()` at line 910 does not follow the same idiom. That is a
real inconsistency with a real (narrow) behavioural consequence: on Windows under Python 3.13, a
driveless-absolute image URI planted by a third-party extension is NOT rehomed, where on 3.12 it
was.

**The owner's decision was: fix the test, file the product issue, keep this phase's zero-product-
lines fence intact for the release.** Honour both halves. Making the symptom disappear without
filing the inconsistency would lose the finding entirely.
