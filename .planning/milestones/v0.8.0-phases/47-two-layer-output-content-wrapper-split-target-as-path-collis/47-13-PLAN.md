<objective>
Close `47-VERIFICATION.md` gap 9b / `47-REVIEW.md` CR-01 — the BLOCKER that keeps Phase 47 at
`gaps_found`: `TypstBuilder._compute_master_included_docnames()` is a fifth site reading
`typst_documents` and needing the "is this entry usable" answer, and it never consults
`_is_usable_typst_documents_entry()`.

Purpose: 47-11 promoted entry usability to a single named predicate and wired it into the four sites
that resolve a wrapper PATH. `_compute_master_included_docnames()` (`typsphinx/builder.py:246-282`)
asks the same question for a different reason — it decides which docnames are "part of a compiled
master", the set `translator.py:3073-3075` consults to choose between a real Typst `link(<label>)` and
a degrade to plain text — and answers it with a bare `if entry` truthiness filter at line 269. The
verifier reproduced both consequences end-to-end against this checkout with real `sphinx-build`
subprocess runs:

1. **A silent wrong artifact that escalates to a hard compile fatal.** With
   `typst_documents = [("index", "manual.typ", …), ("ghost",)]`, the under-length `ghost` entry
   correctly produces no wrapper (post-47-11), so its toctree child's content file is never
   `#include()`d anywhere — yet the truthy 1-tuple still contributes `ghost` and its whole toctree
   closure to `master_included_docnames`. A real master's `:ref:` into that closure is therefore
   judged "safe to link" and emits a label reference that will never exist in any compiled document.
   `-b typst` exits 0 with no diagnostic naming this consequence; `-b typstpdf` on the identical input
   dies with ``TypstError: label `<ghost_child:ghost-child-label>` does not exist in the document`` —
   the exact fatal this degrade mechanism exists to prevent, and it takes the well-formed sibling
   master's PDF down with it.
2. **An uncaught crash.** With `typst_documents = [(["weird"], "manual.typ", …)]` — a non-hashable
   `entry[0]`, a plausible `conf.py` typo, since Sphinx does not type-check config values — the BFS's
   unguarded `docname in included` / `included.add(docname)` set operations raise
   `TypeError: unhashable type: 'list'` at `builder.py:276` and abort the build with a raw traceback,
   instead of the graceful warn-and-skip every other predicate-guarded site in this file now
   guarantees for exactly this shape.

**The semantic subtlety, stated here rather than left for the executor to rediscover:** this fifth
site resolves a *cross-reference safety* decision, not literally a wrapper *output path*. The shared
predicate is nonetheless the correct authority for it, and the reason is one sentence: an entry the
predicate rejects produces no wrapper file, and a docname with no wrapper is never physically
`#include()`d into any compiled document — so it contributes no included subtree and must not enter
`master_included_docnames`. The `isinstance(entry[0], str)` term additionally makes the BFS's set
operations total, which is what closes failure mode 2. Because the predicate's own docstring currently
claims to be "the SINGLE source of truth … consulted by all FOUR sites that resolve a wrapper path"
and enumerates only those four, that claim becomes false the moment the fifth is wired — correcting it
is part of this plan, not a nicety. It is the exact text gap 9b measures against.

Output: `_compute_master_included_docnames()` routed through the shared predicate; the predicate's
docstring telling the truth about its five consumers and about what the fifth one is asking; two new
fixtures; a new eight-test regression gate module; and `47-GAP2-RED-EVIDENCE.md` recording every
pre-fix RED and post-fix GREEN measurement per binding constraint #4.
</objective>

<assumption_delta_decision>
**Noun now primary:** *a usable `typst_documents` entry* — unchanged from 47-11.

**Decision: `promote`, completed.** 47-11 promoted the concept from four ad-hoc inline spellings to one
named predicate, but its own enumeration stopped at the four wrapper-path sites, leaving
`_compute_master_included_docnames()` holding the fifth surviving private spelling (`if entry`). That
is an `add-alongside` in practice: one named owner plus one un-migrated holdout. This plan finishes the
promote so no site keeps a private spelling of the predicate.

The delta this plan records that 47-11's did not: the promoted concept is **broader than
wrapper-path resolution**. "Can this entry produce a wrapper file" turns out to be the same question as
"does this entry contribute a physically-included subtree", because a wrapper is exactly the thing that
`#include()`s the subtree. Recording that generalization is what stops a sixth site from being added
later with a sixth private spelling on the grounds that it "isn't a path question". If a future site
genuinely needs a *different* usability question, it must introduce a second named predicate, not a
sixth inline check.
</assumption_delta_decision>
