1. **The output shape.** One `typst_documents` entry now writes TWO files instead of one. Use the
   canonical illustration from `51-CONTEXT.md` and `.planning/PROJECT.md`: with
   `typst_documents = [("index", "manual.typ", "Title", "Author", "typst")]`, v0.7.x wrote
   `manual.typ` containing the whole document; v0.8.0 writes `manual.typ` as a thin wrapper (template
   application plus one include) and `index.typ` as the document body. Say explicitly that any tooling
   which expects the target filename to hold the full document now finds a wrapper, and that the
   wrapper is still the file to compile. The two code blocks show the emitted file set before and
   after, not the `conf.py` (the `conf.py` is unchanged — that is the point). State that every docname
   gets a content file, not only the ones named in `typst_documents`.

2. **The target-as-path reversal.** A target containing a path separator was rejected in v0.7.x — a
   build warning, and the file written under its basename — and is honoured as-is relative to the
   output directory in v0.8.0. Illustrate with `"manuals/guide.typ"`: v0.7.x wrote `guide.typ` at the
   output root, v0.8.0 writes `manuals/guide.typ`. Note that `..` segments, absolute targets and
   drive-qualified targets are still refused, and point at the new page for the refusal rules rather
   than restating them.

3. **The collision hard error.** A configuration whose target resolves onto a path another claimant
   already owns now aborts the build. Use D-05's canonical illustration,
   `typst_documents = [("index", "index.typ", "Title", "Author", "typst")]`: it built successfully in
   v0.7.x and now raises an `ExtensionError` whose message begins with the literal
   `typst: 1 output path collision(s):`. State that the check runs before anything is written, so no
   `.typ` file is left on disk, and that the fix is to give the entry a target that is not any
   docname's own name. Name the claimants: the reserved `_template.typ`, every docname's content file,
   and every entry's wrapper.

Then add one final bullet WITHOUT the `**Breaking:**` prefix — the file already uses this shape for
"no action needed" items in `Migrating from 0.5.x to 0.6.x`: a document reached from more than one
master now renders in each of those masters' PDFs, at that master's own position and heading level,
where v0.7.x placed it in only one of them. No action is needed; it is the defect this release fixes.

Close the subsection with a short paragraph disambiguating the two renames, which SC#2 requires to sit
adjacent: v0.7.1 already renamed the DEFAULT-DERIVED target from the root docname to
`<project>.typ` when `typst_documents` is unset (a change to what the target is CALLED), while v0.8.0
changes what the target FILE CONTAINS (a change to the output shape). Say plainly that a project that
saw its output renamed at 0.7.1 is seeing a different change now. End with a
`:doc:`/user_guide/output_layout`` cross-reference for the full current contract — the leading-slash
form, because the target page is in a different directory.
