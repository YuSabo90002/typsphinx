## Flagged planner assumptions

- **The substring construction depends on the decided key format.** With the contract's
  `<parent>#<occurrence>><child>` shape, one full edge key is a proper substring of another exactly
  when one child docname is a proper prefix-extension of the other under the same parent and
  occurrence. The fixture therefore needs a docname pair in that relation, and the shorter-named
  document must lose first-encounter-wins to a deeper parent so its parent-side guard is DARK. If the
  key format changes, this fixture stops constructing the hazard — the fixture's own comment block must
  say so.
- **A dark guard whose key is a proper substring of a published key is the strongest fixture-layer
  detector available, but it is not a detector for the one-element trailing-comma degradation.** That
  degradation can only manifest when exactly one key is published, and a project with exactly one
  published key has no second guard to cross-fire. The trailing-comma hazard's real detector is
  therefore the arity-1 Typst type readback: measured by hand in 49-01 and asserted against the
  production rendering function in 49-04's unit module. This plan's substring fixture covers the
  semantics half; it does not and cannot cover the arity-1 half, and the gate's docstring must say so
  rather than implying broader coverage.
