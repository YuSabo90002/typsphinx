## Flagged planner assumptions

- **The occurrence counter must be per-document, and it is, structurally.**
  `TypstWriter.translate()` constructs a fresh translator instance for every document it translates, so
  an instance attribute initialised in the translator's constructor is per-document without an explicit
  reset. Verified by reading `translate()`. If a future change reuses a translator across documents, the
  counter would leak across documents and produce wrong occurrence values — so the unit module asserts
  that a fresh translator starts with an empty counter.
- **The per-document write path can be reached without the builder's own `write()`.** Several existing
  unit tests call the per-document write path directly, and those paths would see an empty edge mapping
  and therefore publish the empty array and leave every guard dark. The mapping is derived by exactly
  one function; `write()` assigns it unconditionally at the top of the write phase (replacing the
  deleted ledger reset), and the per-document write path calls the same function only when the mapping
  is still empty. That second trigger is a lazily-initialised call to the SAME derivation function, not
  a second decision mechanism, and the code comment at that site must say so explicitly so a reviewer
  does not read it as a competing ledger.
- **The emptiness short-circuit must move from the entry list to the include-file list.** The current
  visitor raises the docutils skip signal when the entry list is empty. Post-fix a toctree whose entries
  are all navigation constructs has a non-empty entry list and an EMPTY include-file list, and must emit
  no scope block at all. Any test constructing a synthetic toctree node with only an entry list therefore
  emits nothing; the census's SYNTHETIC-NODE rows are exactly those tests.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `conf.py` / `.rst` author input → emitted Typst source | Docnames are interpolated into the edge-key string literals this plan emits, on both the wrapper's publication side and each content file's guard side |
| Emitted `.typ` → `typst.compile()` | The Typst compiler consumes the state publication and guard lines this plan introduces; a malformed literal would either abort the compile or, in the trailing-comma case, silently change the membership semantics |
| Sphinx `BuildEnvironment` → the new traversal | The traversal reads the environment's toctree include mapping, which Sphinx populates from the same include-file lists its own inlining builders read |

## STRIDE Threat Register

ASVS level 1, blocking threshold `high`. ASVS **V2 (Authentication)**, **V3 (Session Management)**,
**V4 (Access Control)** and **V6 (Cryptography)** are **structurally inapplicable** — typsphinx is a
local Sphinx/Typst document-generation tool with no network service, no authentication, no session and
no cryptographic surface. **V5 (Input Validation)** is the one real seam this phase introduces, and this
is the plan that introduces it. Recorded rather than omitted, per the phase's security contract.
