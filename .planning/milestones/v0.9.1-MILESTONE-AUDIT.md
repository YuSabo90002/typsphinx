All eleven requirement integration paths verified WIRED end-to-end by the integration checker, with
the milestone's three declared collision hazards checked specifically:

- **Phase 58 → 59/60 seam.** `tests/_path_naming.py::path_named_in()` is imported and used by

  and stays green across all three quoting regimes (`repr()` → hardcoded `'...'` → `quote_path()`) —
  the mechanism that made "zero test edits" achievable in Phases 59 and 60.

  at `builder.py:1964-1969` interpolates Phase 59's forward-slash-normalized relocation key **and**

  no lost escaping.

  `typsphinx`. `builder.py:22`, `writer.py:15` and `template_registry.py:33` all import it; no
  import cycle is created.

  `!r`, with a comment explaining that a non-path value would raise `TypeError` — correctly *not*
  routed.

  todo, with no half-routing left behind.

## Tech Debt

**Carried to v0.9.2 — the reason this milestone is not published:**

- **BLOCKER (pre-existing, measured as *not* a v0.9.1 regression, D-06):** an inline image with
  sibling content before it in the same paragraph or list item is emitted adjacent to the preceding
  code-mode expression. Typst answers `expected semicolon or line break` and `-b typstpdf` raises
  `ExtensionError`, so **no** master document in the project produces a PDF.
  `.planning/todos/pending/2026-08-29-inline-image-in-paragraph-emits-unseparated-expression.md`.
  `git diff v0.9.0..HEAD -- typsphinx/translator.py` is 25 lines and touches only IMG-05;
  `visit_image()`'s missing separator is byte-identical to the `v0.9.0` tag.
- **Recorded owner trade-off (D-05):** users on the published `0.9.0` hit this today and get no
  notice — no README `## Known Limitations` entry, no CHANGELOG note — until 0.9.2 ships.

## Verdict

The milestone achieved its **technical** definition of done. Every Windows path defect it scoped —
the path-shape predicate, the image-URI value and syntax, the relocation-key length bound, and the
whole family of path-valued message quoting — is fixed, gated RED-first, and proven green on a
fresh 3-OS matrix including both `windows-latest` lanes. Cross-phase integration is complete with no
orphaned exports and no broken flows.

It did **not** achieve its release definition of done, by deliberate owner decision rather than by
failure: a pre-existing inline-image blocker makes a release whose headline claim is image-URI
correctness not worth making, so v0.9.1 is skipped and REL-09 moves to v0.9.2 intact.
