**lychee is never run locally (D-08).** This is an explicit owner instruction for this
NixOS-sandbox environment. Every lychee execution — including parameter tuning — happens by
pushing the branch and reading the GitHub Actions run. `curl` and `gh` are fine locally.

**Worktree execution.** If `test -f .git` succeeds you are in an isolated worktree. Provision it
before running anything Python: `env -u VIRTUAL_ENV -u UV_PROJECT_ENVIRONMENT uv sync --extra dev`,
then prefix every command with `uv run`. Task 1's verify needs this: measured 2026-07-26, `PyYAML`
is absent from the bare interpreter on this machine and present only inside the project
environment, so `uv run python` is required and plain `python3` fails with `ModuleNotFoundError`.

**RED IS THE SUCCESS CONDITION for Task 3.** The workflow run this plan observes is *expected* to
conclude `failure`. Do not "fix" it. Do not add `continue-on-error`. A green run here means the
mechanism is blind and the plan has failed.

**Evidence file naming.** Transcription goes to `31-EVIDENCE.md`, **not** `31-VERIFICATION.md`.
`{phase}-VERIFICATION.md` is a reserved filename that the verifier agent overwrites wholesale;
evidence written there is destroyed. D-09 says "VERIFICATION.md" but the mechanically safe target
in this project is `31-EVIDENCE.md`.

Workflow body, exact values (per D-01 through D-07):

- `name: Link Check`
- `on:` with `push:` and `pull_request:` as bare keys. No `schedule:` (D-02).
- `permissions:` with `contents: read` as the only entry. Do not copy `drift.yml`'s `issues: write` — nothing here files an issue (research Assumption A3).
- `jobs.link-check.name: Repo-wide link check (advisory)` — putting "advisory" in the check name makes D-04's posture visible in the PR checks list.
- `runs-on: ubuntu-latest`
- Step 1: `uses: actions/checkout@v7` (matches the pin convention in every workflow in this repo).
- Step 2: `name: Check links`, `uses: lycheeverse/lychee-action@v2`, with these inputs:
  - `args:` a folded block scalar (`>-`) containing, in order: `--verbose`, `--no-progress`, `--scheme https --scheme http`, `--extensions md,html,rst,txt,toml`, three `--exclude-path` flags, `--accept '100..=103,200..=299,429'`, `--max-retries 3`, `--retry-wait-time 2`, `--timeout 30`, and finally `.` as the input path.
  - `fail: true`
  - `jobSummary: true`

`--scheme` is what implements D-07, and it is load-bearing rather than cosmetic. lychee checks
**local and relative file paths by default**, not only scheme-bearing URLs — its own help text says
"Omit to check links with any other scheme", and the supported set is `http`, `https`, `file`, and
`mailto`. D-07 puts local and relative file-link existence checking out of scope, so both schemes
must be named explicitly. Concretely, omitting this flag would make the job red on
`examples/advanced/README.md`, which contains a relative reference to a configuration document at a
path that does not exist (measured 2026-07-26: it resolves two directories up to `docs/`, while the
real file lives under `docs/source/user_guide/`). That is a genuine defect, but it is a *local* link
and D-07 excludes it — leaving it in scope would fail SC#3 for a reason this phase has no mandate to
fix. The flag is repeatable: lychee's configuration equivalent is a list (`scheme = ["https"]`), so
naming it twice is the correct CLI form. No plain `http://` URL exists in the repository today
(measured), but naming `http` keeps the detector from silently skipping one added later.

The three `--exclude-path` values are **regular expressions**, confirmed against
`lychee.cli.rs/recipes/excluding-paths` ("The values are treated as regular expressions"). Use
anchored forms so a bare substring cannot over-match: one matching the `.planning` directory
anywhere in a path, one matching a path segment named `CHANGELOG.md` at end-of-string with the dot
escaped, and one matching the `tests/fixtures` directory. Quote each value.

Set `--extensions` to exactly `md,html,rst,txt,toml`. This flag REPLACES lychee's default list
rather than extending it — measured: this repository tracks 447 `.md`, 116 `.rst`, 1 `.toml`
(`pyproject.toml`) and zero `.htm`/`.css`/`.xml`/`.mdx`, so nothing is lost. Adding `toml` is the
fix for RESEARCH.md Pitfall 2. Note `uv.lock` carries 740 URLs but its extension is `lock`, which
is deliberately absent from the list — do not add it.

Do NOT add a caching flag. A cached result would let a newly-dead URL pass inside the cache window,
which is the opposite of what a detector is for.

Do NOT create a `.lycheeignore` file. That file excludes URLs, never paths (Pitfall 1); using it
here would be inert at best and, if populated with a host pattern, would blind the negative control
D-03 forbids blinding.
