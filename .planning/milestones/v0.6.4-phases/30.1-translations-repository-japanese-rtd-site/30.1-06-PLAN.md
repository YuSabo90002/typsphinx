<objective>
Prove the Japanese PDF is **glyph-correct, not merely built**: content-compare the PDF Read the Docs
serves for the Japanese project against a local `SPHINX_LANGUAGE=ja` build of the same source, per
D-03's four-check bar, and record the comparison verbatim.

Purpose: I18N-03's named failure mode presents as a *successful* build. Typst's font fallback is silent
— no error, no warning — so a PDF with substituted glyphs downloads cleanly, extracts the correct
characters, and looks green from every angle a status check can see. Phase 29 met this bar for four CJK
strings in an English PDF; here all 94 pages are CJK, so "the two affected pages" no longer means
anything and the sample must be chosen deliberately. This is a one-off hand-run comparison by explicit
decision (D-03, reaffirming Phase 29 D-15): the RTD-built PDF is unreachable from CI, so a committed
script would be a gate that never runs.

Output: `30.1-EVIDENCE.md` sections identifying both artifacts, recording D-03 checks 1-3 with their
commands and output, recording check 4 honestly as `human_needed` with the exact pages and glyph strings
to inspect, and closing with a consolidated status for all five of the phase's success criteria.

**Autonomy note:** `autonomous: true` because this plan contains no checkpoint task — every task is
machine-executable. D-03 check 4 is a `<verify><human-check>` rather than a blocking checkpoint because
`workflow.human_verify_mode` is `end-of-phase`: the owner's visual confirmation is collected in the
end-of-phase verification batch, and until it is collected the item stands recorded as `human_needed`.
Autonomous execution therefore does not mean I18N-03 closes autonomously — it explicitly does not.
</objective>
