## Issues Encountered

**The `Update translation source pin` workflow (D-08, staged in `translations-repo/.github/workflows/update-pin.yml`)
has a load-bearing defect and has never successfully run.** Its "Advance submodule to latest tracked
branch" step (`git submodule update --remote typsphinx`) requires a `refs/remotes/origin/<branch>` ref
inside the submodule's own `.git`, but the preceding checkout step's default submodule fetch
(`actions/checkout@v7`'s `submodules: true` convenience option, which runs `git submodule update --init
--force --depth=1`) fetches the submodule by its pinned commit SHA only, never creating that
remote-tracking ref. Every future re-trigger will fail identically until an explicit branch fetch (e.g.
`git -C typsphinx fetch origin gsd/v0.6.4-read-the-docs-migration`) is inserted before the `--remote`
step. Full diagnostic evidence — the exact failing command, its error, and the preceding step's log
proving the missing-ref cause — is recorded in `30.1-EVIDENCE.md` § "SC#3 — observed pin-bump run".

This was not fixed in this plan, per Task 2's explicit instruction not to patch the workflow in-flight.
It is the single largest open item this plan produces.
