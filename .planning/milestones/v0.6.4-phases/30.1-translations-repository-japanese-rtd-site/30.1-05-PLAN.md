<objective>
Prove the Japanese site is not frozen: make a real source change in this repository after the ja project
exists, push it, run the pin-bump workflow, and observe both the pin moving and the change arriving on
`/ja/latest/`.

Purpose: SC#3's failure mode is the quietest in the phase. A translations repository whose pin never
advances serves translations of an old English source forever, with every build green, every page
rendering, and no error anywhere. RESEARCH also measured a near-miss: `sphinx-intl update` rewrites
every catalog's `POT-Creation-Date` header on every run, so a naive workflow produces a daily commit
that proves nothing — which would make SC#3 pass on evidence that means nothing.

The source change itself is not manufactured for the test. `docs/source/contributing.rst` currently
tells a would-be translator nothing about where the Japanese catalogs live, and after this phase they no
longer live in this repository at all. Documenting D-12's arrival-half entry point is this phase's own
collateral, in the same class as D-05 — and because `contributing.po` is 0/97 translated, the new
English text is visible on the Japanese site by correct Sphinx fallback, which makes it an honest
propagation probe rather than a contrived one.

Output: one documentation section, and three `30.1-EVIDENCE.md` sections carrying the push, the observed
run with its before/after gitlink SHAs, and the propagation fetch.
</objective>
