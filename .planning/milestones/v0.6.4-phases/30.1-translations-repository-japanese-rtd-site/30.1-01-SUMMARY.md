# Phase 30.1 Plan 01: Translations Repository Staging Files Summary

Authored the three static files that define `typsphinx-doc-translations` — its ja RTD build manifest,
its locale-tooling Makefile, and its README — staged under
`.planning/phases/30.1-translations-repository-japanese-rtd-site/translations-repo/` for review and
copy-out by Plan 03. No file in this repository outside `.planning/` was touched.

## What Was Built

1. **`.readthedocs.yaml`** — a deliberate submodule-prefixed variant of this repository's own parent
   manifest. `build.jobs.post_create_environment` does `rm -rf typsphinx/docs/locale` → `mkdir -p` →
   `cp -a locale/. typsphinx/docs/locale/`, in that order, closing the stale-`.mo`-shadowing hazard
   (threat T-30.1-05): this repository git-tracks 13 compiled `.mo` binaries alongside its `.po`
   catalogs, and without the removal step a submodule checkout would let `gettext_auto_build` reuse a
   stale compiled catalog, serving old or English text on a build that reports success. `python.install`
   is the `path:`-based pip entry (`{method: pip, path: typsphinx, extra_requirements: [docs]}`), not
   the parent's `method: uv` form — the package lives inside the submodule, not the repository root.
   `build.jobs.build.pdf` mirrors the parent's four-command PDF job with `docs/source` replaced by
   `typsphinx/docs/source`, preserving the mkdir-before-copy ordering and the "only the PDF crosses into
   `$READTHEDOCS_OUTPUT`" constraint. `formats: [pdf]` and `build.apt_packages: [fonts-noto-cjk]` carry
   from the parent unchanged, each with the same rationale comment the parent's own file uses.

2. **`Makefile`** — root-level (no `docs/` subdirectory in the translations repository), exposing
   exactly `help` / `locale-update` / `locale-stat`. `locale-update` runs `sphinx-build -M gettext` over
   the submodule's `typsphinx/docs/source`, then `sphinx-intl update` with explicit `-p`/`-d`/`-l` flags
   — the `-d $(LOCALEDIR)` override is required here (and absent from this repository's own
   `docs/Makefile`) because the command runs from the translations-repository root, not from inside
   `docs/`. `locale-stat` reports coverage via `sphinx-intl stat`. No `locale-init` (collapsed into
   `locale-update`, since this repository's own two targets were always byte-identical), no
   `html`/`multilang`/`serve-multilang` target, and no catch-all `%: Makefile` rule.

3. **`README.md`** — the sole human-facing orientation document for the new repository. Records: what
   the repository is and the `sphinx-doc/sphinx-doc-translations` model it follows; the layout; why no
   `.mo` files are committed (`gettext_auto_build = True` plus the removal-before-copy hazard); the
   submodule branch policy (tracks `gsd/v0.6.4-read-the-docs-migration`, with the measured reason and
   the owed post-merge flip to `main`); the `make locale-update` / `make locale-stat` catalog-update
   path with the measured 257/1058 (24.3%) coverage baseline and the four zero-coverage docnames; how
   the D-08 pin-bump workflow keeps the submodule current; and the release procedure as a
   two-repository release set, with the consequence of skipping this repository stated explicitly (a
   404 on `/ja/stable/`, not a failed build). Contains no `github.io` URL — published-URL rewrites
   belong to Phase 31.

## Tracked Branch and Its Reason (PD-02)

The staged `.gitmodules`-facing decision (recorded in the manifest's sibling README, not a file this
plan creates) is that the submodule will track `gsd/v0.6.4-read-the-docs-migration`, not `main`.
Measured 2026-07-26 in this checkout: `origin/main` in the parent repository has no `.readthedocs.yaml`
and its `conf.py` has no `_resolve_language()` helper, so a `main`-tracking submodule would pin a tree
Read the Docs refuses to build and whose language resolution would ignore the ja project's Admin
Language setting. This is deliberately stated as owed future work in the README rather than deferred
silently — after the milestone merges to `main`, `.gitmodules`' `branch` field flips and the pin-bump
workflow runs once.
