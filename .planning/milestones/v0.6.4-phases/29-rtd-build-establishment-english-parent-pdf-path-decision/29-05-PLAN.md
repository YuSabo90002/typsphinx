<objective>
**Branch A only.** Content-compare the PDF that RTD serves against the local `typstpdf` baseline for the
same commit, per D-12's four-check bar, and record the comparison verbatim.

Purpose: RTD-02's named failure mode presents as a *successful* build. Typst's font fallback is silent —
no error, no warning — so a PDF with substituted glyphs downloads cleanly, extracts the correct
characters, and looks green from every angle a status check can see. Only a content comparison plus a
human look closes it. This is a one-off hand-run comparison by explicit decision (D-15): the RTD-built
PDF is unreachable from CI, so a committed script would be a gate that never runs.

Output: `29-VERIFICATION.md` sections identifying both artifacts, recording D-12 checks 1-3 with their
commands and output, and recording check 4 honestly as `human_needed` with the exact pages and glyphs to
inspect — plus a consolidated RTD-02 verdict that does not close while check 4 is open.

**Autonomy note:** `autonomous: true` because this plan contains no checkpoint task — every task is
machine-executable. D-12 check 4 is a `<verify><human-check>` rather than a blocking checkpoint because
`workflow.human_verify_mode` is `end-of-phase`: the owner's visual confirmation is collected in the
end-of-phase verification batch, and until it is collected the item stands recorded as `human_needed`.
Autonomous execution therefore does not mean RTD-02 closes autonomously — it explicitly does not.
</objective>
