<objective>
Close XREF-05 by making `TypstTranslator._sanitize_label` injective, so two distinct docnames can
never produce one Typst label and a cross-reference whose real target is absent from the compiling
master degrades to plain text instead of linking to a same-spelled decoy.

Purpose: `_sanitize_label` encodes every Typst-label-invalid character as `_u{codepoint:x}_`, using
only characters that are themselves inside its own "safe" set. An input that already spells the
encoder's own token therefore passes through untouched, and `a/b` and `a_u2f_b` collapse onto the
identical label `a_u2f_b:nested-target`. Phase 48 measured this and accepted it as a documented
limit; this plan closes it at the encoding layer, with no new Typst machinery (D-01).

Output: a pre-pass inside `_sanitize_label`, a proof-shaped property suite, the inverted real-compile
assertion, an updated fixture comment block, and a verbatim pre-fix RED transcript.

**This plan carries this phase's tracer slice.** Task 1 drives the whole loop end to end on one
path — raw docname → `_sanitize_label` → emitted `.typ` label bytes → `typst.compile()` → PDF link
destinations — recording the pre-fix behaviour and then flipping it. It is production-quality, not a
prototype: the construction it lands is the final one, and Tasks 2 and 3 expand outward from the
proven slice rather than replacing any of it. Plans `55-02` and `55-03` are expansion families in the
next wave.
</objective>

## Measured findings this plan is built on (do not re-derive)

Both constructions the phase's own research documents proposed are **not injective**. Measured this
session by exhaustive search over the alphabet `a _ u 2 f /`:

| Construction | Source | Counterexample | Both map to |
|---|---|---|---|
| Double the leading underscore of a literal `_u<hex>_` token before the main substitution | `55-RESEARCH.md` Pattern 1 and `55-PATTERNS.md` | `a_/b` and `a_u2f_b` | `a__u2f_b` |
| Insert an extra `u` into a literal `_u` + `u*` + hex + `_` run | considered as the obvious repair of the above | `_u2f/` and `/u2f_` | `_u2f_u2f_` |

Root cause of both: they protect only token shapes present in the RAW input, while the main
substitution creates NEW token shapes at the seams between literal text and emitted tokens. The
construction Task 1 lands escapes the token's own **introducer** instead, and was verified by a
decoder round-trip over an exhaustive alphabet plus 400,000 random strings.
