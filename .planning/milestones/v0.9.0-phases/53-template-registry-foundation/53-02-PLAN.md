<objective>
The tracer for Phase 53: wire ONE end-to-end path through every layer the phase touches — config
registration, a new registry module, `write()`, the wrapper loop, and `render_wrapper()` — so that
`render_wrapper()` builds its `TemplateEngine` from a resolved registry definition instead of reading
`typst_template` / `typst_package` / `typst_template_function` straight off `config`, while the
built-in `"typst"` key synthesizes exactly those same globals so the output is unchanged.

This is production-quality code, not a prototype. Validation (CONF-14…CONF-18) is deliberately absent
here — it is expansion built on top of this proven slice in plan 53-03 — but nothing in this slice is
throwaway: every line survives into the final system, and Phase 54 builds directly on it.

Purpose: prove the architecture end-to-end on one path before expanding, so an architectural dead-end
surfaces after one commit rather than after four. The proof is the existing regression net staying
green: this phase changes no output (ROADMAP Phase 53 goal).
Output: `typsphinx/template_registry.py`, the `typst_document_templates` config value, the threaded
registry, and `tests/test_template_registry.py`.
</objective>

<assumption_delta_decision>
**The noun that is now primary:** *a resolved named template definition* — a `TemplateRegistryEntry`
drawn from the `typst_document_templates` registry. It replaces "the template", which until now meant
the single global triple `typst_template` / `typst_package` / `typst_template_function` read straight
off `config`.

**Decision: `promote`** — for the write path. `render_wrapper()` stops knowing that global template
config exists; it is handed a definition. The globals survive only as the values the built-in
`"typst"` key synthesizes, i.e. as a detail of one variant of the general representation, exactly as
TPL-03 specifies ("the built-in key `\"typst\"` resolves to the existing global configuration") and as
D-11 scopes (`typst_template_mapping` reaches only that one key's engine).

**One recorded `add-alongside` residue, deliberate and time-boxed:** `_write_template_file()`
(builder.py:1109-1179) still reads the same globals directly and still writes the root `_template.typ`.
It is explicitly NOT deleted this phase. The forcing function is ROADMAP binding constraint #2: the
tree must be green at every phase boundary, and the regression net asserting the root `_template.typ`
is large (re-measure with `grep -rl "_template\.typ" tests/`). Phase 54 deletes
`_write_template_file()` and the layout it writes, which completes the promote. Until then this is
accepted debt with a named owner phase, not an unbounded parallel path — and it is harmless precisely
because it derives its values from the same globals the `"typst"` key synthesizes.

**Companion invariant (adopted, Task 2):** a test asserting that `render_wrapper()`'s own source
region contains no read of the three global template config names. It goes red the instant a future
phase reintroduces the singular assumption at that call site.
</assumption_delta_decision>
