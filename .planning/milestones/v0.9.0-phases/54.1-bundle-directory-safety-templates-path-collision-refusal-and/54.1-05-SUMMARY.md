## Decisions Made
- The CONF-17 half of the cross-kind fixture pair had to be redesigned mid-task: a first attempt
  declaring "aardvark" as a SECOND `typst_document_templates` registry key produced the WRONG
  exception (`resolve_template_registry()`'s own earlier declared-key CONF-17 check, a separate
  first-offender error, not the hoisted pre-write aggregate this gate targets). Measured this by
  running the test and reading the actual raised traceback, then redesigned to use the global
  `typst_template` setting instead, which correctly routes through the SYNTHESIZED built-in
  `"typst"` key -- the one key the earlier declared-key loop never reaches (CR-01's precise root
  cause, per `54.1-CONTEXT.md`).
- Chose key spellings `"Typst"` / (built-in) `"typst"` deliberately so `sorted(used_keys)` always
  orders `"Typst"` before `"typst"` (`'T' < 't'` in Unicode code-point order) regardless of which
  fixture declares which config statement first -- this makes the ordering assertion meaningful
  rather than accidentally order-independent for an unrelated reason (e.g. alphabetically identical
  strings).
- Recorded the full-suite evidence as an unconditional 0 failures rather than following the stale
  "modulo 7 pre-existing `tests/test_state_guard_shapes_gate.py` failures" carve-out recorded in
  `54.1-VALIDATION.md` -- that carve-out did not reproduce on this worktree lineage (consistent with
  `54.1-01/03/04-SUMMARY.md`'s own independent observations), and the evidence file states this
  explicitly so a reader does not mistake a genuinely clean run for a partially-excused one.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corrected the cross-kind fixture's CONF-17 violation source before it was ever committed**
- **Found during:** Task 1, first draft of `tests/fixtures/mixed_prewrite_failures_a_gate/`
- **Issue:** The plan's `<action>` text describes "the other key is named `aardvark`" as a SECOND
  declared `typst_document_templates` registry key pointing at a root-level file. Declaring it that
  way causes `resolve_template_registry()`'s own declared-key CONF-17 validation loop
  (`template_registry.py:420`) to raise its own separate "typst_document_templates: N invalid
  definition(s)" error BEFORE `_validate_used_template_paths()` (the method under test) ever runs --
  so the fixture as literally described would never actually exercise the cross-kind aggregation
  this gate exists to prove.
- **Fix:** Moved the CONF-17 violation to the global `typst_template = "aardvark.typ"` setting
  (synthesizing the built-in `"typst"` key, the ONE key the earlier declared-key loop never
  CONF-17-checks), keeping the `"aardvark.typ"` filename and the fixture's two-docname /
  two-`typst_documents`-entry shape intact. Documented the measured constraint inline in both
  fixtures' `conf.py` header comments so a future reader does not "simplify" it back to a declared
  key.
- **Files modified:** `tests/fixtures/mixed_prewrite_failures_a_gate/conf.py`,
  `tests/fixtures/mixed_prewrite_failures_b_gate/conf.py` (both drafted correctly before commit --
  no separate fix-up commit was needed since this was caught before Task 1's commit).
- **Verification:** `uv run pytest tests/test_prewrite_failure_aggregation_gate.py -v` -- all 4
  tests pass with the corrected fixture design; the RED transcript against the pre-fix SHA confirms
  the gate exercises the intended cross-kind failure BEFORE this phase's production code existed.
- **Committed in:** `9009930e` (Task 1 commit; the fixtures were written correctly on first commit,
  so this deviation left no separate corrective commit).
