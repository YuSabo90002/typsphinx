## Decisions Made
- Moved `_validate_used_template_paths()`'s per-used-key `TemplateEngine` resolution loop from
  `if templates_path_entries:` to `if used_keys:` — the CONF-17 hoist check needs the resolved
  path for every used key regardless of whether the project sets `templates_path` at all.
- The CONF-17 hoist check runs, and `continue`s to the next key, BEFORE the
  `resolution.source == "default"` skip — unlike the `templates_path` containment check, it does
  NOT itself skip the default source (the packaged default's parent directory can never be
  `srcdir` or an ancestor of it, so the predicate is safely unconditional there; stated explicitly
  in the method's docstring per this codebase's own convention).
- A key that already violates CONF-17 skips that same key's `templates_path` containment check —
  nothing useful is left to report for it, and reporting both would be noise.
- The reserved-key case-collision check is declaration-scoped (iterates every key in
  `self._document_template_registry`, not the reference-derived `used_keys` set the two path
  checks use) — this is a deliberate scope difference from those two checks, not the widening
  CONTEXT.md's Claude's Discretion advised against for THEM; documented explicitly in the
  docstring so a later reader does not collapse the two scopes.

## Issues Encountered
- The `sphinx-build` filenames argument (used by `test_conf17_hoist_refuses_when_restricted_to_other_docname`
  to restrict a build to one docname) resolves relative to the process's CWD, not the source
  directory — passing the bare string `"other.rst"` produced a `WARNING: ... file ... does not
  exist` because it resolved against the worktree root. Fixed by passing the absolute path
  (`str(FIXTURE_DIR / "other.rst")`) instead.
- Two acceptance-criteria greps initially failed because prose (a fixture header comment, two
  method-docstring/comment lines) happened to contain the literal substring under test even though
  it was not a real code reference: `tests/fixtures/conf17_prewrite_gate/conf.py`'s header comment
  said "typst_document_templates registry" (the criterion checks for `0` occurrences, since the
  fixture must declare no such registry), and two docstring/comment lines in `builder.py` wrote
  `` _violates_conf17() `` with trailing parens (the criterion checks the hoisted method calls the
  predicate exactly once). Both were reworded to keep the same meaning without the literal
  substring, then the acceptance-criteria greps re-verified clean.
- `uv run black --check typsphinx/builder.py` initially wanted a reformat after Task 2's edit
  (long lines in the extended docstring); ran `uv run black typsphinx/builder.py` to apply it,
  then re-ran the affected gate tests to confirm behavior was unchanged before committing.
