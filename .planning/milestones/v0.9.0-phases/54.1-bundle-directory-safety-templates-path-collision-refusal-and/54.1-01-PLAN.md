<objective>
Close the runtime half of WR-01 with a production-quality end-to-end slice: a used registry key
whose resolved template bundle directory collides with Sphinx's own `templates_path` refuses the
build with an `ExtensionError`, in a pre-write pass at the top of `write()`, leaving zero `.typ`
files on disk.

Purpose: Phase 54 made the resolved template's **parent directory** the unit of copying, so a
project following typsphinx's own published documentation (`typst_template` pointing inside
`_templates/`) has its Sphinx Jinja override directory copied wholesale into public build output.
`typsphinx/` reads `templates_path` nowhere today — this plan introduces the first read and the
guard that makes the republication impossible.

Output: `_paths_related()` and `TypstBuilder._validate_used_template_paths()` in
`typsphinx/builder.py`, wired at the D-04 pre-write slot; a real-`sphinx-build` subprocess gate
module and fixture; and a verbatim pre-fix RED transcript.

**This is the phase's TRACER slice.** It wires ONE path — the `templates_path` collision — through
every layer the phase touches (fixture project → Sphinx `write()` → key-set derivation →
`TemplateEngine` resolution → path-relationship predicate → accumulate-then-raise-once →
`ExtensionError` propagating out of `Builder.build()` → zero written files). Plans 03 and 04 expand
horizontally from this proven skeleton by feeding two more failure kinds into the same `failures`
list and by adding the control/aggregation cases. It is production code, not a prototype: no stubs,
no TODOs, no "wired later".
</objective>
