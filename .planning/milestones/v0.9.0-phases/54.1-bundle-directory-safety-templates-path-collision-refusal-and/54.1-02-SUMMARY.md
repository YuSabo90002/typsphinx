# Phase 54.1 Plan 02: Documentation Half of WR-01 (SC#2) Summary

Retired every published recommendation to put a Typst template inside Sphinx's `templates_path`
Jinja directory, across `docs/source/`, `README.md`, and both runnable `examples/` projects, and
pinned the result with a new executable repo-wide-grep gate module recorded RED against the
pre-fix tree before any documentation edit.

## What Was Built

**Task 1 — `tests/test_docs_template_layout_gate.py`** (new): a run-time `rglob()`-discovery gate
over exactly `docs/source/`, `README.md`, and `examples/` (D-12; `tests/` deliberately excluded).
Three tests: Test 1 catches an assignment-shaped `typst_template = "_templates/..."` recommendation
(narrow); Test 2 catches any surviving bare `_templates` mention whose line does not also name
Sphinx's own `templates_path` config value (broad, line-scoped); Test 3 is a fail-first control
proving both regexes have teeth against synthetic strings only, so the gate can never silently
become vacuous. Recorded RED against commit `9cc529b794563e57f2f070f93f0be9f141f8740e` in
`54.1-02-RED-EVIDENCE.md`: **2 failed, 1 passed**, with the full 31-line offending-`path:line`
list for Test 2 — the actual discovery-time repo-wide grep this phase's SC#2 rests on, superseding
the CONTEXT.md D-08 floor by one additional hit (`examples/advanced/_templates/custom.typ:5`,
recorded separately as D-13).

**Task 2 — example bundle renames**: `git mv` for both templates so history follows:
`examples/advanced/_templates/custom.typ` → `examples/advanced/_typst/custom.typ`, and
`examples/charged-ieee/approach2/source/_templates/_template.typ` →
`.../source/_typst/_template.typ`. `examples/advanced/conf.py`'s `typst_template` value and its
explanatory comment follow the rename; its `templates_path = ["_templates"]` line at line 24
**stays untouched** (D-09) — the example now demonstrates the two directories coexisting, each
with its own meaning. `README.md` and `index.rst` tree diagrams show both directories, with the
Sphinx one annotated by naming `templates_path` on the same line, satisfying Task 1's line-scoped
exemption rule. The in-template header comment inside `custom.typ` that repeated the old
configuration path is updated (D-13). `examples/charged-ieee/approach2/conf.py`'s value and NOTE
comment follow the rename (D-11); this project sets no `templates_path`, so no annotation line was
needed. No `@preview` import line changed in either renamed template
(`git diff ... | grep -c '^[-+].*@preview'` returns `0`).

**Task 3 — retire the recommendation from every published page**: replaced every
`typst_template = "_templates/..."` recommendation, section heading naming a template by
`_templates/` path, tree-diagram entry, in-template path comment, `bibliography(...)` argument, and
"Create a file" instruction across `docs/source/quickstart.rst`,
`docs/source/user_guide/configuration.rst`, `docs/source/user_guide/templates.rst` (4 config
examples, a directory-tree block, an in-template path comment, and a "Create a file" instruction),
`docs/source/examples/advanced.rst` (2 section headings, a `bibliography(...)` argument, 3 config
examples, and the 3-sentence explanation of where the bundle copy lands), and `README.md`'s Quick
Start — all replaced with `_typst/` (D-10), matching the pairing `docs/source/conf.py` already
demonstrates (`templates_path` at line 45, `typst_template = "_typst/custom_template.typ"` at line
96). Also updated the two stale test-file comments the Task 2 renames invalidated:
`test_preview_version_sync.py`'s docstring path mention and
`test_examples_charged_ieee_gate.py`'s NOTE comment quoting the old `typst_template` value — both
comment/docstring text only, no assertion, constant, or test logic changed in either file.

- **Commit:** folded into `10e9ef86` (Task 3's commit, since the reformat happened during Task 3's
  verification pass, before that commit was made).

**2. [Rule 3 - blocking] `uv run ruff check .` could not execute in this NixOS sandbox**
- **Found during:** Task 3's lint verification step.
- **Issue:** `ruff`'s bundled native binary is a generic-linux ELF that NixOS refuses to exec
  directly (a known, previously-recorded environment hazard in this project — distinct from the
  `tox-uv-bare` / `.venv/bin/uv` hazard CLAUDE.md documents, which is already resolved). `uv run
  ruff check .` failed with "Could not start dynamically linked executable: ruff".
  `command -v ruff` also found nothing on `PATH`.
- **Fix:** Located a nix-store-provided `ruff` derivation
  (`/nix/store/rxq02ylzcbjpzk7k9s8n4y4xwlznm0zr-ruff-0.15.14/bin/ruff`) and ran
  `check .` through it directly. Result: "All checks passed!" No code change was needed — this was
  purely a local toolchain substitution to exercise the same check the plan's acceptance criteria
  require.
- **Files modified:** none (verification-only workaround).
- **Commit:** N/A (no code change).

**3. [Rule 3 - blocking] The docs HTML build required the `docs` optional-dependency group**
- **Found during:** Task 3's final Sphinx build verification step.
- **Issue:** `uv sync --extra dev` (this project's standard per-worktree provisioning step) does
  not install `sphinx-autodoc-typehints` / `myst-parser` / `furo`, which `docs/source/conf.py`'s
  `extensions` list requires. The first HTML build attempt failed with
  `ExtensionError: Could not import extension sphinx_autodoc_typehints`.
- **Fix:** `uv sync --extra dev --extra docs`, matching this project's own `tox -e docs-html`
  environment. The subsequent build then succeeded (`build succeeded, 3 warnings`, RC 0). This also
  explains the full-suite count moving from 1297/5-skipped to 1301/1-skipped between the Task 2 and
  Task 3 verification runs — some tests that were skipped for a missing `docs`-extra dependency
  became runnable.
- **Files modified:** none (environment provisioning only; no `pyproject.toml` change).
- **Commit:** N/A (no code change).

### Note on a plan acceptance-criteria heuristic (not a deviation, documented for the record)

The plan's Task 3 acceptance criterion `git diff ... tests/test_preview_version_sync.py
tests/test_examples_charged_ieee_gate.py | grep -E '^\+' | grep -vcE '^\+\+\+|^\+\s*(#|"|\*|$)'`
(expected `0`) returns `1` on the actual diff, not `0`. Manual inspection of the diff shows exactly
one added line in each file, both of which are prose *inside* the module's docstring or an inline
`#` comment — genuinely text-only, no assertion/constant/logic changed. The `1` count is because
the changed docstring line in `test_preview_version_sync.py` starts with a Markdown backtick
(`` ` ``) rather than `#`/`"`/`*`, which the grep heuristic does not recognize as docstring-prose
shape. This is a limitation of the heuristic's character-class list, not a violation of the actual
requirement ("comment/docstring text only, no assertion, no constant, no test logic") — confirmed
by reading both diffs in full before commit.
