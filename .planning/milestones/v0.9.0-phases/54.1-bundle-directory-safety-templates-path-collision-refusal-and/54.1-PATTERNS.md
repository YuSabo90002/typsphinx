## Pattern Assignments

### `typsphinx/builder.py` — new pre-write validation method(s)

**Primary analog A — accumulate-then-raise-once shape:** `_validate_output_path_collisions()` (`builder.py:625-779`)
**Primary analog B — pre-write placement/call-site precedent:** `_validate_registry_key_references()` (`builder.py:780-844`), and the exact insertion slot in `write()` (`builder.py:935-964`)
**Reused predicate (imported, never re-derived):** `_violates_conf17()` (`typsphinx/template_registry.py:137-176`)
**Reused normalization primitive:** `_collision_key()` (`builder.py:494-571`)
**Reused key-derivation inputs:** `_default_typst_documents()` (`builder.py:218-237`) and `_is_usable_typst_documents_entry()` (`builder.py:164-215`)
**Existing (unchanged) `finish()`-side guard D-06 keeps:** `_copy_used_template_bundles()` A-01 check at `builder.py:1628-1639`, resolution construction at `builder.py:1610-1626`

**Call-site slot** (`builder.py:935-964`, verbatim, current tree):
```python
# D-02/D-03: validate BEFORE anything is written -- the per-docname
# content and wrapper files below are the first things write()
# produces on disk. ...
self._validate_output_path_collisions()

self._document_template_registry = resolve_template_registry(
    self.config, str(self.srcdir)
)

# Phase 53 plan 06 (CONF-14, ROADMAP SC#3): validate every usable
# typst_documents entry's registry key reference HERE, before
# prepare_writing() writes anything, ...
self._validate_registry_key_references()

logger.info("preparing documents... ", nonl=True)
self.prepare_writing(docnames)
logger.info("done")
```
The new call (per D-04) goes immediately after `self._validate_registry_key_references()` and before
`logger.info("preparing documents... ", ...)`. No `try`/`except` exists between `write()` and
`finish()` in Sphinx's own `Builder.build()` (`sphinx/builders/__init__.py:389-465`, confirmed by
RESEARCH.md) — a raise here structurally guarantees zero `.typ` files and `finish()` never runs.

**Accumulate-then-raise-once pattern to copy** (`builder.py:690-778`, condensed to the load-bearing
shape):
```python
claims: Dict[str, str] = {}
failures: List[Tuple[str, str]] = []

def _claim(relpath: str, description: str) -> None:
    key = self._collision_key(relpath)
    existing = claims.get(key)
    if existing is not None:
        failures.append(
            (relpath, f"{existing} and {description} both resolve to "
             f"the same output path {relpath!r}")
        )
        return
    claims[key] = description

# ... iterate sorted/stable-ordered input, calling _claim() / appending
# directly to failures for a second failure kind (mirrors OUT-07's
# _reserves_template_prefix() check riding alongside the collision claim
# in the SAME failures list, builder.py:718-727) ...

if failures:
    summary = "; ".join(f"{relpath!r}: {message}" for relpath, message in failures)
    raise ExtensionError(f"typst: {len(failures)} output path collision(s): {summary}")
```
Pitfall 4 in RESEARCH.md is explicit: do NOT copy the `finish()`-side A-01 raise's *immediate*-raise
shape (below) into the pre-write pass — both the CONF-17 hoist and the `templates_path` collision
check must feed the SAME accumulate-then-raise-once `failures` list, iterated in `sorted()` key order
(D-03).

**Reused CONF-17 predicate** (`template_registry.py:137-176`, import and call unchanged — do not
re-derive):
```python
def _violates_conf17(template_abs_path: str, srcdir: str) -> bool:
    parent = os.path.normpath(os.path.dirname(os.path.abspath(template_abs_path)))
    norm_srcdir = os.path.normpath(os.path.abspath(srcdir))
    try:
        return os.path.commonpath([norm_srcdir, parent]) == parent
    except ValueError:
        # cross-drive Windows paths can never share an ancestor -> False
        return False
```
Note it does NOT case-fold (unlike `_collision_key()`) — RESEARCH.md flags this as an open
assumption (A1/Open Question 2), not a locked decision; state whichever choice is made explicitly in
the new method's docstring, following this codebase's convention (see `_collision_key()`'s own
docstring for the "state the scope decision inline" convention to imitate).

**The finish()-side resolution construction to replicate for the pre-write pass** (`builder.py:1610-1639`,
verbatim — the pre-write pass must reproduce this SAME construction per used key, not invent a
different one; D-06 explicitly accepts this write()-vs-finish() duplication):
```python
raw_template_path = entry.template
template_path = None
if raw_template_path:
    template_path = path.join(self.srcdir, raw_template_path)
search_paths = [path.join(str(self.srcdir), TEMPLATE_SEARCH_SUBDIR)]
package_for_engine = resolve_package_for_engine(entry.package, raw_template_path)

template_engine = TemplateEngine(
    template_path=template_path,
    search_paths=search_paths,
    typst_package=package_for_engine,
    typst_template_function=entry.template_function,
)
resolution = template_engine.resolve_template()
resolved_path = resolution.path

if _violates_conf17(str(resolved_path), str(self.srcdir)):
    raise ExtensionError(
        f"typst_document_templates: registry key {key!r}'s "
        f"resolved template {str(resolved_path)!r} has a "
        "parent directory that is srcdir itself, or an "
        f"ancestor of srcdir ({str(self.srcdir)!r}) -- put "
        "the template in its own subdirectory (CONF-17, A-01)"
    )
```
Pitfall 1 (RESEARCH.md): gate the new `templates_path` containment check on
`resolution.source != "default"` before running it — a default-sourced bundle lives inside the
installed package, never under `srcdir`, and must never be tested for `templates_path` containment.
Skip entries where `entry.package and not entry.template` (package-alone has no bundle — mirrors
`builder.py:1605-1608`).

**Reserved-key case-fold routing (D-07)** — route through `_collision_key()` exactly as it already
exists (`builder.py:493-571`), comparing against `RESERVED_REGISTRY_KEY` (`template_registry.py:38`).
Do not write a second `.casefold()`/`.lower()` helper.

**Deriving the checked key set (D-05)** — `_default_typst_documents()` (`builder.py:218-237`) and
`_is_usable_typst_documents_entry()` (`builder.py:164-215`) together define "every usable entry";
this is the SAME predicate `_validate_registry_key_references()` (`builder.py:839-843`) already
iterates:
```python
typst_documents = getattr(self.config, "typst_documents", []) or []
for entry in typst_documents:
    if not _is_usable_typst_documents_entry(entry):
        continue
    resolve_registry_key(self._document_template_registry, entry)
```
When `typst_documents` is unset, `Config.__getattr__` falls back to the callable default
`_default_typst_documents(config)` (`builder.py:218-237`) — the new pass must derive its key set the
same way `_document_template_registry` resolution already does, not special-case the unset case.

**New path-relationship predicate (does not exist yet — sketch only, per RESEARCH.md Pattern 2)**,
generalizing `_violates_conf17()`'s `commonpath()` idiom to a three-way is/contains/is-contained-by
test:
```python
def _paths_related(path_a: str, path_b: str) -> bool:
    """True if path_a IS path_b, path_a CONTAINS path_b, or path_a IS CONTAINED BY path_b."""
    norm_a = os.path.normpath(os.path.abspath(path_a))
    norm_b = os.path.normpath(os.path.abspath(path_b))
    try:
        common = os.path.commonpath([norm_a, norm_b])
    except ValueError:
        return False  # cross-drive on Windows -- cannot be related
    return common == norm_a or common == norm_b
```
Pitfall 3: always `os.path.abspath()` BOTH operands before `commonpath()` — a `templates_path` entry
is typically a short relative string (`["_templates"]"`) and must be resolved against `self.srcdir`
(never `self.confdir` — Pitfall 2 explains why `srcdir` is correct here) before comparison.

### `tests/test_templates_path_collision_gate.py` (new — WR-01 subprocess gate)

**Analog:** `tests/test_template_prefix_reservation_gate.py` — reuse its `_run_sphinx_build()` helper
verbatim (each gate module in this suite carries its own copy rather than importing a sibling's, per
`tests/test_registry_prewrite_validation_gate.py`'s own docstring convention):
```python
def _run_sphinx_build(
    source_dir: Path, build_dir: Path, builder: str
) -> subprocess.CompletedProcess:
    """
    Run ``sphinx-build -b <builder>`` as a subprocess...
    Invoked as ``sys.executable -m sphinx`` (never ``uv run sphinx-build``,
    never a resolved ``sphinx-build`` binary)...
    """
    return subprocess.run(
        [sys.executable, "-m", "sphinx", "-b", builder, str(source_dir), str(build_dir)],
        capture_output=True,
        text=True,
    )
```
and its "zero `.typ` files after refusal" test shape, `test_no_typ_file_written_after_refusal`
(`:154-163`):

### Repo-wide-grep-as-executable-assertion module (new — WR-01 documentation half, SC#2)

**Closest analog:** `tests/test_preview_version_sync.py` — but explicitly **not an exact shape**:
its glob-and-regex-extract pattern (`EXAMPLES_DIR` glob at `:34`, `_PREVIEW_IMPORT_RE` at `:38-41`)
is a "do these N sites AGREE with each other" check, extracting a *value* (version string) from each
site and comparing them. SC#2's need is different: "does ANY file under `docs/source/` + `README.md`
+ `examples/` recommend putting a Typst template under `_templates/`" — a *presence* check (does the
string/pattern `_templates/` appear in a "typst_template = ..." context), not a cross-site agreement
check. Say so explicitly in the new module rather than forcing the version-sync shape onto a
different kind of assertion. Reusable structural elements from `test_preview_version_sync.py`:
- `REPO_ROOT = Path(__file__).resolve().parents[1]` anchor
- glob-based file discovery (`EXAMPLES_DIR.glob(...)` pattern) rather than a hardcoded file list —
  this directly satisfies D-08/D-12's "repo-wide grep at discovery time, not the enumerated floor"
  requirement
- a regex tuned to match only the load-bearing pattern (an actual `typst_template = "..."` /
  `typst_template = '...'` assignment whose value starts with `_templates/`), not bare mentions in
  prose — mirroring `_PREVIEW_IMPORT_RE`'s own care to match only real import statements, not
  docstring examples
- scope: exactly `docs/source/` + `README.md` + `examples/` (D-12) — `tests/`/`tests/fixtures/` are
  explicitly NOT policed (measured zero-hit basis in D-12).

## Shared Patterns

### Accumulate-then-raise-once with `sorted()` iteration (D-03)
**Source:** `typsphinx/builder.py:625-779` (`_validate_output_path_collisions()`), specifically the
`claims`/`failures` dict-and-list pair and the final `if failures: raise ExtensionError(...)` block.
**Apply to:** the new combined pre-write method (both the hoisted CONF-17/A-01 check and the new
`templates_path` collision check must share ONE `failures` list per Pitfall 4).

### Case-folding via `_collision_key()` (D-07)
**Source:** `typsphinx/builder.py:493-571`.
**Apply to:** the reserved-key case-collision check only, per D-07's explicit "never a second
case-folding primitive" instruction. Whether the NEW `templates_path` containment test should ALSO
route through this same primitive is Claude's Discretion (RESEARCH.md Assumption A1 / Open
Question 2) — not settled by CONTEXT.md.

### Subprocess build gate via `sys.executable -m sphinx` (all new test modules)
**Source:** `tests/test_template_prefix_reservation_gate.py:53-77` and
`tests/test_registry_prewrite_validation_gate.py:29-50` (identical helper, independently copied in
each module per this suite's established convention — do not import across test modules).
**Apply to:** all three new gate test modules (`test_templates_path_collision_gate.py`,
`test_conf17_prewrite_gate.py`, `test_reserved_key_case_prewrite_gate.py`).

### Pre-write validation docstring convention (naming known gaps inline)
**Source:** `_validate_registry_key_references()`'s docstring (`builder.py:780-838`) and
`_collision_key()`'s docstring (`builder.py:494-568`) both explicitly state their own scope
limitations inline (e.g. "does NOT apply Unicode normalization", "covers EVERY declared entry...").
**Apply to:** the new method(s)' docstrings should likewise state explicitly: (a) whether
`templates_path` containment is case-folded, (b) that `-c` (separate confdir) is not covered (Pitfall
2), (c) that declared-but-unreferenced registry keys are NOT checked pre-write (Claude's Discretion
"do not widen" recommendation).
