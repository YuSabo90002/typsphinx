The `plan:pre` assumption-delta detector fired (`detected: true`) on two signals, both of which are
prose artifacts rather than architectural changes: the word "multiple" inside the quoted Typst error
`label ... occurs multiple times`, and the word "chosen" inside "before any fix is chosen." Neither
is a pluralization of a domain concept.

There is nonetheless one genuine identity question in scope, so it is answered explicitly rather
than left implicit:

- **Primary noun:** the table node's `ids` list. `ids[0]` is the id that owns the emitted figure
  `<label>`; `ids[1:]` are propagated ids that become `metadata(none)` anchors.
- **Decision: `no-change`.** D-02 locks the current model: the first id keeps the figure label and
  the remainder keep the anchor form. Rationale — typsphinx renders every same-document reference as
  `link(<label>, ...)`, which resolves against either anchor form, so promoting the human-authored
  id would change emitted bytes for every existing document with zero functional gain.
- **Accepted consequence:** for a captioned table with no `:name:`, a docutils auto id owns the
  figure label and the human-authored target id is the one carried as an anchor. That asymmetry is
  accepted, not debt to unwind. What would force a later promote: a requirement that `:numref:`
  text be derived from the human-authored id.
- **Companion invariant test:** already present — the D-03 no-duplicate-label assertion and the
  dangling-reference sweep in plan 42-01's module go red the instant a future change reassigns which
  id owns the label without updating `skip_ids` in lockstep.
</assumption_delta_decision>
