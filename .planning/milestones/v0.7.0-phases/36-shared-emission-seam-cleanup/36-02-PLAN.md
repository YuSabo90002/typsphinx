## The one thing most likely to go wrong in this plan

36-RESEARCH.md measured, on a real build, that a rubric carrying a propagated explicit target inside
a list item currently emits **two** blank lines between its anchor and its opening wrapper. Three
independent pieces of code each write a newline against the same still-true
`list_item_needs_separator` flag and none of them resets it: `_emit_id_anchors`'s internal
consume-then-re-set, `visit_rubric`'s own unconditional newline append, and the copied-in leading
separator check. It looks like an obvious bug. It is out of scope. D-01's copy mandate requires
reproducing it exactly, and the SC#2 fixture (construct R2 in
`tests/fixtures/desc_rubric_decoupling_render_gate/index.rst`) exists specifically to catch a
well-meaning cleanup here. If the byte-identity test fails on that construct, the copy was tidied —
restore the redundancy, do not adjust the golden.

The second-most-likely failure is swapping `depart_desc_signature`'s hand-rolled id-anchor loop for a
call to the shared `_emit_id_anchors` helper. It looks like a DRY improvement; the shared helper
emits a trailing newline after each closing bracket that the hand-rolled loop deliberately omits, so
the swap adds bytes.
