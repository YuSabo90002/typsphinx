Rewrite `depart_desc` per contract §8: if the translator is not currently rendering into a table cell
AND the marker equals the current `len(self.body)`, return without emitting — nothing has been emitted
since the previous `desc`'s break, which is the nested-`desc` case. Otherwise call the existing
`_emit_forced_break` with the paragraph-break token exactly as today, then record the new marker.

Three properties the implementation must have, each of which the plan asserts:

1. **The early return must NOT update the marker.** That is what makes three levels of nesting still
   produce exactly one break rather than one per pair.
2. **Do not implement this as a desc-nesting-depth counter.** A depth counter suppresses the *inner*
   `desc`'s break, which is wrong whenever the parent's body continues after the nested member — the
   member and the following paragraph would run together. The correct discriminator is "was anything
   emitted between the two departures".
3. **The `in_table` guard is required, not defensive noise.** `add_text` routes into
   `table_cell_content` rather than `self.body` inside a table, so `len(self.body)` would not advance
   between two departures there and the suppression would fire wrongly. Inside a table the pre-phase
   unconditional behaviour is retained.

Update `depart_desc`'s docstring: keep the existing FID-06 explanation of why the break is a real
`parbreak()` rather than a cosmetic source newline, and add the SIG-08 paragraph explaining the marker
and, explicitly, why a depth counter was rejected — so a later reader does not "simplify" it back.

Touch nothing else. In particular do not touch `visit_desc_signature`'s FID-03 sibling `linebreak()`
(contract §8: the two mechanisms solve different problems and deliberately do not converge), and do
not touch `visit_desc_content`/`depart_desc_content` (D-09: Phase 38 owns them).
  </action>
