<objective>
Land the two folded rubric defects: give `visit_rubric` and `depart_rubric` their own save slots so a
nested inline-markup child can no longer destroy the state the rubric needs restored, and stop the
rubric from adding a separator newline the id-anchor emitter has already added. Then regenerate the one
golden file whose bytes legitimately change, by hand-derivation.

Purpose: plan 39-02 recorded both defects RED. The first is this phase's classic GATE-01 RED — its
visible consequence is that every paragraph after an inline-markup rubric loses its paragraph wrapper,
to the end of the document. The second is the double-blank-line wart that `visit_rubric`'s own
docstring names this phase as the owner of.

Output: an edited `typsphinx/translator.py` scoped strictly to the two rubric handlers, and a
regenerated `tests/fixtures/desc_rubric_decoupling_render_gate/golden.typ`. This plan does NOT edit
`visit_strong`, `depart_strong`, `visit_desc_signature` or `depart_desc_signature`, and it does NOT
touch Phase 38's indent wrapper — the rubric consumes that step, it does not redefine it.
</objective>

  <action>
Guard `visit_rubric`'s leading-separator emission so the rubric contributes no newline that
`_emit_id_anchors` has already contributed.

The double-count has two halves and both must be closed. `_emit_id_anchors` emits its own leading
separator newline when the node is inside a list item with the flag already set, and emits its own
trailing newline after the anchor; it then re-arms the flag on its way out. `visit_rubric` afterwards
appends an unconditional newline and then, because the flag was just re-armed, appends a second one
from its own separator check. So when the rubric is anchored, the rubric owes zero further newlines;
when it is not anchored, it owes exactly what it emits today.

The concrete shape is Claude's discretion. A workable form: capture whether `_emit_id_anchors` emitted
anything — either by observing the emission buffer's length across the call or by reading the node's
ids before calling it — and make both the unconditional append and the separator check conditional on
it having emitted nothing. Do not close only one half; closing only the unconditional append leaves
the re-armed flag firing the other one.

Do not change `_emit_id_anchors`. It is shared by many body-element handlers and its bookkeeping is
correct for all of them; the double-count is the rubric's for adding a second separator on top.

Verify against all four behavioural cases before moving on, not only the one the fixture exercises:
anchored inside a list item, anchored at top level, unanchored inside a list item, unanchored at top
level. The anchored-at-top-level case is exercised by
`tests/fixtures/rubric_propagated_target_render_gate/`, and its separator shape changing is the same
wart, not a regression — re-derive any assertion in that module that moves, by hand, and record it.

Add a short comment at the guard naming D-11 and stating that the id-anchor emitter already handled
separation, so a future reader does not re-add the unconditional append.

| Boundary | Description |
|----------|-------------|
| One handler's instance state → another handler's restore path | The three save slots are a real internal trust boundary: three handlers write the same `self.__dict__` keys, and the inner writer's deletion destroys the outer writer's saved value. This plan moves that boundary. |
| `_emit_id_anchors`'s shared bookkeeping → every body-element handler that calls it | A change to the shared emitter would reach far beyond the rubric; this plan changes only the caller |
| translator → emitted `.typ` → `typst.compile()` | Where a mis-counted separator becomes a rendering defect or a build fatal |
