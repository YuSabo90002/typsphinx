<objective>
Record this phase's classic GATE-01 RED and the D-11 wart RED, both against the untouched translator,
both on real emitted bytes.

D-13's defect: a rubric containing a real inline bold child consumes and deletes the three save slots
its own handler shares with the bold handler (Phase 36 D-02 made that sharing deliberate), so
`depart_rubric`'s restore is silently skipped and the translator's list-item state stays stuck for the
rest of the document. The visible consequence is that every subsequent paragraph loses its paragraph
wrapper call. D-11's wart: a rubric carrying a propagated target inside a list item runs the
leading-separator check twice on top of an unconditional newline, producing two blank lines where one
separator was intended.

Purpose: both defects compile perfectly. Neither produces a Typst error, so the RED must be structural
— a wrapper call absent, a newline run over-long — and D-12 records that the phase's classic RED comes
from here, not from ADM-05's indentation property, which already holds.

Output: a new fixture and gate module for D-13, a newline-run assertion added to the existing
decoupling gate for D-11, and `39-GATE-EVIDENCE-02.md`. This plan does NOT touch `typsphinx/` and does
NOT regenerate `golden.typ`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.rst` fixture source → translator | Author-controlled build-time text; the only untrusted-input analog in a build-time tool |
| One handler's instance state → another handler's restore path | The shared save slots are a real internal trust boundary: three handlers write the same three `self.__dict__` keys, and the inner writer's `delattr` destroys the outer writer's saved value |
| translator → emitted `.typ` → `typst.compile()` | Where a mis-counted separator becomes a rendering defect or a build fatal |
