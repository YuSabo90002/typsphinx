<objective>
Implement the whole of Phase 40's source change: the definition-side handlers
(`visit_citation`, `depart_citation`, `visit_label`) that render a run of citation definitions as one
hanging-indent grid with HTML-shaped back-reference markers, and the guarded own-`ids` anchor in

`visit_reference`'s existing refid and xref branches already emit the right link call for both
same-document and cross-document sites. What is missing is the definition side, which today emits two
juxtaposed code-mode expressions and aborts the compile.

Add three handlers and one private helper. Model the open/close shape on
`_visit_admonition`/`_depart_admonition`, not on the footnote handlers.

The run-adjacency helper. Given a citation node and a direction, walk `node.parent.children` from
`node.parent.index(node)` one step at a time in that direction, skipping any sibling that emits
nothing -- a docutils comment or a system message -- and report whether the first sibling that WOULD
emit is another citation. Both `visit_citation` and `depart_citation` use this same helper, in
opposite directions. Scanning through emit-nothing siblings is load-bearing, not a nicety: this
repository's fixture convention puts a comment above and between constructs, and treating a comment
as a run break would silently split one rendered reference list into two independently-aligned grids
with no error anywhere.

`visit_citation`. Do NOT call `_emit_id_anchors` on the node -- the citation anchors its own id
through the label cell's bracket-wrap below, and defining the same label twice aborts the entire
compile at Typst's semantic pass, which is the hazard `visit_table` already documents for captioned
tables. Then:

- If the previous emitting sibling is not a citation, this is the first row of a run: emit the
  list-item leading newline the same way `_visit_admonition` does, then open a grid call with two
  columns, the first sized automatically and the second taking the remaining space. Give it a column
  gutter and a row gutter; the values are Claude's Discretion per D-04, and the probe in
  `40-RESEARCH.md` § "Code Examples" used half an em and four-fifths of an em respectively, which is
  a reasonable starting point. If the previous emitting sibling IS a citation, emit nothing here --
  the grid is already open and the previous row's trailing comma has already separated them.
- Render the label cell. Take the citation's first child, which is its `label` node, and render that
  node's OWN CHILDREN through the normal visitor chain using the buffer-swap idiom -- save
  `self.body`, swap in a fresh list, walk each child, join, restore. Walk the label node's children
  rather than the label node itself, because `visit_label` (below) skips the label node. Save and
  restore `in_paragraph` and `paragraph_has_content` around the swap, per the established convention;
  without that a nested child resets both on depart and silently clobbers the outer separator state.
  This routing is what puts the label text through the existing central escaping path, which is the
  whole of this phase's V5 input-validation surface -- do not interpolate the label's raw text into a
  string literal instead.
- Compose the label cell content from the buffered label content and the length of the node's
  `backrefs` list, in the three shapes D-03 and D-07 fix. In every shape the label text is surrounded
  by literal square brackets, matching CIT-02's `[Label]` requirement and Sphinx's own HTML. With zero
  backrefs, the bracketed label is plain, non-linked text (D-07). With exactly one, the label text
  inside the brackets becomes a link to that single citing site's anchor and no parenthesised marker
  is emitted (D-03; Sphinx HTML puts the anchor tag inside the brackets, so the brackets stay outside
  the link). With two or more, the bracketed label stays plain and is followed by a parenthesised
  list of one-based ordinal markers, each linking to its own citing site's anchor, separated by a bare
  comma with no space (D-03), the whole marker group sitting immediately after the label in the same
  left column (D-02).
- Compute every back-reference target with `_namespace_label` over the CITATION node's own `docname`
  attribute -- Sphinx adds it -- never over `_current_docname()`. For a definition the two usually
  coincide, which is precisely why using the wrong one would pass every single-document test and fail
  only on D-10's duplicate-key case. Skip a backref entry whose anchor Task 1 declined to emit (the
  citation-derived reference that was immediately followed by an explicit target), so the marker list
  never points at a label that does not exist; renumber the remaining markers so the visible ordinals
  stay contiguous.
- Attach the citation's own definition anchor to the whole label cell using the bracket-wrap
  label-attachment form -- the same shape `depart_term` uses. Derive the token with `_namespace_label`
  over the node's own `docname` and its first id. If the node carries no ids at all, emit the cell
  without an attachment rather than emitting a malformed one.
- Emit the label cell, then the cell separator, then open the body cell as a code block so the

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.rst` source -> translator | Author-controlled build-time text. A citation key, a docname and an entry body all cross here and all reach either a Typst string literal or a Typst label token. |
| translator -> emitted `.typ` -> `typst.compile()` | Where a mis-derived label token, a duplicated label definition, or a miscounted separator becomes a whole-document compile abort. |
| docutils `backrefs` / `ids` -> emitted link targets | The definition side emits links to anchors that only the citing side defines; a mismatch on either side is a fatal `label does not exist`, and a double definition is a fatal `label occurs multiple times`. |
