<worktree_provisioning>
Worktree isolation is this project's STANDING execution mode (CLAUDE.md § "Worktree-isolated
execution"). Before ANY other command, run once from the worktree root:

1. `env -u VIRTUAL_ENV -u UV_PROJECT_ENVIRONMENT uv sync --extra dev`
2. `for t in uv ruff; do ln -sf "$(command -v $t)" ".venv/bin/$t"; done`

Then invoke EVERY command through `uv run`.

**Both shims are mandatory and non-optional for this plan specifically.** STATE.md § "Operator Next
Steps" records the measurement: a fresh worktree's `uv sync`-installed `.venv/bin/uv` is itself a
generic-linux ELF that fails under the NixOS stub loader with exit 127, and it shadows the correct
Nix-store `uv` on `PATH` for any `subprocess.run(["uv", "run", "sphinx-build", ...])` child. Without
both shims, 45 integration tests fail with exit 127 — and this plan's entire output is a claim that
the suite is green, so a false RED here would be recorded as a phase-blocking failure that does not
exist. Create both shims via `command -v` BEFORE any `.venv/bin` entry is on `PATH`, and record in
the evidence file that you did.

Before starting, confirm the post-bump state actually reached this worktree:
`uv run python -c "import typsphinx; print(typsphinx.__version__)"` must print `0.7.0`. If it prints
anything else, the wave-1 merges have not landed here and every measurement below would describe the
wrong tree — stop and report it.
</worktree_provisioning>
