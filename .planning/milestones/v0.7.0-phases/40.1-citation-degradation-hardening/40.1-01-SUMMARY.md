## Decisions Made

- **G1 (silent degradation):** neither arm of the backref filter warns. Rationale (three points, recorded in `40.1-GATE-EVIDENCE-01.md` §5): (1) the reproducible trigger is a legitimate `.. only::` documentation pattern, not an authoring error; (2) warning asymmetrically on only the new arm would reintroduce the exact asymmetry WR-01 closes; (3) the footnote dangling-target precedent doesn't transfer — here the citation *definition* exists, only a back-reference marker to a pruned citing site is dropped.
- **D-01 provenance:** WR-01's RED is a real `sphinx-build`, established on the first attempt (`.. only:: <undefined-tag>` around a citing `[Label]_`) — no assembled-doctree fallback was needed, per `40.1-CONTEXT.md` D-01's "enumerate attempts, don't prove impossibility" discipline.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed `_citation_row_region`'s cell-boundary-crossing regex in the new test module**
- **Found during:** Task 3, while re-verifying the marker-shape test post-fix (the second citation's row assertion failed on a captured fragment that included bytes from the FIRST citation's row too)
- **Issue:** The helper's non-greedy regex searched for `[#{...} <def_anchor>]` from the START of `index.typ`, so for the second-or-later citation row it matched the NEAREST `[#{` opener — which belongs to a different citation — silently capturing bytes across a cell boundary
- **Fix:** Rewrote the helper to locate the target def-anchor's own closing marker first, then scan BACKWARDS for its own `[#{` opener, guaranteeing the captured fragment belongs to that row alone
- **Files modified:** `tests/test_citation_degradation_gate.py`
- **Verification:** `uv run pytest tests/test_citation_degradation_gate.py -k wr01 -v` — all 5 pass post-fix
- **Committed in:** `1cf39c7` (separate from Task 3's translator.py fix, so Task 3's own commit touches only `typsphinx/translator.py` and the evidence file, per its acceptance criteria)
