## 4. D-01 attempt list for WR-01

Per `40.1-CONTEXT.md` D-01, "a real `sphinx-build` cannot construct this topology" is established by
enumerating attempts, not by proving impossibility. `40.1-RESEARCH.md` § "D-01/D-08 constructibility
findings" → "WR-01" already ran this enumeration this session (2026-08-02); it is carried here
verbatim rather than re-run, since RESEARCH's own finding already succeeded on the first attempt.

**Attempt 1 (SUCCEEDED): `.. only:: <tag-not-in-app.tags>` around citing `[Label]_` references.**

This is exactly the shape used in § 2 above (`.. only:: never`). Mechanism: Sphinx's `only`-tag
filter transform runs AFTER the citation domain's `backrefs`-population step, so a backref can name
a node the writer will never see. The reference inside the `only:: never` block is assigned an id
during Sphinx's read/resolve phase (before filtering removes the block's content from the doctree),
so that id makes it into the citation's `backrefs` — but the RESOLVED doctree the translator actually
walks no longer contains a `nodes.reference` carrying that id, because the `only`-tag filter already
pruned it. `_find_citing_reference(that_id)` therefore returns `None`, and unfixed `visit_citation`'s
`ref_node is not None and not ...` condition short-circuits to `False`, falls through the `continue`,
and appends a `link()` target for a label nothing ever attaches.

**Attempt 2 (NOT RUN, recorded for D-01 completeness): a citing site in a document excluded from
every toctree (`:orphan:`).** Not attempted because Attempt 1 already succeeded — no further attempts
were needed to establish constructibility. Judged (per RESEARCH) likely NOT to reproduce this
specific hazard: an orphan document's own citing reference and its citation definition would
typically be built independently of any master document, rather than sharing one `backrefs` list
across an include/exclude boundary the way the `only`-tag shape does.

**Attempt 3 (NOT RUN, recorded for D-01 completeness): an incremental/stale-environment second
build.** Also not attempted — Attempt 1 already succeeded, and simulating Sphinx's pickle-cache reuse
path across two builds has materially higher setup cost than the `only::` shape that already worked.

**Provenance verdict:** WR-01's RED is a **real `sphinx-build`**, not an assembled doctree — per D-01,
"a real build whenever one is available" — reproduced end-to-end in § 2/§ 3 above with the new
fixture, matching RESEARCH's own worked example exactly.

## 5. G1 decision: a skipped back-reference degrades silently (recorded, not deferred)

**Decision:** neither arm of `visit_citation`'s backref filter warns. The `ref_node is None` arm this
plan adds (Task 3) is silent, matching the already-shipped `_citing_reference_has_own_anchor`-returns-
`False` arm beside it.

**Rationale (three points, from `40.1-01-PLAN.md` § "Claude's-Discretion items", recorded here so a
future maintainer reads the reason rather than inferring it from the absence of a `logger.warning`
call):**

1. The reproducible real-build trigger is `.. only:: <tag>` around a citing `[Label]_` — a
   legitimate, common documentation pattern, not an authoring error. Dropping the back-reference
   marker for a citing site that genuinely is not in the output document is the *correct* answer, and
   warning on correct input is noise. This repository's own docs builds do not pass `-W`
   (`warningiserror`) today, but a downstream project that does would have correct sources turned
   into build failures by a warning here.
2. Warning on only one of the two arms of the same `if` would reintroduce exactly the asymmetry WR-01
   is about. Warning on **both** arms would change already-shipped Phase 40 behaviour that no decision
   in this phase authorises changing.
3. The nearest precedent — `visit_footnote_reference`'s dangling-target guard, which warns then skips
   — does not transfer here: it fires when the *target* is missing, a genuine authoring error. Here
   the target (the citation definition) exists; only a back-*reference* marker pointing at a
   non-existent citing site is dropped.

**Obligation this choice carries (stated explicitly, per `40.1-CONTEXT.md`):** because
`visit_citation` enumerates the **filtered** list, dropping a backref changes the marker's *shape*
under Phase 40's D-03. The emitted shape for every degraded citation is therefore asserted, not left
to chance — Task 2's fixture and tests carry all three transitions (3→2, 2→1, 1→0) and assert each
one explicitly (§ 3 above).
