## Warnings

### WR-01: `_resolve_xref_docname` still runs twice per citing reference with live backrefs — the "single derivation point" is unified in logic but not in call site, and the regression test doesn't catch it

**File:** `typsphinx/translator.py:2807-2899` (`_reference_anchor_decision`), consumed at `typsphinx/translator.py:3063` (`visit_citation`'s backref loop) and `typsphinx/translator.py:4354` (`visit_reference`)
**File:** `tests/test_citation_degradation_gate.py:1108-1161` (`TestWr03XrefResolutionAndWarningFireOnce`)

**Issue:** The phase's stated goal (translator.py:2807-2822's docstring, and the WR-03 section header in the test module) is that `_reference_anchor_decision` is now "the ONE place" the D-14 judgement is derived, consumed by both `visit_reference` and `visit_citation`'s backref loop, specifically so nothing computes it twice. In practice the *logic* was unified but the *call site* was not: for a citing reference that both (a) has a citation pointing back to it via `backrefs`, and (b) carries a `refuri` (the WR-03 topology itself), `_reference_anchor_decision` — and therefore `_resolve_xref_docname` — is invoked twice: once when the translator visits the reference node itself (`visit_reference`), and again later when `visit_citation`'s backref loop looks the same node up via `_find_citing_reference` and calls `_reference_anchor_decision(ref_node)` a second time.

I proved this by patching `TypstTranslator._resolve_xref_docname` with a call-counting `side_effect` wrapper and rendering `TestWr03DegradedCitingSiteAnchor`'s own fixture (a citing reference with `refuri` + a citation with `backrefs=["id1"]` pointing at it):

```
call_count: 2
```

(one call from `visit_reference`, one from `visit_citation`'s backref loop re-deriving the decision for the same node).

Currently this is harmless — `_reference_anchor_decision` is a pure function of `node` + fixed builder state, so both calls agree and no double-fire of the cross-document `logger.warning` occurs (that warning lives only in `visit_reference`'s own branch, never inside the predicate, confirmed by the same instrumentation run: exactly one warning fired). But the *test* that exists specifically to guard this exact concern —
`test_wr03_xref_resolution_happens_once_per_reference`, whose docstring says "the D-06 rewrite must not cause `_resolve_xref_docname` to run twice per reference (once inside the predicate, once again in `visit_reference`'s own downstream branches)" — builds a citing reference with **no** paired citation/`backrefs` at all (`_build_cross_doc_reference_doctree`, tests/test_citation_degradation_gate.py:1118-1131). That fixture can never exercise `visit_citation`'s backref loop, so the test only proves `visit_reference` itself doesn't call `_resolve_xref_docname` a second time internally — it does **not** prove the "once per reference" claim across both consuming call sites, which is exactly the scenario the WR-03 fixture two classes above (`TestWr03DegradedCitingSiteAnchor`) actually builds.

The practical risk: if a future change adds any side effect to `_reference_anchor_decision` (e.g. moving the cross-document degrade warning into the shared predicate — a natural-looking refactor given every other `_resolve_xref_docname`/`_namespace_label` call site in this file logs right next to the derivation), that warning would silently fire twice per citation with a degraded, backref'd citing site, and this test suite — despite having a test with exactly the right name and docstring — would not catch it, because the regression test's own fixture structurally cannot reach the double-invocation path.

**Fix:** Either (a) memoize the decision per node — e.g. cache `_reference_anchor_decision`'s result in a small `dict` keyed by `id(node)` populated the first time `visit_reference` computes it, and have `visit_citation`'s backref loop consult the cache before recomputing — or (b) at minimum, extend `TestWr03XrefResolutionAndWarningFireOnce` with a case built from `TestWr03DegradedCitingSiteAnchor`'s own topology (a citing reference *with* a paired citation/backrefs) so the "once per reference" claim is actually exercised end-to-end, e.g.:

```python
def test_wr03_xref_resolution_happens_once_per_reference_with_backref(self):
    original_resolve = TypstTranslator._resolve_xref_docname
    with mock.patch.object(
        TypstTranslator, "_resolve_xref_docname",
        autospec=True, side_effect=original_resolve,
    ) as mocked_resolve:
        doc = TestWr03DegradedCitingSiteAnchor()._build_degraded_doctree()
        _render_body(doc)
    # Document the CURRENT double-invocation explicitly (call_count == 2)
    # until (a) lands, rather than leaving the "once per reference" claim
    # unverified for the one topology where it actually applies.
```

## Info

### IN-01: WR-02's own docstring caveat about weakened list-item inertness is currently moot — citations inside a bare `list_item` are independently broken pre-existing, but the caveat text doesn't say so

**File:** `typsphinx/translator.py:2734-2752` (`_citation_run_neighbour` docstring's WR-02 caveat)

**Issue:** Out of scope for this phase (reproducible with or without the WR-02 fix, so it predates Phase 40.1 and isn't a regression the review needs to block on) — noted for awareness only. The docstring honestly flags that an ids-less `nodes.target` is only *approximately* inert inside a list item ("this inertness is *approximate* inside list items... strictly *weaker* than `comment`"), framing it as a minor separator-state nuance. I checked how far that nuance actually goes by hand-building the harness's own WR-02 topology (`a2020` citation, ids-less target, `b2020` citation) inside a `bullet_list`/`list_item` and compiling it: `typst.TypstError: expected expression`. I then removed the intervening target entirely (two citations back-to-back directly inside one bare `list_item`, no target at all) and got the *identical* failure — confirming the compile fatal is unrelated to WR-02's skip-list widening and instead a pre-existing defect in how citation grids render inside list items in general (unrelated to this phase's diff, out of scope per the review's scope note). Flagging only so the WR-02 caveat isn't misread as bounding the full list-item risk — the caveat's own "weaker than comment" framing undersells that citations-in-list-items don't compile at all today, target or no target, so the caveat's practical exposure is currently zero.

**Fix:** No action required for this phase. If the pre-existing citations-in-list-items defect is ever fixed, re-verify the WR-02 skip-list widening doesn't reopen the same style of separator-state bug documented in the caveat.
