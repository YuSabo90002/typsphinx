### Locked Decisions

**RED provenance and placement**

- **D-01: "A real `sphinx-build` cannot construct this topology" is established by enumerating the attempts, not by proving impossibility.** Per warning, build several RST shapes for real, measure each resolved doctree (`env.get_and_resolve_doctree`), and record what each one produced and why the target topology did not appear. Only after that list exists does the RED fall back to a directly-assembled doctree. Rejected: reading the docutils/Sphinx transform chain to prove the topology cannot be generated — high cost, and it bakes in a premise about today's Sphinx that WR-03 is precisely about not depending on. Also rejected: a single attempt then substitute — cheapest, but if the topology later turns out to be buildable, the recorded claim "not reproducible in a real build" is itself wrong.

- **D-02: Tests go in a new module with its own fixture directory, and Phase 40's are not touched.** `tests/test_citation_degradation_gate.py` plus `tests/fixtures/citation_degradation_gate/`. Rationale: SC#5 uses the byte-identity of Phase 40's fixture output as the control proving the change is confined to the degradation paths, and the cheapest way to keep that control honest is to not edit the thing being measured. Accepted cost: citation assertions now live in two modules (`tests/test_citation_render_gate.py` is 1,113 lines / 3 classes today), and any helper the new module wants from it must be duplicated or imported deliberately. Rejected: adding classes to the existing module, and splitting by evidence kind across the gate module and `tests/test_translator.py`.

- **D-03: RED evidence is recorded per plan, numbered the way Phase 40 numbered it.** `40.1-GATE-EVIDENCE-01.md`, `-02.md`, … one per plan, same convention as `40-GATE-EVIDENCE-01.md` (662 lines) and `-02.md`. Each file records, for every warning it covers, the enumerated RST attempts from D-01, the resulting provenance verdict, and the verbatim RED output. Rejected: one file with a section per warning (would make concurrent plans write to the same file under worktree-isolated execution). Consequence for planning: whoever splits this phase into plans must make the warning-to-plan mapping explicit, because the evidence filenames follow the plans, not the warnings.

- **D-04: The RED chases the real fatal wherever the fatal is reachable.** WR-01 and WR-03 both terminate in a `link()` to a label nothing attaches, so their RED is the classic `typst.compile()` failure with the verbatim error captured — reclaiming, for these two, the classic RED that the v0.7.0 GATE-01 amendment otherwise reserves to Phase 40 / CIT-01. This holds even when the topology comes from a directly-assembled doctree: the translator still produces a `.typ` and that `.typ` can still be compiled. WR-02 compiles cleanly by construction (it is a silent misalignment), so its RED is a structural assertion on the emitted `.typ` — the count of `grid(` openings across the citation run. Rejected: one structural form for all three, and layering both forms on every warning.

**WR-03 — removing the duplicated D-14 eligibility judgement**

- **D-05: The D-14 judgement is extracted into one shared predicate that both call sites consult.** `visit_reference` (translator.py:4226) currently decides with `node.get("ids") and opens_wrapper and not next_is_target`; `_citing_reference_has_own_anchor` (2712-2742) re-derives the same answer from the `next_is_target` half alone. After this phase there is exactly one place where that condition is written, so the two cannot drift. Rejected: having the callee also check the remaining two conditions (the review's own second suggestion) — smaller, and it leaves `visit_reference`'s hot path untouched, but the condition still exists in two places and only a test would hold them together. Also rejected: recording the anchors actually emitted in a set and having `visit_citation` consult it — the strongest form in principle ("fact" rather than "matching judgement"), but it is visit-order dependent, and a forward reference (definition before citing site, a shape Phase 40's own probe carries) would query the set before the anchor was recorded.

- **D-06: The predicate derives its own inputs — it takes the node, not three booleans.** `refuri`, `refid`, `degrade_xref_to_text` and `next_is_target` are all derived inside it, and `visit_reference` uses the predicate's answer instead of its own local `opens_wrapper` computation (4191). Both the judgement and the derivation of its inputs then exist in exactly one place. Note `degrade_xref_to_text` reads `builder.master_included_docnames` (4162-4165), so the predicate is not a pure function of the node — it needs builder state, the same way `visit_reference` does today. **Consequence, stated at decision time: this rewrites a hot path taken by every link in the codebase, so D-14's non-regression obligation must be re-discharged for this phase — byte-identical emission for every reference that is not a citation target, with the full-corpus `-b typstpdf` gate as the evidence.** Rejected: a pure predicate taking three booleans (judgement in one place, derivation still in two — the drift just moves upstream). Also rejected: leaving the builder-dependent half out of the predicate, which would take back the one route by which `opens_wrapper` provably goes false today.

- **D-07: The predicate returns the anchor label too, not just a boolean.** Measured this session: the label string is also built independently at two sites — `_namespace_label(self._current_docname(), node["ids"][0])` in `visit_reference` (4227-4229) and `_namespace_label(docname, refid)` in `visit_citation` (2862). For a same-document backref the two coincide (D-08/D-13 explain why), but nothing in the code enforces it. Returning "if it anchors, this is the label" makes the link target and the attached anchor come out of one expression, closing a second drift source of the same class as WR-01/WR-03 in the same change. It is also the natural extension of Phase 40's D-13 (every emitted label has a single derivation point). Rejected: boolean only, on the argument that `_namespace_label`/`_sanitize_label` are already the single derivation point so equal arguments suffice — true, but "equal arguments" is exactly the unenforced invariant WR-03 is about. Also rejected: a separate label helper alongside the predicate (cleaner separation, two new helpers instead of one).

- **D-08: WR-03's RED measures both condition-breaking routes and takes whichever the real build can construct.** The two routes are `opens_wrapper` false (the `degrade_xref_to_text` path — an xref to a document not in `master_included_docnames`, which the review notes already proves `opens_wrapper` can be false for some references) and `ids` empty (unlikely under today's citation domain, which always populates `ids`, so it leans toward the assembled-doctree fallback). Both are attempted in a real build; the one that works becomes the RED and the other is written into D-01's attempt list. This is the same posture as D-01 rather than a second policy. Rejected: committing up front to either route alone.

## Summary

This phase closes three narrow, already-diagnosed gaps in Phase 40's citation code
(`typsphinx/translator.py`), each in the "graceful degradation" contract the citation feature is
supposed to apply consistently. The fixes themselves are small (a boolean flip in WR-01, one more
`isinstance` branch in WR-02, and a predicate extraction in WR-03) and are not this phase's hard
part. **The hard part, and the part this research settles empirically, is D-01/D-08's mandate: for
each warning, determine whether a real `sphinx-build` can construct the hazardous doctree topology,
and if not, say so with an attempt list, then fall back to a directly-assembled doctree.**

This session ran that protocol against Sphinx 9.1.0 / docutils 0.22.4 for all three warnings, with
concrete, reproducible results:

- **WR-01 IS constructible via a real `sphinx-build`.** A `.. only:: <undefined-tag>` block
  containing a citing `[Label]_` reference is pruned from the RESOLVED doctree
  (`env.get_and_resolve_doctree`) by Sphinx's own `only`-tag filtering, but the citation's
  `backrefs` list — populated earlier, before that pruning — still names the pruned reference's own
  `id`. `_find_citing_reference` then returns `None` for that id, and the CURRENT (unfixed)
  `visit_citation` appends the dangling label anyway. Reproduced end-to-end this session: a real
  `-b typstpdf` build over this exact shape emits `link(<index:id1>, [1])` with no matching
  `#label("index:id1")` anywhere in `index.typ`, and `typst.compile()` on that real output raises
  `TypstError: label \`<index:id1>\` does not exist in the document` — the classic D-04 fatal,
  reproduced against a real build, not assembled.
- **WR-02 is NOT constructible via a real `sphinx-build`, in every RST shape attempted.** Every
  shape that produces an ids-less `nodes.target` (chained internal targets, duplicate-named
  targets) does so only as the NON-TERMINAL member of a 2+-node adjacent target chain; the chain's
  terminal member always keeps a real, non-empty `ids` and sits immediately next to the ids-less
  one — so it independently breaks the citation run regardless of whether the WR-02 fix is applied.
  A minimal "exactly one emit-nothing sibling between two citations" topology could not be produced
  this way. WR-02's RED falls back to a directly-assembled doctree (trivial: insert a bare
  `nodes.target()` with `ids=[]` between two `nodes.citation` siblings via the docutils API
  directly, bypassing the transform chain that always pairs it with a real-id sibling in a real
  build) — verified this session to reproduce exactly the pre-fix defect (2 grids instead of 1).
- **WR-03 is NOT constructible via a real `sphinx-build`, on EITHER of D-08's two candidate routes.**
  Route "`ids` empty": structurally unreachable through `_citing_reference_has_own_anchor`'s only
  real caller (`_find_citing_reference` only ever returns a node whose `ids` already contains the
  `refid` being searched for, so `node.get("ids")` is non-empty by construction for any node that
  function returns) — this is a fact about the code's own control flow, not about what Sphinx
  produces, so it holds independent of Sphinx version. Route "`opens_wrapper` false via
  `degrade_xref_to_text`": requires a `refuri`-carrying reference whose id is ALSO in some
  citation's same-document `backrefs` — but independently reproduced this session that (a) a
  same-document citing reference always carries `refid`, never `refuri` (mutually exclusive), and
  (b) `backrefs` never contains a cross-document citing site's id (confirmed directly: a
  cross-document citing reference's own `id` is absent from the target citation's `backrefs` list,
  even though that reference happens to carry a same-shaped `id1`-style id in its OWN document's
  namespace). Both attempts are recorded; WR-03's RED is directly-assembled — verified this session
  with a working stub-builder script that reproduces the exact fatal
  (`TypstError: label \`<index:id1>\` does not exist in the document`) against the UNMODIFIED
  current translator.

**Primary recommendation:** Split GATE-EVIDENCE recording per D-03's per-plan convention using the
reproductions below directly — WR-01's real-build `only::` shape needs no new scaffolding beyond
what `tests/test_citation_render_gate.py` already uses (subprocess `sphinx-build -b typstpdf`); WR-02
and WR-03 both need a small hand-built-doctree harness (a `TypstTranslator` instantiated with a
`StubBuilder`, `document.walkabout(translator)`, then `translator.astext()` wrapped in
`"#{\n" + body + "}\n"` and compiled directly via `typst.compile()` with NO template/imports needed —
this exact wrapping is what `TypstWriter.translate()` does for a non-master document body, verified
by reading `typsphinx/writer.py:132-141`). Concrete code for both harnesses is in "Code Examples"
below, already run and verified against the CURRENT (unfixed) translator this session.

## D-01/D-08 constructibility findings

All measurements below were run this session (2026-08-02) against the installed Sphinx 9.1.0 /
docutils 0.22.4 / typst-py 0.15.0, via real `sphinx-build`/`typst.compile()` invocations in a scratch
project — never from training-data recall. `[VERIFIED: real sphinx-build + typst.compile(), this
session]` unless otherwise marked.

### WR-01 — citing reference not found for a backref id

**Attempt 1 (worked): `.. only:: <tag-not-in-app.tags>` around a citing `[Label]_` reference.**

```rst
.. only:: never

   Cite here [Krizhevsky2012]_ inside an excluded only-block.

See [Krizhevsky2012]_ for details. Also cited again [Krizhevsky2012]_.

.. [Krizhevsky2012] Krizhevsky, A. et al.
```

Dumping the RESOLVED doctree (`env.get_and_resolve_doctree`):

```
CITATION ids= ['krizhevsky2012'] backrefs= ['id1', 'id2', 'id3'] docname= index
REF ids= ['id2'] refid= krizhevsky2012 refuri= None text= [Krizhevsky2012]
REF ids= ['id3'] refid= krizhevsky2012 refuri= None text= [Krizhevsky2012]
```

`id1` — the reference INSIDE the `only:: never` block — was assigned during Sphinx's read/resolve
phase (before `only`-tag filtering removes the block's content from the doctree the writer sees),
so it made it into `backrefs`, but the resolved doctree the translator actually walks has only TWO
`reference` nodes (`id2`, `id3`). `_find_citing_reference('id1')` therefore returns `None`.

**Why it works:** the `only`-tag filter transform runs AFTER the citation domain's
`backrefs`-population step, so a backref can point at a node the writer will never see. This is a
genuine, reproducible topology under real Sphinx — not hypothetical.

**Confirmed fatal, real translator, real build (unfixed code):**

```
$ sphinx-build -b typst <src> <build>   # exits 0, warns nothing about this
$ python -c "import typst; typst.compile('<build>/index.typ')"
typst.TypstError: label `<index:id1>` does not exist in the document
```

The relevant fragment of the real emitted `index.typ` (label cell of the grid row):

```typst
[#{text("[") + text("Krizhevsky2012") + text("]") + text(" (") + (link(<index:id1>, [1]),link(<index:id2>, [2]),link(<index:id3>, [3])).join(",") + text(")")} <index:krizhevsky2012>], {par({text("Krizhevsky, A. et al.")})
```

`link(<index:id1>, [1])` targets a label that is emitted nowhere in the document — only
`#label("index:id2")` and `#label("index:id3")` exist. **This is the WR-01 RED, reproduced against a
real `sphinx-build`, real `typst.compile()`, unfixed translator. Use this shape (or an equally
minimal variant) for the phase's GATE-EVIDENCE, not an assembled doctree — D-01 prefers a real build
whenever one is available.**

**Other attempts considered but not run (recorded for D-01 completeness, since attempt 1 already
succeeded no further attempts were exhausted, but these remain plausible alternates a future
maintainer might reach for):** a citing site in a document excluded from every toctree (`:orphan:`)
— untested, likely does not reproduce this specific hazard since an orphan doc's own citing
reference and its citation definition would typically be built independently rather than sharing one
`backrefs` list across the include/exclude boundary; an incremental/stale-environment second build —
untested, would require simulating Sphinx's pickle-cache reuse path, higher setup cost than the
`only::` shape which already succeeded.

### WR-02 — ids-less `nodes.target` between two citations

**Attempts (all did NOT produce the minimal single-blocker topology):**

1. **A single named internal target with no URI directly between two citations**
   (`` .. _`anonymous target`: `` / `.. _alias-one:` alone). Result: the target keeps its OWN id
   (`ids=['alias-one']` or similar) — never empty. `[VERIFIED]`
2. **Two adjacent named internal targets with DIFFERENT names, chained**
   (`.. _alias-one:` immediately followed by `.. _alias-two:`, then a citation). Result: the FIRST
   of the pair gets `ids=[]`, the SECOND gets the merged real ids
   (`ids=['alias-two', 'alias-one']`) — TWO target siblings exist between the citations, one
   ids-less and one real. `[VERIFIED]`
3. **Two adjacent targets with the SAME name (duplicate target, triggers a Sphinx warning)**
   (`.. _dup:` immediately followed by `.. _dup:`). Same shape as attempt 2: first `ids=[]`, second
   `ids=['id5', 'dup']`. `[VERIFIED]`
4. **A true anonymous target (`__ <uri>`, double-underscore form).** Result: gets its own
   auto-assigned id (`ids=['id4']`) — never empty. `[VERIFIED]`
5. **A single named target immediately preceding a citation (no second target in the chain).**
   Result: no propagation onto the citation node; the target keeps its own id, non-empty.
   `[VERIFIED]`

**Conclusion:** in every shape tested, an ids-less `nodes.target` is produced ONLY as the
non-terminal member of a 2+-node chain of adjacent target directives, and docutils' target-chaining
transform (0.22.4) always leaves the chain's TERMINAL member with a real, non-empty `ids`. Since
chain members are — by the chaining mechanism itself — mutually adjacent, the terminal (real-id)
member necessarily sits in the SAME gap between the two citations as the ids-less one, and it alone
is sufficient to break `_citation_run_neighbour`'s scan regardless of whether the WR-02 fix is
applied. **The minimal single-blocker WR-02 topology (citation, one ids-less target, citation,
nothing else in between) is therefore not constructible via a real Sphinx/docutils build in this
version, and WR-02's RED falls back to a directly-assembled doctree per D-01.** This finding is
provenance-worthy on its own (D-01's "a negative result is exactly as valuable as a positive one"):
a future maintainer reading only the review's suggested fix might assume some ordinary RST
reproduces this; it does not, in Sphinx 9.1.0 / docutils 0.22.4.

The assembled-doctree route is trivial and was verified this session (see Code Examples): build a
`nodes.target()` node with `node['ids'] = []` directly via the docutils node API (no parser, no
transform chain involved) and insert it as `section.children[i]` between two `nodes.citation`
siblings. This reproduces the CURRENT (unfixed) `_citation_run_neighbour` splitting one intended run
into 2 independently-aligned grids — the exact structural RED D-04 calls for.

### WR-03 — the two eligibility routes

**Route A — `_citing_reference_has_own_anchor`'s `ids`-empty gap.** Not a build-constructibility
question at all: it is a fact about `_citing_reference_has_own_anchor`'s only real caller. Re-read
`_find_citing_reference` (translator.py:2685-2710):

```python
for candidate in self.document.findall(nodes.reference):
    if refid in (candidate.get("ids") or []):
        return candidate
return None
```

Any node this function returns, by construction, has `refid` as a member of its own `ids` — so
`candidate.get("ids")` is non-empty for every node `visit_citation` ever passes to
`_citing_reference_has_own_anchor`. **The "ids empty" drift route the review describes is therefore
unreachable through `visit_citation`'s own call site, independent of Sphinx/docutils version** — it
would only become reachable if some FUTURE caller invoked `_citing_reference_has_own_anchor` with a
node obtained some other way (e.g. directly from `self.document.ids[refid]`, the STALE-pointer path
`_find_citing_reference`'s own docstring says it was written to avoid). Recorded here rather than
attempted-and-failed against a real build, because no real build is relevant to settling it — it is
a control-flow fact, verified by reading the code, not measured.

**Route B — `opens_wrapper` false via `degrade_xref_to_text`.** Attempted against a real two-document
build (`index.rst` toctree-including `second.rst`, citation defined in `second.rst`, cited once from
each document):

```
index REF ids= [] refid= None refuri= second.html
index REF ids= ['id1'] refid= None refuri= second.html#same2020
second CITATION ids= ['same2020'] backrefs= ['id1']
second REF ids= ['id1'] refid= same2020 refuri= None
```

The cross-document citing reference in `index.rst` DOES carry a non-empty own `id` (`'id1'` —
coincidentally, and confusingly, the SAME string as the same-document citing reference's id in
`second.rst`, since docutils' auto-id counter is per-document) — but `second.rst`'s citation's own
`backrefs` list contains only `['id1']`, which resolves to the SAME-DOCUMENT reference in
`second.rst` itself, never to the cross-document one in `index.rst`. **`backrefs` never contains a
cross-document citing site's id** (independently reproduced this session, corroborating
`40-CONTEXT.md` D-08's own prior measurement). Combined with the earlier, also-reproduced fact that a
same-document citing reference (the only kind that ever appears in `backrefs`) always carries
`refid`, never `refuri` (Sphinx's citation domain resolves same-doc citing sites via `refid` and
cross-doc ones via `refuri`, never both on one node) — and `degrade_xref_to_text` can only ever
become `True` when `refuri` is present (`xref = self._resolve_xref_docname(refuri) if refuri else
None`) — **route B is also not constructible via a real build: a node reachable through
`_find_citing_reference` never carries a `refuri`, so `opens_wrapper`'s `degrade_xref_to_text` term
can never be the reason it goes `False` for such a node.**

**Conclusion:** both of D-08's candidate routes are unreachable via a real `sphinx-build` under
Sphinx 9.1.0. WR-03's RED is directly-assembled for both, hand-constructing a reference node that

### Anti-Patterns to Avoid

- **Recomputing `refuri`/`degrade_xref_to_text` a second time inside the new shared predicate AND
  independently inside `visit_reference`'s existing degrade-to-text warning branch.** See "Landmines
  in the D-06 predicate extraction" below — this risks a duplicate `logger.warning` call per degraded
  reference, and risks the two computations drifting if one copy is edited later and the other is
  not. The predicate must be pure/silent (no logging, no side effects); `visit_reference` keeps its
  OWN existing degrade-to-text warning exactly where it is today.
- **Editing `tests/test_citation_render_gate.py` or `tests/fixtures/citation_render_gate/` for this
  phase.** Frozen by D-02 — they are SC#5's byte-identity control. Any helper this phase's new
  module needs from there must be copied, not imported cross-module (importing would still work
  technically, but duplicating keeps the two modules independently understandable and avoids a
  cross-module coupling nothing else in this repo's test suite has).

## Common Pitfalls

### Pitfall 1: Assuming WR-02's minimal topology is reachable via RST source

**What goes wrong:** Writing an RST fixture with what looks like "an ids-less target between two
citations" (e.g. an anonymous hyperlink target, a duplicate-named target) and being surprised the
resulting doctree always has a SECOND, real-id target adjacent to it, so the pre-fix/post-fix grid
count doesn't actually differ.

**Why it happens:** docutils' target-chaining transform (`docutils.transforms.references`) never
produces a solitary ids-less target; ids-less-ness is a property of being a NON-TERMINAL chain
member, and the terminal member is always adjacent.

**How to avoid:** Use the directly-assembled doctree harness (Pattern 3) for WR-02's RED. Don't
spend further budget searching for a real-build shape unless you have a NEW idea not in the attempt
list above.

**Warning signs:** A fixture's `grid(` count is the same before and after applying the fix — that
means some other sibling in the gap is still a real blocker.

### Pitfall 2: Calling `_resolve_xref_docname`/recomputing `degrade_xref_to_text` twice per reference after the D-06 refactor

**What goes wrong:** If the new shared predicate independently re-derives `refuri`/`xref`/
`degrade_xref_to_text` from the node (as D-06 requires — "derives its own inputs"), and
`visit_reference` is not carefully rewritten to consume the predicate's answer INSTEAD of its own
local computation (rather than in ADDITION to it), the cross-document degrade-to-text warning
(`logger.warning("cross-reference to non-included document ...")`, translator.py ~4300) can fire
TWICE per degraded reference — once from the predicate's internal (re-)computation if it is not kept
silent, once from `visit_reference`'s own existing branch.

**Why it happens:** `opens_wrapper`'s computation and the degrade-to-text WARNING are currently
fused into one code path (translator.py:4160-4166, 4290-4306); D-06 asks for the eligibility
JUDGEMENT to move into the predicate, but the WARNING must stay exactly where it is.

**How to avoid:** The predicate returns booleans/labels only, never logs. `visit_reference` keeps its
existing `logger.warning` call in its existing branch, unchanged, and simply consumes the predicate's
`opens_wrapper`/`next_is_target`/`anchor_label` outputs everywhere it previously computed them
locally (translator.py:4191, 4202-4208, 4226-4229) — a single predicate call, not two.

**Warning signs:** the full-corpus gate or any existing xref-degrade test (e.g.
`tests/test_xref_orphan_degrade_render_gate.py`) starts asserting or logging the warning twice, or a
test that greps stderr for exactly one occurrence of the warning string starts failing.

### Pitfall 3: `next_is_target` is consumed by TWO different branches in `visit_reference`, not one

**What goes wrong:** Designing the shared predicate to return ONLY `(eligible: bool, anchor_label:
str | None)` and discovering that `visit_reference`'s OTHER `next_is_target` consumer — the
markup-mode bracket-wrap for label attachment at line 4235-4241, which fires whenever the NEXT
sibling is a target regardless of `ids`/`opens_wrapper` — has nowhere to get its own `next_is_target`
value without either recomputing the sibling-index lookup a second time or exposing it from the
predicate too.

**Why it happens:** `next_is_target` is used for two DIFFERENT, mutually-exclusive purposes in the
same function: (1) the D-14 own-anchor eligibility gate (line 4226, `and not next_is_target`), and
(2) the pre-existing target-attachment markup wrap (line 4235, `if next_is_target:`), which existed
before D-14/Phase 40 and is untouched by this phase.

**How to avoid:** the predicate's return value must expose `next_is_target` (or equivalently,
`visit_reference` must keep computing it itself and pass it INTO the predicate as D-06 says the
predicate derives it — either way, compute it exactly once per reference and use the same value for
both purposes).

**Warning signs:** a reference immediately followed by an explicit target starts emitting a
double-computed or inconsistent sibling check; the fastest way to catch this is the full-corpus gate
(any of Sphinx's own `doc/` files with an explicit target directly after a link would surface it).

### Pitfall 4: `_citing_reference_has_own_anchor`'s only real caller guarantees `ids` is non-empty — don't "fix" the ids-empty branch as if it were reachable

**What goes wrong:** Spending implementation effort making the predicate defensively handle an
ids-empty `ref_node`, under the impression this closes a real gap.

**Why it happens:** The review's WR-03 writeup mentions "ids empty" as a theoretical future risk, and
D-08 asked for both routes to be attempted. This research found Route A structurally unreachable
through `_find_citing_reference`'s own matching logic (see "D-01/D-08 constructibility findings"
above) — it's real defensive code (worth keeping, since `_find_citing_reference`'s contract could
change later), but it is not a demonstrable bug today, and no RED should be built around it as if it
were.

**How to avoid:** record Route A's unreachability explicitly in the GATE-EVIDENCE file (per D-01's
"a negative result is exactly as valuable as a positive one"), and build the actual assembled-doctree
RED around Route B (`opens_wrapper` false via `degrade_xref_to_text`) instead, per Pattern 4 above.

|---------|--------|----------------------|
