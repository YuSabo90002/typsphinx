<objective>
Implement CONF-07's Python and template surface: add a `lang` parameter to `templates/base.typ`'s `project()` and wire it into `set text(...)`, add `lang` to `ELEMENTS_ALLOWLIST`, add a pure conversion helper that turns a Sphinx `language` value into a Typst text-language code (D-02) or warns and omits (D-03), give `TemplateEngine` a template-resolution provenance so the default-template path can be judged from an actual load result rather than a declaration (D-06), and wire `writer.py` to pre-merge the auto-derived value underneath the user's explicit `typst_elements` so precedence stays structural (D-05).

Purpose: today `base.typ:61` hardcodes `lang: "en"`, so a `language = "ja"` project gets translated body text but English Typst-generated labels — the Phase 25 captioned table renders "Table 1" instead of 「表 1」. This plan makes the typesetting language follow Sphinx's own `language`, without breaking any user who is on a custom template, a `<srcdir>/base.typ` shadow, or a Typst Universe package.

Output: edited `base.typ`, `template_engine.py`, `writer.py`, plus unit tests pinning the conversion rule, the provenance predicate, and the precedence merge. The real-`typst.compile()` GATE-01 proof lands in Plan 03 (Wave 2); the docs follow-up is Plan 02 (Wave 1, parallel).
</objective>
