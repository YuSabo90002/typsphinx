## Summary

Reviewed the CONF-07 implementation (deriving Typst's `lang` from Sphinx's
`language` config) at standard depth: `template_engine.py`'s
`derive_typst_lang()`/`resolve_template()`/`uses_bundled_default_template()`,
`writer.py`'s pre-merge and `uses_bundled_default_template()` gating,
`templates/base.typ`'s new `lang` parameter, the full `GATE-01` real-compile
test suite and its eight fixtures, the unit tests in
`test_template_engine.py`, and the corresponding docs/`.po` changes.

The core design (D-02 generic split-and-lowercase rule, D-03 ASCII-scoped
2-3-letter accept test with warn-and-omit, D-05 explicit-wins precedence via
right-biased dict union, D-06 resolution-based `uses_bundled_default_template()`
judgment covering all three exclusion paths — explicit template, package-alone,
and `<srcdir>/base.typ` shadow) is sound and is exercised thoroughly by both
the unit tests and the real-compile `GATE-01` gate, including a genuine
pre-fix-basis regression reconstruction. Traced `uses_bundled_default_template()`
against all three exclusion routes and confirmed each returns `False` as
designed, matching the fixtures (`custom_template_no_lang`,
`srcdir_shadow_no_lang`, `package_no_lang`).

One genuine regression was found: the new `effective_elements` pre-merge in
`writer.py` unconditionally applies `dict | typst_elements`, which raises an
unhandled `TypeError` and aborts the entire Sphinx build if a user's `conf.py`
sets `typst_elements = None` — a value that was silently tolerated before this
phase (`map_parameters()`'s own `typst_elements or {}` guard handled it) and
that Sphinx's own config-type check only warns about rather than rejecting or
normalizing. A documentation clarity defect and a minor code-duplication note
are also reported below.

## Critical Issues

### CR-01: `typst_elements = None` in conf.py now crashes the build with an unhandled TypeError

**File:** `typsphinx/writer.py:246`
**Issue:**

```python
effective_elements = ({"lang": auto_lang} if auto_lang else {}) | typst_elements
```

`typst_elements` here is `getattr(config, "typst_elements", {})` (line 219).
Before this phase, that raw value was passed straight into
`TemplateEngine.map_parameters(sphinx_metadata, typst_elements=typst_elements)`,
whose own defense — `for key, value in (typst_elements or {}).items()`
(`template_engine.py:471`) — safely treats `None` as an empty dict.

This phase's new pre-merge bypasses that defense entirely: `dict | None`
raises `TypeError: unsupported operand type(s) for |: 'dict' and 'NoneType'`
regardless of whether `auto_lang` is set, and regardless of which template
path is in use (the crash happens before `uses_bundled_default_template()`'s
result even matters, since the `|` runs unconditionally on line 246).

`typst_elements` is registered as `app.add_config_value("typst_elements", {},
"html", [dict])` (`typsphinx/__init__.py:48`). Sphinx's own
`check_confval_types()` (`sphinx/config.py:777`) only *warns* on a type
mismatch — it never resets or coerces the value — so a user who writes
`typst_elements = None` in `conf.py` (a plausible way to explicitly express
"no elements," mirroring how `typst_template = None` / `typst_package = None`
are written elsewhere in this same config surface) gets a full Sphinx build
abort with this phase's change, where the exact same `conf.py` built
successfully before it.

No fixture or test in this phase's own test suite (`test_typst_lang_gate.py`,
`test_template_engine.py`) exercises `typst_elements = None`, so this
regression is currently silent.

**Fix:**

```python
effective_elements = ({"lang": auto_lang} if auto_lang else {}) | (
    typst_elements or {}
)
```

Add a regression test (e.g. in `TestEffectiveElementsMerge` or a new gate
fixture) asserting that `writer.translate()` / `map_parameters()` does not
raise when `typst_elements` is `None`, whether or not `auto_lang` is set.

## Warnings

### WR-01: Docs precedence example uses the same value on both sides, so it does not actually demonstrate precedence

**File:** `docs/source/user_guide/configuration.rst:230-236`
**Issue:**

```rst
An explicit ``typst_elements`` ``lang`` entry always wins over the value
derived from ``language``, on every template path, and an explicit value
is passed through to Typst exactly as written with no validation.

.. code-block:: python

   language = "ja"

.. code-block:: python

   typst_elements = {"lang": "ja"}
```

The prose claims the explicit `typst_elements["lang"]` value "wins" over the
auto-derived one, but the two code samples both use `"ja"`. A reader cannot
tell from this example which value actually took effect, because they are
identical — the example fails to demonstrate the very behavior it is
describing. The test fixture that actually proves this precedence
(`tests/fixtures/typst_lang_gate/precedence/conf.py`) deliberately uses two
*different* values (`language = "de"` vs. `typst_elements = {"lang": "ja"}`)
for exactly this reason.

**Fix:** Mirror the fixture's contrast in the docs, e.g.:

```rst
.. code-block:: python

   language = "de"
   typst_elements = {"lang": "ja"}  # wins: the compiled document uses "ja",
                                    # not the "de" that language alone would derive
```

## Info

### IN-01: `derive_typst_lang()` duplicates its warning block verbatim across both rejection branches

**File:** `typsphinx/template_engine.py:132-138` and `typsphinx/template_engine.py:145-149`
**Issue:** The non-str/empty-input early return and the malformed-head fallthrough
both log the exact same `logger.warning(f"typsphinx: could not derive a Typst "lang'...")`
f-string, copy-pasted rather than shared. Currently harmless (both copies are
identical), but a future edit to one copy (e.g. adding more context) could
silently drift from the other.

**Fix:** Factor the shared warn-and-return-None into a single local helper,
e.g.:

```python
def _reject(value):
    logger.warning(
        f"typsphinx: could not derive a Typst 'lang' from Sphinx "
        f"'language' = {value!r} -- omitting 'lang' (falling back to the "
        f"template's own default)."
    )
    return None

if not isinstance(sphinx_language, str) or not sphinx_language:
    return _reject(sphinx_language)

head = re.split(r"[_\-@]", sphinx_language, maxsplit=1)[0].lower()
if re.fullmatch(r"[a-z]{2,3}", head):
    return head
return _reject(sphinx_language)
```
