<objective>
Update the user-facing configuration documentation so the newly working `lang` element key is discoverable and accurately scoped (D-09), then refresh the Japanese translation catalog with the same scope-limited `gettext` procedure Phase 27 established.

Purpose: Phase 27 just finished realigning these docs against measured behavior. Shipping a new working config key without documenting it re-opens exactly the drift that phase closed — and documenting it carelessly is worse, because the caveats are load-bearing: auto-derivation applies only on the bundled default-template path, an explicit value always wins, and region is unsupported so `zh_TW` renders simplified Chinese.

Output: an edited `configuration.rst` with a new language section and a corrected supported-keys sentence, plus the regenerated `user_guide/configuration.po` (and its `.mo` if a docs build regenerates it). This plan runs in Wave 1 in parallel with Plan 01 — it shares no file with any other plan in this phase and depends on no code change.
</objective>

`env -u VIRTUAL_ENV -u UV_PROJECT_ENVIRONMENT uv sync --extra dev --extra docs`

then run everything via `uv run`.

Two invocation hazards in this NixOS sandbox, both already established in this repo:
- Never call `sphinx-build` as a console script. Use `uv run python -m sphinx -b <builder> ...`, the same routing the test suite's `sys.executable -m sphinx` helper uses.
- `uv run sphinx-intl ...` may hit the same dynamic-linker error. If it does, fall back to `uv run python -c "from sphinx_intl.commands import main; main()" update -p <potdir> -d <localedir> -l ja`, which passes the same subcommand and flags through click's argv handling.
- If `uv run ruff check .` fails with a linker error, fall back to `nix-shell -p ruff --run "ruff check ."`. This plan changes no Python, so lint is informational here.

The worktree safety checker false-flags any Bash command containing the literal substring `source` (as in a `docs/source` path) as invoking the shell builtin. Work around it by assembling the path at runtime inside a small `uv run python` snippet using `subprocess.run`, rather than typing the path directly into a shell command.

    Edit docs/source/user_guide/configuration.rst only. Two changes.

    First, correct the supported-keys sentence in the "Paper Size and Format" section. Today it asserts that the two keys shown are the only supported `typst_elements` keys. Reword it so it states that `papersize` and `fontsize` are the paper-size and base-font-size keys, that `typst_elements` supports three keys in total, and that the third is `lang`, with a cross-reference to the new section added below. Keep the existing section heading text byte-identical — the Japanese catalog already carries a translation for that heading, and renaming it would obsolete a real translation for no benefit.

    Second, add a new section at the same heading level immediately after "Paper Size and Format", suggested title "Document Language", covering all four points below. Write it as normal user-guide prose plus one short `conf.py` code-block example.

    (a) What the key does: `lang` is passed to the template's `project()` and reaches Typst's text setup, which is what selects the language of Typst-generated labels — figure and table supplements in particular. Give the concrete, measured outcome: with a Japanese setting the captioned table renders as 「表 1」 and a figure as 「図 1」, where the default English setting renders "Table 1" and "Figure 1".

    (b) Automatic derivation: when the project uses the bundled default template, `lang` is derived from Sphinx's own `language` setting and needs no explicit configuration. State the derivation rule in user terms — the part of the value before the first underscore, hyphen, or at-sign, lowercased — and give the worked examples `ja` to `ja`, `zh_CN` to `zh`, `pt_BR` to `pt`. State the fallback plainly: if a `language` value cannot be reduced to a two- or three-letter code, typsphinx emits a build warning naming the value and leaves the parameter unset, so the template's own default applies and the build still succeeds.

    (c) Scope and opt-in — this is the load-bearing caveat, do not compress it. Automatic derivation applies ONLY when the bundled default template is what actually gets used. It does not apply when `typst_template` is configured, when `typst_package` is configured, or when a file named `base.typ` sits next to `conf.py` in the source directory (which silently shadows the bundled template). The reason, stated for the reader: a template that does not declare a `lang` parameter would receive an argument it never asked for, and Typst aborts the compile on an undeclared argument. Tell such users how to opt in: declare a `lang` parameter in their own `project()` (or equivalent entry function) and then set it explicitly through `typst_elements`.

    (d) Precedence and the known limitation. An explicit `typst_elements` `lang` entry always wins over the value derived from `language`, on every template path, and an explicit value is passed through to Typst exactly as written with no validation. Then record the limitation: region subtags are not supported, so a `zh_TW` project resolves to `zh` and renders simplified-Chinese supplement text 「图 1」 rather than the traditional 「圖 1」; a reader who needs traditional Chinese should set the value explicitly through their own template.

    The code-block example for this section MUST be standalone and package-free — a `language` assignment plus, separately, an explicit `typst_elements` example. Do NOT add a `lang` entry to the existing "Complete Example" block: that block configures `typst_package` with a `typst_template_function`, and an element key on the package path is forwarded to the package's own entry function, which does not declare `lang` — the documented example would abort the Typst compile for anyone who copied it. Leave that block otherwise untouched.

    Before finishing, run a repo-wide grep for other user-facing surfaces that state how many `typst_elements` keys are supported or enumerate them, over `docs/`, `examples/`, and `README.md` — Phase 27's lesson is that scoping the sweep to the named file misses copies. Known results to expect and how to handle them: `docs/usage.rst` and `docs/installation.rst` sit at the `docs/` root, outside `docs/source/`, and are the same orphan class as the file Phase 27 deleted; do NOT edit or delete them here — record them in the SUMMARY as a follow-up. `examples/advanced/conf.py` and `examples/advanced/README.md` set `typst_elements` keys that are not in the allowlist at all (`author`, `date`, `margin`, `primary_color`), which is a pre-existing interaction with Phase 26's fail-loud unknown-key behavior, NOT a CONF-07 concern; do NOT fix it here — record it in the SUMMARY as a follow-up todo. `README.md`'s one-line mention states no key count and needs no change.
