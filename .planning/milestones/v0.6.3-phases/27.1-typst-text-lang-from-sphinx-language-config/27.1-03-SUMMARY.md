# Phase 27.1 Plan 03: GATE-01 real-compile lang gate + non-regression fixtures + red-to-green record Summary

**A new `tests/test_typst_lang_gate.py` (18 tests, 8 classes) with seven real-compile fixture projects proves CONF-07's `lang` typesetting parameter actually reaches the compiled PDF and changes Typst's generated figure/table supplement labels — via the D-07 split proof (font-independent `ja` source assertion + `de` pypdf-extraction linkage assertion with a new NBSP-tolerant matcher) — while three non-regression fixtures prove no non-default template path ever receives an injected argument it never declared, and a durable pre-fix-basis reconstruction plus a manually recorded red-to-green transition close the loop.**

## Accomplishments

- `tests/test_typst_lang_gate.py` — new GATE-01 real-compile module (18 tests, 8 classes), mirroring `tests/test_typst_elements_pass_through_gate.py`'s `_run_sphinx_build()`/`_show_rule_call_region()` helpers verbatim, plus one genuinely new helper: `_supplement_matches()`, the first NBSP-tolerant (`\s+`, matching U+00A0) PDF-text-extraction assertion helper in this codebase.
- Seven fixture projects under `tests/fixtures/typst_lang_gate/`: `ja_default`, `de_default` (with a captioned table + figure, Phase 25's motivating case), `precedence`, `malformed_language`, `custom_template_no_lang`, `srcdir_shadow_no_lang`, `package_no_lang` — every `conf.py` carries a header comment naming which success criterion/D-decision it pins.
- `TestJapaneseSourceProof` proves the D-07 source half of SC#1 (real compile + `.typ`-source `lang: "ja"` assertion, no PDF extraction).
- `TestGermanLinkageProof` proves the D-07 linkage half of SC#1 — the actual behavioral proof — with real pypdf extraction confirming `"Tabelle\xa01"` and `"Abbildung\xa01"` appear and the English forms do not.
- `TestPrecedence` proves SC#2 (explicit `typst_elements["lang"]` beats the Sphinx-`language`-derived value) via the faster source-only `-b typst` builder.
- `TestMalformedLanguage` proves SC#4 (a CJK `language` value cannot abort the build) via a real `-b typstpdf` compile.
- `TestCustomTemplateNoLang` / `TestSrcdirShadowNoLang` / `TestPackageNoLang` prove SC#3's three non-regression paths; the two lang-less template fixture files are derived from the real, current `typsphinx/templates/base.typ` (parameter + wiring reverted), not hand-written stubs.
- `TestPreFixBasisFailureProof` adds the durable red proof in both directions: an omission reconstruction (recompiles a mutated German master with the `lang` line stripped, proving the recompiled PDF falls back to English) and an undeclared-argument reconstruction (splices a `lang` argument into a lang-less template's master, proving a real compile raises).
- Manual red-to-green confirmation performed and recorded (see below).

## Decisions Made

See `key-decisions` in the frontmatter for the full list. The most consequential runtime discovery: `pytest -k` substring matching against the plan's suggested filter tokens (`ja`, `de`, `precedence`, `malformed`, `custom_template_no_lang`, `srcdir_shadow_no_lang`, `package_no_lang`) does not automatically select the intended test unless that literal substring appears in a test id — abbreviated class/method names (e.g. `TestGermanLinkageProof`, `test_explicit_lang_wins_over_derived_value`) either miss the target (`-k de` selecting nothing from the German class) or collide with an unrelated match (`"derived"` containing `"de"`). Resolved by spelling out the fixture-name token explicitly inside every affected test method name (e.g. `test_de_default_german_table_supplement_present`, `test_custom_template_no_lang_real_compile_produces_valid_pdf`) and renaming the one collision (`derived` → `auto`). All seven `-k <token> -q` acceptance-criteria commands from the plan were re-verified after this fix and each now selects the correct case(s) (see Deviations below for the ledger).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `pytest -k` filter false-negatives/collisions against the plan's suggested tokens**
- **Found during:** Task 1 acceptance-criteria verification (`uv run pytest tests/test_typst_lang_gate.py -k de -q`)
- **Issue:** `-k de` initially selected only `TestPrecedence::test_explicit_lang_wins_over_derived_value` (a false-positive collision via the substring `"de"` inside `"derived"`) and zero tests from the intended `TestGermanLinkageProof` class, because neither the class name nor any of its original method names (`test_real_compile_produces_valid_pdf`, `test_german_table_supplement_present`, etc.) contained the literal substring `"de"`.
- **Fix:** Renamed `TestGermanLinkageProof`'s four method names to include the `de_default` token explicitly (e.g. `test_de_default_german_table_supplement_present`), and renamed `TestPrecedence`'s colliding method from `test_explicit_lang_wins_over_derived_value` to `test_explicit_lang_wins_over_auto_value` to remove the accidental `"de"` substring. Applied the same explicit-token convention preemptively to the three Task-2 non-regression classes (`custom_template_no_lang`, `srcdir_shadow_no_lang`, `package_no_lang`) after discovering the same substring-matching gap during their own acceptance-criteria verification.
- **Files modified:** `tests/test_typst_lang_gate.py`
- **Verification:** re-ran all seven plan-specified `-k <token> -q` commands (`ja`, `de`, `precedence`, `malformed`, `custom_template_no_lang`, `srcdir_shadow_no_lang`, `package_no_lang`) after the rename; each now exits 0 and selects the intended case(s) — `-k de` additionally still (harmlessly) selects `TestPrecedence` too, since `"precedence"` itself contains the substring `"de"` (`prec-ede-nce`), which the plan's acceptance criterion does not prohibit.
- **Committed in:** `9f8dcb7` (Task 1) and `d0325d2` (Task 2) — folded into each task's own commit rather than a separate fix-up commit, since the rename happened during that same task's own acceptance-criteria verification pass before the commit was made.

**Total deviations:** 1 auto-fixed (Rule 1 — a test-naming defect discovered via the plan's own acceptance criteria, fixed before committing each affected task; no production code was touched).
**Impact on plan:** None on scope, coverage, or correctness — every case the plan specifies is present, real-compiled where required, and independently verified; only test method NAMES changed to make the plan's own `-k` filter commands work as intended.
