<corpus_loop>
**The corpus loop.** 70-11 reuses this definition word for word. Given a list file, one directory
per line, and an output root `OUT`, run the whole loop inside one `uv run bash -c '…'` invoked from
the worktree root. For each directory `d`, in list order:

1. Set `out="$OUT/${d//\//__}"` and run `mkdir -p "$out"`.
2. Take `date +%s.%N` before and after the build, and append `d` and the elapsed seconds to a
   separate timing file.
3. Run `LC_ALL=C PYTHONDONTWRITEBYTECODE=1 python -m sphinx -b typst "$d" "$out" > "$out.log" 2>&1`.
   Capture `rc=$?`.
4. Set `n` to the number of files `find "$out" -type f -name '*.typ'` finds.
5. Compute `dg` as the SHA-256 of the output of
   `(cd "$out" && find . -type f -name '*.typ' -print0 | LC_ALL=C sort -z | xargs -0 -r sha256sum)`.
6. Append the line `<d> exit=<rc> typ=<n> digest=<dg>` to the manifest file.

The manifest therefore has exactly one line per project, in list order. Its SHA-256 is the value
compared across sides. `.doctrees/` never enters the digest; research found its pickles differ by
path and timing.
</corpus_loop>
