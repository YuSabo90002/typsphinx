<objective>
Make `typst_documents` resolve to a Sphinx-native derived default when the user never sets it, so a
project that follows the Quick Start exactly produces a PDF instead of zero output — and prove the
explicit setting still wins.

Purpose: today `typst_documents` defaults to the literal `[]`, `TypstPDFBuilder.finish()` returns
early on it, and `sphinx-build -b typstpdf` exits 0, emits one WARNING, and writes **no PDF at all**.
Sphinx's own LaTeX builder does not require `latex_documents` — it registers the callable default
`default_latex_documents` — and this phase follows that precedent verbatim, deriving from
`root_doc`/`project`/`author` with the target name in LaTeX's own shape (`<project>.typ`, per D-02).

Output: a new module-level `_default_typst_documents(config)` in `typsphinx/builder.py`, the
one-line registration change in `typsphinx/__init__.py`, two purpose-built fixtures (the first
`conf.py` in this repo that deliberately omits `typst_documents`, and an explicit-wins counterpart),
a real-`sphinx-build` subprocess gate, a unit module pinning D-01's degradation table, the deliberate
update of the two existing tests that encoded the old `[]`-default, and a recorded RED→GREEN
evidence file whose RED commit SHA plan 44-03 consumes as its pre-change side.
</objective>
