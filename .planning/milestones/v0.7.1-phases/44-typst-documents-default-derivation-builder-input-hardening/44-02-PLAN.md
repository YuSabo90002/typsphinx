<objective>
Harden the one method CONF-08's derivation flows through against a non-`str` docname, and correct the
opt-out message that becomes reachable only through an explicit empty list once the derived default
lands.

Purpose: `finish()` reads `docname = doc_tuple[0]` and hands it straight to
`_directory_preserving_relpath`, which calls `posixpath.dirname(docname)` — a raw
`TypeError: expected str, bytes or os.PathLike object, not int` raised **before** the `try:` block
that aggregates into `failures`, so a single malformed entry kills the whole `sphinx-build` process
with a bare traceback instead of a scoped, reported failure. Separately, the message
`"No documents defined in typst_documents. Nothing to compile."` reads as if the setting were absent,
which after plan 44-01 can no longer be true: unset now resolves to the derived list, so this branch
is reachable only when the user wrote `typst_documents = []` deliberately.

Output: one type guard and one reworded warning in `typsphinx/builder.py`, two purpose-built
fixtures, two real-`sphinx-build` subprocess gate modules, a resolved and recorded answer to the one
Discretion note the phase left open, and a RED→GREEN evidence file.
</objective>

<discretion_resolution>
`44-CONTEXT.md` left four items to Claude's discretion. Three were resolved by `44-RESEARCH.md`
(the error shape — join the existing `failures` list, never raise immediately; the validation width —
type-only; the evidence-file naming — `44-GATE-EVIDENCE-*.md` in the phase directory). The fourth was
left open and is resolved here.

**Discretion (d) — should `sphinx-build -b typst` alone warn on an explicit empty
`typst_documents`? Decision: NO, and this plan asserts that decision rather than leaving it
implicit.** Measured grounds, not preference:

1. **The two builders are not in the same state.** With an empty list, `-b typstpdf` produces **zero
   artifacts of its declared kind** — no PDF at all — which is what makes a warning informative.
   `-b typst` still writes a `.typ` for **every** document; the emitted file is untemplated but
   compiles standalone (`44-CONTEXT.md` `<specifics>` §1 measured `typst.compile()` on exactly such a
   file producing an 8209-byte PDF). There is no missing output to warn about.
2. **Adding it would be a second undiscussed behaviour change in a patch release.** Every project
   that today sets `typst_documents = []` and builds with `-b typst` would gain a new WARNING, and
   any such build running under `-W` — which this repository's own docs builds and many users' CI
   use — would flip from success to failure. That is precisely the class of change D-02 refused to
   fold in alongside CONF-08's rename.
3. **The LaTeX precedent does not transfer.** Sphinx's LaTeX builder warns because an empty
   `latex_documents` means *no documents will be written at all*; typsphinx's `-b typst` writes them
   all regardless, so the analogy that justifies D-03's `typstpdf`-side wording does not reach the
   `-b typst` side.

Reversibility: **reversible** — adding the warning later is one `logger.warning` call in
`TypstBuilder`; nothing depends on its absence beyond the assertion this plan adds.
</discretion_resolution>
