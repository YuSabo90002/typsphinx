## Pattern Assignments

### `typsphinx/translator.py` — `visit_title` (source site 1 of 2)

**Analog:** itself, L785-810 (`typsphinx/translator.py`)

**Current emission (to be changed)** (lines 797-809):
```python
# D-06: clamp to a minimum of level 1 -- a top-level titled
# non-section (section_level == 0) would otherwise emit
# heading(level: 0, ...), which Typst rejects (levels are >= 1).
emitted_level = max(1, self.section_level)
# Pitfall-1 fix: wrap the title content in a code block {...} so
# multi-child title content is one expression, not several
# juxtaposed statements (mirrors _depart_admonition's existing
# {...} wrap of the buffered admonition title).
if self._title_section_ids:
    self.add_text(f"[#heading(level: {emitted_level}, {{")
else:
    # Use heading() function (no # prefix in code mode)
    self.add_text(f"heading(level: {emitted_level}, {{")
```

**Required change (per CONTEXT.md D-04/D-07 scope):**
- Rename `emitted_level` → whatever variable name is chosen (semantics unchanged: `max(1, self.section_level)` still holds — D-04's rationale-comment item says the clamp *survives* but the `# D-06:` comment's stated reason (Typst rejecting `level: 0`) must be rewritten because `depth` is likewise `>= 1`).
- Replace both `heading(level: {…}` emission sites (L806 markup-bracket form, L809 bare code-mode form) with `heading(depth: {…}`.
- The `# D-06:` comment block (L797-799) needs its rationale rewritten per CONTEXT.md line 98-100 — do NOT reuse the `D-06` label for the new rationale (ambiguity warning in CONTEXT.md).
- The two emission sites are each other's own best analog: whatever transformation is applied to L806 must be applied identically to L809 (this is exactly the kind of self-mirroring the codebase already does — note the existing comment "Pitfall-1 fix" governs both branches).

**No auth/CRUD/error-handling pattern applies** — this is a pure string-emission transform inside a `SphinxTranslator` visitor method; the only "pattern" is the two-branch (bracket-wrapped vs bare-code) emission mirrored 1:1.

### `typsphinx/translator.py` — `visit_toctree` (source site 2 of 2)

**Analog:** itself, L4718-4790 (`typsphinx/translator.py`), and the docstring prose that documents the line it must move with

**Current emission (to be changed)** (lines 4758-4762):
```python
# Generate scope block for all includes (unified code mode)
# Use {...} scope block to isolate set rules while maintaining code mode
# Start scope block (no # prefix in code mode)
self.add_text("{\n")
self.add_text("  set heading(offset: 1)\n")
```

**Docstring lines that must move with it** (L4724, L4729):
```
- Apply #set heading(offset: 1) to lower heading levels
...
- Apply #set heading(offset: 1) once per toctree
```

**Required change per D-07 (locked, option-a):** replace the absolute assignment with a context-relative
increment. The exact verified shape (CONTEXT.md "specifics" item 10, built and queried against real
`sphinx-build` output):
```typst
context {
  set heading(offset: heading.offset + 1)
  include("shared.typ")
}
```
So the two `add_text` lines become (illustrative — exact string literals are the executor's call, but
must keep the `{...}` scope block's outer shape intact since nothing else in the method changes):
```python
self.add_text("context {\n")
self.add_text("  set heading(offset: heading.offset + 1)\n")
```
closing `}` at the existing close-scope site is unchanged (CONTEXT.md: "Everything else in the method
... is unchanged").

**No other pattern applies.** This is the single emission point for the heading offset in the entire
codebase (`grep -rn 'heading(offset' typsphinx/` → 3 hits, all in this one method: 2 docstring, 1 emit).
`templates/base.typ` contributes zero occurrences (verified, discharges SC#8's template half).

### `tests/test_topics.py` (unit test — mixed positive/negative/docstring — D-04 highest-risk category)

**Analog:** the file's own idiom; `TestTitleLevelClamp.test_title_at_section_level_zero_clamps_to_one`
(L156-177) is the canonical shape for both the positive and negative form in one test.

**Negative-assertion pattern to rewrite** (4 sites — L62, L96, L141, L177 — currently `heading(level:`
substring checks that prove the OLD keyword is absent from non-heading paths):
```python
assert "heading(level:" not in output          # L62, L96, L141 — becomes "heading(depth:" not in output
assert "heading(level: 0" not in output         # L177 — becomes "heading(depth: 0" not in output
```
**CONTEXT.md's explicit warning applies here:** after the fix, the string `"heading(level:"` never
appears in ANY output (both `visit_title` sites now emit `depth:`), so a negative assertion left as
`"heading(level:" not in output` becomes **vacuously true** and stops testing anything. D-04 requires
each of these 4 be reproved failing against the pre-fix commit before being rewritten to the
`depth:`-form negative check.

**Positive-assertion sites** (L176, L208 — same idiom as `test_translator.py` above):
```python
assert "heading(level: 1" in output     # L176 -> "heading(depth: 1"
...
assert "heading(level: 1, {" in output  # L208 -> "heading(depth: 1, {"
```

**Rationale-comment site** (L161-162, docstring prose inside
`test_title_at_section_level_zero_clamps_to_one`, currently states the clamp exists "because Typst
rejects `level: 0`"): must be reworded — `depth` is likewise `>= 1` in Typst, so the clamp's *mechanism*
(`max(1, self.section_level)`) survives untouched, but the stated *reason* needs updating to reference
`depth` rather than `level`. This mirrors exactly the source-side rationale-comment rewrite required at
`translator.py:797-799` above — same wording problem, same fix shape, apply consistently.

### `tests/test_toctree_requirement13.py` (D-04 addendum — the 2 toctree-side sites, in scope under D-07)

**Analog:** the two tests are each other's analog — same mock-builder construction idiom
(`simple_document`, `mock_builder` fixtures at top of file), same `visit_toctree` call, differing only

**`test_toctree_with_heading_offset`** (lines 83-110), current assertion:
```python
assert "set heading(offset: 1)" in output
assert "{\n" in output or "{" in output
assert "}\n" in output or "}" in output
```
Under D-07's emitted shape this must become an assertion over `"context {"` opening the scope and
`"set heading(offset: heading.offset + 1)"` as the increment — i.e. the literal being asserted changes
entirely, not just a keyword swap. This is a bigger rewrite than the `level:`→`depth:` sites; treat it
as "new assertion over the new literal," proved failing pre-fix, not a find-replace.

**`test_toctree_heading_offset_appears_once`** (lines 231-265), current regex:
```python
pattern = r"set heading\(offset: 1\)"
matches = re.findall(pattern, output)
assert (
    len(matches) == 1
), f"Expected 1 occurrence of set heading(offset: 1), got {len(matches)}"
```
The exactly-once semantics must survive (CONTEXT.md D-04 addendum explicit requirement) but the pattern
must change to match the new literal, e.g. `r"set heading\(offset: heading\.offset \+ 1\)"` (exact
literal is the executor's call once the emission string is finalized — must match byte-for-byte what
`visit_toctree` actually emits, escape all Typst punctuation for `re`).

Note both mock-builder fixtures (`simple_document`, `mock_builder` at top of file, lines ~15-40) are
unchanged — the toctree tests run `translator.visit_toctree(toctree)` directly with no real Sphinx
builder, so `getattr(self.builder, "_included_docnames", None)` falls back to `None` (no-dedup path);
this is a pre-existing, orthogonal pattern already in the file and needs no touching.

return subprocess.run(

**skipif/slow-mark pattern** (lines 260-263):
```python
@pytest.mark.skipif(
    not (TYPST_AVAILABLE and PYPDF_AVAILABLE),
    reason="typst-py and pypdf are both required for the D-04 render gate",

```
For the new gate this becomes `not TYPST_AVAILABLE` only (per CONTEXT.md: `typst.query` needs no PDF at
all, so pypdf is not a dependency of this specific gate — do not import/require pypdf for it).

**Compile step to adapt** (lines 244-254 style, but target `typst.query` instead of
`typst.compile`+pypdf-extract):
```python
pdf_output = build_dir / "index.pdf"
typst.compile(str(index_typ), output=str(pdf_output))
assert pdf_output.exists(), "PDF file was not created"
...
reader = pypdf.PdfReader(str(pdf_output))
return "\n".join(page.extract_text() for page in reader.pages)
```
Replace with (per CONTEXT.md "Reusable Assets" — `typst.query` signature
`(input, selector, field=None, one=False, format=None, root=None, …)`, returns a **JSON string**):
```python
import json
result = typst.query(
    str(index_typ), "heading", field="level", root=str(build_dir)
)
levels = json.loads(result)
```
`root=` MUST be the build directory (not the `.typ` file's own directory) because emitted `include()`
paths are relative to the build root — CONTEXT.md flags this explicitly as a correctness requirement,
not a style choice.

## Shared Patterns

### Rationale-comment rewrite (applies to 2 sites, source AND test)
**Source:** `typsphinx/translator.py:797-799` (the `# D-06:` comment)
**Also applies to:** `tests/test_topics.py:161-162` (docstring inside
`test_title_at_section_level_zero_clamps_to_one`)
Both currently justify the `max(1, ...)` clamp by "Typst rejects `level: 0`." Both must be reworded to
state the clamp survives because `depth` is likewise `>= 1` in Typst — the clamp's *mechanism* is
unchanged, only its *stated reason* needs a keyword swap plus a clause explaining depth vs level. Do
these two rewrites with matching wording so they don't drift apart.

### The "prove-failing-against-pre-fix-commit" gate (applies to ALL new/rewritten assertions)
**Source:** CONTEXT.md D-04 (governs every one of the 14 test edit sites: the original 12 + D-07's 2
addendum sites)
No value observed in a post-fix run may be transcribed into an assertion without first proving that
same assertion FAILS against the pre-fix commit (this is what caught the 4 vacuous-negative-assertion
risk and the "collapsed" 1,2,2-vs-1,2,3 nested-scope prediction being wrong). Apply this discipline
uniformly — it is not specific to any one file.

### skipif/slow-mark convention for real-compile gates
**Source:** `tests/test_pdf_render_gate.py:260-263`
**Apply to:** any new SC#1/SC#2 gate class
```python
@pytest.mark.skipif(not TYPST_AVAILABLE, reason="typst-py is required for the resolved-level gate")
```
(drop the `PYPDF_AVAILABLE` half — the new gate needs no PDF, per CONTEXT.md.)
