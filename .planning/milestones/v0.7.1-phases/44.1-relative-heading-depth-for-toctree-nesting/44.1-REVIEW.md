## Summary

This phase touches exactly one production file (`typsphinx/translator.py`), at two emission
sites, per the diff against `8a57aef4c5558a55c4e03b5aa33807cf580d3e78`:

1. `visit_title` (L794-813): switches the emitted Typst call from the absolute
   `heading(level: N, ...)` to the relative `heading(depth: N, ...)`. The pre-existing
   `max(1, self.section_level)` floor-clamp is untouched in mechanism, only renamed
   (`emitted_level` → `emitted_depth`); no dangling reference to the old name remains anywhere in
   the file.
2. `visit_toctree` (L4773-4824): switches the scope opener from the absolute
   `{ set heading(offset: 1) ... }` to the context-relative `context { set heading(offset:
   heading.offset + 1) ... }`, so nested toctree scopes accumulate their parent's offset instead of
   replacing it. Both the empty-entries early `raise nodes.SkipNode` path (before any text is
   emitted) and the normal path (which always reaches the closing `}\n\n` before its own
   `SkipNode`) leave the block balanced — traced both branches, no way to exit with an open
   `context {`.

I verified the two-parameter interaction (`depth:` + ambient `offset:`) empirically rather than
taking the CONTEXT.md rationale on trust: ran `tests/test_heading_depth_render_gate.py` in
isolation (7/7 pass, real `typst.compile()` + `typst.query()` against a 3-level parent → child →
grandchild fixture, asserting the exact resolved level sequence `[1, 1, 1, 2, 3, 4, 3, 4]`), then
ran the full suite (`870 passed, 1 skipped`) to check for regressions elsewhere. Also specifically
checked `tests/test_duplicate_include_label_render_gate.py` (a real `typstpdf` compile of a
toctree diamond) to rule out the `context { }` wrapper causing the Typst label-uniqueness fatal it
exists to guard against — passes clean. Grepped the whole `typsphinx/` package for any other
`heading(level`/`heading(offset` site that might now be inconsistent with the two changed call
sites — none found; the only other `set heading(...)` call in the package
(`typsphinx/templates/base.typ:65`, `numbering:`) is an unrelated parameter and is asserted absent
of any `heading(offset` construct by the new `TestNoHeadingOffsetOutsideVisitToctree` guard.

All six updated test files (and the one updated golden fixture) track the renamed literal
(`level:` → `depth:`) and the new scope-opener shape (`context { set heading(offset:
heading.offset + 1) }`) consistently; the one deliberately-weak disjunctive assertion in
`test_integration_multi_doc.py::test_include_directives_have_heading_offset` is honestly
documented in its own docstring as not discriminating between the old and new shape, so it is not
a hidden gap.

No hardcoded secrets, dangerous functions (`eval`, `exec`, shell-outs), empty catch blocks, or
debug artifacts in the diff. No security-relevant surface changed. One minor pre-existing (not
introduced by this phase) documentation-quality nit noted below.

## Info

### IN-01: `visit_toctree`'s docstring "Notes" section describes an emission shape the code has never used

**File:** `typsphinx/translator.py:4749-4753`
**Issue:** The `Notes:` block says the method "generates Typst `#include()` directives for each
toctree entry within a single content block `#[...]`" — but the code emits a plain code-mode
`{...}` block (now `context {...}`), never a markup-mode `#[...]` bracket block. `git blame`
confirms this line predates the current phase (introduced 2025-10-13, unrelated commit) — it is
not a regression from this diff — but the phase touched the two lines immediately below it
(4780-4782) without correcting the now-even-more-stale neighboring prose, which risks compounding
confusion for the next person who edits this function based on the docstring rather than the code.
**Fix:**
```python
        Notes:
            This method generates Typst #include() directives for each toctree entry
            within a single context-relative offset scope block (`context { ... }`) to
            apply the accumulating heading offset without displaying the block
            delimiters in the output. This simplifies the generated Typst code and
            improves readability.
```
