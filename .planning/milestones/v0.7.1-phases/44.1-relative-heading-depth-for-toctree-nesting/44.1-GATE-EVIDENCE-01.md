## 4. The RED is a level mismatch, not an exception

Confirmed directly from § 3: every failure is a Python `AssertionError` raised by this test
module's own `assert child_level == master_level + 1` / `assert levels == expected` lines,
comparing two Python integers/lists derived from `typst.query(..., field="level", ...)` output.
None of the following appear anywhere in the captured output: a non-zero `sphinx-build` exit
code, `RuntimeError: failed to compile document`, or any `typst`/`TypstCompilationError`
traceback. `sphinx-build` exits `0` and `typst.query` returns valid JSON at every call; the
comparison of *values* is what fails.

**Which heading is at the wrong level (named explicitly):** the child document's title, "Chapter
1" (from `tests/fixtures/integration_nested_toctree/chapter1/index.rst`), resolves at level `1`
instead of the required `2` (one below the master's "Nested Toctree Test" at level `1`); and the
grandchild's title, "Section 1" (from `chapter1/section1.rst`), also resolves at level `1` instead
of the required `3` (two below the master). Both are pinned to level `1` because `visit_title`
emits Typst's absolute `level:` argument, which `heading()` resolves independently of any ambient
`set heading(offset: ...)`.

alone cannot satisfy SC#2 regardless of what `visit_title` emits, because the offset it is
relative to never accumulates across nested scopes.
