## §1. Writer enumeration, from the assignment target

**Command** (AST walk over `TemplateEngine.map_parameters()`, collecting every `Assign` whose
target is a `Subscript` on `Name(id="params")`):
```python
import ast
from pathlib import Path

path = Path('typsphinx/template_engine.py')
tree = ast.parse(path.read_text(encoding='utf-8'))
func = next(n for n in ast.walk(tree) if isinstance(n, ast.FunctionDef) and n.name == 'map_parameters')
print('map_parameters() spans lines %d-%d' % (func.lineno, func.end_lineno))
rows = []
for node in ast.walk(func):
    if not isinstance(node, ast.Assign):
        continue
    for target in node.targets:
        if not (isinstance(target, ast.Subscript) and isinstance(target.value, ast.Name)
                and target.value.id == 'params'):
            continue
        slice_node = target.slice
        if isinstance(slice_node, ast.Constant) and isinstance(slice_node.value, str):
            rows.append((node.lineno, repr(slice_node.value), 'literal'))
        elif isinstance(slice_node, ast.Name):
            rows.append((node.lineno, slice_node.id, 'dynamic'))
rows.sort()
for lineno, slice_repr, kind in rows:
    print('  line %4d: params[%s] = ... (%s slice)' % (lineno, slice_repr, kind))
```

## §5. Why neither open suggested fix was transcribed

**`44.2-REVIEW.md` WR-01's proposed sentence** (verbatim, lines 133-137):
```
``typst_authors`` survives as the sole source whenever the active mapping does
not send ``"author"`` to the template key ``"authors"`` -- whether because
``"author"`` is absent from the mapping entirely, or because it is present but
routed to a *different* target key (e.g. a custom template whose function
parameter is named something other than ``authors``).
```
**Falsified by row `project-to-authors-present`** (§2, row F): the mapping `{"project": "authors"}`
does NOT send `"author"` to `"authors"` (there is no `"author"` key in the mapping at all), so
WR-01's sentence predicts the seed SURVIVES. Measured: `survived=False`,
`params["authors"] == ('P',)` -- the seed is destroyed by the project name. Publishing WR-01's
sentence verbatim would have made this the third consecutive round of a rule one predicate short.

**`44.2-VERIFICATION.md`'s `missing:` bullet 1** (verbatim):
```
State the precise trigger — per 44.2-REVIEW.md's own suggested fix: the mapped TARGET key must be
literally "authors", not merely that "author" is present as a mapping source key — in
configuration.rst (both sites), the template_engine.py D-05 comment, and the two test-file
docstrings.
```
This is correct as far as it goes (it does name the TARGET key as decisive), but its companion test
bullet ("Add a Group 2 test cell exercising `parameter_mapping={"author": "<non-authors-key>"}`...")
only asks for rows D/E (`"author"` routed away from `"authors"`) — it never asks for a row where a
NON-author key is routed INTO `"authors"` (rows F/G), so a repair following only this bullet's
test-coverage instruction would still ship without a test that could catch round 2's actual defect.

**The methodological through-line:** round 1 searched for the rule's boundary by enumerating CONFIG
SHAPES ("package-alone build"). Round 2 searched by enumerating the mapping's SOURCE key ("does the
mapping map `"author"`?") — closer, because it is stated over a real predicate the code checks, but
still keyed on the wrong operand: the code's `if sphinx_key in sphinx_metadata` guard tests the
SOURCE key's presence, but the branch that reaches `"authors"` at all is selected by the TARGET key
(`if template_key == "authors"`, implicit in `params[template_key] = value` only mattering when
`template_key == "authors"`). This round derived its search set from §1's AST enumeration of the
ASSIGNMENT TARGET instead — the one thing every prior round treated as a constant ("we're talking
about `params["authors"]`") rather than as the axis to enumerate over. Enumerating over the target
instead of the source is what surfaces rows F and G, which neither prior round's search set could
produce.
