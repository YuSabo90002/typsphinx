### Locked Decisions

- **D-01: An empty-string `entry[2]` / `entry[3]` is a value, not a signal to fall back.** It
  renders as an empty title / empty author. Matches Sphinx's `LaTeXBuilder.write_documents()`,
  which has no fallback branch. Measured: a real `-b typstpdf` build with `title: ""` / `authors: ()`
  compiles to a 14587-byte PDF (vs 17109 bytes with values); only the title block goes blank.
- **D-02: A missing element or `None` falls back silently to `config.project` / `config.author`; a
  non-`str` element emits a `logger.warning` and then falls back.** Mirrors the guards already in
  `builder.py`.
- **D-03: The override applies uniformly to every template route (A1–A4)**, implemented by
  substituting `project`/`author` inside the `sphinx_metadata` dict built at `writer.py` (near

- **D-08: SC#4's "identical output" set is redefined by three conditions** (ROADMAP's "104/5/99" is

- **D-10: `entry[4]` is accepted-and-ignored, and `configuration.rst` says so explicitly.** No code

## Summary

This phase is a pure Python config-plumbing change inside a single Sphinx extension package — no
new library, no new architecture, no framework upgrade. The entire "domain" is: read two more
elements out of a tuple that is already being partially read in three other places
(`writer.py:68`, `builder.py:141`, `builder.py:194-195`, `builder.py:986`), and thread the result
through `TemplateEngine.map_parameters()`'s existing precedence chain. CONTEXT.md (D-01…D-11) has
already made every product decision; this research's job was to (a) verify every file:line citation
against the current tree, (b) resolve the five items CONTEXT.md explicitly left to research, and
(c) **empirically verify** — by writing the actual code change into a throwaway spike, running the
full 871-test suite against it, and reverting — which tests actually go RED, rather than trust
CONTEXT.md's own (partially incorrect) prediction.

The spike found the real RED set is **smaller** than CONTEXT.md's D-08 list and includes **one test
CONTEXT.md never named**. It also found that D-05's "entry[3] beats typst_authors" headline is a
simplification: the actual, measured effect of the minimal code change is broader — `typst_authors`
is discarded whenever `"author"` is an active key in the template engine's `parameter_mapping`
(which is every route except a package-alone build using a custom mapping that omits `"author"`),
regardless of whether the winning value came from an explicit `entry[3]` or from a plain
`config.author` fallback. This is exactly what makes D-05's own "unbreaks `typst_authors` + bundled
`base.typ`" claim true, and it means CONTEXT.md's own citation of
`tests/test_package_only_config_gate.py` and `tests/test_template_engine.py:964` as "will change"
sites is **not borne out by measurement** — those stay green. See Common Pitfalls for the full
correction and Architecture Patterns for the verified code shape.

The D-08 corpus-partition numbers were also re-measured and found materially different from
CONTEXT.md's own re-measurement: **108** `conf.py` files set `typst_documents` (not 83), yielding
**111** parsed entries (not 83): **107** four-tuples and **3** five-tuples (not zero) — `docs/source/
conf.py`, `examples/charged-ieee/approach1/conf.py`, and `examples/charged-ieee/approach2/conf.py`
all carry a fifth element `"typst"`, directly contradicting D-10's claim that only
`_default_typst_documents` produces one. The **72** inline-in-test/docs occurrence count and the
**5** divergent-`entry[2]`/**0**-divergent-`entry[3]` figures ARE confirmed correct — plus one new
divergent entry D-08 missed (`tests/fixtures/non_str_docname_gate/conf.py[1]`, which is inert in
practice because its docname is the integer `123` and can never match a real document).

**Primary recommendation:** add one small, pure helper (module-level function in `writer.py`, not an
extension of `_is_master_document`) that resolves `(title, author)` for the current master's entry
with D-01/D-02 fallback semantics; substitute its result into `sphinx_metadata` at the existing
construction site; and move the existing `typst_authors` block in `map_parameters()` to run
**before** the mapping loop instead of after it. That is the entire code diff. Verified via a full
local spike: **3 tests need updating, 867 pass unchanged, 1 pre-existing skip**, and the corpus-wide
real-compile gate (`test_corpus_gate.py`) stays green.

### Pattern 1: First-match entry lookup with typed fallback (the new helper)

**What:** A small, pure, module-level function that looks up `entry[index]` for the FIRST
`typst_documents` entry whose `entry[0] == docname`, applying D-01/D-02's fallback rule.

**When to use:** Called exactly twice per master-document write, in `TypstWriter.translate()`,
right where `sphinx_metadata` is built — never earlier (before `_is_master_document` has
established this really is a master) and never inside `TemplateEngine` (which is Sphinx-config-
agnostic by design and must stay that way — it never imports `typst_documents` itself).

**Recommended placement, over the alternatives actually measured:**

| Candidate | Blast radius measured | Verdict |
|-----------|----------------------|---------|
| Extend `_is_master_document` to return the entry instead of `bool` | 1 call site inside `translate()`, but the METHOD NAME and boolean contract are relied on by nothing else in this file — however, CONTEXT.md flags it as risky specifically because a signature change on a method already in production changes its public boolean contract for anyone subclassing `TypstWriter`. `grep -rn "_is_master_document"` shows exactly 1 call site (translate() itself), so the blast radius is actually small — but the method's DOCSTRING and semantics ("Check if... True/False") would need rewriting for what is now a getter, mixing two concerns (existence-check + value-extraction) in one method. | Rejected: mixes concerns even though blast radius is small |
| New private helper **method** on `TypstWriter` (e.g. `self._resolve_entry_metadata(...)`) | 0 external call sites (new code); but needs `self` for no reason — the function touches no instance state | Workable, but adds unneeded coupling to the class |
| **New module-level function in `writer.py`** (e.g. `_resolve_entry_element(typst_documents, docname, index, default)`) | 0 external call sites (new code); pure function, trivially unit-testable without constructing a `TypstWriter`/`Sphinx` app | **Recommended** — matches the existing precedent of `resolve_package_for_engine()` and `derive_typst_lang()` in `template_engine.py`, which are module-level pure functions for exactly this reason (single-responsibility, framework-agnostic, directly unit-testable) |
| Builder-side helper alongside `_resolve_output_stem` (`builder.py:186-200`) | Would require threading the resolved title/author from `TypstPDFBuilder`/`TypstBuilder` down into `TypstWriter.translate()` via a new `self.builder.X` attribute or method call — `_resolve_output_stem` exists on the builder because the BUILDER needs the resolved stem (for the file path); the WRITER needs the resolved title/author (for `sphinx_metadata`), and `translate()` already has `self.builder.config` in hand | Rejected: adds an unnecessary builder↔writer round-trip for data the writer can already read directly off `self.builder.config` |

**Recommended signature** (return-shape distinguishing absent vs. present, per D-01/D-02):

```python
def _resolve_entry_element(
    typst_documents: list, docname: str, index: int, default: str
) -> str:
    """First-match entry[index] lookup with D-01/D-02 fallback.

    - No matching entry, or entry too short to have `index`, or the
      element is None -> `default` (silent, D-02).
    - Element present and a non-empty OR empty str -> returned verbatim
      (D-01: "" is a value, not a fallback signal).
    - Element present but not a str -> `logger.warning(...)`, then
      `default` (D-02).
    """
    for entry in typst_documents:
        if entry and entry[0] == docname:
            if len(entry) <= index:
                return default
            value = entry[index]
            if value is None:
                return default
            if not isinstance(value, str):
                logger.warning(
                    f"typst_documents element [{index}] for docname "
                    f"{docname!r} is not a str: {value!r} -- "
                    f"falling back to {default!r}"
                )
                return default
            return value
    return default
```

Called twice at the `sphinx_metadata` construction site in `translate()` — once with `index=2,
default=config.project`, once with `index=3, default=config.author`. Bare `list`/`str` parameter
types (no `typing.List`/`Dict` import) match this file's existing style (`writer.py` currently
imports only `from typing import Any`); `builder.py`'s own `_default_typst_documents(config:
Config) -> list:` uses the identical bare-`list` convention (`builder.py:28`).

**A duplicate-docname entry (two `typst_documents` tuples with the same `entry[0]`) resolves
silently to the FIRST match** — the `for entry in typst_documents: ... return` shape above stops at
the first hit, exactly mirroring `_is_master_document` (`writer.py:68`, no `break` needed since it
`return`s immediately) and `_resolve_output_stem` (`builder.py:194-197`, explicit `break`). No new
warning is added for this case: CONTEXT.md's own discretion note draws a hard boundary against
absorbing the adjacent duplicate-*target* defect, and adding detection logic here (which would
require scanning the WHOLE list for a second match, not just returning on the first) is the same
shape of scope creep — silent first-match costs zero new code, matches 2-for-2 existing precedent,
and needs no test beyond confirming the existing behavior is preserved.

### Pattern 2: The `typst_authors` reorder (D-05) — verified minimal diff

**What:** In `TemplateEngine.map_parameters()`, move the existing block

```python
if self.typst_authors:
    params["authors"] = [
        {"name": name, **details}
        for name, details in self.typst_authors.items()
    ]
```

from its current position (after the mapping loop and the package-aware back-fill guard, currently
`template_engine.py:456-460`) to run as the FIRST statement in the method body, before the mapping
loop (currently `template_engine.py:421-430`). Leave the mapping loop, the back-fill guard, and the
`typst_elements` merge in their existing relative order.

**Why this — and not a dedicated "entry beats typst_authors" override — is the correct
implementation:** verified empirically (see Common Pitfalls, "D-05 is broader than its headline").
A dedicated override keyed specifically off "was `entry[3]` explicit" cannot be built cleanly
because D-03's substitution point unifies "explicit entry[3]" and "silent fallback to
config.author" into the same `sphinx_metadata["author"]` string before `map_parameters()` ever
sees it — there is no signal left to distinguish them by the time `map_parameters()` runs, and
CONTEXT.md's own D-05 evidence (the `typst_authors` + bundled `base.typ` fix) requires the broader
behavior anyway: on the bundled-template path, `config.author` (with NO `typst_documents` override
at all) must ALSO beat `typst_authors`, not just an explicit `entry[3]`.

**When to use:** This is the single site where the precedence flips; no other file changes for
D-05.

### Pitfall 3: Implementing D-05 as a per-entry "if explicit entry[3], override" instead of a block reorder — and believing CONTEXT.md's own test-citation list without re-measuring

**What goes wrong:** Two separate mistakes compound here:

1. Building a NEW, separate "entry[3] wins" override step (distinct from the existing
   `typst_authors` block) that only fires when the CALLER can prove `entry[3]` was explicit
   (not a D-02 fallback). This is asked-for by D-05's own headline framing ("entry[3] beats
   typst_authors") but is **impossible to build correctly** given D-03's substitution point:
   by the time `map_parameters()` sees `sphinx_metadata["author"]`, an explicit `entry[3]` and a
   silent D-02 fallback to `config.author` are the same plain string — there is no signal left to
   distinguish "this is an override" from "this is the default."
2. Trusting CONTEXT.md's own D-08 grouping that `tests/test_package_only_config_gate.py`
   (`:142/:246/:392/:476-482`) and `tests/test_template_engine.py:964` are "sites that... still
   change" once D-05 lands.

**Why it happens:** CONTEXT.md's D-05 reversibility note ("the order of two assignments") is
CORRECT, but its plain-English headline ("entry[3] beats typst_authors") oversimplifies what that
reorder actually does. The reorder makes the **entire generic author→authors mapping pathway**
(fed by either an explicit `entry[3]` or a silent `config.author` fallback — indistinguishable)
beat `typst_authors`, on EVERY route where `"author"` is an active key in
`self.parameter_mapping` — which is every route except a package-alone build using a *custom*
`typst_template_mapping` that specifically omits `"author"`.

is never a key in that fixture's `self.parameter_mapping`, the reordered mapping loop NEVER touches
`params["authors"]` there — `typst_authors` remains the sole, unchallenged source, exactly as
before.

### Pitfall 4: Assuming `writer.py` already has a `logger` to call `.warning()` on

**What goes wrong:** `logger.warning(...)` in the new helper raises `NameError: name 'logger' is
not defined`.

**Why it happens:** `writer.py` currently imports only `from typing import Any` and
`from docutils import writers` / `from typsphinx.template_engine import (...)` /
`from typsphinx.translator import TypstTranslator` `[VERIFIED: typsphinx/writer.py, read in full

**How to avoid:** Add `from sphinx.util import logging` + `logger = logging.getLogger(__name__)`

gives proper integration with Sphinx's `-W`/warning-count machinery that stdlib `logging` does not.

### Pitfall 6: Confusing D-01's "empty string is a value" with an untested edge in `pypdf`

**What goes wrong:** Assuming an empty `document(title: "")` still produces a `/Title` key in the
compiled PDF's metadata dict (it does not), and writing an SC#1 assertion that checks
`reader.metadata.title == ""` (which will fail — the key is simply absent, so
`reader.metadata.title` is `None`).

**Why it happens:** Typst omits the `/Title` PDF key entirely when the title string is empty,
rather than emitting an empty string.

**How to avoid — verified this session** with a real `typst.compile()` + `pypdf.PdfReader` round
trip: `document(title: "")` -> `reader.metadata` has NO `/Title` key at all (`reader.metadata.title
is None`); `document(author: ("",))` -> `reader.metadata.author == ""` (present, empty — arrays
behave differently from the bare scalar). SC#2's empty-string test case should assert
`is None` for title and `== ""` for author, not symmetrically.

```python
from sphinx.util import logging

logger = logging.getLogger(__name__)


def _resolve_entry_element(
    typst_documents: list, docname: str, index: int, default: str
) -> str:
    """First-match entry[index] lookup with D-01/D-02 fallback semantics."""
    for entry in typst_documents:
        if entry and entry[0] == docname:
            if len(entry) <= index:
                return default
            value = entry[index]
            if value is None:
                return default
            if not isinstance(value, str):
                logger.warning(
                    f"typst_documents element [{index}] for docname "
                    f"{docname!r} is not a str: {value!r} -- "
                    f"falling back to {default!r}"
                )
                return default
            return value
    return default
```
