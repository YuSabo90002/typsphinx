**Step E — land the `writer.py` change (D-01, D-02, D-03).**

Add `from sphinx.util import logging` and a module-level `logger = logging.getLogger(__name__)` to
`typsphinx/writer.py` — Sphinx's logging wrapper, matching `builder.py`, NOT the stdlib module,
because that wrapper is what integrates with Sphinx's `-W` and warning-count machinery.

Add a module-level pure function
`_resolve_entry_element(typst_documents: list, docname: str, index: int, default: str) -> str`,
per RESEARCH.md's verified diff. Module-level, not a method: it touches no instance state, it is
directly unit-testable without constructing a `TypstWriter` or a `Sphinx` app, and it matches the
existing precedent of `resolve_package_for_engine()` and `derive_typst_lang()` in
`template_engine.py`. Do NOT extend `_is_master_document` — its boolean contract stays as it is.
Resolution rules, all four of them:

- iterate `typst_documents` and take the FIRST entry whose `entry[0] == docname`; a falsy/malformed
  entry is skipped rather than indexed, matching `_is_master_document`'s existing guard. Two entries
  naming the same docname resolve silently to the first — the same first-wins convention
  `_is_master_document` and `_resolve_output_stem` already use. No warning and no list-wide second-
  match scan is added; that shape is how the out-of-scope duplicate-target defect would get absorbed.
- entry too short to have `index`, or the element is `None`: return `default` silently (D-02).
- element is a `str`, including `""`: return it verbatim (D-01).
- element is present but not a `str`: `logger.warning(...)` naming the element index, the docname and
  the value it is falling back to, then return `default` (D-02). This is the one case that must not
  be passed through: the template engine's numeric formatting branch would emit an unquoted value and
  Typst's document title argument requires a string or content, so the compile would abort.

Bare `list` / `str` annotations, matching `builder.py`'s `_default_typst_documents(config: Config)
-> list:`. Do not import `typing.List` / `typing.Dict`.

Then substitute in `translate()`. Read `typst_documents` off `self.builder.config` defensively
(`getattr(config, "typst_documents", []) or []`), call the helper twice — `index=2` with
`config.project` as default, `index=3` with `config.author` as default — and build the
`sphinx_metadata` dict from those two resolved values plus the unchanged `config.release`. The dict's
KEYS are unchanged (`project`, `author`, `release`): only their values are now entry-resolved. That
is what makes this reach all four template routes at once without introducing a template parameter,
and what keeps a user's `typst_template_mapping` remapping working unchanged. The call site sits
AFTER `translate()`'s existing early return for non-master documents, so the lookup only ever runs
for a docname that already matched. Keep the existing explanatory comment about `copyright` being
deliberately absent from this dict; extend it rather than replacing it.

Nothing else in `writer.py` changes: `_is_master_document`, `_compute_template_import_path`, the
included-document import block, the `TemplateEngine` construction, the `effective_elements` union and
the `template_file` routing branch are all untouched.
