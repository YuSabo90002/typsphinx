## Empty-string / absent-element semantics

| Option | Description | Selected |
|--------|-------------|----------|
| LaTeX-faithful: an empty string is a value | Sphinx's `write_documents` assigns `title`/`author` verbatim with no fallback branch; measured that `title: ""` / `authors: ()` still compiles (14587-byte PDF) | ✓ |
| Empty string means "unset", fall back | Same output as today's measured behaviour (`title: "Fallback Project"`) | |
| Pass through as a value but emit a WARNING | Matches `builder.py`'s degenerate-target warnings, but fails `-W` builds | |

**User's choice:** LaTeX-faithful — an empty string is a value.
**Notes:** —

| Option | Description | Selected |
|--------|-------------|----------|
| Missing/`None` silent, non-`str` warns then falls back | Mirrors `_resolve_output_stem`'s silent no-match (`:201`) plus its warn-and-fall-back guards (`:240`, `:259`, `:279`) and BLD-01's non-`str` docname handling | ✓ |
| All three fall back silently | One rule, but a config mistake is swallowed | |
| Coerce non-`str` with `str()` and use it | `_format_typst_value`'s final `else` already quotes `str(value)`, but an unintended value reaches the PDF | |

**User's choice:** Missing/`None` silent, non-`str` warns.
**Notes:** The first presentation of this question was answered, then the user asked for it to be
re-issued and gave a different answer; the second answer is the one recorded.

## Override scope across template routes

The first framing of this question was rejected. The user asked for **every route to be enumerated
first**, and listed four they were tracking: bundled `base.typ` with no package; package plus a
function named in `conf.py`; a custom template declaring the same parameters as `base.typ`; a custom
template with an arbitrary function named in `conf.py`.

A five-row enumeration was produced and was **also** corrected by the user — collapsing "package"
and "package + function name" into one row was wrong, because the function/params choice is an
independent axis. The enumeration was redone as a 2×N matrix (A1–A4 template sources × B1–B3
function forms), which is what CONTEXT.md D-03/D-04 record.

| Option | Description | Selected |
|--------|-------------|----------|
| Uniform across A1–A4 | Substitute into `sphinx_metadata`; the mapping loop runs before the package guard so all four routes already receive `title`/`authors` | ✓ (with the B3 carve-out below) |
| A1 only (bundled default) | CONF-07/D-06's `uses_bundled_default_template()` gate — but that gate existed to avoid pushing a *new* parameter onto templates that never declared it, which does not apply to `title`/`authors` | |
| A1–A3, excluding the package route | Would leave `config.project` reaching A4 while the entry value does not — an asymmetry, not an abstention | |

**User's choice:** Uniform across A1–A4, **except B3**.
**Notes:** Verbatim rationale — *"typst_documents 等で渡す引数はあくまで標準呼び出し関数の引数を指定
するものであって、ユーザーが具体的に関数と引数を指定しているのであればその決定を上書きすべきでない
からだ"*. This requires no new code: `render()`'s existing D-08 merge already applies
`typst_template_function["params"]` last.

## `typst_authors` precedence and future

The precedence question was issued once and the user asked to clarify instead of answering, then
asked directly whether the LaTeX builder has a `latex_authors` equivalent. Measured answer: it does
not — none of the 17 registered `latex_*` config values is author-specific; the closest analog is
`latex_elements`' `'author'` key, and `update_doc_context` overwrites it with `entry[3]` after
`init_context` applied it, so LaTeX lets the entry win. The user then chose to remove `typst_authors`
outright, which settled the precedence implicitly.

| Option | Description | Selected |
|--------|-------------|----------|
| Decide precedence only; removal is a separate phase | SC#2 requires only the stated-and-tested order; removal is breaking and v0.7.1 already carries two user-visible changes | ✓ |
| Add a deprecation warning in 44.2 | Would be a third user-visible change in a patch release | |
| Remove it entirely in 44.2 | Outside the phase goal's boundary | |

**User's choice:** Precedence only in 44.2; removal deferred.

| Option | Description | Selected |
|--------|-------------|----------|
| A `todo` file with `resolves_phase: TBD` | Matches how the duplicate-target defect is being carried | |
| An entry under REQUIREMENTS.md §Future Requirements | Sits with `CFG-01` / `CONF-06`; makes the "v0.8.0 or later" positioning explicit | ✓ |
| Both | Split the measurement (todo) from the positioning (requirement) | |

**User's choice:** Future Requirements entry.
**Notes:** Prompted by the user's question about what an unset `typst_documents` passes as `author`.
Measured answer: unchanged `config.author`, because `_default_typst_documents` already puts it in
`entry[3]` — the change is one of route, not value. That led to measuring whether
`typst_template_function["params"]["authors"]` can replace `typst_authors`: it reproduces the
`authors:` value byte-for-byte, differing only in named-argument order.

| Option | Description | Selected |
|--------|-------------|----------|
| Write only the new precedence into `configuration.rst` | Leaves the removal signalled solely in planning docs | |
| Precedence **plus** a future-removal notice | Documentation-only, so no third breaking change; the byte-identical replacement example can be shown | ✓ |
| Leave the `typst_authors` sections untouched | A reader of those sections would not learn that `entry[3]` now wins | |

**User's choice:** Precedence plus future-removal notice.

## The in-repo divergent entries (SC#4)

Before this area was opened, ROADMAP's "104 entries / 5 divergent / other 99 identical" figures were
re-measured and found wrong on two counts (AST walk finds 83 parseable entries, all 4-tuples; the
divergent set is larger than 5 once test-inline conf strings are counted). Both corrections were
presented before the question.

| Option | Description | Selected |
|--------|-------------|----------|
| Leave every divergent entry, accept the changed output | The fixtures themselves become proof the feature works; test assertions get updated | ✓ |
| Edit `conf.py` files so `entry[2] == project` | Keeps output frozen but deletes the divergence and needs a new fixture | |
| Leave the tests, align only `examples/` | Split treatment for the user-facing example | |

**User's choice:** Leave everything; accept the changed output.

| Option | Description | Selected |
|--------|-------------|----------|
| Redefine "identical" by three conditions | `entry[2] == project` **and** `entry[3] == author` **and** `typst_authors` unset — because D-05 and D-04 change output independently of `entry[2]` | ✓ |
| Drop the count claim; enumerate changed sites exhaustively | Avoids the `conf.py`-vs-inline counting mismatch entirely | |
| Rewrite ROADMAP §Phase 44.2's numbers first | Requires checking no other phase cites them | |

**User's choice:** Three-condition redefinition.
**Notes:** The first attempt at the evidence-method question was rejected; the user asked what
"remaining entries" even meant. Answering that surfaced the `typst_authors` hole in the "99
identical" claim, which is what produced this question.

| Option | Description | Selected |
|--------|-------------|----------|
| Static AST walk to partition; real build only for the failing group | The walk over 83 entries was measured to take seconds | ✓ |
| Static walk plus sample real builds from the satisfying group | Adds a positive control for the argument's premise | |
| Full two-build byte-invariance across `docs/source` and `tests/roots` | Phase 42's `GATE-EVIDENCE-05` method; most rigorous, slowest | |

**User's choice:** Static walk; real build only where the conditions fail.

## The fifth element (SC#5)

Presented with the measured asymmetry: zero in-repo `conf.py` entries carry a fifth element, while
all 10 published examples in `docs/source` do.

| Option | Description | Selected |
|--------|-------------|----------|
| Document it as accepted-and-ignored | No code change; the published contract becomes true | ✓ |
| Warn on an unrecognized value | Mirrors LaTeX's `self.themes.get(themename)` lookup, but would fire only on hand-written non-`typst` values | |
| Drop the fifth element from the docs | Would contradict `_default_typst_documents`' 5-tuple and reverse Phase 44's D-02 | |

**User's choice:** Accepted-and-ignored, documented.
**Notes:** Noted but not acted on — `default_latex_documents` puts `config.latex_theme` there, so the
reference implementation's fifth element has meaning and validation. Matching that would mean adding
a `typst_theme`-style config, outside CONF-09.
