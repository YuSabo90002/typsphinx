<objective>
Make the translator's table container state survive nesting, so a table inside another table's cell
stops clobbering the enclosing table's accumulated cells, column count, column widths, caption,
header-row flag and span counters (TBL-04, roadmap SC#1).

Purpose: today the emitted document is structurally well-formed and compiles cleanly, but it states
something false — the INNER table's body is emitted underneath the OUTER table's caption and every
outer cell is gone, with `sphinx-build` exiting 0 and no warning. That is silent structural data
loss against the project's core value ("emitted output must be faithful"), and it has no downstream
error surface at all.

Output: a seven-section GATE-01 fixture, a render-gate test file, a recorded RED for every section
against the unfixed translator, and the state save/restore + markup-routing fix in
`typsphinx/translator.py`.
</objective>

<assumption_delta_decision>
**Noun now primary:** the *open-container frame* — the translator's identity for "which table is
currently being filled". The model moves from **singular** (one table at a time, held in flat
instance scalars) to **plural** (arbitrarily nested, N-deep).

**Decision: `add-alongside`.** The flat scalars stay the primary representation; nesting is handled
by a snapshot save/restore pushed onto a private stack (`self._table_state_stack`) at
`visit_table` and popped at `depart_table`, **only when a table is already open**.

**Rationale (measured this planning session, re-grepped against the current tree):**
`self.in_table` has ten read sites (`typsphinx/translator.py` lines 432, 663, 1621, 1626, 1651,
3158, 5545, 5562, 5891, 5905) and every one of them asks *"is any table open?"*, never *"which
one?"*. A `promote` (a `list[TableState]` as the primary representation with every consumer reading
the innermost frame) would rewrite all ten call sites for zero behavioural gain, and would put the
Phase 25 `table_cell_content` lifetime invariant at risk in the same diff that changes routing.
`visit_caption`/`depart_caption` (`typsphinx/translator.py:2532-2589`) already establishes the exact
save/restore idiom in this file, so `add-alongside` imitates a proven local pattern instead of
inventing one. Save/restore also generalizes over depth by construction — one push per level, no
per-depth special casing — which is what D-01's three-deep fixture case exists to falsify.

**Accepted debt.** `add-alongside` is debt: the scalars still lie about arity, and a reader must
know the stack exists to reason about them. Two things force a later `promote`:
1. **A third scalar-state container joins the set.** Tables and figures each get their own stack in
   this phase (plans 43-01 and 43-03). A third container with the same clobber shape (CONTEXT
   Deferred Ideas explicitly anticipates this) makes three parallel ad-hoc stacks, at which point a
   single generalized frame object is cheaper than a third copy.
2. **A consumer needs to read a NON-innermost frame.** Every consumer today asks a boolean. The
   first consumer that must ask the *enclosing* table a question — e.g. an inner table sizing its
   columns against the outer cell's width — cannot be served by a scalar-plus-stack at all.

**Phase 25 invariant: PRESERVED, not superseded.** `table_cell_content` keeps its documented
lifetime (created by the first `visit_entry`, reset to `[]` and never deleted at `depart_entry`,
`del`eted only at `depart_table` so `hasattr` goes False for the next table). The single change is
that the `del` fires only when the state stack becomes empty — i.e. when the closing table is the
OUTERMOST one. An inner table's close never deletes the buffer. The comment block at
`typsphinx/translator.py:3376-3388` must be extended to say so, not replaced.
</assumption_delta_decision>
