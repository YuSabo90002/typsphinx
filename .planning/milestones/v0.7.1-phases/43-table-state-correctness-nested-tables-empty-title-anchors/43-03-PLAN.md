<objective>
Give the translator a `legend` node handler and make figure container state survive nesting, so a
figure nested inside another figure keeps the outer figure's caption, ids and state, and the inner
figure renders inside the outer figure's legend (FIG-01, roadmap SC#6).

Purpose: `visit_legend`/`depart_legend` do not exist, so docutils' `unknown_visit` fires (warn and
continue — it does not skip children) and the legend's children stream unwrapped straight after the
outer `image(...)` call. Typst parses `image(...)` followed by any expression as a bad second
argument, so the whole compile aborts. The outer caption is lost on the way.

Output: a four-section GATE-01 fixture, a render-gate test file, a recorded classic-`TypstError` RED
against the unfixed translator, and the `legend` handler plus figure-state save/restore in
`typsphinx/translator.py`.

Scope is set by two CONTEXT decisions, both rated **costly** there and carried through here. **D-02:**
nested figures are fixed in this phase, not filed as a todo — the owner's reason is that it is the
same class of change in the same file as TBL-04, and making it twice is worse than making it once.
**D-03:** the work is tracked as ONE requirement defined by behaviour (FIG-01), not as two split by
cause; the `legend` handler and the `in_figure`/`figure_caption` nesting safety are implementation
means under it, matching how Sphinx's own LaTeX builder presents the same input — one correct nesting,
not two layers.
</objective>

a figure" (RESEARCH Pitfall 4).
