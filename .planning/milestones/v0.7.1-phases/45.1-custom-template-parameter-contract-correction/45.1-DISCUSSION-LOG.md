## Fix route

The workflow's first three attempts to put this to a vote were declined in favour of the owner
re-deriving the problem structure. That re-derivation replaced the option set entirely, so the
routes originally offered (A: docs-only / B: withhold on the passing side / C: `..args` sink /
A+C) were never voted on. They are recorded here because the measurements taken to evaluate them
stand.

**Owner's re-derivation, in order:**

1. The first split is whether `typst_template_function` names a function **and its arguments**.
   When it does, the user has declared in `conf.py` which function is called with which arguments,
   so the parameter-contract question does not apply to that case.
2. `typst_package` templates are authored by Typst Universe registrants and cannot be expected to
   share `base.typ`'s signature, so the intended flow for a package **is** the function+arguments
   route — it merges into case 1.
3. A custom `typst_template` splits four ways: function name only; function name plus arguments;
   no function with `typst_documents`; no function without `typst_documents`.
4. Therefore the phase needs exactly two things: document the default parameter set for the
   no-arguments case, and make the arguments case pass only the declared arguments — "which is
   how I intended it, but the implementation did not do that".

**Assistant correction accepted into the record:** the additive union is not Phase 44.2's doing.
`git log -S` places it at `dd225a9 feat: add Typst Universe template support (Issue #13)`; 44.2
only documented it, and 44.2's own rationale sentence (`configuration.rst:63-68`) states the
exclusivity intent that the mechanism never implemented.

### Sub-decision: `typst_package` + function name only (no params)

| Option | Description | Selected |
|--------|-------------|----------|
| Move `writer.py:326-330` inside the D-05 gate | Withhold `typst_elements` / `toctree_*` on the package path too | |
| Close it in documentation | Deprecate the name-only form; no code change | ✓ |

**User's choice:** documentation.
**Notes:** "これはある意味当然の挙動なのでドキュメントで非推奨を言うのが筋。何かコード的に対応するのは一貫性が無い."
Consequence accepted: a user who ignores the rule still reaches
`TypstError: unexpected argument: papersize` (measured live against `@preview/charged-ieee:0.1.4`).

### Sub-decision: how far exclusivity applies

| Option | Description | Selected |
|--------|-------------|----------|
| Full exclusivity on every route + CHANGELOG | Declared semantics; `typst_elements` and `toctree_*` also drop | ✓ |
| Full exclusivity + build-time warning | Same, plus a warning when `params` omits `title`/`authors`/`date` | |
| Exclusivity on the package path only | Leaves `typst_template` additive; existing users unaffected | |

**User's choice:** full exclusivity, announced in the CHANGELOG.
**Notes:** the silent failure mode was stated before the vote — an existing project that sets
`params` to add one key will render with the template's own defaults (empty title, no author)
rather than erroring.

### Sub-decision: `params: {}` semantics

| Option | Description | Selected |
|--------|-------------|----------|
| Treated as specified → pass nothing | Predicate is the presence of the `params` key; enables zero-parameter templates | ✓ |
| Treated as unspecified → pass the default set | Only a non-empty dict triggers exclusivity | |

**User's choice:** treated as specified.
