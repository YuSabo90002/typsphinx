# Phase 45.1: Custom-Template Parameter Contract Correction - Context

**Gathered:** 2026-08-10
**Status:** Ready for planning

<domain>
## Phase Boundary

Make the published custom-template parameter contract and the parameters typsphinx actually
passes agree in both directions, and settle *which* parameters a user-authored template
receives at all.

The phase was inserted to carry DOC-13 (`templates.rst:187-192` publishes four parameters;
`writer.py:326-330` also passes `toctree_*` and the `ELEMENTS_ALLOWLIST` keys). The discussion
established that the defect is **broader than the source todo recorded** and that the correct
repair is **not documentation alone** — see `<specifics>` for the measurements and `<decisions>`
for what that widened the phase to. The owner explicitly reaffirmed the widened scope after the
cost was stated (D-F, D-H).

**In scope:** the parameter set reaching a user-authored template on every route, the published
contract in `templates.rst` / `configuration.rst` / `examples/advanced.rst`, the removal of
`typst_authors`, and the `lang` auto-derivation asymmetry.

**Out of scope:** the `..args` argument sink (deferred with its measurement), any change to
`extract_toctree_options()`'s own extraction logic, and the outline-depth mapping (Phase 44.1
D-03 still holds).

</domain>

<decisions>
## Implementation Decisions

### The parameter contract when `typst_template_function["params"]` is absent

- **D-A:** Publish the default parameter set in `templates.rst` exactly as measured — nine named parameters plus the trailing positional `body`, each with its emission condition. The set is `title` / `authors` / `date` (unconditional on the non-package path, via `map_parameters()`'s back-fill), `papersize` / `fontsize` (only when set in `typst_elements`), `lang` (see D-I), and `toctree_maxdepth` / `toctree_numbered` / `toctree_caption` (only when the master carries a toctree). `templates.rst` must also state that `authors` is always a Typst **array** — never a bare string — that a `str` source is **split on commas**, and (until D-F lands) that its element type varies. The repository already contains two correct nine-parameter declarations (`typsphinx/templates/base.typ:39-50` and `docs/source/_typst/custom_template.typ:64-75`); the published page is the only surface that drifted.

- **D-C:** `typst_package` combined with a function **name only** (no `params`) is treated as expected behaviour, not a defect. typsphinx cannot know a third-party Typst Universe function's signature, so passing it the default set is misuse rather than a bug. Owner decision: handling this specially in code would be inconsistent. `templates.rst`'s Configuration-Based Templates section states that `typst_package` requires `typst_template_function`'s `params`, and deprecates the name-only form. **No code change.** Note this leaves a real compile fatal reachable for a user who ignores the rule — measured, see `<specifics>` item 4.

### The parameter contract when `typst_template_function["params"]` is present

- **D-B:** When `params` is specified, **only those parameters are passed**. This replaces today's additive union (`template_engine.py:687-694`, D-08, where auto-derived values are the fallback and `params` merely wins on key collisions) with wholesale replacement: the auto-derived `title`/`authors`/`date`, the `typst_elements` merge, and the `toctree_*` merge are all discarded. Applies on **every route** — `typst_template`, `typst_package`, and the bundled default alike. Owner framing: this is not a new design judgment but the correction of an intent that was never implemented — Phase 44.2 already published the rationale verbatim in `configuration.rst:63-68` ("a user who has named both the template function and its arguments has already made a more specific decision than either") while documenting the mechanism as per-key override. The trailing positional `body` is unaffected: it flows through the `#show:` rule, not as a named argument. — **Reversibility:** one-way — this changes a published contract. A project that sets `params` today to add one key and relies on the auto-derived rest will silently render with the template's own defaults (an empty title, no author) rather than erroring. Undo requires a second published behaviour reversal.

- **D-D:** `params: {}` (an explicitly empty dict) counts as **specified** — nothing is passed. The predicate is the presence of the `params` key, a single rule with no emptiness special case. This makes a zero-named-parameter template (`#let project(body) = {...}`) usable for the first time; today `title`/`authors`/`date` always arrive and make it impossible. Note this differs from today's parsing, where an absent `params` and `params: {}` both resolve to `self.typst_template_params = {}` (`template_engine.py:244-256`) — the parse must start distinguishing them. — **Reversibility:** costly — it is part of D-B's published semantics.

### `typst_authors`

- **D-F:** Remove `typst_authors` in this phase. Owner rationale: typsphinx bills itself as a LaTeX alternative and should follow `latex_documents`; LaTeX has no facility for supplying an author as a dictionary. Rich author structure is to be expressed through the `typst_template_function` `params` route instead, which D-B makes an explicit, self-contained declaration. Measured blast radius (excluding `_build/`, `.venv/`, `.planning/`): 14 implementation sites (`template_engine.py` 11, `writer.py` 1, `builder.py` 1, `__init__.py` 1), **71 test sites** across 7 files (`test_entry_metadata_precedence.py` 37, `test_template_engine.py` 13, `test_params_authors_writers.py` 7, `test_authors_pipeline_stage_gate.py` 7, `test_package_only_config_gate.py` 6, plus 2), one fixture (`tests/fixtures/package_only_config_gate/conf.py`), 13 documentation sites, and the shipped sample `examples/charged-ieee/approach1/conf.py`, which currently presents `typst_authors` as **"Recommended"**. Most of the test mass is Phase 44.2's own work from this milestone. — **Reversibility:** one-way — a public config value disappears; restoring it means re-adding the registration, the seed, the precedence rule, and its test matrix.

  **Concern stated and overridden.** Phase 44.2 published a forward-removal notice saying `typst_authors` is "slated for removal in a future **major** release", and v0.7.1 is a bug-fix round whose next phase is release prep. Removing it here lands the removal earlier than the published notice promised. The owner reaffirmed the decision after this was stated; recorded here so Phase 46's CHANGELOG curation can say so plainly.

### `lang` auto-derivation

- **D-I:** Pass the auto-derived `lang` on **every non-package template route**, not only the bundled default. Concretely: drop the `resolve_template().source == "default"` half of `uses_bundled_default_template()`'s judgment and **keep the `typst_package` guard**, which remains load-bearing for the same reason D-C gives. CONF-07's D-06 withheld `lang` because an explicit `typst_template` might not declare it — a rationale D-A weakens by publishing the nine-parameter contract, and one the LaTeX-parity argument of D-F cuts against (Sphinx's LaTeX builder derives `babel`/`polyglossia` from `language` regardless of `latex_elements`). This lets `docs/source/conf.py:98-113` drop its workaround, which imports `derive_typst_lang` directly from `typsphinx.template_engine` and rebuilds `typst_elements["lang"]` by hand; the `typsphinx-doc-translations` repository carries the same workaround. — **Reversibility:** costly — an existing custom template that declares fewer than nine parameters and omits `lang` starts failing with `unexpected argument: lang`.

### Documentation surfaces

- **D-E:** Rewrite `configuration.rst:199-265`'s two-stage precedence model to follow D-B. Under exclusivity there is no per-key merge: stage 2 discards stage 1 entirely. Stage 1's own content (the target-key rule, the `typst_authors` seed survival condition) stays factually correct but becomes subordinate to "when `params` is absent". The `.. note::` at `:259-265` must be rewritten regardless of D-F's timing — under D-B its advice ("`typst_authors` is fully replaceable by `params["authors"]`; new configurations should prefer `params`") becomes actively harmful, because migrating for `authors` alone silently drops the other eight parameters.

- **D-G:** Fix and **verify by real build** all eight example templates across the docs — five in `templates.rst` (`:144`, `:214`, `:237`, `:272`, `:287`) and three in `examples/advanced.rst` (`:61`, `:144`, `:238`) — plus the four `typst_template_function` configuration examples (`templates.rst:44`, `:201`, `examples/advanced.rst:32`, `:186`), whose behaviour D-B changes. Four of the five `templates.rst` examples are measured to fail today. Verification is by build, not by reading — this is also SC#2's stated method.

- **D-J:** Record the standing consequence ("adding a template parameter is a breaking change for a correctly-written custom template") in **prose only**. Do **not** build a sync test that holds the contract's surfaces in lockstep, even though `tests/test_preview_version_sync.py` is an established precedent for exactly that shape and `docs/source/_typst/custom_template.typ` has been flagged since the v0.6.4 review as an unguarded lockstep site. Owner decision.

- **D-K:** SC#3's GATE-01 regression fixture **stands** — D-J rejects only the sync test. Build a project whose custom template declares exactly the documented parameters, prove it RED against the pre-fix commit, then lock it green. Two independent RED cases are already measured and available (see `<specifics>` items 1 and 2).

### Planning documents

- **D-H:** Amend `ROADMAP.md` and `REQUIREMENTS.md` immediately after this discussion, before planning — the Phase 44.1 D-01 precedent (`gsd-verifier` reads ROADMAP success-criterion text directly, so an unsatisfiable or absent criterion produces a wrong verdict). Two concrete needs: **SC#6 as written is falsified by D-F** ("no behaviour outside the template-parameter contract changed" — removing a public config value is exactly such a change), and **no success criterion covers D-B, D-F, or D-I**. `REQUIREMENTS.md` needs a requirement carrying the behaviour changes alongside DOC-13, which describes only the contract correction; coverage is currently 15/15 with zero orphans and must stay balanced.

### Claude's Discretion

- The implementation site of D-B's exclusivity (inside `TemplateEngine.render()`'s merge, or upstream in `writer.py` before `map_parameters()` is called) was not discussed. Research/planning may choose, subject to D-D's "presence of the `params` key" predicate surviving into whatever code reads the config.
- The migration guidance for `typst_authors` users — where it lives and how detailed it is — was not specified.
- How `examples/charged-ieee/approach1/conf.py` is rewritten once `typst_authors` is gone.

<code_context>
## Existing Code Insights

### Reusable Assets
- `TemplateEngine.uses_bundled_default_template()` (`template_engine.py:344-382`): the project's existing single judgment point for "withhold a parameter this template may not declare". D-I narrows it rather than replacing it; its `typst_package` guard is documented as load-bearing for a reason independent of the template-resolution walk, and D-C confirms that reasoning.
- The `if not self.typst_package` back-fill gate (`template_engine.py:497-509`, D-05) already encodes exactly D-B's rationale for `title`/`authors`/`date`. D-B generalizes it from "the package path" to "whenever the user has declared `params`".
- `tests/test_preview_version_sync.py`: the structural precedent for a multi-surface lockstep test. D-J declines it here — noted so a later reviewer does not read the absence as an oversight.
- `derive_typst_lang()` (`template_engine.py:84+`) is already public and already imported by `docs/source/conf.py`; D-I removes the need for that import rather than the function.

### Established Patterns
- **`.typ` signatures are never introspected from Python.** `template_engine.py:69-76` (CONF-04 D-03) and `:232-239` (D-05) both record this. It rules out any repair that filters parameters by parsing a template's declaration, and it is why D-B keys off the user's own `params` declaration instead.
- **Unknown configuration fails loudly rather than being dropped.** `ELEMENTS_ALLOWLIST` raises `ExtensionError` on an unrecognized key (`template_engine.py:519-530`, D-06/D-07). This is the stance that rules out the `..args` sink (see `<deferred>`).
- **GATE-01:** every behaviour change ships a real `sphinx-build → typst.compile()` fixture recorded RED against the unfixed code before it is accepted. D-K keeps it.
- Line length 88 (black), `N802` ignored for docutils visitors, Python 3.12+, and no typing modernization (`UP006`/`UP035` stay ignored).

### Integration Points
- `writer.py:322-330` is where all three merges converge and is the single place D-B's exclusivity is easiest to observe; `render()` (`template_engine.py:687-694`) is where the union it replaces lives.
- `__init__.py` registers `typst_authors`; `builder.py` and `writer.py` each read it once. Removal (D-F) touches four implementation files.
- `docs/source/conf.py` and the separate `typsphinx-doc-translations` repository both carry the D-I workaround. Only the former is in this repository; the latter is a **handoff item**, not an in-phase edit.
- The `typst` builder emits `.typ` without compiling, so every measurement in `<specifics>` is cheap to re-run; only the `unexpected argument` claims need `-b typstpdf`.

<specifics>
## Specific Ideas

Everything below was measured during the discussion against the working tree (Sphinx 9.1.0,
typst-py 0.15.0, typsphinx 0.7.0), not inferred from reading code.

1. **The `templates.rst` "Minimal Template" example fails with no toctree and no `typst_elements`.**
   A project whose `_templates/custom.typ` is `templates.rst:272-280` verbatim and whose `index.rst`
   has no toctree aborts with `TypstError: unexpected argument: authors`. Cause: `map_parameters()`
   back-fills `title`/`authors`/`date` unconditionally on the non-package path. **The defect is
   therefore not the toctree-specific one the source todo recorded** — the four-parameter contract
   is wrong even in the single-document case the todo believed still worked.

2. **Four of the five `templates.rst` examples are under-declared** — Basic Structure (`:144`, four
   params), Wrapping External Packages (`:237`, no `date`), Minimal (`:272`, `title` only), Academic
   Paper (`:287`, no `date`). Only the `typst_template_function` example at `:214` sidesteps it, and
   only because it is not presented as a complete template.

3. **The full emitted call, measured.** With `typst_elements = {"papersize": "a4", "fontsize":
   "11pt", "lang": "en"}` and a `:maxdepth: 3 :numbered: :caption: My Contents` toctree:
   ```typst
   #show: project.with(
     title: "Demo Title", authors: ("Alice",), date: "1.0",
     papersize: "a4", fontsize: 11pt, lang: "en",
     toctree_maxdepth: 3, toctree_numbered: true, toctree_caption: "My Contents",
   )
   ```
   `fontsize` is emitted unquoted (a `RawTypst`); the other elements are quoted strings.

4. **The same defect reaches the `typst_package` path and produces a real compile fatal.** With
   `typst_package = "@preview/charged-ieee:0.1.4"`, `typst_template_function = "ieee"` and
   `typst_elements = {"papersize": "a4"}`, the package downloads and compiles, then aborts:
   `TypstError: unexpected argument: papersize`. The emitted call carries `papersize` and all three
   `toctree_*` and **nothing else** — `title`/`authors`/`date` are correctly withheld by the D-05
   gate, while the two merges in `writer.py:326-330` run outside it. D-C closes this by
   documentation rather than code.

5. **`typst_template_function` does not change the parameter set.** Measured: the string form
   (`"mytpl"`) only renames the emitted function; the dict form emits the same nine plus the
   `params` keys, with `params` winning on collision (`title: "OVERRIDE"` observed). This is the
   additive behaviour D-B replaces, and it predates Phase 44.2 — `git log -S` places it at
   `dd225a9 feat: add Typst Universe template support (Issue #13)`. Phase 44.2 documented it; it
   did not introduce it.

6. **Cases ③ and ④ are indistinguishable in the parameter set.** With `typst_documents` set versus
   absent (Phase 44's CONF-08 derived default), the emitted key set is identical; only the values'
   provenance differs (`entry[2]`/`entry[3]` versus `config.project`/`config.author`). Case ④'s
   output filename was measured as `demoproject.typ`, derived from `project`.

7. **`authors` is always an array, is comma-split, and changes element type.** Measured:
   `entry[3] = "Alice Smith"` → `("Alice Smith",)`; `entry[3] = "Alice Smith, Bob Jones"` →
   `("Alice Smith", "Bob Jones",)` (`_convert_to_authors_tuple` splits on `,`); with a surviving
   `typst_authors` seed → `((name: "Alice Smith", department: "Eng", email: "a@x.com"),)`. Every
   example in `templates.rst` calls `authors.join(", ")`, which is a Typst type error against the
   dict form. D-F removes the dict form; D-A must still document the array shape and the
   comma split.

8. **The `..args` sink is viable in Typst.** `#let project(title: "", ..args, body)` compiles, and
   the sink may precede the trailing positional `body`. Verified by `typst.compile()` with
   `authors`, `date` and `toctree_maxdepth` passed to a template declaring only `title`. Recorded
   because it is the one measured fact behind the deferred option.

9. **The repository works around its own `lang` asymmetry.** `docs/source/conf.py:98-113` explains
   in a comment that setting `typst_template` "silently drops that auto-derivation unless it is
   replicated here explicitly", then imports `derive_typst_lang` and rebuilds
   `typst_elements["lang"]` by hand. This is D-I's strongest evidence.

10. **`docs/source/index.rst`'s first toctree is `:maxdepth: 2 :caption: Getting Started`.** Only
    the first toctree node is read (`extract_toctree_options`), so the repository's own build
    receives `toctree_caption: "Getting Started"` — relevant to any SC#5 comparison of the docs
    build before and after.

</specifics>

<deferred>
## Deferred Ideas

- **`..args` argument sink in `templates/base.typ` plus a documented convention.** Measured to
  compile (item 8 above). Rejected for this phase on three grounds: (a) a sink silently swallows
  typos in `typst_template_function["params"]`, which today fail loudly, reversing the stance
  `ELEMENTS_ALLOWLIST` takes (CONF-04 D-06/D-07); (b) it hides the contract mismatch rather than
  resolving it, and SC#2 explicitly asks for agreement checked by enumerating emission sites;
  (c) it weakens SC#4's constraint, whose purpose is to make the *next* parameter addition a
  deliberate decision. Keep as the option of record if a future phase needs to add a parameter
  without breaking correctly-written templates.

- **A lockstep sync test over the contract's surfaces** (emission sites, `base.typ`,
  `templates.rst`, `custom_template.typ`) — declined by D-J. `docs/source/_typst/custom_template.typ`
  therefore remains the unguarded fourth lockstep site the v0.6.4 review flagged.

- **`typsphinx-doc-translations`' copy of the `lang` workaround.** D-I makes it removable there
  too, but that repository is outside this one. Carry it as a handoff item, alongside the standing
  second-repository tagging cost.

- **The `typst_authors` migration path for existing users.** D-F removes the config; where and how
  detailed the migration guidance is was left to planning.
