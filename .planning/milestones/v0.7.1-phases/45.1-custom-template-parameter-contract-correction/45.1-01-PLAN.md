<objective>
Make a declared `typst_template_function["params"]` the complete parameter set (CONF-11, D-B),
with the presence of the `params` key — not its emptiness — as the predicate (D-D), and prove it
end to end on the thinnest possible slice: a project whose custom template declares no named
parameters at all.

Purpose: today the parameter set is an additive union (`template_engine.py:687-694`) in which the
auto-derived `title`/`authors`/`date`, the `typst_elements` merge and the `toctree_*` merge are the
fallback and `params` merely wins on a key collision. That makes a zero-named-parameter template
impossible and makes a partial `params` declaration a compile fatal. D-B replaces the union with
wholesale replacement; D-D makes `params: {}` mean "pass nothing".

Output: the `typst_template_params_specified` predicate, `render()`'s exclusive branch, a new
real-compile gate fixture and module, and the existing suite re-derived onto the new semantics.
</objective>

<assumption_delta_decision>
**Noun now primary:** *the declared parameter set* — the set of named arguments the user themselves
declared in `typst_template_function["params"]`. The auto-derived nine (`title`/`authors`/`date` +
the `typst_elements` allowlist keys + the `toctree_*` keys) are demoted to *the default parameter
set*: the value of the primary noun in the one variant where the user declared nothing.

**Decision: `promote`.** `render()` gains a single boolean-guarded branch that selects between two
whole strategies — the declared set or the derived set — rather than keeping the additive union and
bolting a filter onto it. `__init__` grows `self.typst_template_params_specified` so an absent
`params` and an empty `params` stop collapsing to the same `{}` (`template_engine.py:244-256`).
There is no residual union code path and no "merge mode" flag: the additive union is deleted, not
disabled.

Rationale: the additive union is not a second legitimate mode a user might want — Phase 44.2
already published the intent verbatim at `configuration.rst:63-68` ("a user who has named both the
template function and its arguments has already made a more specific decision than either") while
documenting the mechanism as per-key override. Keeping both would preserve exactly the ambiguity
D-B exists to remove.

**Companion invariant test (suggested, built here):** `tests/test_params_exclusivity_gate.py`
asserts that a `params` declaration whose key set is a strict subset of the auto-derived key set
emits *only* the declared keys. That assertion goes red the instant a future phase reintroduces the
additive-union assumption, because the union would re-add the auto-derived remainder.
</assumption_delta_decision>
