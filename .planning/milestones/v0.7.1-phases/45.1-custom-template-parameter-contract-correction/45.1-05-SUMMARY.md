## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `advanced.rst`'s styled config passed a Python string where a Typst color constructor was required**
- **Found during:** Task 3's build verification (preparing the `styled` fixture)
- **Issue:** `"primary-color": "rgb(0, 102, 204)"` is a Python `str`, which `typst_template_function`'s params route always formats as a quoted Typst string literal, never a bare function call. `set text(fill: primary-color, ...)` would abort with a Typst type error (`str` is not a color).
- **Fix:** Declared `primary-color` as a hex string (`"#0066cc"`) and converted it inside the template with `rgb(primary-color)`, which Typst's `rgb()` constructor accepts directly. Added a `.. note::` explaining why every params value is a Python-literal-to-Typst-literal conversion, never a raw Typst expression.
- **Files modified:** `docs/source/examples/advanced.rst`
- **Verification:** real `sphinx-build -b typstpdf` against the fixture text, exit 0, valid PDF (14432 bytes)
- **Committed in:** `ffa7130` (Task 3 commit)

**2. [Rule 1 - Bug] `advanced.rst`'s custom_ieee template used a nonexistent `.lower()` string method**
- **Found during:** Task 3's build verification (preparing the `custom_ieee` fixture)
- **Issue:** `name.split(" ").at(0).lower()` — Typst's `str` type has no `.lower()` method in typst-py 0.15.0; the compile aborted with `TypstError: type string has no method 'lower'`.
- **Fix:** Replaced with the free function form: `lower(name.split(" ").at(0))`.
- **Files modified:** `docs/source/examples/advanced.rst`
- **Verification:** real `sphinx-build -b typstpdf`, exit 0
- **Committed in:** `ffa7130` (Task 3 commit)

**3. [Rule 1 - Bug] `advanced.rst`'s custom_ieee template's `bibliography` argument was a bare path string with an incorrect relative path**
- **Found during:** Task 3's build verification (preparing the `custom_ieee` fixture)
- **Issue:** `bibliography: "refs.bib"` — charged-ieee's `ieee()` requires the *result of a call to* Typst's own `bibliography()` function, not a bare string; and even after wrapping it as `bibliography("refs.bib")`, the compile still failed with `file not found` because typsphinx flattens the template file itself to the output root (`_template.typ`) while `copy_template_assets()` preserves the source `_templates/` subdirectory for copied assets — so a relative path written inside the (now-flattened) template resolves from the output root, not from `_templates/`.
- **Fix:** `bibliography: bibliography("_templates/refs.bib")`, with a `.. note::` explaining the asset-copy/template-flattening path mismatch for future readers who add their own file-referencing template code.
- **Files modified:** `docs/source/examples/advanced.rst`
- **Verification:** real `sphinx-build -b typstpdf` with a real `refs.bib` fixture asset, exit 0, valid PDF (27410 bytes)
- **Committed in:** `ffa7130` (Task 3 commit)
