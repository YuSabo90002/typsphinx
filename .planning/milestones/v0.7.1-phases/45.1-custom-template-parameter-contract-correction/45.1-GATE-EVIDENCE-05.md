# Phase 45.1 Plan 05 -- D-G Build Verification Evidence

**Purpose:** D-G requires every documented example on `templates.rst`, `configuration.rst`
(implicitly, via its cross-references) and `examples/advanced.rst` to be verified by a real
build, not by reading. This file records that verification for the twelve enumerated
examples named in the plan's Task 3: five example templates in `templates.rst`, three in
`examples/advanced.rst`, and four `typst_template_function` configuration examples.

**Method:** a throwaway Python harness under the session scratch directory (NOT under
`tests/`, per D-J's prohibition on a permanent lockstep-style test) materialized ten real
Sphinx projects -- one per distinct documented template/configuration pairing -- from the
exact text now published on the two pages, and ran `sphinx-build -b typstpdf` over each via
`sys.executable -m sphinx` (the same invocation shape `tests/test_package_only_config_gate.py`
uses). Two pairs of the twelve documented examples share one underlying build because they are
literally the same template+configuration pairing referenced from two different headings on
the same page section (the "Custom Parameters" config block and its template, and the "styled"
config block and its template) -- each still gets its own row below, with its own page/section
identity, both citing the one real build that proves it.

**Environment:** Sphinx 9.1.0, typst-py 0.15.0, typsphinx 0.7.0 (this worktree, post Tasks 1-2).
Network access was available (charged-ieee 0.1.4 fetched from the Typst Universe registry,
already cached locally from prior phase work). Harness location:
`gate05/` under the session scratch directory -- `gen_fixtures.py` (fixture generator) and
`run_builds.py` (the `sphinx-build -b typstpdf` runner + `#show:` region extractor).

**Master shape:** every fixture's master document (`index.rst`) carries a real toctree
(`:maxdepth: 3 :numbered: :caption: My Contents`) with one child document, and every fixture's
`conf.py` sets `typst_elements = {"papersize": "a4", "fontsize": "11pt", "lang": "en"}` --
so the conditional half of the contract (`papersize`/`fontsize`/the three `toctree_*` keys) is
live on every build, not dormant. Where the documented example itself declares `params`, this
also proves the exclusivity gate: the toctree and `typst_elements` are present in the build but
correctly absent from the emitted call.

### Entry 7 -- `examples/advanced.rst` Custom Template Wrapping / custom_ieee (build: `custom_ieee`)

```
python -m sphinx -b typstpdf <fixtures>/custom_ieee <builds>/custom_ieee
```

Exit code: `0`. PDF: `output.pdf`, 27410 bytes, `%PDF-` magic bytes confirmed. Two real bugs
in this example were found and fixed while preparing this build (both Rule 1, documented in
the SUMMARY): `name.split(" ").at(0).lower()` used a `.lower()` **method** that does not
exist on Typst's `str` type in typst-py 0.15.0 (the free function `lower(...)` does); and
`bibliography: "refs.bib"` passed a bare path string where `ieee()` requires the result of a
call to Typst's own `bibliography()` function, whose relative path must in turn account for
typsphinx's actual asset-copy layout (`_templates/refs.bib` in the output, since the template
file itself is flattened to the output root as `_template.typ`).

### Entries 8-9 -- `examples/advanced.rst` Custom Styling / styled template + config block (build: `styled`)

```
python -m sphinx -b typstpdf <fixtures>/styled <builds>/styled
```

Exit code: `0`. PDF: `output.pdf`, 14432 bytes, `%PDF-` magic bytes confirmed. A real bug was
found and fixed while preparing this build (Rule 1): the documented `params` value
`"rgb(0, 102, 204)"` is a Python `str`, which `typst_template_function`'s params route always
formats as a quoted Typst string literal -- never a bare `rgb(...)` call -- so `set text(fill:
primary-color, ...)` would have aborted with a Typst type error (`str` is not a color). Fixed
by declaring `primary-color` as a hex string and converting it inside the template with
`rgb(primary-color)`, which Typst's `rgb()` constructor accepts directly.

```typst
#show: codly-init.with()
#codly(languages: codly-languages)

#import "_template.typ": project

#show: project.with(
  title: "My Styled Document",
  primary-color: "#0066cc",
)
```

Exactly the two declared `params` keys -- no `toctree_*` (despite a real toctree in the
build), confirming exclusivity even though the styled template does not declare any of the
nine default parameters at all.
