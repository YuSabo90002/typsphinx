<decisions>
## Implementation Decisions

### Scope — the phase discovered three defects, not one

The discussion measured the tree past the point `46-CONTEXT.md` `<specifics>` item 6 honestly
stopped at (`tox -e lint --notest`, the provisioning layer only). Running the *commands* layer
surfaced two further defects. See `<specifics>` 1–6 for the transcripts.

- **D-01: Phase 45.2 repairs defect ① (the `tox-uv` meta package's bundled `uv` binary) and defect ② (`tox.ini`'s `deps` being silently ignored by `uv-venv-lock-runner`). Defect ③ (`ruff`'s generic-linux ELF) is routed out.** ① and ② are both project-configuration defects with fixes that work on every platform. ③ has no equivalent — every available repair (`pkgs.ruff` in `flake.nix`, patchelf on the wheel, system `nix-ld`) is a NixOS-local workaround, which is exactly the category D-18 rejected when it declined `TOX_UV_PATH`. Fixing ② does **not** fix ③: a corrected `tox` environment installs `ruff` from the same lockfile and gets the same unrunnable wheel binary.

- **D-02: Defect ② is fixed with `extras = dev` on the affected `tox.ini` environments, not with PEP 735 `[dependency-groups]`.** `runner = uv-venv-lock-runner` builds each environment with `uv sync` from `uv.lock`, so it can only install what `pyproject.toml` declares — extras and dependency-groups. `tox.ini`'s own `deps = …` lists are a pip mechanism the lock runner never consults, which is why `black`, `ruff`, `mypy` and `pytest` are absent from `[testenv]`, `lint`, `type` and `cov`. `docs-html`/`docs-pdf`/`docs` already use `extras = docs` and are the correct shape to copy. Choosing `extras = dev` keeps `pyproject.toml`'s only change inside the `dev` extra, so **SC#7 stands unamended** — the fence Phase 46's SC#3 depends on. Accepted cost: each tox environment installs the full `dev` extra (measured: `.tox/lint` holds 25 distributions today; the `dev` extra adds 13 direct packages plus transitive deps). The finer-grained `[dependency-groups]` split is captured as `SEED-003` — deferred on scope grounds, not on merit. — **Reversibility:** reversible — four lines in `tox.ini`.

- **D-03: The `ruff` defect gets a todo, not a fix, and it is NOT reframed as an environmental false positive.** Measured: `.venv/bin/ruff` is a generic-linux ELF (`interpreter /lib64/ld-linux-x86-64.so.2`) and `.venv/bin/ruff --version` dies with `Could not start dynamically linked executable`; `command -v ruff` finds nothing outside the venv. `ruff check .` — which `CLAUDE.md` lists as a standard command — has therefore never run on this machine. `nixpkgs#ruff` is 0.15.14, inside the project's `ruff>=0.15,<0.16` floor, so a fix exists; it is out of scope here.

- **D-04: The CI false-green closes as a consequence of D-02; `.github/workflows/ci.yml` is not touched.** Measured on CI run `31287786840` (main, 2026-08-09): the `lint: freeze>` line shows `.tox/lint` contains **neither `black` nor `ruff`**, yet `black --check .` and `ruff check .` both ran and passed — because CI invokes `uv run tox -e lint`, and `uv run` prepends `.venv/bin` (populated by the preceding `uv sync --extra dev --locked`) to `PATH`. **CI's green does not currently validate `tox.ini`.** Once D-02 puts the tools inside each tox environment, local and CI measure the same thing.

### Correction of record

- **D-05 [correction of record]: the "13 test modules" figure in `ROADMAP.md` and `REQUIREMENTS.md` is a miscount; the real number is 5.** A discovery-time grep separating real `subprocess` invocations from prose shows only `tests/test_examples_basic.py` and the four `tests/test_integration_{basic,advanced,multi_doc,nested_toctree}.py` actually execute `["uv", "run", "sphinx-build", …]`. The other 8 (`test_pdf_render_gate.py`, `test_admonition_bucket_render_gate.py`, `test_admonition_locale_title_precedence_gate.py`, `test_epigraph_render_gate.py`, `test_authors_pipeline_stage_gate.py`, `test_preview_smoke_gate.py`, `test_package_template_routing.py`, `test_readthedocs_config.py`) only *mention* `uv` in docstrings explaining why they use `sys.executable -m sphinx` instead. 13 is what `grep -l "uv" tests/` returns. The 5-file set matches every archived measurement (`26-01-SUMMARY.md`, `22.1-01-SUMMARY.md` both name exactly those five).

- **D-06 [correction of record]: the 8 prose-mention docstrings are NOT misdiagnosed, contrary to SC#6's premise.** Their actual text reads "a stray non-Nix `uv` binary installed into `.venv/bin` (shadowing the correct Nix-provided `uv` earlier on PATH for subprocess children) makes `["uv", "run", ...]` exit 127 ('Could not start dynamically linked executable')" — which is the correct diagnosis. What goes stale after this phase is the *tense*: they describe a hazard that will no longer exist. **The correction is to move them to past tense and update the rationale** — "the cause was removed by QUA-04 (2026-08-10); `sys.executable -m sphinx` is kept because it depends on no PATH resolution at all" — not to rewrite the diagnosis. The genuinely wrong record is elsewhere: `.planning/STATE.md:349` calls the 45 failures "the known NixOS `uv` exit-127 **false positives**", framing a fixable dependency defect as an unfixable environmental one.

- **D-07: SC#6's sweep reaches live records only.** In scope: `.planning/STATE.md`, `.planning/PROJECT.md`'s current (uncommented) footer, and the 8 docstrings per D-06. Out of scope and left byte-unchanged: everything under `.planning/milestones/`, `.planning/RETROSPECTIVE.md`, and `PROJECT.md`'s HTML-commented prior footers — these are dated records of what was believed at the time, and rewriting them destroys the audit trail rather than correcting it.

### Forward workflow guidance

### Measurement protocol and evidence

- **D-13: The pre-fix baseline is captured once, in the main tree, before any plan executes.** What is being measured is the *environment*, not the code, so per-worktree capture would produce numbers that cannot be compared — each worktree's own `uv sync` reinstalls the broken binary. Verified at discussion time that the main tree is **uncontaminated right now**: `.venv/bin/uv` is the raw generic-linux ELF with no shim applied, which is the exact as-is state SC#1 and SC#3 need recorded first.

- **D-15: Evidence is written to `45.2-TOOLCHAIN-EVIDENCE.md`.** Not `45.2-VERIFICATION.md` — that name belongs to `gsd-verifier` and will be clobbered (the Phase 41 D-15 / `41-RELEASE-EVIDENCE.md` precedent, carried forward by Phase 46's D-15).

- **D-16: SC#4's CI run is triggered by pushing the branch and then dispatching the workflow manually.** Measured: `ci.yml`'s `on:` is `push: [main, develop]` / `pull_request: [main, develop]` / `workflow_dispatch`, so a push to `gsd/v0.7.1-bug-fix-round` triggers **nothing** — which is why all three prior branch CI runs are `workflow_dispatch`. `gh workflow run CI --ref gsd/v0.7.1-bug-fix-round` matches that precedent, covers the Windows and macOS lanes, and needs no PR. The branch is already on `origin` (currently 101 commits ahead). Rejected: opening a draft PR (entangles with Phase 46's release PR).

- **D-17: SC#4's evidence is the before/after of an existing CI log line; `ci.yml` gains no assertion step.** tox prints the `uv` it resolved. Today CI logs `lint: uv-sync> .venv/bin/uv sync --locked …`; with the wheel gone it must resolve the `astral-sh/setup-uv`-installed binary instead, and that single line changing is the proof that CI reaches `uv` by a different route than the local build does. Adding a permanent assertion step would move `.github/`, outside this phase's fence.

- **D-18: A red CI caused by this phase's own changes is fixed inside this phase.** D-02 changes what CI installs, so the current green is not a guarantee. Phase 46 must not inherit a red tree. A failure demonstrably unrelated to `pyproject.toml` / `tox.ini` (e.g. a pre-existing Windows-only issue) is isolated, recorded in the evidence file, and filed as a todo.

- **D-19: If `tox -e docs-pdf` fails for a reason outside the dependency/`tox.ini` scope, isolate and record rather than chase it.** SC#1 then closes on "provisioning and command execution both reached", with the unrelated cause documented in `45.2-TOOLCHAIN-EVIDENCE.md` and filed as a todo. `docs-html`/`docs-pdf` already declare `extras = docs` correctly, so they are the environments most likely to work unchanged.

## Specific Ideas

Everything below was measured during this discussion (2026-08-10) against the live tree, the
GitHub API, or CI logs — not inferred. Items 1–6 continue past the point `46-CONTEXT.md`
`<specifics>` item 6 stopped at.

1. **Only 5 test modules actually invoke `uv`.** A grep separating real `subprocess` argument lists
   (`^\s*"uv",\s*$`) from prose returns `test_examples_basic.py` and the four
   `test_integration_*.py`. Eight further modules match a bare `grep -l "uv"` on docstrings alone.
   This is the source of the "13" figure (D-05).

2. **`tox -e lint` fails past provisioning, for a reason `tox-uv-bare` does not touch.** With
   `TOX_UV_PATH` supplied (simulating the post-fix state):
   ```
   lint: uv-sync> …/uv sync --locked --python-preference system --no-editable
                  --reinstall-package typsphinx -p …/.venv/bin/python3
   lint: commands[0]> black --check .
   lint: Exception running subprocess [Errno 2] No such file or directory: 'black'
   lint: FAIL code 2
   ```
   `.tox/lint/` holds **25 distributions** — typsphinx and its runtime dependencies. No `black`,
   no `ruff`. With `.venv/bin` forced onto `PATH` the failure changes shape but not outcome:
   `lint: failed with black is not allowed, use allowlist_externals to allow it`.

3. **The cause is `runner = uv-venv-lock-runner` ignoring `deps`.** That runner provisions from
   `uv.lock` via `uv sync`, which can only install what `pyproject.toml` declares. `[testenv]`,
   `lint`, `type` and `cov` declare their tools in `deps`; `docs-html`, `docs-pdf` and `docs`
   declare theirs in `extras = docs` and are the only four environments configured correctly.

4. **CI's green does not validate `tox.ini`.** Run `31287786840` (main, 2026-08-09), Lint job:
   ```
   uv sync --extra dev --locked          →  + black==26.5.1   + ruff==0.15.20
   lint: uv-sync> .venv/bin/uv sync --locked …
   lint: freeze> .venv/bin/uv --color never pip freeze
   lint: alabaster==1.0.0,babel==2.18.0,…,typsphinx @ file://…,typst==0.15.0,urllib3==2.7.0
   lint: commands[0]> black --check .
   lint: commands[1]> ruff check .
   lint: OK
   ```
   The freeze output contains neither `black` nor `ruff`, yet both commands ran — `uv run tox`
   put `.venv/bin` on `PATH` and the tools were picked up from outside the tox environment.

5. **Exactly three binaries in `.venv/bin` are unrunnable, and `black`/`mypy` are not among them.**
   Scanning every executable for ELF format returns `uv`, `uvx`, `ruff` — all Rust programs shipped
   as compiled binaries inside their wheels. Direct invocation:

   | tool | result |
   |---|---|
   | `black` | `black, 26.5.1 (compiled: yes)` ✓ |
   | `mypy` | `mypy 2.1.0 (compiled: yes)` ✓ |
   | `pytest` | `pytest 9.1.1` ✓ |
   | `sphinx-build` | `sphinx-build 9.1.0` ✓ |
   | `ruff` | `Could not start dynamically linked executable: .venv/bin/ruff` ✗ |
   | `uv` | `Could not start dynamically linked executable: .venv/bin/uv` ✗ |

   `black` and `mypy` report "compiled: yes" because of mypyc extension modules, which the Nix
   CPython loads without a separate loader. `command -v ruff` finds nothing outside the venv, and
   `flake.nix`'s devShell provides `python3` and `uv` but **not** `ruff`. `nixpkgs#ruff` is
   `0.15.14`, within the project's `ruff>=0.15,<0.16` floor.

6. **`ci.yml` does not run on pushes to this branch.** `on:` is `push: [main, develop]` /
   `pull_request: [main, develop]` / `workflow_dispatch`. Confirmed against the run list: all three
   prior `CI` runs on `gsd/v0.7.1-bug-fix-round` are `workflow_dispatch`; the only push-triggered
   runs on the branch are `Link Check`.

7. **The main tree is an uncontaminated pre-fix baseline right now.** `.venv/bin/uv` is a
   63,949,040-byte generic-linux ELF, not a symlink — no shim has been applied. `command -v uv`
   resolves `/nix/store/…-uv-0.11.25/bin/uv` (interpreter
   `/nix/store/…-glibc-2.42-67/lib/ld-linux-x86-64.so.2`). `importlib.metadata` reports all four of
   `tox`, `tox-uv`, `tox-uv-bare`, `uv` installed — `tox-uv-bare` is already present as a
   transitive dependency of `tox-uv`, so D-01 removes a package rather than adding one.

8. **Running `tox` during this discussion created `.tox/lint/` only.** `.tox/` is gitignored
   (`.gitignore:31`); `git status` stayed clean, the main `.venv` was not modified, and
   `import typsphinx` still resolves to the working tree via the editable finder.
