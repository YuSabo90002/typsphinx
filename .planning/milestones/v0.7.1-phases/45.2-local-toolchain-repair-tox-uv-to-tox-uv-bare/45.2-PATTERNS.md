### `tox.ini` — `requires` (task-runner-config)

**Analog:** same file, current on-disk state, verbatim (lines 1-11):

```ini
[tox]
env_list = py312, py313, lint, type, cov, docs
isolated_build = True
# tox-uv pinned via ~= (not >=1.35,<2): tox's own ini-list loader splits
# single-line `requires` values on "," (only multi-*entry* lists preserve
# newline-splitting), so a literal ">=1.35,<2" is parsed as two bogus
# requirements ("tox-uv>=1.35" and "<2") and tox fails to even start.
# ~=1.35 is the packaging-spec equivalent of >=1.35,<2 (see D-07) with no
# comma, sidestepping the parser bug. Verified equivalent via
# `packaging.specifiers.SpecifierSet` in 04-01-SUMMARY.md.
requires = tox-uv~=1.35
```

SC#5 requires the comma-splitting comment to be **rewritten, not deleted** — its explanation of *why*
`~=` is used instead of `>=1.35,<2` remains true verbatim for `tox-uv-bare`; only the package name
token(s) inside the comment and the `requires = tox-uv~=1.35` line itself need `tox-uv` →
`tox-uv-bare` substitution (with `~=1.35` preserved per SC#5).

### `tests/test_pdf_render_gate.py::_run_sphinx_build_typst` (test-docstring, canonical)

**Analog:** itself — this is the primary D-06 edit site; the other 7 modules clone this prose.

**Current docstring, verbatim (lines 150-166 area; full function starts line 150):**

```python
def _run_sphinx_build_typst(
    source_dir: Path, build_dir: Path, extra_args: tuple = ()
) -> subprocess.CompletedProcess:
    """
    Run `sphinx-build -b typst` as a subprocess and return the completed
    process (stdout/stderr captured as text).

    Invoked as `sys.executable -m sphinx` (the sphinx-build console entry
    point's module form) rather than shelling out to `uv run sphinx-build`:
    this guarantees the exact interpreter/venv already running this test is
    reused, with no dependency on external PATH resolution of a `uv`
    executable. This matters in this project's dev sandbox specifically -- a
    stray non-Nix `uv` binary installed into `.venv/bin` (shadowing the
    correct Nix-provided `uv` earlier on PATH for subprocess children) makes
    `["uv", "run", ...]` exit 127 ("Could not start dynamically linked
    executable") when invoked from inside a pytest-launched subprocess, even
    though the same command succeeds when run directly in a shell.
    `sys.executable -m sphinx` sidesteps that PATH-shadowing hazard entirely.

    `extra_args` is an optional tuple of additional sphinx-build CLI
    arguments (e.g. `("-D", "todo_include_todos=0")`) spliced into the
    ...
```

Per D-06, this is **factually correct today** and must NOT be rewritten as a diagnosis correction —
only tense and rationale need updating: move "a stray non-Nix `uv` binary installed into
`.venv/bin`... makes `["uv", "run", ...]` exit 127" to past tense, and append/adjust to something
like "the cause was removed by QUA-04 (2026-08-10); `sys.executable -m sphinx` is kept because it
depends on no PATH resolution at all" (CONTEXT.md's own suggested wording, D-06). The same prose
also appears a second time in this same file as an inline `#`-comment block (lines ~213-219,
grepped earlier) — both occurrences need the same tense/rationale edit.
