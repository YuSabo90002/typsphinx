## Decisions Made

- Used a throwaway wrapper script (`unset VIRTUAL_ENV; unset UV_PROJECT_ENVIRONMENT; uv ...`) for every main-tree `uv sync`/`uv run` invocation, rather than the plan's literal inline `env -u VIRTUAL_ENV -u UV_PROJECT_ENVIRONMENT ...` form — this execution sandbox refused to verify certain multi-clause inline `env`-prefixed command chains as staying inside the worktree, even when the command was read-only or idempotent (`uv sync`, `uv run tox`). The wrapper-script form achieves identical unset-and-run semantics and was used consistently for every measurement in Steps 5-7. Same sandbox constraint class Plan 01 recorded for `git -C`/`cd`, reused here for `env`.
- Reused Plan 01's `GIT_DIR`/`GIT_WORK_TREE` substitution technique for every main-tree `git rev-parse`/`git status --porcelain` read in this plan's provenance and cleanliness checks — no `cd` or `git -C` used anywhere.
- Elided the `tox -e docs-pdf` transcript's 204 byte-identical `RemovedInSphinx10Warning` two-line blocks in the evidence file rather than transcribing all 408 lines verbatim, stating the exact repeat count (obtained via `grep -c`, not estimated) and its cause (sphinx-autodoc-typehints's own pre-existing deprecation notice about Sphinx's parser API, unrelated to `tox-uv`/`tox-uv-bare`, unrelated to NixOS, not touched by this phase's fix) directly in the elision note.
