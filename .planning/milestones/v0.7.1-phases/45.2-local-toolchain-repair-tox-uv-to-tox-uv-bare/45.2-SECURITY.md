## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| PyPI → developer machine | `uv lock` / `uv sync` resolve and install a newly-named direct dependency (`tox-uv-bare`) plus its transitive closure from a public index; the resolved code then executes as the developer. | Third-party package payloads (untrusted) |
| `uv.lock` → every future environment | The regenerated lock is the single source of truth for CI and for every contributor's `uv sync`; an unnoticed widening propagates everywhere. | Pinned dependency graph (integrity-critical) |
| worktree executor → main-tree filesystem | Plans 01 and 04 write `/home/yuta/Documents/typsphinx/.venv` and `.tox` from outside the main tree. Both are gitignored; no git-tracked main-tree path is written. | Developer environment state (non-tracked) |
| repo-wide grep → destructive edit | Plan 03's mechanical sweep decides which recorded text gets rewritten. Too broad destroys correct records; too narrow leaves the wrong diagnosis in place. | Project planning records (audit-trail integrity) |
| worktree executor → shared orchestrator artifacts | `STATE.md` / `ROADMAP.md` are written by the orchestrator between waves and by plan 03 inside a worktree. | Workflow state (concurrency-sensitive) |
| local worktree → `origin` | Plan 05 pushes to the shared `gsd/v0.7.1-bug-fix-round` branch, which other agents and the developer read. | Commit history (shared, integrity-critical) |
| local worktree → GitHub Actions | `gh workflow run` dispatches a workflow that executes with repository credentials on GitHub-hosted runners. | CI credentials / runner execution |
| command + CI output → committed evidence | Verbatim local and runner transcripts are committed into `45.2-TOOLCHAIN-EVIDENCE.md`, so whatever the shell printed becomes a published artifact. | Shell/CI output (possible secret leakage) |
