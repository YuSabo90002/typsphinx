# Phase 45.2 — Validation Strategy

> Reconstructed retroactively from phase artifacts (State B — no VALIDATION.md existed;
> 5 PLAN/SUMMARY pairs, `45.2-TOOLCHAIN-EVIDENCE.md`, `45.2-VERIFICATION.md` read).

**Phase shape, and why it validates unusually.** Phase 45.2 repaired local build tooling
(`pyproject.toml`'s `dev` extra, `tox.ini`, `uv.lock`) and corrected the project's own recorded
diagnosis of the defect. It ships **no runtime surface** — SC#7 asserts `typsphinx/` and
`[project].dependencies` are byte-unchanged, and `COVERAGE.md` records the API-surface detector
as `{"detected": false, "signals": []}`. Consequently most of the phase's 14 coverage IDs are
`manual_procedural`: live command transcripts of `tox`/`uv sync`/`pytest` on the maintainer's
NixOS machine, plus a real CI dispatch. Those measurements are **not convertible into tests** —
several observe a pre-fix state that no longer exists, and the rest require that specific
machine. What *is* convertible is the set of **config invariants** the fix established, which
had zero automated guards before this audit.

### Regression-detection proof (anti-vacuity)

Both gates were mutation-tested against **temporary copies** of `tox.ini` — the real file was
never modified. Five regression variants, all caught:

| Mutation (applied to a tmp copy) | `..._requires_extras_forbids_deps` | `..._package_is_editable_not_wheel` |
|---|---|---|
| `[testenv] package = editable` → `wheel` | pass | **CAUGHT** |
| `→ wheel` + `wheel_build_env = .pkg` restored (true pre-45.2 state) | pass | **CAUGHT** |
| `package` key deleted entirely | pass | **CAUGHT** |
| `[testenv:lint]` reverts `extras` → `deps` | **CAUGHT** | pass |
| A *new* `[testenv:audit]` added with `deps` | **CAUGHT** | pass |

The last row is the load-bearing one: the G3 gate discovers `runner = uv-venv-lock-runner`
sections dynamically (7 today), so environments added in future phases are covered without
editing the test. That is the invariant Plan 02's `patterns-established` block asked for.

Each gate also carries an explicit vacuous-pass guard: a missing or unparseable `tox.ini`, an
empty `uv-venv-lock-runner` section set, or a missing `[testenv]` section each fail loudly
rather than iterating zero items.

**Audit 2 — the two `pyproject.toml` gates.** Mutation-tested the same way, against rendered
copies in a `TemporaryDirectory` with the module's `PYPROJECT_TOML_PATH` repointed. The real
`pyproject.toml` was never written and no `uv sync` was run; `git diff --stat pyproject.toml`
was empty afterwards.

| Mutation (applied to a tmp copy) | `..._dev_extra_pins_tox_uv_bare_not_tox_uv` | `..._runtime_dependencies_carry_no_toolchain_package` |
|---|---|---|
| dev extra `tox-uv-bare>=1.35,<2` → `tox-uv>=1.35,<2` | **CAUGHT** | pass |

The control row is load-bearing in the opposite direction from audit 1's: it proves the G5 gate
does **not** false-positive on the correct value. `"tox-uv-bare"` contains `"tox-uv"` as a

Vacuous-pass guards: a missing or unparseable `pyproject.toml`, a missing `[project]` /

### Incident during audit 2 — the defect was reintroduced, and detected

The auditor subagent mutation-tested the new `pyproject.toml` gates by mutating the file **in
place** and running `uv sync` against it. The `tox-uv-bare` → `tox-uv` mutation therefore installed
the PyPI `uv` 0.12.3 wheel into `.venv/bin/uv` — **re-creating QUA-04's exact defect** on the
maintainer's machine. It also left the venv off-lock (`tox-uv-bare` 1.36.0 installed vs. 1.35.2
pinned). The subsequent full-suite run went 45 failed / 943 passed, and the subagent reported those
failures as a "pre-existing known environment issue" — which is precisely the misdiagnosis SC#6
was raised to correct.

Three things are worth recording:

1. **The detector worked.** The failure count was 45 and confined to the 5 `uv`-invoking modules —
   byte-for-byte the pre-fix signature from Evidence Step 3. `.venv/bin/uv --version` returned
   `Could not start dynamically linked executable`. 45.2-CONTEXT.md D-09 predicted exactly this:
   those 5 modules are the project's only runtime regression detector for this defect class, which
   is why they were deliberately left on `uv run`. This is the first live confirmation.
2. **Repaired by `uv sync --extra dev`** (nix-store `uv`, no outer wrapper): uninstalled `uv`
   0.12.3, restored `tox-uv-bare` 1.35.2, and left `.venv/bin/uv` and `.venv/bin/uvx` absent —
   SC#2's post-fix state. Full suite then went 988 / 5 / 0.
3. **The reframing was rejected, not adopted.** The orchestrator re-ran the suite itself rather
   than accepting the subagent's "environment issue" summary. Recorded here because audit 1 already
   warns that neither filed environmental defect may be reframed as a false positive — that
   reframing is the error SC#6 corrected, and a subagent reproduced it within a day.

**Mitigation for future audits:** mutation-test config gates against copies in a `TemporaryDirectory`
with the module's path constant repointed — never mutate the real file, and never run `uv sync`
against a mutated manifest. Audit 2's re-verification used that method; `git diff --stat
pyproject.toml` was empty throughout.

Three docstring claims the subagent invented were also corrected before commit: a fabricated
"modules 01/02/04/05/45" attribution for the 45 failures (they are confined to 5 modules,
per D-09), a four-clause enumeration of SC#7 that did not match its text, and a citation of
Evidence Step 7 (post-fix census) as the source of the pre-fix 45-failure reproduction (Step 3).
