# Phase 45.2: Code Review Report

**Reviewed:** 2026-08-11T00:00:00Z
**Depth:** standard
**Files Reviewed:** 8
**Status:** issues_found

## Summary

This is a toolchain-repair phase: `tox-uv` → `tox-uv-bare` in `pyproject.toml`'s `dev`
extra and in `tox.ini`'s `requires`, a `deps` → `extras = dev` rewrite across
`[testenv]`/`[testenv:lint]`/`[testenv:type]`/`[testenv:cov]`, a `package = wheel` →
`package = editable` change on `[testenv]` (inherited by every other environment
section), and docstring-only past-tense edits to six render-gate test modules'
`_run_sphinx_build_typst` PATH-shadowing explanations.

I verified the concrete, checkable claims rather than re-litigating the recorded
decisions:

- `tox-uv-bare` installs the identical `tox_uv` module and the identical
  `[tox] tox-uv = tox_uv.plugin` entry point as `tox-uv` (confirmed from the
  installed `tox_uv_bare-*.dist-info/entry_points.txt` and `RECORD`), so
  `runner = uv-venv-lock-runner` resolves exactly as before — no functional gap
  from the package rename.
- `package = editable`'s claimed status as `uv-venv-lock-runner`'s own default is
  correct — `tox_uv/_run_lock.py` declares `default="editable"` for that config key.
- `~=1.35` is spec-equivalent to `>=1.35,<2` for two-component versions (PEP 440
  compatible-release semantics), matching the comment's claim.
- `[testenv]`'s settings (`package`, `runner`) are inherited by every
  `[testenv:*]` section that doesn't override them, including `docs-html`/
  `docs-pdf`/`docs` (confirmed against tox's base-section inheritance model and by
  the pre-phase file already relying on this for `[testenv:cov]`'s `runner`). This
  means the `wheel` → `editable` change silently also affects the docs-building
  environments, not just test/lint/type/cov — an effect the phase's rationale
  (dropped `templates/base.typ` under non-editable installs) argues *for*, since
  `docs-pdf` also needs that same template file via the `typstpdf` builder. Not a
  defect; flagged in Info below only because it's an easy-to-miss blast radius.
- `uv.lock` already reflects the `tox-uv-bare` rename consistently (`package.metadata.requires-dist`
  and `package.optional-dependencies.dev` both list `tox-uv-bare`, not `tox-uv`) — no
  stale-lockfile risk.
- The six test-file docstring edits are internally consistent with each other and
  with `tox.ini`'s decision comment: all six now read "was removed by QUA-04
  (2026-08-10)" in past tense, with `test_pdf_render_gate.py` additionally naming
  the mechanism ("`tox-uv` -> `tox-uv-bare` drops the bundled generic-linux `uv`
  wheel binary"). No self-contradictory statement was introduced (e.g., no file
  simultaneously claims the hazard is both present and removed).

One genuine documentation-drift defect was found, external to the reviewed file
list but directly caused by (and only by) this phase's rename: **`CLAUDE.md`
still describes the pre-rename `tox-uv` package** in two places, which is now a
false statement about the toolchain this exact phase repaired.

## Warnings

### WR-01: CLAUDE.md documents the removed `tox-uv` package, not `tox-uv-bare`

**File:** `CLAUDE.md:11`, `CLAUDE.md:77`
**Issue:** This phase renamed the `dev` extra's tox-runner dependency from
`tox-uv` to `tox-uv-bare` in both `pyproject.toml:38` and `tox.ini:4-11`, but
`CLAUDE.md` — the project's own onboarding/guidance document, auto-loaded into
every future Claude Code session working in this repo — still says:

- Line 11: "Development uses `uv` for env/dependency management and `tox` (with
  `tox-uv`) as the task runner."
- Line 77: "`tox.ini` pins `tox-uv~=1.35` (not `>=1.35,<2`) deliberately — see
  the comment in that file; tox's ini parser splits a single-line `requires` on
  commas and breaks otherwise."

Both statements are now factually wrong: `tox.ini` pins `tox-uv-bare~=1.35`
(line 11), not `tox-uv~=1.35`, and the task runner dependency is `tox-uv-bare`.
Since `CLAUDE.md` is checked into the codebase specifically to keep automated
agents and contributors from re-litigating settled decisions, a stale reference
to the very package this phase replaced risks a future agent "fixing" `tox.ini`
back toward `tox-uv`, or citing the wrong package name when explaining the pin
to a user.
**Fix:**
```diff
- Development uses `uv` for env/dependency management and `tox` (with `tox-uv`) as the task runner.
+ Development uses `uv` for env/dependency management and `tox` (with `tox-uv-bare`) as the task runner.
```
```diff
- `tox.ini` pins `tox-uv~=1.35` (not `>=1.35,<2`) deliberately — see the comment in that file; tox's ini parser splits a single-line `requires` on commas and breaks otherwise.
+ `tox.ini` pins `tox-uv-bare~=1.35` (not `>=1.35,<2`) deliberately — see the comment in that file; tox's ini parser splits a single-line `requires` on commas and breaks otherwise.
```

## Info

### IN-01: `runner = uv-venv-lock-runner` is now redundant in every `[testenv:*]` section

**File:** `tox.ini:34,41,49,56`
**Issue:** `[testenv]` (line 34) already sets `runner = uv-venv-lock-runner`, and
tox's base-section inheritance model means every `[testenv:lint]`/`[testenv:type]`/
`[testenv:cov]` section inherits it automatically (this was already relied on
pre-phase: the old `[testenv:cov]` had no `runner =` line of its own and still
worked). Repeating the identical value in all four child sections adds no
behavior change but is pure duplication that could drift if `[testenv]`'s runner
ever changes and only some child sections are updated.
**Fix:** Optional cleanup — drop the redundant `runner = uv-venv-lock-runner`
lines from `[testenv:lint]`, `[testenv:type]`, and `[testenv:cov]`, relying on
inheritance from `[testenv]` as the pre-phase file already did for `cov`. Low
priority; not a behavioral bug.

### IN-02: `package = editable`'s blast radius extends to `docs-html`/`docs-pdf`/`docs`, undocumented at the point of change

**File:** `tox.ini:33`
**Issue:** The comment justifying `package = editable` (lines 19-32) frames the
change entirely in terms of the test/lint/type/cov environments' pytest failures
(`FileNotFoundError: Default template not found`). Because `[testenv:docs-html]`,
`[testenv:docs-pdf]`, and `[testenv:docs]` don't set their own `package =`, they
also silently move from `wheel` to `editable` as a side effect of this one-line
change at `[testenv]`, even though those three sections aren't mentioned anywhere
in the surrounding rationale. In this case the side effect is beneficial (the
`typstpdf` builder invoked by `docs-pdf` needs the same packaged
`templates/base.typ` that was the root cause here), but the comment reads as if
its scope were narrower than it actually is — a future reader diagnosing a
`docs-*` environment issue may not think to check `[testenv]`'s `package =` line.
**Fix:** Optional — extend the existing comment block to note explicitly that
`docs-html`/`docs-pdf`/`docs` inherit this too and benefit from it for the same
templates-file reason, so the comment's scope matches its actual effect.
