### Why REL-16 is satisfied and not `partial`

The status matrix reads *passed + missing frontmatter → partial (verify manually)*, so this audit
verified it manually rather than accepting the checkbox.

The frontmatter absence is **not** an omission. Phase 75's cross-cutting constraint required
`requirements-completed: []` in *every* plan, because REL-15 must never be closed by a plan; REL-16
rode along in that blanket declaration and was closed by `phase.complete` instead, which is exactly
what SC3 anticipated ("REL-16 is the one release requirement this phase **does** close").

Measured here, at HEAD `563bf4ed`:

- `grep -n "^### Known Limitations" CHANGELOG.md` → exactly **2** hits: the pre-existing `[0.1.0b1]`
  entry and the new one at line 91, inside `## [0.9.6]`.
- `uv run python scripts/extract_changelog_section.py 0.9.6` → **100 lines**, containing
  `### Added`, `### Changed`, `### Fixed`, `### Known Limitations` and `### Verified`. The Known
  Limitations entry names NUM-01 with its precondition (multi-master only), both symptoms
  (diverging number; fallback to raw label text) and an explicit `**Workaround:**` line.

**The candidate-set correction is sound.** REL-16's literal text names three defects; the section
names one. The other two were re-measured during Phase 75's discussion and found stale — both
closed in v0.8.0 — and the correction is recorded on the record in four places
(`75-DISCUSSION-LOG.md:171-178`, `75-CONTEXT.md:147-157`, `75-RESEARCH.md:71-72`,
`75-CHANGELOG-EVIDENCE.md:163-172`). This audit confirmed the closures independently rather than
accepting them: `.planning/todos/completed/2026-08-10-rehomed-converted-image-collides-with-srcdir-images-dir.md`
and `.planning/todos/completed/2026-08-04-duplicate-typst-documents-target-silently-drops-a-master.md`
both exist, and neither appears under `.planning/todos/pending/`. Disclosing a defect that is
already fixed would have been a false statement in a release note, so the narrowing is a correction,
not a scope reduction.

### Why REL-15 is held, not a gap

ROADMAP constraints 1 and 9 state that REL-15's checkbox is checked only at
`/gsd-complete-milestone`, against four observations (the merge commit on `origin/main`'s
first-parent history, `git ls-remote --tags origin`, a PyPI 200 for `0.9.6`, `gh release list`) —
and never by phase-completion tooling. This is the same treatment v0.9.3's REL-12 and v0.9.5's
REL-14 received in their audits. The FAIL gate is not fired: the requirement is not unsatisfied,
it is not yet due.

The fence that protects it was re-run by this audit and holds — see the frontmatter's
`held_by_design` block for the measured values.
