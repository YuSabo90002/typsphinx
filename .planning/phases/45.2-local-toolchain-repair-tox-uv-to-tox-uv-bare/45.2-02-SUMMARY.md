## Decisions Made
- **Task 1 gate approval:** the human maintainer approved `tox-uv-bare` after reviewing the PyPI facts this plan gathered (12 releases spanning `1.32.0`-`1.36.0` including `1.35.x`, identical maintainer `Bernát Gábor <gaborjbernat@gmail.com>` and identical repository `github.com/tox-dev/tox-uv` as `tox-uv`, and confirmation via `uv.lock` that `tox-uv-bare` was already installed transitively before this change). No installs or lock/sync commands ran before approval.
- **Version specifier style in `pyproject.toml`:** kept the `>=1.35,<2` form (matching the surrounding `dev`-extra entries' style) rather than switching to `~=1.35` — `pyproject.toml` is a TOML list, so SC#5's comma-splitting hazard (which binds only `tox.ini`'s single-line `requires`) does not apply.
- **`tox -e py312` orthogonal blocker:** Task 3's literal verify command (`tox config -e py312,lint,type,cov`) fails on `py312` specifically — not because of this plan's `deps` → `extras` conversion, but because no Python 3.12 interpreter exists locally (`flake.nix` provides only `pkgs.python3`, which resolves to 3.13 in this nixpkgs channel), and `uv`'s Python auto-download fetches a generic-linux glibc build that cannot execute on NixOS (`Could not start dynamically linked executable`, the same defect class as the already-routed-out `ruff`/`uv` ELF issue, D-03). This is a newly-discovered, pre-existing, NixOS-local environmental gap, unrelated to the fix and out of this plan's fence — it does not affect CI, which runs on generic Linux runners where `py312` is available. Verified the `extras = dev` conversion itself is sound by substituting `py313` (which IS locally available): `tox config -e py313,lint,type,cov` exits 0 and reports `extras = dev` with no `deps` key for all four environments — identical shape to what `py312` would report if a local interpreter existed.
