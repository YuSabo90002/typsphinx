<objective>
Make the one bundle rule real: every used registry key's template bundle is copied wholesale to
`<outdir>/_template/<key>/`, and every wrapper imports its own key's template by a root-absolute
path that does not depend on the wrapper's nesting depth.

Purpose: this is the phase's spine. Phase 53 already resolves `typst_document_templates` into
registry entries and already threads the resolved entry into `render_wrapper()`, so element `[4]`
is read — but every wrapper still imports one shared file written from global config, so naming a
key changes nothing observable. This plan closes that gap end to end on the thinnest real path
first: one used key, its bundle on disk, a wrapper importing it root-absolutely, compiled green by
a real `typst.compile()`. The three gates `54-01` recorded RED are the acceptance test for it.

Output: a write-time accumulator of used keys, a finish-time bundle-copy driver, a root-absolute
import-path computation, `importlib.resources`-based resolution of the bundled default, the
relocated shadow-template search path, and the migration of every test assertion that named the old
import string.
</objective>

## Flagged planner assumptions

These are planner judgements, not owner decisions. Each is implemented as stated; each is listed
here so the owner can overturn it cheaply.

- **A-01 (NOT from the probe — the residual of RESEARCH.md's Pitfall 0 that D-14 does not cover).**
  D-14 relocates the *search-path* shadow so a resolved template's parent can no longer be the
  source directory by that route. It does not cover the *explicit* route: a `conf.py` setting
  `typst_template` to a bare filename with no directory component resolves to a file directly under
  the source directory, whose parent is the source tree itself — the identical harm D-14 exists to
  prevent, reached through Priority 1 instead of Priority 2. This shape is live in the tree today
  (`tests/test_entry_metadata_route_uniformity.py` writes `custom_template.typ` at the source root
  twice). **Assumption:** the same parent-directory predicate CONF-17 already applies to every
  declared key is applied to the RESOLVED path of every key including the built-in one, raising an
  `ExtensionError`. The owner's own recorded reasoning forecloses the alternatives — copying just
  the resolved file was rejected in D-14 as "exactly one recorded exception to a phase whose SC#2
  says the built-in key is under the same rule", and warn-and-skip leaves the wrapper importing a
  file that was never placed. The cost D-14 cited for an `ExtensionError` (turning the shadow tests
  red, deleting a documented route) does not apply here: no published page documents a bare-filename
  `typst_template`, and every documented example uses a subdirectory.
- **A-02 (TPL-02, unclassified).** "Two visibly different templates" is treated as: the two PDFs
  differ byte-wise AND each wrapper imports its own key's bundle path. The rendering judgement
  itself stays a manual check, already recorded in `54-VALIDATION.md` § Manual-Only Verifications.
- **A-03 (CONF-19, unclassified).** Treated as: presence of the name in the raw `conf.py` namespace
  is the trigger, regardless of the value assigned — a `conf.py` setting a removed value to `None`
  or `[]` still warns, because the user still wrote the line and still holds a wrong belief.
- **A-04 (OUT-05, unclassified).** Treated as: "resolves" means the real `typst.compile()` exits
  zero AND the asset file is present inside the copied bundle. A compile that succeeds because the
  reference was silently dropped would satisfy the first and not the second, so both are asserted.
- **A-05 (OUT-06, unclassified).** Treated as: "does not depend on nesting depth" is proven by
  string EQUALITY between two wrappers at different depths naming the same key, not by each
  matching a literal independently. Two independent literal matches would pass even if the function
  re-acquired a depth term that happened to be zero in both cases.
- **A-06 (OUT-07, unclassified).** Treated as: the reservation covers the first path segment of
  any output path the builder would write for a content file or a wrapper, compared after the
  builder's existing normalize-then-casefold folding — so `_TEMPLATE/x` and `_template/x` are both
  refused. Implemented in `54-07`.
- **A-07 (BLD-06, unclassified).** Treated as: "excludes" is proven by set EQUALITY over the copied
  bundle's file manifest against an enumerated expected set, not by asserting the four excluded
  names are absent. Absence-only would pass while silently publishing a fifth unexpected file.
