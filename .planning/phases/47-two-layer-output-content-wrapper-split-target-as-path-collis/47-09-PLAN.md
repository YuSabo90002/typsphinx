<objective>
Replace CR-01's per-entry warn-and-fall-back collision guard with ONE pre-write validator over a
single logical-file-to-physical-path map, covering all four collision kinds, erroring with no
fallback, and enumerating every offending entry in a single `ExtensionError`.

Purpose: the content/wrapper split CREATES this hazard. Once every docname unconditionally gets a
content file, the most common configuration in the wild — `[("index", "index.typ", ...)]` — puts a
wrapper and a content file on one physical path, and whichever write runs last wins silently: a
build that reports success and produces a PDF with no title page, no outline and none of its
children, with no `TypstError` to catch it. The old fallback is not merely being tightened; it is
unusable after the split, because falling back to the docname lands the wrapper exactly on that
docname's content file, which is the collision it was trying to avoid.

This plan is also the phase's full-suite-green gate (binding constraint #8).

Output: `TypstBuilder._validate_output_path_collisions()`, the CR-01 in-function block deleted, the
existing collision gate's assertions inverted, and the whole suite green.

**This plan is NOT autonomous.** Two locked decisions in it are one-way and each carries a blocking
`checkpoint:decision` before the task that implements it.
</objective>

This is a **one-way** decision. `docs/source/user_guide/configuration.rst:46-52` publishes the
opposite contract — a colliding target warns and falls back — and `typsphinx/builder.py:275`'s
`effective != docname` guard deliberately allows the self-collision case today. The configuration
`typst_documents = [("index", "index.typ", ...)]` builds successfully in v0.7.x and will stop
building. Measured on this repository: **87 of the 100 fixture projects under `tests/fixtures/`

measure of how common the pattern is in real configurations. Undoing this after release means
re-breaking every user who has already renamed their targets.

The alternative — keeping a fallback — is unusable after the split: falling back to the docname lands
the wrapper exactly on that docname's content file, which is the collision being avoided.

human-readable description of the logical file that claimed it, populated in this order: the literal

content path; then every `typst_documents` entry mapped to its resolved wrapper path. On each

shape: a count followed by `"; "`-joined `key: message` pairs.

one physical path, never whether a docname is repeated.
