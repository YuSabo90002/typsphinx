and called 28 times by `tests/test_builder_output_stem.py` — and by **zero** production call sites
(`grep -rn "_resolve_output_stem" typsphinx/` returns the definition plus seven docstring/comment

`_content_output_path()` (docname-derived, unconditional) or `_wrapper_output_relpath()` →
`_resolve_target_stem()` — the very design `_wrapper_output_relpath()`'s own docstring says was
introduced to BYPASS this function's docname-based first-match search, so that D-04's
repeated-docname-different-target case resolves correctly. This is structurally identical to the prior
WR-01 that 47-12 already fixed one file over, and the sibling case in `builder.py` was missed.

**Decision, made here rather than left as "consider": DELETE.** Retention-with-a-docstring is
rejected for the same reason 47-12 rejected it: an unreferenced, thoroughly-documented method in a
1500-line module is exactly what a future maintainer assumes is load-bearing, and a green 28-test suite
over a route no build reaches reports confidence in nothing. There is no future consumer — OUT-01 made
a target a path relative to outdir and D-04 made resolution per-entry, both of which point away from a
docname search, and CONF-13 (the reserved fifth tuple element) reinforces per-entry positional reading.

**The evidence re-anchoring this plan owes.** `47-VERIFICATION.md` truth #5 (OUT-01) currently cites
"`test_builder_output_stem.py` passes unmodified" as part of its regression evidence. That citation
cannot survive a deletion that rewrites the module, so this plan names its replacement explicitly:
after this plan, OUT-01's unit-level evidence is the twenty-two assertions retargeted onto
`_resolve_target_stem()` / `_wrapper_output_relpath()` in that same module, and its build-level
evidence is `tests/test_two_layer_output_gate.py`'s wrapper/content placement assertions;
OUT-02's unit-level evidence is the three escape-shape assertions within the same retargeted set, plus
`tests/test_out02_escape_target_gate.py` unmodified. The next verification pass cites those, not a

<assumption_delta_decision>
**Noun now primary:** *the output-path resolution route*.

**Decision: `promote`** — and the promotion is completed here rather than introduced here. Phase 47
plan 09 already elected the pair `_content_output_path()` (for content, docname-derived) and
`_resolve_target_stem()` (for a specific entry's own target) as the primary routes, and demoted
`_resolve_output_stem()` (docname first-match over the config list) to a superseded implementation —
but left it in the tree, which is an `add-alongside` in practice. This plan finishes the promote by
removing the demoted sibling, so exactly one route exists per question with one owner.

The demotion was not merely a refactor: the docname first-match route is *wrong* for D-04's
repeated-docname case, which is why `_wrapper_output_relpath()` was written to bypass it. Keeping a
known-wrong resolver alive as "reference" is the accepted-debt shape this decision refuses.
</assumption_delta_decision>
