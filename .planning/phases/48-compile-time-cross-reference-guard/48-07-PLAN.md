<objective>
Close G-48-4: give every content file a stable self-anchor, route the whole-document reference case
through the existing compile-time guard against it, and measure the dead links out of the built
documentation PDF.

Purpose: today `_resolve_xref_docname` returns `None` for any refuri without a fragment, so
`visit_reference` falls into its external-reference branch and emits a string-url link to a file the
build never produces — the reader's viewer resolves it as a local file URI and reports
ERR_FILE_NOT_FOUND. The gap is PRE-EXISTING (that region traces solely to Phase 15's commit
`510f8e17`), and the owner chose to close it as a Phase 48 gap because the mechanism that closes it
is this phase's own guard.

Output: the emitter change, both new gates flipped from strict xfail to plain assertions, a green
suite, and an appended `48-EVIDENCE.md` section carrying the before/after PDF link enumeration.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `conf.py` / `.rst` author input → emitted Typst source | A docname now reaches the emitted output as part of a label token; already the case for every anchor, and routed through the same `_sanitize_label` |
| Emitted `.typ` → `typst.compile()` | A new label is defined once per content file; a duplicate would be a compile fatal, so the duplicate-include gate is run explicitly |
| Published PDF → reader's PDF viewer | The gap itself: a URI action instructing the viewer to open a nonexistent local path |

## STRIDE Threat Register

ASVS level 1, blocking threshold `high`. ASVS **V2 (Authentication)**, **V3 (Session Management)**,
**V4 (Access Control)** and **V6 (Cryptography)** are **structurally inapplicable** — typsphinx is a
local Sphinx/Typst document-build tool with no network service, no authentication, no session and no
cryptographic surface (`48-RESEARCH.md` § Security Domain). **V5 (Input Validation)** is covered by
the existing `escape_typst_string` / `_sanitize_label` machinery: the new token is a fixed literal and
the docname half is sanitized by the same helper as every other label.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48-07-01 | Information Disclosure | Dead `file://` URI actions in a published PDF | medium | mitigate | Closed by this plan; measured out in task 3 against a pinned baseline |
| T-48-07-02 | Denial of Service | A duplicate self-anchor label aborting a whole compile | medium | mitigate | The token is unreachable from any docutils/domain id (argued and measured in 48-05), the anchor is emitted at most once per content file, and `tests/test_duplicate_include_label_render_gate.py` is run explicitly in task 1's acceptance criteria |
| T-48-07-03 | Spoofing | A reference resolving to the wrong document via a label-string collision | low | accept | The pre-existing, filed and owner-accepted label-collision limit. The whole-document path cannot worsen it: its label's raw id is a fixed token no docutils `make_id` output and no domain id can spell |
| T-48-07-04 | Tampering | A relative link to a genuine file asset silently losing its link | low | mitigate | The policy predicate is deliberately narrow under both recorded options, and a plain invariance guard in the fast unit module pins the property |
| T-48-SC | Tampering | npm/pip/cargo installs | low | accept | Not applicable — no packages are installed; binding constraint #7 forbids new runtime dependencies and a fifth `@preview` package |
</threat_model>
