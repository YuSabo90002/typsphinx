<objective>
Move the "does this label exist" decision from a build-time Python union to a Typst compile-time
guard, end to end, on the primary emission site — and delete the build-time mechanism in the same
change rather than leaving it half-alive.

Purpose: this is the phase's tracer. One thin path — a cross-document reference in
`visit_reference`'s resolved-xref branch — is wired all the way through the new shared helper, the
emitted `.typ`, `typst.compile()` and a real `pypdf` link-annotation readback on a two-master
fixture, before the other two emission sites expand out from it. Proving the mechanism end to end on
one path first is what catches an architectural dead end after one commit instead of after three.

Output: the shared guard helper, the guarded `visit_reference` cross-document branch, the deletion of
the build-time union and its degrade field and warning, and the migration of the three test modules
whose premises those deletions invalidate. The phase-scoped suite is green at the end of this plan.
</objective>

<assumption_delta_decision>
**The pluralization detected in this phase's scope is real, and the resolution is `promote`.**

**What pluralized:** a content `.typ` used to be compiled exactly once. After Phase 47 it is compiled
zero, one, or many times — once per wrapper that `#include()`s it — and the same degrade decision
must come out differently in each compile.

**The noun that is now primary:** the identity that decides label existence is no longer *the
docname*. It is **the (content file, compiling wrapper) pair** — equivalently, "this document as
compiled inside this specific wrapper". A single per-docname answer, however computed in Python,
cannot name that pair, because the pair does not exist until Typst resolves one wrapper's include
graph.

**Decision: `promote`.** The generalized representation (Typst's own per-compile `query(<label>)`)
becomes the primary and only mechanism, and the old specific representation (the build-time union
across all masters) is **deleted**, not kept alongside. SC#3 and D-09 demand exactly this: any plan
that leaves both mechanisms alive contradicts the phase's own success criteria, because the two can
disagree and nothing would hold them together.

**Suggested (not required) invariant test:** a structural test asserting that no module under
`typsphinx/` reads any builder attribute in order to decide whether to emit a label link — i.e. that
the demand-side decision has no Python-side input at all. That would go red if a future phase
reintroduces the singular per-docname assumption under a new name. This checkpoint is advisory and
blocks nothing.
</assumption_delta_decision>

**Step 1 — settle the body-mode question by measurement before writing translator code.** The guard's
`let`-bound body is a Typst CONTENT block, but today a cross-document reference's children stream as
the second ARGUMENT of `link(<L>, ...)`, i.e. in code mode with `_in_link` driving `+`
concatenation. Two candidate spellings exist and only one preserves today's child-emission bytes:

- `[#{` … `}]` — a content block wrapping a code block. Children keep streaming in code mode exactly
  as today (`_in_markup_mode` stays False, `_in_link` stays True), so every other visitor's emission
  is unchanged and the corpus-wide body bytes do not move. This is the planner's derived choice and
  is NOT yet measured.
- `[` … `]` — the bare content block research measured with hand-written markup children. Choosing
  it forces children into markup mode (`_in_markup_mode` True, no `_in_link` concat context), which
  changes the emitted body of every cross-document reference in the corpus.
