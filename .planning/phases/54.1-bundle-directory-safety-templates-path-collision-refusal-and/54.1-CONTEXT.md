# Phase 54.1: Bundle Directory Safety — `templates_path` Collision Refusal and Pre-Write Path Validation - Context

**Gathered:** 2026-08-16
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase closes exactly two findings from Phase 54's `/gsd-code-review`, both defects in what
Phase 54 shipped, both on the same `builder.py` bundle-copy surface:

- **WR-01** — the wholesale bundle copy can republish a project's Sphinx `templates_path` Jinja
  directory into public build output, while the published documentation actively recommends the
  colliding layout (`typst_template = "_templates/custom.typ"`).
- **CR-01** — the A-01/CONF-17 guard on the built-in `"typst"` key, and the reserved-key case
  collision, are discovered only at `finish()`, after `write()` has emitted every content and
  wrapper `.typ` file.

**Not in this phase** (recorded so planning does not drift into them): `WR-02` (CHANGELOG coverage
of the `typst_template_assets` removal — Phase 57's curation), `WR-03` (a declared key with neither
`template` nor `package` shares the reserved key's shadow search path), `WR-04` (duplicate local
re-import of `TEMPLATE_OUTPUT_DIR`), `IN-01` (private cross-module helper import). The five
v0.8.0-derived defects are Phase 55; the documentation rewrite is Phase 56.

The "one bundle rule, no exceptions" (PROJECT.md, Phase 54 OUT-04) is **not** re-opened. No option
that copies less than the whole bundle — including "copy only the resolved `.typ` when the parent
collides" — is on the table.

</domain>

<decisions>
## Implementation Decisions

### `templates_path` collision (WR-01)

- **D-01:** A used key's resolved bundle directory that collides with Sphinx's `templates_path` is
  **refused with `ExtensionError`**, not warned about. The error names the registry key, the
  resolved bundle directory, and the colliding `templates_path` entry. This follows the shape every
  other layout-level guard in this codebase already uses — CONF-17
  (`template_registry.py:417-424`), CONF-14 (`_validate_registry_key_references()`,
  `builder.py:780`), OUT-07 (`_validate_output_path_collisions()`, `builder.py:625`) all raise. The
  rejected alternative was `logger.warning` + skip that key's bundle copy (the shape D-07/CONF-19
  chose for removed config values): measured, skipping the copy leaves the wrapper's
  `#import "/_template/<key>/….typ"` pointing at a file that was never written, so `-b typstpdf`
  fails inside `typst.compile()` with an unrelated-looking error and `-b typst` reports success over
  a `.typ` tree that cannot compile. — **Reversibility:** costly — every v0.8.x project that set
  `typst_template = "_templates/…"` alongside a `templates_path` containing `_templates` must move
  its template before it can build v0.9.0. That migration is announced once, in the v0.9.0
  CHANGELOG, and cannot be un-announced. (Loosening the refusal back to a warning later is itself
  cheap; the user-facing migration is what is not.)

- **D-02:** Detection is a **path-relationship test against the live `templates_path` config
  values** — the bundle directory *is*, *contains*, or *is contained by* an entry — never a name
  match on the literal string `_templates`. Measured consequences of that choice, all three of which
  the plans should assert rather than assume:
  - `examples/charged-ieee/approach2/conf.py:25` sets `typst_template = "_templates/_template.typ"`
    but sets **no** `templates_path` → does **not** trip the check.
  - `examples/basic/conf.py:19` sets `templates_path = ["_templates"]` but no `typst_template` →
    does **not** trip the check.
  - `examples/advanced/conf.py` sets **both** (`templates_path` at :24, `typst_template =
    "_templates/custom.typ"` at :70) → **does** trip the check. It is the only such file in the
    tree; `docs/source/conf.py` sets `templates_path` at :45 but points `typst_template` at
    `_typst/custom_template.typ` (:96) and is unaffected.
  - `templates_path` entries are `srcdir`-relative; the comparison must resolve them against
    `srcdir` before relating them to the resolved bundle path.

- **D-03:** Multiple colliding keys are **accumulated and raised once**, in one `ExtensionError`
  naming every offending key with its colliding `templates_path` entry — the
  `_validate_output_path_collisions()` / bundle-destination-collision idiom (`builder.py:625`,
  `builder.py:1658`), not `_validate_registry_key_references()`'s first-offender raise (which exists
  only because `resolve_registry_key()` already owned CONF-14's message shape; this is new message
  text, so that constraint does not apply). Keys are iterated `sorted()` so the message is
  byte-identical across runs.

### Where the checks run (CR-01 + WR-01)

- **D-04:** Both the hoisted A-01/CONF-17 check **and** the new `templates_path` collision check run
  in a **pre-write pass at the top of `write()`**, positioned with the two existing pre-write
  validations — after `resolve_template_registry()` (`builder.py:950`) and
  `_validate_registry_key_references()` (`builder.py:961`), before `prepare_writing()`
  (`builder.py:964`). A refusal therefore leaves **zero** `.typ` files on disk, which is exactly the
  property CR-01 says is broken today.

- **D-05:** Pre-write, the checked key set is **the keys every usable `typst_documents` entry
  references** — including the entries `_default_typst_documents()` (`builder.py:218`) synthesizes
  when `typst_documents` is unset — **not** the write-time `self._used_template_keys` accumulator
  (`builder.py:1351`), which is still empty at that point. This deliberately covers entries whose
  docname is not in *this* build's `docnames` set, which is the same order-independence property
  `_validate_registry_key_references()` was given under Phase 53's D-05. A registry key that is
  *declared* but referenced by no entry is **not** checked pre-write (it is still caught at
  `finish()` if it ever becomes used) — see Claude's Discretion for the one open sub-question this
  leaves.

- **D-06:** The existing `finish()`-side A-01/CONF-17 guard (`builder.py:1628-1639`) **stays**. The
  duplication is accepted deliberately: many existing tests drive `write_doc()` /
  `_write_typst_files()` and `finish()` directly without ever calling `write()` — the reason
  `builder.py:1322-1331`'s lazy registry fallback exists at all — and on that path the pre-write
  pass never runs. Removing the `finish()` guard would silently drop A-01 protection for every such
  caller.

- **D-07:** SC#4's reserved-key case collision (a declared key differing from `RESERVED_REGISTRY_KEY
  = "typst"` only by case, which CONF-18 does not catch because it compares declared keys only
  against each other) is detected in the **same pre-write pass**, routed through the existing
  `_collision_key()` folding (`builder.py:494`) — never a second case-folding primitive. This is the
  route Phase 53's Deferred Ideas already chose for this exact collision.

### Documentation and examples (WR-01, SC#2)

- **D-08:** The fix covers `docs/source/` **and** `README.md` **and** the runnable `examples/`
  projects — not only the two pages the review named. Milestone invariant #11 governs: an
  "anywhere under X" criterion is checked by a **repo-wide grep at discovery time**, never against
  the file list this document happens to enumerate. The enumeration below is a floor measured on
  2026-08-16, not the search set:
  `docs/source/quickstart.rst:100`, `docs/source/user_guide/configuration.rst:117`,
  `docs/source/user_guide/templates.rst:91,92,98,110,123,168,321,351`,
  `docs/source/examples/advanced.rst:62,107,117,124,127,130,172,216,254`, `README.md:164`,
  `examples/advanced/{conf.py:70, README.md:20,64,85,233,247,299, index.rst:85}`,
  `examples/charged-ieee/approach2/conf.py:25`.

- **D-09:** `examples/advanced/_templates/` is **renamed to `examples/advanced/_typst/`** (it holds
  exactly one file, `custom.typ` — no Jinja override actually lives there), and
  `conf.py:70` / `README.md` / `index.rst`'s tree diagram follow. The
  `templates_path = ["_templates"]` line at `conf.py:24` **stays** — it keeps its own Sphinx
  meaning, and leaving it in place is what keeps the example a demonstration of the two directories
  coexisting correctly. The rejected alternative was deleting that line instead: it removes the
  collision but leaves the example still showing a Typst template inside `_templates/`, which is the
  layout SC#2 exists to stop recommending. Measured: nothing breaks on the rename —
  `tests/test_preview_version_sync.py` reaches these files through an `examples/**/*.typ` glob
  (`EXAMPLES_DIR` at :34), and its only path mention is prose in a docstring (:20); no test builds
  `examples/advanced/`.

- **D-10:** The replacement directory name everywhere is **`_typst/`**, matching
  `docs/source/conf.py:96` and Phase 54's D-14 (which moved the shadow route to
  `<srcdir>/_typst/base.typ` for the same reason). This is not re-opened.

### Claude's Discretion

- Whether the pre-write pass is **one** new method or two (e.g. a combined
  `_validate_used_template_paths()` versus separate CONF-17 and `templates_path` methods), and
  whether the `finish()`-side guard shares its message text with the pre-write one.
- Whether to additionally check registry keys that are *declared but referenced by no
  `typst_documents` entry*. D-05 says the pre-write set is reference-derived; widening it to the
  whole resolved registry would catch a broken unused entry earlier but turns configs that build
  fine today into hard failures. **Recommendation: do not widen** — stay reference-derived, matching
  `_validate_registry_key_references()`'s own scope, and note the gap in the new method's docstring.
- Exact wording of the new `ExtensionError` messages, subject to: naming the registry key, the
  resolved bundle directory, the colliding `templates_path` entry, and pointing the user at a
  non-colliding directory (`_typst/` is the name this repository uses).
- Test file naming and placement, and the composition of the RED fixtures — subject to SC#5's bar
  (each fix pinned by a test recorded RED against the pre-fix tree) and to the shape
  `tests/test_template_prefix_reservation_gate.py::test_no_typ_file_written_after_refusal` already
  established for the sibling "zero `.typ` files after refusal" property.
- Whether the v0.9.0 CHANGELOG entry for the new refusal is written in this phase or left entirely
  to Phase 57. **Recommendation: write the `Unreleased` breaking-change entry here** — Phase 54's
  plan `54-03` set that precedent for the relocated shadow route, and Phase 57 curates rather than
  authors.
- Whether `examples/advanced/README.md`'s surrounding prose changes beyond the paths.

## Existing Code Insights

### Reusable Assets

- `_violates_conf17(template_abs_path, srcdir)` (`template_registry.py:137`) — the CONF-17 predicate
  the hoisted pre-write check reuses verbatim. No second predicate is minted.
- `_collision_key(relative_path)` (`builder.py:494`) — the single normalization/case-folding
  primitive; D-07's reserved-key case check routes through it.
- `_validate_output_path_collisions()` (`builder.py:625`) — the accumulate-into-`failures`,
  `sorted()`-iterate, raise-once-with-a-summary shape D-03 copies.
- `_default_typst_documents()` (`builder.py:218`) and `_is_usable_typst_documents_entry()`
  (`builder.py:164`) — together they define "every usable entry", the exact input D-05's key set is
  derived from.

### Established Patterns

- **Pre-write validation slot.** Two validations already sit at the top of `write()` with docstrings
  explicitly stating the "zero `.typ` files on disk" rationale (`builder.py:935-941`, `954-961`).
  New checks join that block rather than inventing a new hook.
- **Layout violations raise; removed config values warn.** CONF-14/CONF-17/OUT-07 raise
  `ExtensionError`; CONF-19's removed-value detection warns (D-07 of Phase 54). D-01 places the
  `templates_path` collision on the raising side.
- **Warnings carry no `type`/`subtype`** (Phase 54 D-08) — nothing in this extension is individually
  suppressible via `suppress_warnings`, and this phase does not become the first.
- **No `sys.platform` branches in path comparison** — `_collision_key()`'s docstring makes the
  case-folding unconditional on every platform so Linux CI catches what only a case-insensitive
  filesystem would.

### Integration Points

- `write()` (`builder.py:905`) — where the new pre-write pass is called; `TypstPDFBuilder` inherits
  it unchanged, so both builders get the guarantee from one call site.
- `self.config.templates_path` — a config value this extension reads **nowhere** today. This phase
  introduces the first read; the only current mention in `typsphinx/` is the comment at
  `template_engine.py:36`.
- `_copy_used_template_bundles()` (`builder.py:1491`) — unchanged except that its A-01 guard becomes
  a second line of defence (D-06) rather than the only one.

<specifics>
## Specific Ideas

- The published replacement guidance must agree with what this repository's own configuration does:
  `docs/source/conf.py:96` sets `typst_template = "_typst/custom_template.typ"` while
  `docs/source/conf.py:45` keeps `templates_path = ["_templates"]` for Jinja. That pairing — both
  directories present, each with its own meaning — is the shape the docs and `examples/advanced`
  should show after D-09.
- The error message should read as an instruction, not just a diagnosis: a user who hits it should
  learn *where to move the template*, not only that the current location is wrong.
- SC#2 is verified by grepping the whole tree at discovery time. The file list in D-08 was measured
  on 2026-08-16 and is a floor; treating it as the search set is exactly the failure mode milestone
  invariant #4/#11 was written against.
