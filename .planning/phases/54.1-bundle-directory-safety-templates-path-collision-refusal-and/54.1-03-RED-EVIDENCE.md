## Reserved-key case collision — direct `sphinx-build` invocation

**Fixture:** `tests/fixtures/reserved_key_case_prewrite_gate/` — a DECLARED registry key
`"Typst"` (differing from `RESERVED_REGISTRY_KEY = "typst"` only by capitalisation), used by the
fixture's single `typst_documents` entry. The built-in `"typst"` key itself is never used.

**Command:**

```
.venv/bin/python -m sphinx -b typst tests/fixtures/reserved_key_case_prewrite_gate /tmp/54_1_03_red/build2
```

**Result:** `returncode == 0` — `build succeeded.` The build does not refuse at all.

**Verbatim tail (from the real run):**

```
preparing documents... done
writing output... [index] done
typst: wrote 1 wrapper file(s) -- compile these: index_out.typ
build succeeded.
```

**Survivors:**

```
/tmp/54_1_03_red/build2/_template/Typst/other.typ
/tmp/54_1_03_red/build2/index.typ
/tmp/54_1_03_red/build2/index_out.typ
```

**Why it is RED on this tree:** CONF-16 rejects only the literal spelling `"typst"` at
declaration time; CONF-18 compares declared keys only against EACH OTHER, never against the
synthesized built-in key. Because this fixture never USES the built-in `"typst"` key (only the
declared `"Typst"` key is referenced), even the `finish()`-side bundle-destination-collision check
(`builder.py:1892-1904`, which folds through `_collision_key()`) never runs a comparison against
it — the built-in key is never added to `destinations` at all when it is not used. The build
completes successfully and publishes `_template/Typst/other.typ`, silently reserving a bundle
destination that would collide with the built-in key's own destination the moment a later config
change also uses it.
