<recorded_assumption>
**A1 (RESEARCH.md Assumptions Log) — the second-order reserved-namespace collision is left
unguarded, deliberately.** If a real source directory happens to exist at
`<srcdir>/_typst_converted/<the same relative path>`, relocating there does not escape the collision
and the same silent-loser failure mode IMG-01 fixes recurs one level down. This is a judgment call,
not a measured fact, and it is recorded here as a visible choice rather than left implicit.

Accepted because the event is compound-improbable — a project using an image-conversion extension AND
keeping a real source asset at exactly that relative path under a directory named after this project's
own reserved namespace — and because it matches this codebase's own precedent of not guarding
implausible compound collisions until they are measured (`_template.typ` has no runtime guard against
a docname literally being `_template`).

**The documented alternative, if this is ever measured to occur:** append a short hash of
`resolved_uri` (the true absolute source path) to the reserved-namespace key. That stays a pure
function of the source path alone, so two independent builds of the same project still produce the
identical key — it does not reintroduce the write-order dependence D-03 rejects, because nothing about
WHEN the image is tracked feeds into the hash. It is not implemented here.

A related residual, recorded in 50-01 as FA-02: two DIFFERENT escaping images whose basenames coincide
would both relocate to the same `_typst_converted/<basename>` key. Same acceptance, same rationale.
</recorded_assumption>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party Sphinx extension → `TypstBuilder._track_image()` | An `ImageConverter`-family post-transform supplies an ABSOLUTE `node["uri"]`. Stock Sphinx always writes under `<doctreedir>/images/`, but nothing enforces that on a third-party transform, so the location is untrusted relative to this builder's assumptions. |
| `self.images` key → `copy_image_files()` filesystem write | The tracked key IS the destination (`path.join(self.outdir, imguri)`); any parent segment surviving into the key becomes a write outside `outdir`. |
