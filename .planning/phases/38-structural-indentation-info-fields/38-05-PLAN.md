Give `visit_desc_content` and `depart_desc_content` real bodies, per contract §2.

`visit_desc_content` emits the wrapper's opening form — the shared indent step's name interpolated into
Typst's padding call followed by an opening code-mode content block — through `self.add_text(...)`.
`depart_desc_content` emits the closing form, closing both the content block and the call, followed by
a newline.

Three properties the implementation must have:

1. **`self.add_text`, never `self.body.append`.** `add_text` routes into the table-cell buffer when the
   translator is rendering a table; a direct append does not, and the prototype proved that produces
   broken output for a `desc` inside a table cell (D-12). The fixture from plan 38-01 contains that
   case.
2. **The trailing newline on the close is load-bearing, not cosmetic.** `depart_desc` immediately
   follows with the break helper, which prepends no newline of its own outside a list item. Without the
   newline the wrapper's result and the break call juxtapose on one physical source line, which is the
   Typst "expected semicolon or line break" fatal class this codebase has hit four separate times.
   `depart_block_quote` already carries a trailing newline for the same reason.
3. **No depth counter, at all.** Nesting composes because each `pad` closes with its own node's depart.
   D-01 forbids a counter and IND-05 is satisfied by asserting the sibling case, not by resetting
   anything.

Then own D-10 in `depart_desc_content`: before emitting the close, record whether the duplicate-break
suppression marker still equals the current emission position; emit the close; and if it did, advance
the marker past the close's own bytes. That makes the outer `depart_desc` still see "nothing happened"
and correctly suppress its own duplicate. `depart_desc` itself needs no code change.

Correct `depart_desc`'s docstring in this same edit. Its premise sentence assumes nothing at all is
appended between two departures; that is now only true because the wrapper's closer is deliberately
propagated through as a byte that counts as nothing. Say that, and keep the existing paragraph
explaining why a depth counter is the wrong discriminator — a later reader must not be able to
"simplify" either mechanism back.

The newline and list-item separator bookkeeping around the wrapper is yours under D-12. Decide it with
the fixtures, not by reasoning: `tests/test_field_list_in_list_item_render_gate.py` and
`tests/test_desc_bodyless_concat_render_gate.py` are the controls, and plan 38-01's fixture contains a
`desc` in a list item and a `desc` in a table cell. Record the decision and its falsifier in the
