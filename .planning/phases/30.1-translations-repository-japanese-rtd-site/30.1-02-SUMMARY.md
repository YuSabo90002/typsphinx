## Decisions Made

- **Workflow display name locked as an interface**: `Update translation source pin`, exactly as
  Plan 05 will invoke it with `gh workflow run`.
- **No `repository_dispatch` trigger**: adding one would require a `.github/workflows/` edit in
  *this* repository (outside this plan's file-touch list) and couple two milestone phases'
  commits — `schedule` + `workflow_dispatch` is self-contained inside the translations
  repository alone.
- **`permissions: {contents: write}` only, written explicitly**: the default `GITHUB_TOKEN` at
  this scope already suffices to push to the *same* repository; no PAT/secret needed. Spelled
  out rather than inherited so a repository-wide default cannot silently widen it (threat
  T-30.1-01).
- **Commit condition is an OR, not a `.po`-only test**: a pin that moved with zero msgid change
  must still be committed, because RTD builds the submodule commit the translations repository
  has recorded — a `.po`-only condition would leave the ja site permanently frozen at the first
  pin.
- **D-05 amendment scope kept to text only**: the assertion (no locale/language flag on the
  parent's sole `sphinx-build`) is still true and useful — only its stated *reason* was stale.
  Deleting or weakening the assertion under cover of a rationale edit is exactly the coverage-
  loss class milestone invariant #5 exists to catch.

## Issues Encountered

- **Full pytest suite initially showed 45 failures** in
  `tests/test_integration_{advanced,basic,multi_doc,nested_toctree}.py` — this is the
  documented worktree-only NixOS ELF-exec hazard (a freshly-synced worktree venv's `uv` wheel
  is a generic-linux ELF that NixOS's `stub-ld` can't exec; those integration tests
  `subprocess.run(["uv","run","sphinx-build",...])`, which resolves the venv's own broken
  `uv`), not a regression introduced by this plan. Applied the known fix — 
  `ln -sf "$(command -v uv)" .venv/bin/uv` after `uv sync` — which restored a clean
  **661 passed, 1 skipped** full-suite signal, byte-identical in shape to the main tree's
  baseline.
- **`uv run ruff` fails the same ELF-exec way** even after the `.venv/bin/uv` shim (ruff's own
  wheel is generic-linux ELF, independent of the `uv` binary issue). Used the documented
  fallback `nix-shell -p ruff --run "ruff check <file>"`, which passed cleanly.
