### Gaps Summary

Two of the five ROADMAP success criteria have real, machine-evidenced, reproducible failures — not
merely unconfirmed items:

1. **SC#3 (submodule pin auto-advance)** is completely unmet: the one triggered run of the D-08
   `update-pin.yml` workflow failed before it could push anything, due to a structural defect
   (`actions/checkout@v7`'s shallow submodule fetch never creates the remote-tracking ref
   `git submodule update --remote` needs). This verifier independently confirmed the defect by reading
   the workflow file directly — it is not a flaky or environmental failure; every future run will fail
   identically until an explicit branch-fetch step is added. This is the mechanism by which I18N-01's
   named failure mode ("a Japanese project rendering English while a webhook/build stays green") would
   arrive through a different door: the ja site would silently freeze at whatever commit it was created
   against.

2. **SC#4 / I18N-03 (glyph-correct PDF)** is unmet: automated checks (page count, text extraction, CJK
   font enumeration) found a genuine defect — 10 literal NUL bytes replacing 3 specific kanji (発/単/釈)
   across 7 pages in the RTD-served PDF, compared against a proven same-source local baseline. The
   distinguishing question (does this look wrong to a human eye, or only in the invisible text layer)
   requires the still-open D-03 check 4. Per this phase's own verification standard, I18N-03 cannot be
   recorded as satisfied while that check is open — and the NUL-byte finding itself is a confirmed defect
   independent of that outcome.

Both gaps are honestly recorded as such in `30.1-EVIDENCE.md` by the executing agents themselves (no
SUMMARY.md claims of success were made for either) — this verification confirms, rather than discovers,
both findings, and additionally reproduces the SC#3 root-cause defect by direct file inspection. Neither
gap should be read as reflecting poorly on this phase's execution discipline: the phase's design
explicitly prioritized honest failure recording over false-positive passes, and both defects come with
a specific, actionable fix already diagnosed and ready to apply (an explicit submodule branch fetch for
SC#3; the owner's visual check plus root-causing the NUL bytes for SC#4).

Three criteria are not gaps: SC#1 (machine-verified, real Japanese served), SC#5 (correctly discharged by
a recorded handoff, not a false serving claim), and SC#2 (its machine-verifiable half — the parent-side
Translations link and independent version activation — passes; only its visual-widget half is open,
which is a legitimate human-verification item, not a failure).
