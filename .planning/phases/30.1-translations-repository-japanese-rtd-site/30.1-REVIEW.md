## Warnings

### WR-01: Documented clone command omits submodule init, so the very next command in the same block would fail

**File:** `docs/source/contributing.rst:303-311`
**Issue:** The `Translations` section's code-block instructs a contributor to:
```bash
git clone https://github.com/YuSabo90002/typsphinx-doc-translations.git
cd typsphinx-doc-translations
make locale-update
```
`typsphinx-doc-translations` consumes the `typsphinx` parent repo as a **git submodule**
(confirmed via the staged `translations-repo/Makefile`: `SUBMODULE = typsphinx`, `SOURCEDIR =
$(SUBMODULE)/docs/source`). A plain `git clone` (no `--recurse-submodules`) leaves the
`typsphinx/` directory empty. `make locale-update`'s first step is `sphinx-build -M gettext
$(SOURCEDIR) $(BUILDDIR)`, which reads from `typsphinx/docs/source` — a path that does not exist
after a plain clone. A contributor following these instructions verbatim, in order, hits a
"source directory doesn't exist" `sphinx-build` failure on the very first command after `cd`,
before ever reaching `make locale-stat`. This is a factual-accuracy defect the phase context
explicitly asked this review to check for.

Note: RTD itself does not hit this because its own manifest declares `submodules: {include: all,
recursive: false}` (RTD-side config, not exercised by a manual `git clone`), so the live `/ja/`
site build is unaffected — this only breaks the human contributor path documented here.

**Fix:**
```diff
    # Clone the translations repository
-   git clone https://github.com/YuSabo90002/typsphinx-doc-translations.git
+   git clone --recurse-submodules https://github.com/YuSabo90002/typsphinx-doc-translations.git
    cd typsphinx-doc-translations
```
(or, equivalently, add `git submodule update --init` immediately after `cd
typsphinx-doc-translations` and before `make locale-update`).
