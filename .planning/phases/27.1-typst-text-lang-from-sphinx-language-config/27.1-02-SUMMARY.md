## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Cleared a Babel fuzzy-match artifact in the ja catalog to an empty msgstr**
- **Found during:** Task 2 (ja catalog regeneration)
- **Issue:** `sphinx-intl update`'s underlying Babel `Catalog.update()` fuzzy-matched the new msgid `"Document Language"` against the unrelated, already-translated `"**Document title**"` → `"**ドキュメントタイトル**"` entry (pure text-similarity heuristic, no CLI flag to disable), producing a `#, fuzzy` entry with a wrong pre-filled msgstr. Sphinx compiles `.mo` with `use_fuzzy=False` by default, so this was functionally inert at build time, but it left a misleading suggested translation in the source `.po` and technically violated the task's acceptance criterion that every newly added entry has an empty msgstr.
- **Fix:** Removed the `#, fuzzy` flag and cleared the msgstr to empty for that one entry (`Document Language`). This is not a hand-authored translation — it reverts an incorrect automatic guess back to the neutral, untranslated state the task explicitly requires.
- **Files modified:** `docs/locale/ja/LC_MESSAGES/user_guide/configuration.po`
- **Verification:** `grep -n fuzzy docs/locale/ja/LC_MESSAGES/user_guide/configuration.po` returns no matches; obsolete-line count and diff re-verified after the fix
- **Committed in:** `514d2d6` (Task 2 commit)

**2. [Rule 1 - Bug] Reverted two out-of-scope .mo regenerations triggered by a verification build**
- **Found during:** Task 2 (post-update ja-language docs build used to verify the catalog compiles)
- **Issue:** Running `sphinx-build -b html` with `SPHINX_LANGUAGE=ja` (to verify the updated catalog compiles cleanly) incidentally regenerated `docs/locale/ja/LC_MESSAGES/examples/advanced.mo` and `docs/locale/ja/LC_MESSAGES/user_guide/builders.mo` (timestamp-triggered rebuild of stale `.mo` files unrelated to this plan's edits; byte-identical size, content-equivalent per `git diff --stat` showing 0 insertions/deletions on a binary diff).
- **Fix:** `git checkout -- docs/locale/ja/LC_MESSAGES/examples/advanced.mo docs/locale/ja/LC_MESSAGES/user_guide/builders.mo` (single-file revert, not a blanket reset) to keep the diff scoped to exactly the target catalog, per Task 2's explicit scoping requirement.
- **Files modified:** none (reverted, not committed)
- **Verification:** `git status --porcelain docs/locale/` shows only `user_guide/configuration.po`
- **Committed in:** N/A (reverted before commit)

## Issues Encountered
- The plan's suggested gettext invocation form (passing `user_guide/configuration.rst` as a bare relative-to-srcdir positional filename) produced 0 matched source files (Sphinx's positional filenames are resolved relative to the process cwd, not the srcdir) and silently fell back to processing all 13 docnames. Fixed by passing the path relative to cwd (`docs/source/user_guide/configuration.rst`), which correctly scoped the build to 1 command-line source file.
- Even correctly scoped, gettext additionally emitted `index.pot` and `user_guide/index.pot` (toctree-referencing documents), not just `user_guide/configuration.pot`. Resolved by copying only the target `.pot` into an isolated throwaway pot directory before running `sphinx-intl update`, so only `user_guide/configuration.po` was touched — verified via `git status --porcelain docs/locale/`.
- Both invocation hazards flagged in the plan's `<execution_environment>` block (console-script `sphinx-build`, NixOS dynamic-linker risk on `sphinx-intl`) were checked: the module form (`python -m sphinx`) was used throughout for the gettext/html builds; the `sphinx-intl` console script itself ran without any linker error, so the documented Python-fallback invocation was not needed.
