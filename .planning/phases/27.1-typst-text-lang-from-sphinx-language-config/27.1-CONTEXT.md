# Phase 27.1: Typst 組版 lang の Sphinx `language` 連動 - Context

**Gathered:** 2026-07-25
**Status:** Ready for planning

<domain>
## Phase Boundary

Typst の組版言語 (`set text(lang:)`) を Sphinx の `language` conf に連動させる。`templates/base.typ` の `project()` に `lang` パラメータを追加し、**既定テンプレートを実際に使う経路のみ** `config.language` から自動導出し、`typst_elements["lang"]` の明示指定が全経路で優先する。目的の可視結果は Phase 25 の captioned table と figure の supplement が言語に追従すること（`language = "ja"` で「表 N」「図 N」）。

**In scope:**
- `templates/base.typ`: `project()` への `lang` パラメータ追加 + `set text(size: fontsize, lang: lang)` への配線（**この2点のみ** — SC#5）
- Python 側: Sphinx 言語コード → Typst `lang` の変換 + 検証、既定テンプレート経路の判定、`ELEMENTS_ALLOWLIST` への `lang` 追加（Phase 26 の `map_parameters(typst_elements=)` 経路に乗せる）
- GATE-01 実 `typst.compile()` フィクスチャ（D-05 の証明方式）+ SC#3 の非破壊回帰フィクスチャ（D-07 の2ケース）
- docs 更新（`docs/source/user_guide/configuration.rst` + ja `.po` 追従）— D-08

**Out of scope（スコープアンカー — ドリフト禁止）:**
- `region` パラメータ（D-01 で却下、deferred）
- `typst_elements` の他キー追加（CONF-06 は将来マイルストーン）
- 新しいトップレベル `typst_lang` 設定名の登録（`typst_elements` が唯一の窓口 — CONF-04 の踏襲）
- `@preview` 版バンプ / 新ランタイム依存（マイルストーン不変量、3-way 版同期面の**版文字列**は未変更）
- 本文の翻訳そのもの（Sphinx の i18n transform は既に機能している — 実測済み）
- CJK フォントの同梱・フォント設定（D-05 で却下）

<decisions>
## Implementation Decisions

### 実測で確定した前提（推測ではなく計測 — 2026-07-25、`.venv/bin/python` + 実 `typst.compile()`）

これらは discuss 中に実測した**事実**であり、planner/researcher は再調査ではなく前提として使ってよい。

| `set text(...)` | figure / table supplement |
|---|---|
| `lang: "en"` | Figure 1 / Table 1 |
| `lang: "ja"` | 図 1 / 表 1 |
| `lang: "de"` | Abbildung 1 / Tabelle 1 |
| `lang: "fr"` | Fig. 1. – / Tableau 1. – |
| `lang: "zh"` = `lang:"zh", region:"CN"` | 图 1 / 表 1 |
| `lang: "zh", region: "TW"` | **圖** 1 / 表 1（region で変わる唯一の実測ケース） |
| `lang: "pt"` = `lang:"pt", region:"BR"` | Figura 1 / Tabela 1 |

- **ロケール付き値の素通しは hard fatal**: `lang: "zh_CN"` / `"日本語"` / `""` はいずれも `TypstError: expected two or three letter language code (ISO 639-1/2/3)` でコンパイル中止。→ Python 側の変換・検証は必須（SC#4 の根拠）。
- **未知の 2〜3 文字コードは fatal にならない**: `lang: "xyz"` は成功し英語にフォールバック。大文字 `"JA"` も成功（Typst 側で正規化、「図 1」）。
- **supplement の区切りは通常空白ではなく NBSP (`\xa0`)**: 抽出テキストは `'図\xa01: cap'`。テキスト抽出アサートを `"図 1"`（ASCII 空白）で書くと落ちる。
- **CJK は環境依存**: `ignore_system_fonts=True`（CJK フォント不在の再現）で `lang: "ja"` はコンパイル成功するが抽出は `'\x00\xa01: cap'`（豆腐/notdef）。CI は 3-OS マトリクス（ubuntu/windows/macos）で、ubuntu ランナーの CJK フォント有無は未確認。
- **`<srcdir>/base.typ` は同梱テンプレートを黙って上書きする**: `TemplateEngine(template_path=None, search_paths=[srcdir])` + `template_name` 既定 `"base.typ"` の Priority 2 経路。実測で確認済み（`get_template_content()` がユーザーのファイルを返す）。`writer.py:191` と `builder.py:576` の両方が `search_paths=[srcdir]` を渡す。docs には未記載、`tests/test_template_engine.py` にテストあり。

### 言語コードの変換規則
- **D-01: region は非対応 — `lang` のみ。** `base.typ` の変更は `project()` への `lang` パラメータ追加とその `set text()` 配線の**1パラメータのみ**に留め、SC#5 とマイルストーン不変量の改訂文面をそのまま守る。結果として `language = "zh_TW"` は `lang: "zh"` になり supplement は簡体字「图 1」になる（繁体字にならない）— これは**既知の限界として受容**し、docs に明記して region 対応は deferred に回す。SC#4 の「（必要なら region）」は本フェーズでは不要と判断。
- **D-02: 変換は汎用規則、マップ表は持たない。** 「先頭から最初の区切り文字（`_` / `-` / `@`）までを取り小文字化」の1行規則。`ja`→`ja`、`zh_CN`→`zh`、`pt-BR`→`pt`、`sr@latin`→`sr`、`en`→`en`。Sphinx 対応言語 ~70 件分の対応表を手保守しないで済み、新しいロケールが増えても破れない。テストは代表値をパラメトライズして固定する。

### 未知・非標準値の扱い（SC#4）
- **D-03: 変換後が 2〜3 文字英字にならなければ `lang` を渡さず、Sphinx `logger.warning` で値を名指しする。** `params` に `lang` を入れないので `base.typ` の既定値（`"en"`）が効き、ビルドは落ちない（SC#4）。明示的に `"en"` を渡す案は却下 — base.typ の既定値と二重の真実の源になり、将来既定が変わったとき追従しない。`ExtensionError` で fail loud も却下 — `language` は typsphinx の設定ではなく Sphinx 標準設定で、HTML/LaTeX ビルダーは同じ値で落ちない。typst ビルダーだけが止まるのは筋が悪く、SC#4 の文面とも衝突する。（Phase 26 D-06 の fail-loud 先例は *typsphinx 自身の設定の未知キー* に対するもので、ここには適用しない。）
- **D-04: 明示 `typst_elements["lang"]` の値は検証せず素通し。** Phase 26 **D-09 の先例に一致** — `fontsize` は Python 側で長さ文法を検証せず「ユーザーが書いた Typst リテラルをそのまま出し、不正なら Typst が落とす」と決めた。`typst_elements` はこのビルダー専用設定なので、ユーザーは Typst の値を直接指定しているとみなす。したがって D-03 の検証は**自動導出値にのみ**適用する。

### precedence と配線
- **D-05（precedence）: `lang` を `ELEMENTS_ALLOWLIST` に `STRING` 種別で追加し、優先順位は既存構造に任せる。** Phase 26 の実装では elements マージが `map_parameters` の**最後**に走る（`parameter_mapping` → package-path back-fill guard → `typst_authors` override → elements マージ）。自動導出値を先に `params["lang"]` に入れておけば、明示指定は後から上書きするので precedence は構造的に成立する（Sphinx LaTeX の `init_context()` — 言語別既定が先、`latex_elements` が最後に勝つ — と同型）。新しい precedence 分岐ロジックを書かないこと。
- **D-06（判定境界）: 「既定テンプレート経路」は宣言ではなく*ロード結果*で判定する。** `typst_template is None and typst_package is None` という宣言ベースの判定では、実測済みの `<srcdir>/base.typ` シャドウ経路（両方 None なのにユーザー自作テンプレートが使われる）で `lang` を注入し、SC#3 が防ぎたい `unexpected argument: lang` の hard fatal を*自分で作ってしまう*。判定は「実際にロードされるテンプレートが同梱の `base.typ` か」に一致させる（`load_template` / `get_template_content` の解決結果を利用 — どの経路で解決したかを返す小さな手入れが必要）。`<srcdir>/base.typ` の存在チェックを判定に足すだけの簡易案は却下: `load_template` の優先順位ロジックが2箇所に重複し、`search_paths` / `template_name` の規則が変わるとズレる。
- 判定は writer 側の `TemplateEngine`（params を作る側）で行う。`builder.py::_write_template_file` は `_template.typ` を書くだけで params を作らないので、そちらに判定を重複させないこと（WR-04「1つの規則を1箇所に」の踏襲）。

### GATE-01 の証明方式
- **D-07: `ja` は「実コンパイル成功 + `.typ` に `lang: "ja"`」、supplement の言語連動は `de` の PDF テキスト抽出で証明する。**
  - `language = "ja"` ケース: 実 `typst.compile()` が成功し、生成 `.typ` の `#show: project.with(...)` に `lang: "ja"` が出ることをアサート（フォント非依存）。
  - supplement 連動の本体: `language = "de"` で実コンパイル → pypdf 抽出 → `"Abbildung 1"` / `"Tabelle 1"` をアサート。ラテン文字なので Typst 同梱フォントで全 OS 安定。
  - **理由（実測）**: `ja` の PDF テキスト抽出は CJK フォントの有無に依存し、`ignore_system_fonts=True` で豆腐（`\x00`）になる。CI の ubuntu ランナーに CJK フォントがある保証は確認できていないため、`ja` 抽出アサートは CI 限定 flaky のリスクを持つ。CJK フォントをリポジトリに同梱する案（数 MB のバイナリ + ライセンス表記）も却下。
  - **⚠ ROADMAP SC#1 の解釈変更**: SC#1 の文面は「`language = "ja"` でコンパイル済み PDF の figure/table supplement が『図 N』『表 N』になることを実 `typst.compile()` の GATE-01 フィクスチャで証明する」と書かれている。上記は *supplement が言語連動すること* を `de` で証明し、*ja が正しく渡ること* を `.typ` で証明する分割方式。**verifier はこの分割を SC#1 の未達と扱わないこと。** 実装後に ROADMAP SC#1 の文面をこの証明方式に合わせて更新するのが望ましい。
  - red→green は自動的に成立する（修正前は `lang: "en"` ハードコードなので `de` ケースは "Figure 1" を出して落ちる）。GATE-01 慣行どおり fail-pre-fix を記録すること。
- **D-08: SC#3 の非破壊回帰フィクスチャは 2 ケースを覆う（D-06 から必然）。** ① `typst_template` に `lang` 未宣言のカスタムテンプレートを明示指定 + `language = "ja"` → ビルド成功、② `<srcdir>/base.typ` に `lang` 未宣言のテンプレートを置く（`typst_template` / `typst_package` は未設定）+ `language = "ja"` → ビルド成功。②が D-06 の判定境界そのものの証明になる。

### docs
- **D-09: docs もこのフェーズで更新する。** Phase 27 で docs を実測整合した直後なので、新しく動くキーを書かないと即座に乖離が再発する。対象: `docs/source/user_guide/configuration.rst`（`typst_elements` の対応キー記述 — 現在 papersize/fontsize の2キーと書いてある箇所に `lang` を追加、`language` 連動の挙動、既定テンプレート以外では自動導出されないこと、`zh_TW` が簡体字になる D-01 の限界）+ `docs/locale/ja/LC_MESSAGES/user_guide/configuration.po` の追従（Phase 27 と同じ**スコープ限定**の `sphinx-build -b gettext`、除去 msgid は `#~` のまま残す — 手で剥がさない）。

### Claude's Discretion
- 変換ヘルパーの置き場所と名前（`template_engine.py` のモジュール関数か小さなプライベートメソッドか）、`config.language` を `TemplateEngine` に届ける手段（`__init__` 引数か `map_parameters` 引数か）、`load_template` が「どこから解決したか」を返す形（戻り値の変更か属性か小さな dataclass か）— D-05/D-06 の不変条件（elements マージが最後に走る構造を壊さない／判定は writer 側1箇所）を守れば planner/executor の裁量。
- フィクスチャのレイアウト（`tests/roots/` の Sphinx プロジェクトか inline `conf.py` 構築か）は Phase 22.x/25/26 の既存 GATE-01 慣行に合わせる。
- `de` 抽出アサートで figure と table の両方を見るか片方かは executor 判断（両方が望ましい — Phase 25 の captioned table が本フェーズの動機なので table は必須）。

## Existing Code Insights

### Reusable Assets
- `ELEMENTS_ALLOWLIST` + `map_parameters(typst_elements=)`（Phase 26/CONF-04）— `lang` を1行足すだけで「明示指定が全経路で渡る」が手に入る。新しい設定サーフェスは不要。
- `map_parameters` のマージ順序 — elements が最後に走るので、自動導出→明示上書きの precedence が**追加ロジックなしで**成立する。
- `logger.warning` の既存慣行（`template_engine.py` の template-not-found 警告、`builder.py` の package+template 併用警告）— D-03 の不正値警告はこの形に合わせる。
- 既存 GATE-01 フィクスチャ群（Phase 22.x/25/26）— 実 `typst.compile()` + pypdf 抽出 + fail-pre-fix 記録の型がそのまま使える。

### Established Patterns
- **allowlist キーは `base.typ` の `project()` 宣言と 1:1**（`template_engine.py:44-57` のコメントが明文化）。`lang` を allowlist に足すのと `base.typ` に `lang` パラメータを足すのは**同一コミットで**行わなければならない（片方だけ入ると undeclared kwarg で全ビルド fatal）。
- **ユーザー明示値は second-guess しない**（D-09）。検証は自動導出値にのみ。
- **1つの規則は1箇所に**（WR-04 / `resolve_package_for_engine`）。テンプレート経路の判定を writer と builder で二重に持たない。
- **included document には template が当たらない**（`writer.py` の `_is_master_document` 分岐、`#include()` は import を継承しないので最小 import だけ前置される）。Typst の `set` ルールは `#include()` された内容にカスケードするので、master 側の `set text(lang:)` だけで included 文書にも効く — included 側に手当ては不要。

### Integration Points
- `config.language`（Sphinx 標準設定、既定 `"en"`）→ writer.py → `TemplateEngine`（既定テンプレート判定 + 変換 + 検証）→ `map_parameters` の `params["lang"]` → `_format_typst_value` → `#show: project.with(lang: "ja", ...)` → `base.typ` の `set text(lang: lang)` → Typst の figure/table supplement。
- typsphinx は現在 `config.language` をどこでも読んでいない（grep 済み: `translator.py:1760` の `node.get("language")` はコードブロックの言語で無関係）。これが最初の消費点になる。

## Specific Ideas

- 動機となる可視結果: `language = "ja"` のプロジェクトで、Phase 25 の captioned table が "Table 1" ではなく「表 1」、figure が "Figure 1" ではなく「図 1」になること。本文は既に翻訳されている（Sphinx i18n transform は機能済み — 実測確認）ので、残っているのは Typst が生成するラベルだけ。
- テキスト抽出アサートを書くときは区切りが **NBSP (`\xa0`)** であることに注意（`"Tabelle 1"` の空白も同様に NBSP の可能性があるため、正規化してから比較するか部分一致にする）。
- `de` を証明言語に選んだのは "Abbildung"/"Tabelle" が英語と明確に異なりラテン文字で全 OS 安定だから。`fr` は "Fig. 1. –" のようにピリオドとダッシュが入り抽出アサートが脆いので避ける。

<deferred>
## Deferred Ideas

- **`region` パラメータ対応**（D-01 で却下）— `base.typ` の `project()` に `region` を追加し、`zh_TW` → `lang:"zh", region:"TW"` で繁体字「圖」を出す。実測で差が出るのは `zh_TW` のみ（`zh_CN`/`pt_BR` は region 無しと同一出力）。マイルストーン不変量の再改訂が必要なため将来フェーズ（CONF-06 系の続き）。
