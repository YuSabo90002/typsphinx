# Phase 27.1 Plan 01: Typst lang parameter + conversion helper + template-resolution provenance Summary

**`base.typ`'s `project()` gains a `lang` parameter wired into `set text(lang:)`, driven by a new `derive_typst_lang()` conversion helper and a `uses_bundled_default_template()` provenance predicate that gates auto-derivation to the default-template path only, with explicit `typst_elements["lang"]` always winning.**

## Accomplishments

- `templates/base.typ`'s `project()` now declares a `lang: "en"` parameter wired into `set text(size: fontsize, lang: lang)` — exactly two lines changed (SC#5), no `@preview` import touched.
- `derive_typst_lang(sphinx_language)` implements D-02's generic "split at first `_`/`-`/`@`, lowercase" rule with D-03's ASCII-scoped `re.fullmatch(r"[a-z]{2,3}", head)` accept test — deliberately NOT `str.isalpha()`, which is Unicode-aware and would silently forward a CJK/Cyrillic head into a hard Typst compile fatal. Rejection warns via `logger.warning` naming the value with `!r}` and returns `None` (never raises, never substitutes a literal `"en"` fallback).
- `ELEMENTS_ALLOWLIST` now carries a third `"lang": STRING` entry, landed in the **same commit** as the `base.typ` parameter (Pitfall 2 avoidance — landing either alone is a defect).
- `TemplateResolution` (frozen dataclass: `content`, `source`) + `TemplateEngine.resolve_template()` refactor the existing three-priority `load_template()` walk to record which priority actually resolved (`"explicit"` / `"search"` / `"default"`), with `load_template()` reduced to a one-line delegation — zero blast radius on its public `-> str` contract or any existing caller.
- `TemplateEngine.uses_bundled_default_template()` is the single D-06 judgment predicate: `False` immediately if `typst_package` is set, otherwise `resolve_template().source == "default"`. This correctly returns `False` for the `<srcdir>/base.typ` shadow case (Priority 2 search hit), which a naive declaration-based check (`typst_template is None and typst_package is None`) would have missed.
- `writer.py::translate()` now gates auto-derivation on `template_engine.uses_bundled_default_template()`, computes `auto_lang` via `derive_typst_lang(getattr(config, "language", None))` only when that gate is True, and pre-merges it under the user's `typst_elements` into a NEW `effective_elements` dict (`{"lang": auto_lang} if auto_lang else {} | typst_elements`) — the explicit value always wins on collision (D-05), with zero new precedence logic inside `map_parameters()` itself.
- `map_parameters()`'s four-stage merge order, `typsphinx/builder.py`, and `typsphinx/__init__.py` are all confirmed unchanged (`git diff` against the plan's base commit `605dd69` is clean for the latter two).

## Decisions Made

- Followed the plan's Claude's-Discretion latitude: `derive_typst_lang()` placed as a public module-level function immediately after `ELEMENTS_ALLOWLIST` and before `resolve_package_for_engine()` (mirrors that function's "public, module-level, imported by writer.py" shape).
- `TemplateResolution`/`resolve_template()` chosen over a bare `self.template_source` attribute per RESEARCH.md's own recommendation — a small, explicit, greppable sentinel type, matching this module's existing `RawTypst`/`_ElementsEmissionKind` convention.
- `config.language` read via `getattr(config, "language", None)` (defensive, though Sphinx guarantees a non-`None` `str` by build time) rather than a direct attribute access, matching the existing house style at the `typst_elements`/`typst_template` reads immediately above it in `writer.py`.
