## 6. Claude's-Discretion decisions, recorded with their locations

**G1 — a skipped back-reference degrades SILENTLY.** Decided in `40.1-01-PLAN.md` § "Claude's-
Discretion items", recorded in full (three-point rationale) in `40.1-GATE-EVIDENCE-01.md` §5. Neither
arm of `visit_citation`'s backref filter (`ref_node is None`, or `_citing_reference_has_own_anchor`
returns `False`) emits a `logger.warning`. Rationale: (1) the reproducible real-build trigger
(`.. only:: <tag>`) is a legitimate documentation pattern, not an authoring error; (2) warning
asymmetrically on only the new arm would reintroduce the exact asymmetry WR-01 closes, and warning on
both arms would change already-shipped Phase 40 behaviour no decision in this phase authorises
changing; (3) the nearest precedent (`visit_footnote_reference`'s dangling-target guard) does not
transfer — here the citation *definition* exists, only a back-reference marker to a pruned citing site
is dropped. **Obligation this choice carries:** because `visit_citation` enumerates the FILTERED list,
dropping a backref changes the marker's shape under Phase 40's D-03 — the emitted shape for every
degraded citation is asserted (all three transitions: 3→2, 2→1, 1→0), not left to chance.

**G2 — WR-02's fix stays NARROW.** Decided in `40.1-02-PLAN.md`, recorded in `40.1-GATE-EVIDENCE-02.md`
§7. One literal disjunct (`isinstance(sibling, nodes.target) and not sibling.get("ids")`) added
alongside the existing `comment`/`system_message` check — no general "emits nothing" predicate, no new
helper method. **Measured caveat:** an ids-less target is inert only OUTSIDE list items —
`visit_target`'s ids-falsy branch still writes a leading separator and sets
`list_item_needs_separator = True` when `self.in_list_item`, strictly weaker than `comment`'s
unconditional `SkipNode`. Rationale for staying narrow: (1) `40.1-CONTEXT.md`'s `<deferred>` section
explicitly defers generalising the emit-nothing concept beyond citations; (2) the general claim would
be false as written, per the list-item caveat; (3) a general predicate would need to be correct for
every node type to earn its name, while this disjunct only needs to be correct for the one type
measured end-to-end.

**Three sub-discretion outcomes, recorded so a future maintainer finds them without re-deriving:**

1. **The predicate's name and eight-field return shape:** `_ReferenceAnchorDecision`
   (`refuri: str, refid: str, xref: Tuple[str, str] | None, degrade_xref_to_text: bool,
   opens_wrapper: bool, next_is_target: bool, eligible: bool, anchor_label: str | None`) —
   `TypstTranslator._reference_anchor_decision`, decided in `40.1-03-PLAN.md`, landed in commit
