## Claude's-Discretion item G2 — decided here: WR-02's fix stays NARROW

CONTEXT.md left open whether WR-02's fix adds only the ids-less `nodes.target` case the review
proposed, or generalises "a sibling that emits nothing" into a predicate.

**Decision: narrow.** Extend `_citation_run_neighbour`'s existing skip condition with exactly one
disjunct — `isinstance(sibling, nodes.target) and not sibling.get("ids")` — beside the existing
`comment` / `system_message` tuple. No general predicate, no new helper method.

Rationale:

1. CONTEXT.md `<deferred>` explicitly defers *"Generalising 'a sibling that emits nothing' beyond
   citations"* out of this phase. A general predicate is precisely the seed of that generalisation:
   the moment it exists, the same question is live for every other run-adjacency and
   separator-protocol site in the translator, which this phase does not touch.
2. **The general claim would be false as written.** RESEARCH measured that an ids-less `target` is
   inert only *outside* list items — `visit_target` still writes `"\n"` when
   `self.in_list_item and self.list_item_needs_separator`, and sets `list_item_needs_separator = True`
   afterwards. It is therefore strictly *weaker* than `comment`, whose `visit_comment` raises
   `SkipNode` before touching separator state. A predicate named "emits nothing" would encode a
   claim the code does not honour; a literal one-case disjunct makes no general claim at all.
3. A general predicate has to be correct for every node type to earn its name. This disjunct has to
   be correct for exactly one, and that one has been measured end-to-end.

The measured caveat in point 2 is recorded in the docstring rather than papered over — that is Task 2's
explicit obligation, not a nicety.
