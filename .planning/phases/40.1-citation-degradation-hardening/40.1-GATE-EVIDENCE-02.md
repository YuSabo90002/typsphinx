## 1. WR-02's fix site (unchanged at this commit, for reference)

```python
def _citation_run_neighbour(self, node: nodes.citation, offset: int) -> bool:
    ...
    if node.parent is None:
        return False
    children = node.parent.children
    i = node.parent.index(node) + offset
    while 0 <= i < len(children):
        sibling = children[i]
        if isinstance(sibling, (nodes.comment, nodes.system_message)):
            i += offset
            continue
        return isinstance(sibling, nodes.citation)
    return False
```

Only `nodes.comment`/`nodes.system_message` are skipped. An ids-less `nodes.target` (`visit_target`'s
"ids falsy" branch, `typsphinx/translator.py:3503-3560`, emits no anchor when `not node.get("ids")`)
is NOT on this list, so it is treated as a real, run-breaking sibling.

## 2. D-01 attempt list for WR-02 (the full five-attempt enumeration)

Per `40.1-CONTEXT.md` D-01, "a real `sphinx-build` cannot construct this topology" is established by
enumerating attempts, not by proving impossibility. `40.1-RESEARCH.md` § "WR-02 — ids-less
`nodes.target` between two citations" already ran this enumeration this session (2026-08-02); it is
carried here verbatim, per plan (D-03: the evidence file must carry the full attempt list, not merely
reference RESEARCH.md).

**Attempt 1 (VERIFIED, did NOT produce the minimal topology): a single named internal target with no
URI directly between two citations** (`` .. _`anonymous target`: `` / `.. _alias-one:` alone).
Result: the target keeps its OWN id (`ids=['alias-one']` or similar) — never empty.

**Attempt 2 (VERIFIED, did NOT produce the minimal topology): two adjacent named internal targets
with DIFFERENT names, chained** (`.. _alias-one:` immediately followed by `.. _alias-two:`, then a
citation). Result: the FIRST of the pair gets `ids=[]`, the SECOND gets the merged real ids
(`ids=['alias-two', 'alias-one']`) — TWO target siblings exist between the citations, one ids-less
and one real.

**Attempt 3 (VERIFIED, did NOT produce the minimal topology): two adjacent targets with the SAME name
(duplicate target, triggers a Sphinx warning)** (`.. _dup:` immediately followed by `.. _dup:`). Same
shape as Attempt 2: first `ids=[]`, second `ids=['id5', 'dup']`.

**Attempt 4 (VERIFIED, did NOT produce the minimal topology): a true anonymous target (`__ <uri>`,
double-underscore form).** Result: gets its own auto-assigned id (`ids=['id4']`) — never empty.

**Attempt 5 (VERIFIED, did NOT produce the minimal topology): a single named target immediately
preceding a citation (no second target in the chain).** Result: no propagation onto the citation
node; the target keeps its own id, non-empty.

**Conclusion:** in every shape tested, an ids-less `nodes.target` is produced ONLY as the non-terminal
member of a 2+-node chain of adjacent target directives, and docutils' target-chaining transform
(0.22.4) always leaves the chain's TERMINAL member with a real, non-empty `ids`. Since chain members
are — by the chaining mechanism itself — mutually adjacent, the terminal (real-id) member necessarily
sits in the SAME gap between the two citations as the ids-less one, and it alone is sufficient to
break `_citation_run_neighbour`'s scan regardless of whether the WR-02 fix is applied.

**Provenance verdict: directly-assembled doctree.** The minimal single-blocker WR-02 topology
(citation, one ids-less target, citation, nothing else in between) is not constructible via a real
Sphinx/docutils build in Sphinx 9.1.0 / docutils 0.22.4. This is a negative result of independent
value (D-01's "a negative result is exactly as valuable as a positive one"): a maintainer reading
only the review's suggested fix would reasonably assume ordinary RST reproduces it — it does not, in
this version. WR-02's RED therefore uses the assembled-doctree harness (`_StubBuilder`,
`_make_document`, `_make_citation`, `_render_body`) added to `tests/test_citation_degradation_gate.py`
in this commit, per D-01's "real build whenever available, fallback otherwise" discipline and
`40.1-RESEARCH.md`'s Pattern 1/3.
