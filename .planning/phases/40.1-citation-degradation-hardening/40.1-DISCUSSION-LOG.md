## WR-03 duplication removal shape

### The shape of the single source of truth

| Option | Description | Selected |
|--------|-------------|----------|
| Extract a shared predicate | One method answers "does this reference anchor itself"; both `visit_reference` and `visit_citation` consult it; the condition physically exists once, so drift becomes structurally impossible. Requires recomputing `opens_wrapper` (a `visit_reference` local, builder-dependent via `degrade_xref_to_text`) | ✓ |
| Callee checks the other two conditions | The review's second suggestion; smallest change, hot path untouched, but the condition still lives in two places held together only by a test | |
| Record emitted anchors and consult the set | "Fact" rather than "matching judgement", but visit-order dependent — a forward reference (definition before citing site, a shape Phase 40's probe carries) queries the set before the anchor is recorded | |

**User's choice:** Extract a shared predicate → D-05

### How far the input derivation is unified

| Option | Description | Selected |
|--------|-------------|----------|
| Derivation inside the predicate | Pass the node; derive `refuri`/`refid`/`degrade_xref_to_text`/`next_is_target` inside; `visit_reference` drops its own local computation. Judgement *and* derivation exist once. Rewrites a hot path taken by every link, so D-14's byte-identity proof must be re-discharged | ✓ |
| Pure predicate taking three booleans | Judgement in one place, derivation still in two — the drift moves upstream; `visit_reference`'s output path effectively unchanged | |
| Leave the builder-dependent half out | Smallest, but gives back the one route by which `opens_wrapper` provably goes false today (the `degrade_xref_to_text` path) | |

**User's choice:** Derivation inside the predicate → D-06

### What the predicate returns

| Option | Description | Selected |
|--------|-------------|----------|
| Boolean + label | The anchor label is *also* built twice today — `_namespace_label(_current_docname(), ids[0])` at 4227-4229 vs `_namespace_label(docname, refid)` at 2862 — so returning the label closes a second drift source of the same class in the same change; extends Phase 40's D-13 | ✓ |
| Boolean only | `_namespace_label`/`_sanitize_label` are already a single derivation point, so equal arguments suffice — but "equal arguments" is exactly the unenforced invariant WR-03 is about | |
| Separate label helper | Cleaner separation of concerns, two new helpers instead of one | |

**User's choice:** Boolean + label → D-07

### Which condition-breaking route the RED uses

| Option | Description | Selected |
|--------|-------------|----------|
| Measure both, take what builds | Try the `opens_wrapper`-false route and the `ids`-empty route in a real build; the one that works becomes the RED, the other goes into D-01's attempt list — same posture as D-01 rather than a second policy | ✓ |
| `opens_wrapper`-false only | The `degrade_xref_to_text` path the review itself cites as proof that `opens_wrapper` can be false; most likely to be real-buildable, but no fallback if it misses | |
| `ids`-empty only | Today's citation domain always populates `ids`, so this leans toward the assembled-doctree fallback from the start | |

**User's choice:** Measure both, take what builds → D-08
