## 1. WR-03's fix sites (unchanged at this commit, for reference)

**`_citing_reference_has_own_anchor`** (currently `typsphinx/translator.py:2735-2765`):

```python
def _citing_reference_has_own_anchor(self, ref_node: nodes.reference) -> bool:
    parent = ref_node.parent
    if parent is None:
        return True
    index = parent.index(ref_node)
    if index + 1 < len(parent.children) and isinstance(
        parent.children[index + 1], nodes.target
    ):
        return False
    return True
```

Only checks `next_is_target` (via a fresh sibling-index lookahead), assuming — without checking —
that `ref_node.get("ids")` is non-empty and that `opens_wrapper` is `True`.

**`visit_reference`'s D-14 guard and its `opens_wrapper` derivation** (currently
`typsphinx/translator.py:4171-4272`, the load-bearing excerpt):


## 2. D-01/D-08 attempt list — both routes, in full

Per `40.1-CONTEXT.md` D-01/D-08, both of WR-03's candidate condition-breaking routes are attempted
against a real build (or, where a real build is not the relevant test, against the code's own
control flow), and both are recorded here whether or not each one succeeds.

### Route A — `_citing_reference_has_own_anchor`'s `ids`-empty gap

**Not a build-constructibility question at all.** This is a fact about
`_citing_reference_has_own_anchor`'s only real caller, verified by reading the code rather than
measured against a build — independent of Sphinx/docutils version. Re-reading `_find_citing_reference`
(`typsphinx/translator.py:2708-2733`):

```python
def _find_citing_reference(self, refid: str) -> nodes.reference | None:
    for candidate in self.document.findall(nodes.reference):
        if refid in (candidate.get("ids") or []):
            return candidate
    return None
```

Any node this function returns, **by construction**, has `refid` as a member of its own `ids` — the
matching condition `refid in (candidate.get("ids") or [])` cannot be `True` for a candidate whose
`ids` is empty or does not contain `refid`. So `candidate.get("ids")` is non-empty for every node
`visit_citation`'s backref loop ever passes to `_citing_reference_has_own_anchor` through this call
site. **The "`ids` empty" drift route is therefore structurally unreachable through
`visit_citation`'s own call site**, and this holds regardless of which Sphinx/docutils version is
installed, because it is a fact about *this repository's own control flow*, not about what any
version of Sphinx's citation domain happens to produce.

It would only become reachable if some FUTURE caller invoked `_citing_reference_has_own_anchor` with
a node obtained some OTHER way — e.g. directly from `self.document.ids[refid]`, the exact
stale-pointer path `_find_citing_reference`'s own docstring (2713-2723) says it was written to avoid.
Per Pitfall 4 (`40.1-RESEARCH.md`/this plan's `<tasks>` block), **no RED is built on Route A** — it
is recorded here as a negative result of independent value (D-01: "a negative result is exactly as
valuable as a positive one"), and the invariant test added in Task 2
(`test_wr03_eligibility_decision_and_emitted_anchor_agree`, case (iv): `refid` set, `ids` empty)
covers it as defensive code, not as a demonstrated bug.

### Route B — `opens_wrapper` false via `degrade_xref_to_text`

**Attempted against a real two-document build** this session (`index.rst` toctree-including
`second.rst`, a citation defined in `second.rst`, cited once from each document) — the verbatim
resolved-doctree dump (`40.1-RESEARCH.md` § "WR-03 real-build corroboration of D-08's two routes",
carried here verbatim per this evidence file's own convention of recording RESEARCH's
already-reproduced session findings rather than re-running an identical build, matching
`40.1-GATE-EVIDENCE-01.md` §4's precedent):

```
index REF ids= []       refid= None        refuri= second.html
index REF ids= ['id1']  refid= None        refuri= second.html#same2020
second CITATION ids= ['same2020'] backrefs= ['id1']
second REF ids= ['id1'] refid= same2020    refuri= None
```

The cross-document citing reference in `index.rst` DOES carry a non-empty own `id` (`'id1'` —
coincidentally, and confusingly, the SAME string as `second.rst`'s own same-document citing
reference's id, since docutils' auto-id counter is per-document, not shared) — but `second.rst`'s
citation's own `backrefs` list is `['id1']`, which resolves to the SAME-DOCUMENT reference inside
`second.rst` itself, **never** to the cross-document one in `index.rst`. **`backrefs` never contains
a cross-document citing site's id.**

Combined with the second, also independently-reproduced fact that a same-document citing reference
(the only kind that ever appears in a citation's `backrefs`, since matching is on the node's own
`ids`) always carries `refid`, never `refuri` — Sphinx's citation domain resolves same-document
citing sites via `refid` and cross-document ones via `refuri`, mutually exclusively on one node — and
that `degrade_xref_to_text` can only ever become `True` when `refuri` is present
(`xref = self._resolve_xref_docname(refuri) if refuri else None`, `visit_reference:4201`):
**Route B is also not constructible via a real build — a node reachable through
`_find_citing_reference` never carries a `refuri`, so `opens_wrapper`'s `degrade_xref_to_text` term
can never be the reason it goes `False` for such a node.**

### Verdict

Both of D-08's candidate routes are unreachable via a real `sphinx-build` under Sphinx 9.1.0 /
docutils 0.22.4. **Provenance: directly-assembled doctree for both routes**, per D-01's "a real build
whenever one is available, fallback otherwise" — the fallback triggers here because neither route
can be reached at all, not merely because a more exotic RST shape wasn't tried.

WR-03's RED (§3 below) hand-constructs a reference node that VIOLATES both real-build invariants at
once — a populated own `ids` AND a `refuri` resolving to a document excluded from
`master_included_docnames` — a shape only reachable by writing to `node.attributes` directly
(`_make_citing_reference`, `tests/test_citation_degradation_gate.py`), never by parsing RST.
