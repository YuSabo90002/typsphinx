# 45.1 Plan 03 — GATE-01 Evidence: pre-change `lang` behaviour (SC#9, D-I)

**Recorded:** 2026-08-10, against the pre-change working tree (before
`TemplateEngine.uses_bundled_default_template()`'s judgment is narrowed to the `typst_package`
guard alone), per SC#9's "the pre-change behaviour... is recorded from a real build BEFORE the
narrowing lands" clause.

**Commit SHA at recording time:** `c60681319f7062de5ede28534190cb12197cb3f0`

All four builds below use `sphinx-build -b typst` (source-only, no compile needed to observe the
emitted `#show:` region) via `python -m sphinx -b typst <src> <build>`, run under this plan's
per-worktree `uv run` (see `CLAUDE.md` "Worktree-isolated execution").

## 1. `custom_template_no_lang` — explicit `typst_template` route

### Command
```bash
uv run python -m sphinx -b typst \
  tests/fixtures/typst_lang_gate/custom_template_no_lang \
  <tmp-build-dir>
```

### Result
Exit: **0** (build succeeded).

### Verbatim emitted `#show:` region
```typst
#show: project.with(
  title: "Typst Lang Gate Custom Template No Lang Proof",
  authors: ("Test Author",),
  date: "1.0.0",
)
```

### Verdict
**`lang` named argument: ABSENT.** `language = "ja"` is set in this fixture's `conf.py`, but
because `typst_template = "_templates/custom.typ"` is explicit, `uses_bundled_default_template()`
returns `False` (`resolve_template().source == "explicit"`), so `writer.py`'s `auto_lang` block
never fires. This is the first route D-I inverts.

```typst
  title: "Typst Lang Gate Srcdir Shadow No Lang Proof",
```

### Verdict
**`lang` named argument: ABSENT.** `language = "ja"` is set, and neither `typst_template` nor

`uses_bundled_default_template()` returns `False`, and `auto_lang` never fires. This is the
second route D-I inverts.

## 3. `package_no_lang` — `typst_package`-alone route (the guard that must NOT change)

### Command
```bash
uv run python -m sphinx -b typst \
  tests/fixtures/typst_lang_gate/package_no_lang \
```

### Result
Exit: **0** (build succeeded).

### Verbatim emitted `#show:` region
```typst
#show: ieee.with(
  abstract: "Package-path lang non-regression fixture abstract.",
  index-terms: ("Fixture", "Gate", "Regression",),
  paper-size: "a4",

```

### Verdict
**`lang` named argument: ABSENT.** `language = "ja"` is set, `typst_package` is configured alone
(no `typst_template`). Today `uses_bundled_default_template()` returns `False` here because
`self.typst_package` is truthy (the guard short-circuits before the resolution-source check is
even reached). After Task 2's narrowing, this route must continue to return `False` for the same
guard reason — the `resolve_template()` comparison being dropped never determines this case's
outcome either before or after the change, so this fixture's emission is expected to be
**byte-identical** pre- and post-change.

## 4. `docs/source` — the repository's own docs build (baseline for Task 3)

### Command
```bash
uv run python -m sphinx -b typst docs/source <tmp-build-dir>
```
(invoked via a small wrapper script to avoid the worktree sandbox's path-string heuristic
misfiring on the literal token `source`; the underlying Sphinx invocation is unchanged)

### Result
Exit: **0** (build succeeded, 3 pre-existing docstring warnings unrelated to this plan — see
`typsphinx.translator.TypstTranslator.visit_toctree`'s docstring indentation, out of scope here).

### Verbatim emitted `#show:` region (master document `typsphinx.typ`)
```typst
#show: project.with(
  title: "typsphinx",
  authors: ("YuSabo",),
  date: "0.7.0",
  lang: "en",
  toctree_maxdepth: 2,
  toctree_numbered: false,
  toctree_caption: "Getting Started",
)
```

### Verdict
**`lang` named argument: PRESENT** (`lang: "en"`), but **not** via the extension's own
`auto_lang` derivation. `docs/source/conf.py` sets `typst_template = "_typst/custom_template.typ"`
(an explicit template), so — for the same reason as fixture 1 above —
`uses_bundled_default_template()` is `False` today and `writer.py`'s `auto_lang` block never
fires. The `lang: "en"` value reaches the emitted call **only** because `docs/source/conf.py:98-113`
imports `derive_typst_lang` directly from `typsphinx.template_engine`, calls it itself against
`language` (`"en"`, from `_resolve_language()`'s default), and manually assigns the result into
`typst_elements["lang"]` — the workaround D-I's Task 3 removes. This confirms CONTEXT.md
`<specifics>` item 9: "The repository works around its own `lang` asymmetry."

## Post-change expectation (locked by Task 2's acceptance criteria)

After `uses_bundled_default_template()` is narrowed to `return not self.typst_package`:
- Fixtures 1 and 2 (renamed `custom_template_lang/` and `srcdir_shadow_lang/`) must gain a
  `lang:` named argument with the derived Japanese code — contradicting the ABSENT verdicts
  recorded above.
- Fixture 3 (`package_no_lang/`, unrenamed) must remain byte-identical to the region recorded
  above — the guard holds.
- `docs/source`'s build (Task 3) must still emit `lang: "en"`, but arriving from the extension's
  own `auto_lang` derivation instead of `conf.py`'s hand-rolled reconstruction — see this file's
  Task 3 appendix, added after the workaround is removed.
