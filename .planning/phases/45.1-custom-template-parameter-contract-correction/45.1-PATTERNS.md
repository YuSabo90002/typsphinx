## Pattern Assignments

### `typsphinx/template_engine.py` — `__init__` parse of `typst_template_function` (D-D's predicate)

**Location to change:** lines 244-256

**Current code (collapses absent `params` and `params: {}` to the same thing):**
```python
# Parse typst_template_function: support both string and dict formats
if isinstance(typst_template_function, dict):
    self.typst_template_function_name = typst_template_function.get(
        "name", "project"
    )
    self.typst_template_params = typst_template_function.get("params", {})
elif isinstance(typst_template_function, str):
    self.typst_template_function_name = typst_template_function
    self.typst_template_params = {}
else:
    self.typst_template_function_name = None
    self.typst_template_params = {}
```

**Pattern to copy:** D-D requires the predicate to be "presence of the `params` key", not "truthiness of the resulting dict". Follow the project's existing style of using `.get(key, sentinel)` with an explicit sentinel distinct from `{}`, or track a boolean alongside — mirror how `uses_bundled_default_template()` (lines 344-382) already models a tri-state judgment ("explicit"/"search"/"default") as a named `TemplateResolution.source` string rather than collapsing states. A `self.typst_template_params_specified: bool` sibling attribute (set via `"params" in typst_template_function` when dict) is the shape most consistent with the existing `self.typst_template_function_name` / `self.typst_template_params` pair.

### `typsphinx/template_engine.py` — `render()`'s additive union (D-B replaces this)

**Location to change:** lines 687-694

**Current code:**
```python
# Merge template-specific params with standard params.
# D-08: auto-derived Sphinx metadata is the fallback; explicit
# typst_template_function["params"] configuration is authoritative
# and wins on a key collision. Applies on both the template path and
# the package path.
all_params = {}
all_params.update(params)  # Auto-derived params first (fallback)
all_params.update(self.typst_template_params)  # Explicit config wins
```

**Pattern to copy:** replace the additive union with an exclusive branch keyed on the D-D predicate above:
```python
if self.typst_template_params_specified:
    all_params = dict(self.typst_template_params)
else:
    all_params = dict(params)
```
This mirrors the exact shape of the existing `if not self.typst_package:` gate in `map_parameters()` (lines 502-509) — a single boolean-guarded branch that swaps entire sourcing strategy rather than merging. Reuse that gate's comment style (explain WHY the branch exists, cite D-B) since this is the same kind of "whole-strategy switch, not a per-key override" decision the codebase already documents at length for D-05.

## Shared Patterns

### `typst_authors` removal (D-F) — four-file cross-cutting change
**Sites:** `typsphinx/__init__.py:56`, `typsphinx/writer.py:255`, `typsphinx/builder.py:631`, `typsphinx/template_engine.py` (`__init__` param `:211`, `:226`, `:242`; `map_parameters()` seed block `:416-485`; the `not self.typst_package` back-fill comment references at `:437-439`, `:471-473`, `:513`)
**Apply to:** every file above — delete in lockstep, since a partial removal (e.g. dropping the config registration but leaving `getattr(config, "typst_authors", None)` in writer.py) would silently pass `None` and mask a stale reference.
**Pattern:** the four production sites are individually trivial (delete one line/kwarg each); the test-file mass (71 sites) is the real cost — grep-driven removal, verified by `pytest` going green with zero `typst_authors` references remaining (`grep -rn typst_authors typsphinx/ tests/ docs/ examples/` should return only historical/CHANGELOG mentions after this phase).

### D-B's exclusivity rule — one predicate, two call sites
**Source:** the `if not self.typst_package:` gate pattern at `typsphinx/template_engine.py:502-509` (D-05's existing precedent for "whole-strategy switch based on a boolean, not per-key merge")
**Apply to:** both `typsphinx/template_engine.py`'s own `render()` (`:687-694`) AND — per CONTEXT.md's "Claude's Discretion" note — potentially `writer.py`'s three merges (`:319-330`, i.e. `effective_elements`, `map_parameters()` call, `extract_toctree_options()` `.update()`). Whichever call site implements it, the SAME boolean (`typst_template_params_specified`, set once in `__init__`) must gate all of them — do not compute the predicate twice or in two different places (mirrors the codebase's stated preference for `uses_bundled_default_template()` as "the single judgment point", `template_engine.py:344-347`).

### GATE-01 real-compile regression convention
**Source:** `tests/test_package_only_config_gate.py` (module docstring lines 1-44), `tests/test_pdf_render_gate.py` (sibling PDF-gate convention, not re-read here but same family), `tests/test_preview_smoke_gate.py` (cited for the NixOS PATH-shadowing subprocess-invocation rationale)
**Apply to:** the new D-K regression test — every `sphinx-build` invocation goes through `sys.executable -m sphinx` (never a resolved `sphinx-build` binary), every real-compile assertion checks `returncode`/artifact existence/magic bytes rather than parsing compiler stdout, and no assertion matches on exact Typst error message text.
