# Phase 45.1 Plan 01: Custom-Template Parameter Contract Correction — Exclusivity Summary

**A declared `typst_template_function["params"]` (even `{}`) is now the complete, exclusive parameter set — the additive union that always back-filled title/authors/date/toctree_*/typst_elements is gone, proven end to end by a real zero-named-parameter template compile.**

## Performance

- **Duration:** ~50 min (continuation session)
- **Tasks:** 3 (checkpoint resolution + tracer implementation + suite re-derivation)
- **Files modified:** 11 (1 production, 5 new fixture/test files, 5 existing test modules re-derived)

## Accomplishments
- `TemplateEngine.typst_template_params_specified` predicate (D-D): computed once in `__init__` from `"params" in typst_template_function`, distinguishing an absent `params` from an explicitly empty `params: {}`.
- `render()`'s two-call additive union (`all_params.update(params)` then `all_params.update(self.typst_template_params)`) deleted and replaced with a single boolean-guarded exclusive branch (D-B) — `grep -c 'all_params.update' typsphinx/template_engine.py` returns `0`.
- New real-compile fixture (`tests/fixtures/params_exclusivity_gate/zero_params_template/`) proves a custom template declaring **no** named parameters at all builds and compiles to PDF through a genuine `sphinx-build -b typstpdf`, with the pre-fix RED failure recorded verbatim in `45.1-GATE-EVIDENCE-01.md`.
- `tests/test_params_exclusivity_gate.py` locks zero-argument emission, the nine-auto-derived-key absence, byte-identical repeat builds, and the adjacency (colliding-key) case as a permanent regression gate.
- Existing suite re-derived: 7 modules named in the plan's `<files>` list were audited; 5 needed changes (2 confirmed unaffected: `tests/test_params_authors_writers.py`, `tests/test_config_other_options.py`, `tests/test_package_template_routing.py` — none construct `TemplateEngine` with a dict-form `typst_template_function` carrying `params`).

## Decisions Made
- **Task 1 checkpoint resolved option-a** (human-confirmed): D-B (declared `params` is the complete set) and D-D (`params: {}` means "pass nothing") land as locked, one-way-door semantics. Not re-opened.
- **Implementation site: inside `render()`**, not upstream in `writer.py` — `map_parameters()` keeps running on every route so its `ELEMENTS_ALLOWLIST` validation still raises `ExtensionError` on an unrecognized `typst_elements` key, per the plan's explicit rationale (short-circuiting upstream would silently skip that validation).
- **BUG-C's original guarantee is preserved, not lost**: `test_package_only_config_gate.py`'s fixture always declares `params`, so under D-B it can no longer demonstrate "authors reaches output as array of dicts" (authors is now entirely discarded on that route). That guarantee remains covered directly at the `map_parameters()` level by `test_template_engine.py::TestTypstAuthorsConfig::test_typst_authors_through_pipeline_produces_native_array_of_dicts`, which was already unaffected by this plan (it asserts on `map_parameters()`'s own output, never through a `params`-specified `render()` call).
- **`examples/charged-ieee/approach1/conf.py` left unmodified**: its `typst_authors` + `typst_template_function["params"]` combination is now a self-contradiction under D-B (the seed can never survive), but removing `typst_authors` from this shipped example is explicitly D-F/D-G's (later plan's) work. The gate test was re-derived to assert the sample's current, accurate behavior instead of silently masking the interim state.
