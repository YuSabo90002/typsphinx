### Gaps Summary

**One gap, one file, already identified by this phase's own code review (CR-01) and
independently reconfirmed here by direct inspection.**

`docs/source/user_guide/configuration.rst`'s "Document Language" → "Scope: default template only"
subsection (lines 314-328) was never updated for CONF-12/D-I. It states that automatic `lang`
derivation "does **not** apply when `typst_template` is configured, when `typst_package` is
configured, or when a file named `base.typ` sits next to your `conf.py`." This was true before
this phase (D-06's original rule) and is false after it: `typsphinx/template_engine.py:353`'s
`uses_bundled_default_template()` is now `not self.typst_package` — `lang` reaches every
non-package route unconditionally.

This is not a cosmetic inconsistency. Three facts together make it a phase-goal blocker:

1. **It is reachable from the correct page.** `templates.rst:222-225` (the page plan 05 rewrote
   correctly) explicitly sends the reader to `configuration.rst`'s Document Language section for
   "the full derivation rule." A reader following the phase's own newly-corrected `templates.rst`
   lands on the contradiction by design, not by accident.
2. **The harm is proven, not hypothetical.** `tests/test_typst_lang_gate.py::TestPreFixBasisFailureProof::test_undeclared_argument_basis_raises`
   is a real, passing test in this phase's own suite proving that a pre-existing custom template
   omitting `lang` on the `typst_template` route now aborts compilation with
   `TypstError: unexpected argument: lang`. `configuration.rst` tells the reader this cannot
   happen ("It does **not** apply when `typst_template` is configured"). A reader who trusts that
   claim and skips declaring `lang` gets exactly the hard failure this whole phase exists to
   eliminate.
3. **It falsifies the phase's own stated goal**, not merely a success-criterion technicality.
   The ROADMAP goal is "A reader who writes a custom template from the published documentation
   gets a build that works" — worded about "the published documentation" as a whole, and DOC-13's
   REQUIREMENTS.md text says "the published contract and the parameters typsphinx actually passes
   agree in both directions," also not scoped to a single file. `configuration.rst` is published
   documentation the phase itself edited (three other sections of the same file, in the same
   phase, per plan 05) but left this one contradiction standing.

**Why this was not caught by the phase's own closeout (SC#2, plan 06):** `45.1-CONTRACT-ENUMERATION.md`'s
SC#2 two-way agreement proof is explicitly and only scoped to `templates.rst` ("Names
`docs/source/user_guide/templates.rst` 'Standard Parameters' publishes" — the enumeration never
reads `configuration.rst` at all). Read literally, ROADMAP SC#2's own text is also scoped to
`templates.rst` only ("accounted for in `docs/source/user_guide/templates.rst`"), so SC#2's
literal wording is satisfied and is marked ✓ VERIFIED above on that narrow reading. But the
phase's own goal and DOC-13's own requirement text are broader than SC#2's specific
implementation, and a reader does not experience the docs page-by-page in isolation — this
verifier's mandate is to judge the docs the way a reader encounters them. On that basis, DOC-13
is not fully achieved: the published contract and shipped behaviour do **not** agree in both
directions across the doc set a reader actually navigates.

**Recommended fix (already drafted by 45.1-REVIEW.md CR-01):** rewrite `configuration.rst`'s
"Scope: default template only" subsection (retitling it, since that title is now false) to state
the D-I rule — automatic `lang` derivation applies to every non-package route and is withheld
only when `typst_package` is configured — and update the "opt in explicitly" paragraph to make
clear that declaring `lang` in a custom template is not opt-in but now mandatory to avoid a
compile failure on that route.

This is a small, single-file, low-risk fix (prose only, no code or test changes) fully within
this phase's own established D-A/D-I decisions — it does not require reopening any one-way-door
checkpoint from plans 01-04.
