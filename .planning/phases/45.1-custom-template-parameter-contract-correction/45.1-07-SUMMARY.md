## Decisions Made

- **Tracer feedback gate honored literally.** Task 1 carries `type="tracer"`. `workflow.auto_advance` and `workflow._auto_chain_active` were both measured `false` at execution start, so per the interactive-run branch of the tracer feedback gate, execution stopped immediately after committing Task 1 and returned a `checkpoint:human-verify` rather than proceeding into Tasks 2-3 within the same turn. The orchestrator independently re-verified Task 1's evidence (four retired literals absent, D-I text present, `Precedence and known limitation` byte-unchanged, single-file diff) and sent an "approved" resolution; this continuation resumed from that checkpoint per the resolution's instructions, re-ran the worktree HEAD/branch guard first, and confirmed the base commit had advanced to `46451a5` (the Task 1 commit) as expected rather than treating it as a base mismatch.
- **Claim-page detector's route-token set widened beyond the plan's literal four tokens.** The plan's action text names `typst_template`/`typst_package`/`base.typ`/bundled-default wording as the route tokens `_page_makes_contract_claim()` checks. Empirically, this literal set would NOT catch `docs/source/changelog.rst` (it mentions `` ``typst_elements`` ``/`` ``papersize`` ``/`` ``fontsize`` ``/`` ``lang`` `` but none of those four route tokens) — yet the plan's own `<read_first>` explicitly frames `changelog.rst` as needing a reviewed exclusion ("a historical release note that mentions the typst_elements key set; the reason the guard needs a reviewed exclusion list rather than a bare scan"), which only makes sense if the bare scan catches it. Added `` ``typst_elements`` `` to the page-level route/config-token set to make that exclusion meaningful rather than vacuous; documented this interpretation inline in the module.
- **Sentence classifier requires the literal `lang` token, beyond the plan's stated derivation-keyword + route-token filter.** Empirical testing against the real `configuration.rst` text surfaced a false positive: the CONF-11 "Precedence" subsection (title/authors/date params-exclusivity rule) also uses "auto-derived" + `typst_template`/`typst_package`/"bundled default" wording ("on every route (``typst_template``, ``typst_package``, and the bundled default alike): the auto-derived ``title``/``authors``/``date``...") without ever naming `lang`. Without an additional `` ``lang`` `` literal requirement, this unrelated paragraph would be misclassified as a lang route-scope claim and corrupt the doc-affirmed-routes union (incorrectly adding `typst_package_alone`/`typst_package_and_typst_template` to the affirmed set, since this paragraph names `typst_package` with no withholding marker attached). Verified via a standalone Python prototype against both the exact pre-fix `git show d952a8f:...` text and the post-fix committed text before finalizing the module — both classify correctly with the `lang` requirement in place.
