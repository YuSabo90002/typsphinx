## Summary

Phase 45.1 makes four behavior changes: (1) CONF-11 — a declared
`typst_template_function["params"]` now wholesale-replaces the auto-derived
parameter set instead of merging with it; (2) CONF-12 — the auto-derived
Typst `lang` now reaches every non-package template route, not just the
bundled default; (3) CONF-10 — `typst_authors` is removed, author data
moves onto `params["authors"]`; (4) DOC-13 — the nine-parameter contract is
published in `templates.rst`.

The implementation in `typsphinx/template_engine.py` and `typsphinx/writer.py`
is correct and traces cleanly: `render()`'s exclusivity branch
(`typst_template_params_specified`) does exactly what its extensive comments
claim, `uses_bundled_default_template()`'s narrowing to `not self.typst_package`
is applied consistently at its one call site, and `typst_authors` is cleanly
removed from `__init__.py`, `builder.py`, `writer.py` and `template_engine.py`
with no dangling references anywhere in the tree (verified by repo-wide grep).
The regression-test suite added for this phase (`test_params_exclusivity_gate.py`,
`test_typst_lang_gate.py`, `test_documented_params_contract_gate.py`,
`test_entry_metadata_precedence.py`, `test_authors_pipeline_stage_gate.py`, etc.)
is unusually rigorous: real-compile gates, AST-derived stage-site enumerations,
and set-equality (not subset) assertions on emitted parameter keys.

The one defect found is in documentation, not code: `configuration.rst`'s
"Document Language" section was never updated for CONF-12 and now flatly
contradicts both the shipped code and `templates.rst`'s own (correct)
"Standard Parameters" section on the same page set. Given this phase's explicit
DOC-13 objective ("published documentation matches the code's emission
behavior"), and that following the stale guidance can produce a build that
compiles today but breaks the next time the reader touches their template
(per D-I's own acknowledged cost, see `test_typst_lang_gate.py`'s
`TestPreFixBasisFailureProof.test_undeclared_argument_basis_raises`), this is
rated a blocker.

## Critical Issues

### CR-01: `configuration.rst`'s "Document Language" section documents the pre-CONF-12 behavior, directly contradicting the shipped code and `templates.rst`

**File:** `docs/source/user_guide/configuration.rst:314-328`

**Issue:** The "Scope: default template only" subsection reads:

> Automatic derivation applies **only** when the bundled default template is
> what actually gets used. It does **not** apply when `typst_template` is
> configured, when `typst_package` is configured, or when a file named
> `base.typ` sits next to your `conf.py` in the source directory (which
> silently shadows the bundled template).

This is the pre-CONF-12 (`D-06`) rule. Plan 45.1-03 (`ba56e3c "feat(45.1-03):
widen auto-derived lang to every non-package template route"`) narrowed
`TemplateEngine.uses_bundled_default_template()` to `not self.typst_package`
(`typsphinx/template_engine.py:402`), so as of this phase `lang` auto-derivation
now applies to an explicit `typst_template` and to a `<srcdir>/base.typ` shadow
too — it is withheld **only** on the `typst_package`-alone route. This is
exactly what `templates.rst`'s own "Standard Parameters" section says, correctly,
two pages away:

> `lang` — on every non-package route, auto-derived from Sphinx's own
> `language` setting…

and exactly what `docs/source/conf.py:98-103` (this project's own dogfooded
build, using an explicit `typst_template`) documents in its own comment:
"the extension itself auto-derives the `lang` template parameter … on every
non-package template route, including the explicit `typst_template` set above."

A `git log`/`git diff` check confirms this is not a stale-but-intentional
simplification: `configuration.rst` was touched by three commits in this
phase (58-75, 176-275, 361-390 per `git diff 442a29d^ HEAD -- docs/source/user_guide/configuration.rst`),
none of which overlap the "Document Language" section's line range — plan
45.1-03 (the CONF-12 code change) updated `docs/source/conf.py`,
`templates.rst` was not part of that diff either at that point, and no later
plan in this phase revisited `configuration.rst`'s "Document Language"
section at all.

**Concrete harm:** a reader following this section's own advice — "If you use
a custom template … and want the same behavior, opt in explicitly: declare a
`lang` parameter … and then set it through `typst_elements`" — is told the
extension will not touch their `typst_template` unless they take that step.
In reality the extension **always** injects the auto-derived `lang` argument
into any non-package route now, whether or not the reader opted in via
`typst_elements`. Concretely:
- A reader with an **existing** custom template that does not declare a
  `lang` parameter, who trusts this section's claim that "It does not apply
  when `typst_template` is configured", gets a real compile fatal
  (`unexpected argument: lang`) the next time they build — this is precisely
  the cost `tests/test_typst_lang_gate.py::TestPreFixBasisFailureProof::test_undeclared_argument_basis_raises`
  proves is now real, and precisely the scenario this section claims cannot
  happen.
- A reader who dutifully declares `lang` in their template and then also sets
  `typst_elements["lang"]` "to opt in" (per this section's instructions) gets
  a working build, but for the wrong reason — the explicit `typst_elements`
  entry was never necessary; the auto-derivation is already unconditional on
  their route. The advice adds an unneeded, confusing step without being
  actively harmful in this second case, but the underlying factual claim
  ("does not apply") is still false, and the doc is authoritative in a way
  that misleads.

**Fix:** Rewrite the "Scope: default template only" subsection (and retitle
it, since "default template only" is no longer the scope) to state the D-I
rule: automatic derivation applies to every non-package route (bundled
default, explicit `typst_template`, and a `<srcdir>/base.typ` shadow alike)
and is withheld only when `typst_package` is configured. For example:

```rst
Scope: every non-package route
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Automatic derivation applies on every route EXCEPT ``typst_package`` used
alone: the bundled default template, an explicit ``typst_template``, and a
``<srcdir>/base.typ`` shadow of the bundled template all receive the
auto-derived ``lang`` argument unconditionally. It is withheld only when
``typst_package`` is configured, because typsphinx cannot introspect a
third-party Typst Universe function's signature and would otherwise hand it
an argument it never declared.

This means every documented custom template must declare a ``lang``
parameter (see :doc:`templates`'s nine-parameter contract) -- an existing
custom template that omits it will fail to compile with an "unexpected
argument: lang" error the next time it is built.

If you use ``typst_package`` and want the same behavior, opt in explicitly:
declare a ``lang`` parameter in your own wrapping template and set it
through ``typst_elements``, as shown below.
```
