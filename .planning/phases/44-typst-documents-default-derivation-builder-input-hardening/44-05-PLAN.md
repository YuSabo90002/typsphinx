<planning_measurements>
Measured by the planner in this session against HEAD `b20821d`, so the executor starts from facts
rather than re-deriving them. Every one of these is re-measurable; where a task re-measures, the
measured value wins over this table and the divergence is recorded.

1. **The value that actually determines the written path is NOT the bare stem.**
   `_resolve_output_stem` returns a basename-safe stem; `_directory_preserving_relpath(docname, stem)`
   then returns `stem` when `stem == docname`, else `posixpath.join(posixpath.dirname(docname),
   posixpath.basename(stem))`. Both `write_doc` (builder.py:517-521) and `TypstPDFBuilder.finish`
   (builder.py:974-976) join THAT value with `self.outdir`. `self.env.found_docs` holds full
   `/`-separated docnames. Therefore the collision comparison must be made on
   `self._directory_preserving_relpath(docname, stem)`, not on `stem` — comparing the bare stem would
   both miss nothing at root level and produce false positives for a nested docname whose basename
   happens to match a root-level docname.

2. **`_template.typ` exists only at the outdir ROOT.** `_write_template_file` writes
   `path.join(self.outdir, "_template.typ")` (builder.py:611) unconditionally, and
   `writer.py::_compute_template_import_path` (writer.py:77-119) documents and implements
   "climb from my own directory to the outdir root" — a nested master imports `../_template.typ`.
   So the reserved-name check applies to an effective relative path exactly equal to `_template`, and
   NOT to a nested `sub/_template`. `_directory_preserving_relpath` already makes a nested docname
   incapable of producing a root-level `_template`, so the single equality test is both necessary and
   sufficient.

3. **`self.env` is reachable from `_resolve_output_stem`, but a `found_docs` guard is still required.**
   Every unit test in `tests/test_builder_output_stem.py` constructs `TypstBuilder(app, app.env)` with
   a real (unbuilt) env, and `tests/conftest.py` also ships a `mock_builder` fixture whose `MockEnv`
   has no `found_docs` attribute at all. The house idiom for exactly this situation already exists in
   the same file: `toctree_includes = getattr(self.env, "toctree_includes", {}) or {}`
   (builder.py:142), alongside `getattr(self.config, "typst_documents", []) or []` (builder.py:183).
   Use `getattr(self.env, "found_docs", None) or set()`.

4. **The fallback degrades away from SC#1's promised shape, deliberately.** In the derived-default
   collision case the master is written as `index.typ` / `index.pdf`, NOT `<project>.typ`. That is a
   conscious trade: SC#1's filename shape is sacrificed only in the collision case, in exchange for
   not destroying a real document. The new tests must assert the degraded-but-safe outcome
   (`index.typ` present, the colliding document intact, a warning on the console) and must NOT assert
   SC#1's `<project>.typ` shape for these fixtures.

5. **No pre-existing fixture in this repo trips the new guard.** The planner scanned every non-`.venv`
   `conf.py` that mentions `typst_documents`, parsed each entry's `(source, target)` pair, computed
   the effective relative path, and compared it against the sibling `.rst`/`.md` docnames of that
   fixture and against `_template`: **0 collisions**. So the guard is expected to perturb no existing
   test. Task 3 re-measures this rather than trusting the number; if the re-measurement is non-zero,
   that is a real pre-existing defect to surface, never a reason to weaken the guard.

6. **The existing unit tests are unaffected by construction.** `("index", "index", …)` yields
   `stem == docname`, which the `effective != docname` condition skips; every other target in
   `tests/test_builder_output_stem.py` (`output`, `typsphinx`, `v1.2-manual`, `manual`, `マニュアル`)
   is absent from that fixture's `found_docs` (which contains `index` only, and is empty until a
   build runs).

7. **Warning arity.** In a `-b typstpdf` build the warning fires twice for the same master (once from
   `write_doc`, once from `finish`), because both call the single normalization site. This matches the
   pre-existing D-06/D-07 warnings' behaviour. Assert "the warning appears", never "exactly once".

8. **Out of scope, recorded not planned:** two explicit `typst_documents` entries naming the SAME
   target as each other (master-vs-master collision) is a different mechanism — neither stem is in
   `found_docs`, so this guard does not fire on it. 44-VERIFICATION.md's `missing:` list does not
   require it. Record it in `44-GATE-EVIDENCE-05.md` § 7 as a deferred observation.
