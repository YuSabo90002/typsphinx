## Outline depth interaction

This area was re-asked three times as measurement changed what the real options were.

**Round 1** — framed as "measure and file a todo / fix it here / do nothing". Initially answered
"do nothing, don't even record it", then re-opened by the user.

**Round 2** — the user reframed the problem: the flat outline was itself the defect, because it
disagreed with the HTML and LaTeX hierarchies; this phase restores the intended shape. They then
asked how LaTeX sets the document TOC depth. Measured and reported: Sphinx takes the master's first
toctree `:maxdepth:` into `doctree['tocdepth']`
(`sphinx/builders/latex/__init__.py:313-316`) and emits
`\setcounter{tocdepth}{tocdepth + top_sectionlevel - 2}` (`sphinx/writers/latex.py:448`), which for
the default `manual` theme is `maxdepth - 1` — i.e. N levels counted from the toctree'd document's
title, with the master's own title outside the count.

**Round 3** — the user proposed adding a new argument to the template function. Measured
consequence reported: `writer.py:260-261` merges the toctree options into the template call
unconditionally, and Typst rejects undeclared named arguments (verified: `unexpected argument`), so a
new parameter breaks correctly-written custom templates.

**Round 4** — the user observed that every other template parameter is something the author can
supply from `conf.py` (project, author), whereas `toctree_maxdepth` cannot be known there at all.
Following that thread produced a separate finding: the documented template contract
(`docs/source/user_guide/templates.rst:187-192`) omits the toctree parameters entirely, and the
documented example fails to compile on any project with a toctree — reproduced end to end.

| Option | Description | Selected |
|--------|-------------|----------|
| Redefine `toctree_maxdepth`'s meaning | Pass a resolved outline depth instead of the raw `:maxdepth:` | |
| Add a new parameter | Honest name; breaks custom templates that declare only the current three | |
| Fix the expression in `base.typ` | Non-breaking, master `.typ` untouched; custom templates unfixed | |
| Headings only this phase | Treat outline depth as out of scope | ✓ |

**User's choice:** Headings only — "outline の depth はテンプレートの一部として捉えるのが適切".
**Notes:** Consistent with the existing design statement in `templates/base.typ:3,79` and with the
measured fact that `outline` appears nowhere in `typsphinx/` outside that template. Both the LaTeX
mapping and the broken documented contract are preserved in CONTEXT.md `<deferred>` with their
measurements.

## Resolved-level verification mechanism

Claude proposed a three-way choice about where the helper and the new gate should live. The user
rejected it: "選択肢のトレードオフが見極められていない". On measurement this was correct — there was
no owner-level decision left:

- The mechanism is already fixed by SC#1/#2 (`typst.query` against a compiled document, not a grep).
- The scaffolding convention is established (`_run_sphinx_build_typst()`,
  `tests/fixtures/<name>_render_gate/`, session-scoped build-once fixtures).
- The `slow` marker has no practical trade-off: CI runs `tox` → `pytest tests/` (`tox.ini:22-23`)
  with no `-m` filter, so slow-marked tests run in CI anyway.

**Outcome:** no decision taken; recorded as Claude's Discretion in CONTEXT.md with the measured
starting points.

## Existing-assertion update policy

Claude's first framing ("mechanical substitution vs. convert to resolved-level assertions") was also
rejected — the user said the question did not make sense. It did not: converting mock-based unit
tests into build-and-compile tests was never a realistic option for a patch-release bug fix, and the
rest of the work is mandatory rather than discretionary.

Re-framed after enumerating the actual sites:

- 7 positive assertions — mechanical `level:` → `depth:`.
- 4 negative assertions (`assert "heading(level:" not in output`) — **must** also be rewritten, or
  they become vacuously true and silently stop detecting anything.
- 1 rationale comment (`tests/test_topics.py:161-162`) — SC#4 requires rewriting it.

| Option | Description | Selected |
|--------|-------------|----------|
| Approve | Approve as a policy; edits happen during planning, each traceable to TOC-01 and re-proved failing against the pre-fix commit | ✓ |
| Review each edit in the plan | Defer approval until PLAN.md lists all 12 before/after pairs | |

**User's choice:** Approve.
**Notes:** This is the owner sign-off SC#6 requires. It approves the policy, not specific text; the
pre-fix RED re-proof obligation stands.
