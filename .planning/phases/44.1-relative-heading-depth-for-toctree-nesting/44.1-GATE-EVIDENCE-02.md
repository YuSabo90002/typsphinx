## 2. Vacuity proof

**Command:**
```
grep -rl 'heading(level:' typsphinx/
```
**Output:** **(empty)** — exit code 1, no file matched.

**Why this makes the four negative guards vacuous, in one sentence:** since no path in
`typsphinx/` can currently emit the literal `heading(level:` (both `visit_title` emission sites
were rewritten to `heading(depth:` by plan 01), any assertion of the shape
`assert "heading(level:" not in output` is guaranteed to pass regardless of which code path
produced `output` — including a hypothetically broken translator that reintroduces a stray heading
emission on the topic/contents/clamp paths these four guards exist to protect, as long as that
regression also uses the (also-real) `depth:` keyword.

**Actual pass/fail split, this session:**
```
uv run pytest tests/test_topics.py -v
```
```
2 failed, 3 passed in 0.55s
FAILED tests/test_topics.py::TestTitleLevelClamp::test_title_at_section_level_zero_clamps_to_one - assert 'heading(level: 1' in '#{\nheading(depth: 1, {text("Top Level Title")})\n\n}\n'
FAILED tests/test_topics.py::TestTitleLevelClamp::test_title_with_multiple_children_in_heading_form_does_not_concatenate - assert 'heading(level: 1, {' in '#{\nheading(depth: 1, {text("Mixed ")\nemph({text("Emphasis")})})\n\npar({text("Section body.")})\n\n\n}\n'
```
Exactly the two **positive**-assertion tests fail (176, 208 — both search for the now-absent
`level:` literal and correctly go RED). The three tests carrying only negative guards
(`test_topic_converts_to_clue_box`, `test_topic_title_with_multiple_children_does_not_concatenate`,
`test_contents_topic_renders_boxless_bold_label`) and the negative half of the clamp test all
**pass** — not because the behaviour they protect still holds under scrutiny, but because the
literal they search for cannot be produced by any code path any more. **Conclusion:** each of the
four negative guards (62, 96, 141, 177) passes for a reason that has nothing to do with the
behaviour it was written to protect, and would keep passing even if the topic/contents
buffer-swap early return in `visit_title` were deleted outright — deleting that return would make
the translator fall through to the generic section-heading path and emit a REAL
`heading(depth: N, ...)` call for a topic/contents title, which none of these four guards would
catch, because none of them searches for `heading(depth:` at all today.

**Reasoning for the split, recorded:** the four negative guards (62, 96, 141, 177's negative half)
all sit on translator paths that emit no section heading at all, on either side of the
`level:`->`depth:` rewrite — the buffer-swap early return for topic/contents titles, and the
`max(1, ...)` clamp floor for the zero-level case. A `git checkout <anchor SHA> --
typsphinx/translator.py` changes only what the generic section-heading path emits; it cannot make
any of these four assertions fail, because the paths they guard were never reached by that
emission change. Manufacturing a RED for them — e.g. by temporarily deleting the buffer-swap
early-return just to make the guard fail once — would be exactly the laundered evidence D-04
exists to prevent: it would prove something about a DIFFERENT, deliberately-broken translator, not
about the pre-fix commit. The positive control (same-session proof that the same translator DOES
produce the searched literal on a DIFFERENT path) is the honest substitute: it shows the literal
carries information about SOMETHING, even though that something is not "this specific guard's
path, before this specific fix."
