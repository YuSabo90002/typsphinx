<planner_measurements>
All four measurements below were taken during planning on 2026-08-04 against the repo venv
(typst-py 0.15.0) at `a16deee`. Re-verify before transcribing any of them into an assertion.

**M1 — nested scopes do not accumulate today.** A minimal Typst document with a heading at depth 1,
then a scope opening `set heading(offset: 1)` containing a heading at depth 1, then a further nested
scope opening `set heading(offset: 1)` containing a heading at depth 1, queries as levels
`[1, 2, 2]`. The inner scope's offset **replaced** the outer one. `set` is an absolute assignment on
the style chain, not an increment.

**M2 — a context-relative increment does accumulate.** The same document with each scope written as
`context { set heading(offset: heading.offset + 1); ... }` queries as `[1, 2, 3]`.

**M3 — M2 holds through real `include()` calls, not just inline headings.** Applying both
substitutions (the plan-01 heading keyword, and the offset expression) to the already-built `.typ`
output of `tests/fixtures/integration_nested_toctree` in a scratch copy, then querying the master,
gives the full sequence `[1, 1, 1, 2, 3, 4, 3, 4]` for the headings
`(template caption, Contents, "Nested Toctree Test", "Chapter 1", "Section 1", "Content of section 1",
"Section 2", "Content of section 2")`. That is SC#1 **and** SC#2 met simultaneously. With plan 01's
change alone the same sequence is `[1, 1, 1, 2, 2, 3, 2, 3]` — "Section 1" stuck at 2.

**M4 — what the change would cost.** `grep -rn 'heading(offset' typsphinx/` returns exactly three
sites, all in `typsphinx/translator.py`: `:4724` and `:4729` are prose inside `visit_toctree`'s
docstring describing the emitted form, and `:4762` is the single emission
(`self.add_text("  set heading(offset: 1)\n")`). `templates/base.typ` contains **no** offset site at
all — it sets only `heading(numbering: "1.1")` at `:65` — which independently discharges SC#8's
template half. Two test sites assert the current emitted text:
`tests/test_toctree_requirement13.py::test_toctree_with_heading_offset` (line 83-110, asserting the
literal scope text is present) and `::test_toctree_heading_offset_appears_once` (line 231-265,
asserting a regex over the same literal matches exactly once). Both would fail under option A and
would need their literal updated; `44.1-CONTEXT.md` predicted they need no edit, which is true only
under option B.

**Scope conflict this plan exists to resolve.** `44.1-CONTEXT.md` locks the repair to `visit_title`
and states `visit_toctree` "is NOT changed — it merely becomes effective for the first time". That
lock's stated rationale (that nested scopes would then accumulate) is falsified by M1. ROADMAP SC#2
requires level 3. The planner has no authority to drop SC#2 and no authority to widen a locked
scope, so the decision goes to the owner with the measurements attached.
