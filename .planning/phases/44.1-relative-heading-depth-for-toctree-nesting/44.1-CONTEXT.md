# Phase 44.1: Relative Heading Depth for Toctree Nesting - Context

**Gathered:** 2026-08-04
**Status:** Ready for planning

<domain>
## Phase Boundary

Make a document reached through a `toctree` render its headings one level deeper than its parent, so
the PDF outline nests instead of being flat. One requirement: **TOC-01**.

The repair itself is already locked by ROADMAP.md and REQUIREMENTS.md and is NOT re-opened here:
`visit_title` emits `heading(level: N, …)`; in Typst `level:` is the final absolute level and
overrides the ambient `set heading(offset: …)`, so the `offset: 1` that `visit_toctree` wraps its
`include()` calls in (`translator.py:4762`) is inert. Only `depth:` is relative
(`offset + depth`). The fix is to emit `depth:` in `visit_title`.

Re-verified during this discussion against the pinned typst-py 0.15.0, not taken on trust:

```
set heading(offset: 2)
heading(level: 1, …)  → typst.query(…, 'heading', field='level') → 1   (offset ignored)
heading(depth: 1, …)  → 3                                             (offset + depth)
```

**Not in this phase:**
- The `outline(depth: …)` mapping in the master template (D-03 below — treated as a template-level
  concern, deferred with its measurements).
- Anything about `typst_documents` derivation (Phase 44, shipped).
- The README / changelog documentation work (Phase 45).

</domain>

<decisions>
## Implementation Decisions

### SC#3 — proving master documents are unchanged

- **D-01: ROADMAP.md's SC#3 text must be rewritten before planning.** The clause "byte-identical
  `.typ` for every master document" is unsatisfiable under the locked repair. Measured: master
  documents emit the same heading call as included ones, so the `level:` → `depth:` substitution
  lands in master output too. `docs/_build/pdf/typsphinx.typ` carries four of them (lines 23, 30,
  86, 140), e.g.
  `[#heading(level: 1, {text("typsphinx Documentation")}) <index:typsphinx-documentation>]`. What is
  invariant is the *resolved level* (master renders at `offset: 0`, so `depth == level`), not the
  byte sequence. Owner decision: edit the SC#3 wording in ROADMAP.md rather than leaving it to be
  superseded implicitly, because `gsd-verifier` reads the ROADMAP SC text directly and would return
  NOT-MET against an unsatisfiable criterion.
  — **Reversibility:** reversible — planning-document text.

- **D-02: The SC#3 evidence stacks both proofs.** (a) *Resolved-level invariance* — compile each
  master before and after and assert the `typst.query(…, 'heading', field='level')` sequence is
  identical. (b) *Normalized byte invariance* — apply the mechanical `heading(level:` →
  `heading(depth:` substitution to the pre-fix `.typ` files, then diff against post-fix and assert
  zero remaining difference. (a) shows the rendering does not move; (b) shows the change did not
  leak anywhere beyond the heading keyword. Neither alone is sufficient: (a) would miss a
  non-heading diff, (b) would not show that the substituted text still resolves the same.
  — **Reversibility:** reversible — evidence-gathering scope.

  Corpus is small, measured: `tests/roots/` contains exactly **one** root (`test-basic`), and
  `docs/source` contains **13** `.rst` files. No scope negotiation was needed.

### Outline depth (deliberately out of scope)

- **D-03: The outline-depth mapping is NOT changed in this phase.** The `outline(depth: …)`
  expression is a template-level concern. Owner framing: the flat outline was the defect — it
  disagreed with the HTML and LaTeX
  hierarchies — and this phase restores the intended shape; how deep the rendered table of contents
  goes belongs to the template. This is consistent with the existing design statement in
  `templates/base.typ:3` and `:79` ("#outline() managed at template level, not in body") and with the
  measured fact that `outline` appears nowhere in `typsphinx/` except that template. The known
  consequence is accepted and recorded in `<deferred>` with its measurements.
  — **Reversibility:** reversible — no code is written for it here.

### Test updates (SC#6 owner sign-off)

- **D-04: The owner approved the test rewrite in this discussion. 12 sites change.** The categories,
  enumerated from the repo (not estimated):
  - *Positive assertions, 7* — `tests/test_translator.py:83,97,2199`, `tests/test_topics.py:176,208`,
    `tests/test_pdf_render_gate.py:2766`, and the golden fixture
    `tests/fixtures/desc_rubric_decoupling_render_gate/golden.typ:20`. Mechanical `level:` → `depth:`.
  - *Negative assertions, 4* — `tests/test_topics.py:62,96,141` (`assert "heading(level:" not in
    output`) and `:177` (`assert "heading(level: 0" not in output`). **These must be rewritten too, or
    they become vacuously true and silently stop detecting anything**, because after the fix the
    string `heading(level:` never appears in any output. This is the highest-risk item in the set and
    the one a mechanical find-and-replace of positive assertions would miss.
  - *Rationale comment, 1* — `tests/test_topics.py:161-162` states the clamp exists because Typst
    rejects `level: 0`. SC#4 requires rewriting it: `depth` is likewise `>= 1`, so the `max(1, …)`
    clamp survives, but not for that reason.

  Approved as a policy, with the edits themselves made during planning/execution. Each edit is
  traceable to TOC-01 and each new assertion must be proved failing against the pre-fix commit
  before being accepted — no value observed in a post-fix run may be transcribed into an assertion
  without that proof.
  — **Reversibility:** reversible — test text.

- **D-05: Unit tests stay unit tests.** The 7 positive sites keep asserting on the emitted string;
  they are not promoted to build-and-compile tests. `tests/test_translator.py` and
  `tests/test_topics.py` run against a mock builder with no Typst compile, and converting them would
  add fixtures and runtime out of proportion to a patch-release bug fix. The *resolved-level*
  contract (SC#1/#2) is carried by the new gate instead, not by these files.
  — **Reversibility:** reversible — the promotion could be done later per test.

## Specific Ideas

Everything below was measured in this session against the repo venv (Sphinx 9.1.0, typst-py 0.15.0).
It is evidence the researcher should build on, not re-derive.

**1. `level:` vs `depth:` under an ambient offset, re-verified.** A two-heading document under
`set heading(offset: 2)` queried with `typst.query(…, 'heading', field='level')` returns `[1, 3]` —
`level: 1` stays 1, `depth: 1` resolves to 3.

**2. The current docs corpus, showing exactly what shifts.** From the committed build output:

| file | role | emitted today | resolves to after the fix |
|---|---|---|---|
| `docs/_build/pdf/typsphinx.typ:23,30,86,140` | master | `level: 1`, `level: 2`, `level: 2`, `level: 1` | 1, 2, 2, 1 (unchanged, `offset: 0`) |
| `docs/_build/pdf/quickstart.typ:12,16,79,126,152` | included (offset 1) | `level: 1`, then four `level: 2` | 2, then 3 |
| `docs/_build/pdf/user_guide/index.typ:12,20,41` | included, and itself contains `set heading(offset: 1)` at `:17` | `level: 1`, `level: 2`, `level: 2` | 2, 3, 3; its grandchildren reach `offset: 2` |

**3. Master output is not byte-invariant** — see D-01. The four master heading sites above are the
proof.

**4. Test-assertion census** (excluding `docs/_build/`, which is build output): 13 occurrences of the
literal `heading(level:` across 4 files — `tests/test_topics.py` 8, `tests/test_translator.py` 3,
`tests/test_pdf_render_gate.py` 1, `tests/fixtures/desc_rubric_decoupling_render_gate/golden.typ` 1.
Of these, 2 are inside one docstring (`test_topics.py:161-162`), giving the 12 edit sites of D-04.

**5. `typst.query` has zero existing uses in `tests/`** — all 16 existing render gates end in pypdf
text extraction. The resolved-level check is a new technique for this suite.

**6. CI runs everything** — `.github/workflows/ci.yml` invokes `uv run tox -e <env>`, and
`tox.ini:22-23` runs `pytest {posargs:tests/}` with no `-m` filter. `pyproject.toml` registers the
`slow` marker but `addopts` is only `-v --strict-markers`.

<deferred>
## Deferred Ideas

- **`outline(depth: …)` does not track the toctree hierarchy the way LaTeX does.** Out of scope per
  D-03; recorded here with its measurements so whoever picks it up does not have to redo them.

  Measured in Sphinx 9.1.0: `sphinx/builders/latex/__init__.py:313-316` takes the master's first
  toctree `:maxdepth:` into `doctree['tocdepth']`; `sphinx/writers/latex.py:448` emits
  `\setcounter{tocdepth}{document['tocdepth'] + top_sectionlevel - 2}`. For the default `manual`
  theme, `latex_toplevel_sectioning` is unset so `top_sectionlevel = 1` and `sectionnames` is the
  full 7-element `LATEXSECTIONNAMES`, so the `+1` branch at `:451-453` does not fire — i.e.
  **`tocdepth = maxdepth - 1`**. In LaTeX's absolute units (chapter 0, section 1, subsection 2) that
  means `:maxdepth: N` shows exactly N levels *starting at the toctree'd document's title*, with the
  master's own title on the title page and outside the count.

  typsphinx differs structurally: the master's own title is emitted into the body as a level-1
  heading (`docs/_build/pdf/typsphinx.typ:23`) *in addition to* the template's title page
  (`templates/base.typ:67-74`). So after this phase, an included document's title sits at level 2 and
  its sections at level 3, and the LaTeX-equivalent expression is `outline(depth: maxdepth + 1)`.
  With today's `outline(depth: toctree_maxdepth)` and `maxdepth: 2`, the rendered TOC will show
  included document titles but not their sections. The current mapping only looked correct because
  the flat headings cancelled the error out.

  Three implementation routes were measured, if it is ever taken up: change the expression inside
  `templates/base.typ:84-87` (nothing else changes, master `.typ` untouched, custom templates
  unaffected and unfixed); change the value `template_engine.extract_toctree_options()` passes
  (`template_engine.py:548-553`, which also maps `:maxdepth: -1` → `None`) so custom templates get it
  too, at the cost of the variable no longer meaning `:maxdepth:` and of a one-line diff in every
  master `.typ`; or add a new template parameter, which is the breaking option — see the next item.

- **The documented custom-template contract is wrong, and the documented example does not compile.**
  Found while evaluating the previous item; unrelated to TOC-01 and out of scope here.
  `docs/source/user_guide/templates.rst:187-192` states a template function receives `title`,
  `authors`, `date`, `body`. But `typsphinx/writer.py:260-261` merges
  `extract_toctree_options()` into the parameters unconditionally, so any master with a toctree also
  receives `toctree_maxdepth`, `toctree_numbered`, `toctree_caption`. Typst rejects undeclared named
  arguments (verified: `unexpected argument: outline_depth` on a minimal case), and neither
  `base.typ`'s `project()` (`:39-49`) nor the documented example declares an argument sink.

  Reproduced end to end: a project using the `templates.rst:144-149` example verbatim, with a
  `:maxdepth: 2` toctree, fails with
  `ExtensionError: typstpdf: 1 master document(s) failed: index: Typst compilation failed:
  TypstError: unexpected argument: toctree_maxdepth`. The in-repo example
  `docs/source/_typst/custom_template.typ:68-70` does declare all three, which is why the project's
  own docs build works. Either the documentation or the parameter passing is wrong; this also means
  adding any new template parameter is a breaking change for correctly-written custom templates.
