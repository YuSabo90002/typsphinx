## 3. SC#3(a) result — resolved-level invariance

**The one interpretive decision SC#3(a) forces, recorded rather than applied silently:** `typst
.query` follows Typst's `include()`, so querying a master with a toctree necessarily returns its
children's headings too — exactly what this phase moves. Read literally over the *composed*
document, "identical level sequence before and after" cannot hold (and is not expected to: the
composed sequence for the docs-corpus master changes at 150 of its 156 positions, per § 3's A2
below). The satisfiable reading — SC#3's own next sentence in ROADMAP.md, "the master renders at
offset: 0, so depth == level there" — is that the **master's own** headings are invariant. Both
readings are discharged and recorded, per this plan's own instruction; A1 is the pass/fail
criterion, A2 is the evidence that A1 is not invariance-by-nothing-happening.

### A1 — the master's own headings, isolated by stubbing

**Stubbing transform, applied identically to both sides:** copy the build output tree; for every
`.typ` file EXCEPT the master and `_template.typ`, truncate to empty (`write_text("",
encoding="utf-8")`); query the (now-stubbed) master.

**`_template.typ` is deliberately excluded from stubbing** — an interpretive decision recorded
here rather than applied silently. The master reaches it via `#import "_template.typ": project`
(a Typst **import**, needed to define the `project()` function the master's own `#show:
project.with(...)` show rule calls in order to compile AT ALL), not via toctree `#include()` — the
composition mechanism this phase's fix actually changes. Emptying it would remove the `project`
symbol the import statement names and abort compilation with an unresolved-import error, which is
not "isolate the master's own heading sites," it is "make the master fail to build." Every file
reached by an actual `include(...)` call (confirmed by `grep -n 'include(' <master>.typ`) IS
stubbed.

**Docs corpus** (`typsphinx.typ`, has a toctree — 10 direct `include()` calls confirmed by grep:
`installation.typ`, `quickstart.typ`, `user_guide/index.typ`, `user_guide/configuration.typ`,
`user_guide/builders.typ`, `user_guide/templates.typ`, `examples/index.typ`, `api/index.typ`,
`contributing.typ`, `changelog.typ` — plus 2 more nested one level deeper inside
`examples/index.typ`'s own toctree: `examples/basic.typ`, `examples/advanced.typ`; **12 files
stubbed**, matching the 12-non-master-non-template count exactly):

|---|---|---|
| pre-fix  | `[1, 1, 1, 2, 2, 1]` | `(1,''), (1,'Contents'), (1,'typsphinx Documentation'), (2,'Key Features'), (2,'Quick Links'), (1,'Indices and tables')` |
| post-fix | `[1, 1, 1, 2, 2, 1]` | *identical* |

**Identical: yes.**

**test-basic corpus** (`output.typ`, **no toctree at all** — confirmed: 0 `include()` calls; A1
stubbing truncates zero files, since the only other `.typ` in the build is `_template.typ`, which
is excluded by the rule above):

|---|---|

**A1 verdict: both masters (the one with a toctree and the one without) show an identical resolved
