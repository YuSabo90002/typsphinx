<objective>
Implement the Python-side `typst_elements` pass-through for `papersize`/`fontsize` (CONF-04). Add a raw-Typst marker so a length value emits unquoted, a curated `ELEMENTS_ALLOWLIST` constant, a new `typst_elements` keyword argument to `map_parameters()` that merges the allowlist additively and raises loudly on any unknown key, and rewire `writer.py` to pass `typst_elements` separately (no more laundering it through the Sphinx-metadata dict) while dropping the now-dead `copyright` key.

Purpose: close a laundering bug — today `writer.py` does `sphinx_metadata.update(typst_elements)`, and `map_parameters()` only emits keys in `DEFAULT_PARAMETER_MAPPING` (project/author/release), so `papersize`/`fontsize` (and `copyright`) are silently dropped. This plan makes the two `project()`-declared element keys reach the emitted `#show: project.with(...)` with correct per-key typing, keeps baseline metadata structurally out, and leaves `templates/base.typ` byte-unchanged.

Output: edited `template_engine.py` + `writer.py`, plus unit tests proving the merge/raise/typing/non-leak behaviors at the `map_parameters()`/`_format_typst_value()` level (the real-compile GATE-01 fixtures are Plan 02, Wave 2).
</objective>
