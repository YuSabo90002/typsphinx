## Measured findings this plan is built on (do not re-derive)

All measured this planning session, on Python 3.13.13, against the current tree.

**Finding 1 — the predicate ROADMAP SC#4 names does not close BLD-09.** SC#4 locks
`posixpath.isabs(…) or _is_drive_qualified(…)` and, in the same sentence, requires that a
driveless-absolute Windows URI reach the rehome branch. Those two clauses disagree:

| `resolved_uri` | OS-native on Windows | `posixpath.isabs` | `_is_drive_qualified` | SC#4's literal predicate | with backslashes normalized first |
|---|---|---|---|---|---|
| driveless-absolute Windows, e.g. a leading separator then `typsphinx_test` then `chart.png` | False (3.13) | False | False | **False** | **True** |
| drive-qualified Windows | True | False | True | True | True |
| POSIX-absolute | False | True | False | True | True |
| UNC, two leading separators then `server` then `share` | True | False | False | **False** | **True** |
| ordinary relative, `images/chart.png` | False | False | False | False | False |

The sibling `_escapes_outdir()` has the same latent gap for the same reason — it normalizes
backslashes for its parent-traversal split but calls `posixpath.isabs()` on the RAW stem, so
`_escapes_outdir` returns False for a driveless-absolute Windows stem today.

**Finding 2 — the consequence is a write outside `outdir`, not just a missing rehome.** When the gate
is skipped, `img["uri"]` keeps the rooted URI and reaches `copy_image_files()`, which computes
`path.join(self.outdir, imguri)`. On Windows that join discards `outdir` for a rooted second argument:
joining an output directory on the `C:` drive with a rooted driveless path yields a path at the drive
root. That is why the threat register below rates this `high`.

**Finding 3 — IMG-03's collateral is two currently-GREEN assertions.**
`test_post_process_images_rehome_escape_relocates_with_warning` and
`test_post_process_images_rehome_cross_drive_value_error_relocates` in `tests/test_builder.py` each
assert an exact escape-branch key. They are NOT IMG-03's RED evidence — they characterize the key
SHAPE, which the fix changes. Both fixtures build their URI from a temporary directory, so the updated
assertions must COMPUTE the expected key, never embed a digest literal.

**Finding 4 — no lint suppression is needed for the digest.** This project's ruff selection does not
include the security rule set, so the digest call is not flagged. It is a non-cryptographic
collision-avoidance key over a build-local path string and carries no security property; say so in the
docstring so a future reader with a stricter scanner does not "harden" it into something
process-dependent.
