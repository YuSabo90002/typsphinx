# Phase 44.2: `typst_documents` Title and Author Consumption - Context

**Gathered:** 2026-08-05
**Status:** Ready for planning

<domain>
## Phase Boundary

Make an explicit `typst_documents` entry's `[2]` title and `[3]` author actually reach the rendered
document, as they do in Sphinx's LaTeX builder, instead of being silently ignored while
`config.project` / `config.author` win. Define and test the precedence for every combination that
can occur, and leave no element of the published five-element contract silently inert.

One requirement: **CONF-09**. It reverses Phase 44's D-02, which had deferred this consumption out
of v0.7.1 (owner decision 2026-08-04, recorded in `44-CONTEXT.md`'s superseded note and in
`ROADMAP.md` §Roadmap Evolution).

Not in this phase:

- **Deleting `typst_authors`.** Only its precedence against `entry[3]` is decided here (D-05).
  The deletion itself becomes a Future Requirement (D-06).
- **The duplicate-target defect** (`.planning/todos/pending/2026-08-04-duplicate-typst-documents-target-silently-drops-a-master.md`,
  severity `high`, `resolves_phase: TBD`). It touches the same `typst_documents` surface and the
  same `_resolve_output_stem` method, but it is about two entries sharing a *target name*, not
  about title/author. Do not widen into it.
- **`templates.rst:186-192`.** Its claim that `title` comes "from `typst_documents`" becomes true
  when this phase lands; `ROADMAP.md` assigns Phase 45.1's SC#2 the job of *checking* that claim
  rather than rewriting it. This phase must not edit that file.
- **README Quick Start / the changelog page** — DOC-11 / DOC-12, Phase 45.

</domain>

<decisions>
## Implementation Decisions

Every measurement below was taken during this discussion on the current tree (Sphinx 9.1.0,
typst-py 0.15.0) unless a different date is stated.

### Element semantics — present, absent, empty, non-`str`

- **D-01: An empty-string `entry[2]` / `entry[3]` is a value, not a signal to fall back.** It
  renders as an empty title / empty author. This matches the reference implementation: Sphinx's
  `LaTeXBuilder.write_documents()` destructures `docname, targetname, title, author, themename =
  entry[:5]` and assigns `title` / `author` straight into `docsettings._title` / `docsettings._author`
  — no fallback branch exists anywhere in that path. Measured that an empty value is not a build
  breaker: a real `-b typstpdf` build of `typst_documents = [('index', 'out.typ', '', '')]` with
  `title: ""` / `authors: ()` hand-injected into the emitted `out.typ` compiles through
  `typst.compile()` to a 14587-byte PDF (versus 17109 bytes with values); only the title block goes
  blank.
  — **Reversibility:** reversible — one condition in the lookup helper.

- **D-02: A missing element or `None` falls back silently to `config.project` / `config.author`; a
  non-`str` element emits a `logger.warning` and then falls back.** This mirrors the guards already
  in `builder.py`: `_resolve_output_stem` passes an unmatched docname through silently
  (`builder.py:201`) but warns before falling back on a degenerate target (`builder.py:240`, `:259`,
  `:279`), and BLD-01's non-`str` docname warns and skips (`builder.py:986-999`). Measured reason the
  non-`str` case cannot be passed through: `_format_typst_value`'s `int`/`float` branch
  (`template_engine.py:684-685`) emits `title: 123` **unquoted**, and Typst's `document(title:)`
  requires a string or content, so the compile aborts.
  — **Reversibility:** reversible — local to the lookup helper.

### Scope of the override

- **D-03: The override applies uniformly to every template route.** Measured, the routes are
  determined by exactly four sites — `resolve_package_for_engine()` (`template_engine.py:176`),
  `resolve_template()`'s three-priority walk (`:274-330`), `_write_template_file()`'s early return
  (`builder.py:615`), and `writer.py:288` — and they yield four template-source routes:

  | | Config | Template actually used |
  |---|---|---|
  | A1 | nothing set | bundled `typsphinx/templates/base.typ` → written as `_template.typ` |
  | A2 | nothing set, but `<srcdir>/base.typ` exists | that user file → `_template.typ` (Priority 2 search hit; `template_name` defaults to `"base.typ"`, `template_engine.py:232`) |
  | A3 | `typst_template` | that custom file → `_template.typ` |
  | A4 | `typst_package` | no template file at all; `#import "@preview/…": *` only |

  `typst_package` **and** `typst_template` together is not a fifth route: `builder.py:603-608` warns
  once and `resolve_package_for_engine` suppresses the package, so it collapses into A3/A4's
  template half.

  The implementation that achieves uniformity is substituting `project` / `author` inside the
  `sphinx_metadata` dict built at `writer.py:212-216`. Measured reason this reaches all four:
  `map_parameters`' mapping loop (`template_engine.py:422-430`) runs **before** the
  `if not self.typst_package` back-fill guard (`:436`), so `project→title` / `author→authors` already
  reaches A1–A4 today. Substituting at that level also keeps a user's `typst_template_mapping`
  remapping working unchanged (e.g. `project → document_title`, exercised by
  `tests/test_config_template_mapping.py:130`), and introduces **no new template parameter**, so it
  cannot produce the undeclared-kwarg compile fatal that CONF-07's D-06 existed to prevent.
  — **Reversibility:** reversible — one dict construction in `writer.py`.

- **D-04: `typst_template_function`'s dict-form `params` still win over the entry values.** Owner's
  stated rule: *"typst_documents で渡す引数はあくまで標準呼び出し関数の引数を指定するものであって、
  ユーザーが具体的に関数と引数を指定しているのであればその決定を上書きすべきでない"* — the entry
  elements specify arguments for the standard call; a user who has named both the function and its
  arguments has already made a more specific decision. This needs **no new code**: `render()`'s
  existing D-08 merge (`template_engine.py:643-646`) applies `all_params.update(params)` then
  `all_params.update(self.typst_template_params)`, so explicit config already lands last.
  — **Reversibility:** reversible — it is the absence of a change.

- **D-05: `entry[3]` beats `typst_authors`.** Today `typst_authors` overwrites `params["authors"]`
  unconditionally at the tail of `map_parameters` (`template_engine.py:456-460`, D-07), on both the
  package and template paths. That order inverts. Measured side effect: the combination
  `typst_authors` + bundled `base.typ` currently produces **no PDF at all** — a real `-b typstpdf`
  build emits `authors: ((name: "Jane Doe", organization: "MIT", email: "jane@mit.edu"),)` and
  `base.typ`'s `set document(author: authors)` fails with `TypstError: expected string, found
  dictionary`, surfacing as the aggregate `ExtensionError` at `builder.py:1037`. Letting `entry[3]`
  win means that combination starts producing a PDF again. The pre-existing defect is **not** fixed
  here for a `typst_authors`-only project; it is recorded in Deferred Ideas.
  — **Reversibility:** reversible — the order of two assignments.

### `typst_authors`' future

- **D-06: `typst_authors` is to be removed, but not in this phase — a Future Requirement is filed
  instead.** Owner decision: 44.2 decides only the precedence (D-05); the removal is a separate
  phase because it is a breaking change and v0.7.1 is a patch release already carrying two
  user-visible changes (CONF-08's filename rename and CONF-09's title/author change, both of which
  REL-06 requires the CHANGELOG to call out). The receptacle is a new entry under
  `.planning/REQUIREMENTS.md` §"Future Requirements" (alongside `CFG-01`, `CONF-06`, …). **This
  phase's plan includes writing that entry**, carrying the measurement below.

  Measured basis for the removal being lossless: `typst_authors` is pure sugar over
  `typst_template_function["params"]["authors"]`. Rendering the same author dict through both routes
  produces `authors:` values that are **byte-identical**; the only diff is the order of named
  arguments in the emitted `#show:` call, which is semantically irrelevant in Typst:

  ```
  --- typst_authors            +++ typst_template_function params
   #show: ieee.with(
  +  paper-size: "a4",
     authors: ((name: "John Doe", department: "Computer Science", organization: "MIT", location: "Cambridge, MA", email: "john.doe@mit.edu"),),
  -  paper-size: "a4",
   )
  ```

  Both go through the same `_format_typst_value` list/dict recursion. The one capability that
  disappears is passing rich authors *without* setting `typst_template_function` at all — and that
  combination is exactly the one measured broken in D-05, so nothing usable is lost. The removal
  phase must also rewrite `examples/charged-ieee/approach1/conf.py:37`, whose `typst_authors` block
  moves into its already-present `typst_template_function` dict at `:56`.
  — **Reversibility:** reversible — a Future Requirements entry, not a code change.

### The in-repo entries (SC#4)

- **D-07: Every divergent in-repo entry is left as-is and its output is allowed to change.** No
  `conf.py` is edited to make `entry[2]` match `project`. The changed output becomes SC#4's measured
  evidence, and the divergent fixtures themselves become proof the feature works. Existing test
  assertions are updated to the new values — at minimum
  `tests/test_config_template_mapping.py:156`, which asserts `"Test Project" in content` while that
  test's own conf sets `typst_documents = [('index', 'index', 'Test', 'Author')]` at `:136`; it goes
  RED the moment the entry wins.
  — **Reversibility:** reversible — fixture edits.

- **D-08: SC#4's "identical output" set is redefined by three conditions, because ROADMAP's count is
  wrong.** ROADMAP §Phase 44.2 says "of 104 `typst_documents` entries … only 5 have
  `entry[2] != project`" and SC#4 says "the other 99 entries are shown to produce identical output".
  Re-measured by AST-walking every `conf.py` in the repo:

  - **83** entries parse (not 104 — that figure counted textual occurrences); **all 83 are 4-tuples**,
    zero have a fifth element.
  - **5** have `entry[2] != project`: `tests/roots/test-basic/conf.py[0]`,
    `tests/fixtures/integration_basic/conf.py[0]`, `tests/fixtures/integration_sibling/conf.py[0]`,
    `tests/fixtures/template_named_dir_master/conf.py[1]`, `examples/advanced/conf.py[0]`.
  - **0** have `entry[3] != author` — the author side diverges nowhere in the repo.
  - Beyond `conf.py`, **72** inline `typst_documents = [` occurrences live in test source and docs.
    At least three more test-inline entries diverge: `tests/conftest.py:92`, `tests/test_config.py:36`
    (`'Test Document'` vs `project='Test Project'`), and
    `tests/test_config_template_mapping.py:27` / `:136`.

  More importantly, **`entry[2] == project` is not sufficient for "unchanged"**, because D-05 flips
  the `typst_authors` order and D-04 leaves B3 params winning. The correct condition is
  **`entry[2] == project` AND `entry[3] == author` AND `typst_authors` unset**. Sites that satisfy
  the first two but still change: `examples/charged-ieee/approach1/conf.py:37` and the
  `typst_authors`-injecting assertions in `tests/test_package_only_config_gate.py` (`:142`, `:246`,
  `:392`, `:476-482` — the last explicitly asserts that removing `typst_authors` changes the emitted
  authors value) and `tests/test_template_engine.py:928` / `:964`.

  This phase's artifacts state the corrected numbers and the corrected condition rather than
  repeating ROADMAP's.
  — **Reversibility:** reversible — it is a definition in this phase's evidence, not code.

- **D-09: The partition is proved by static walk; only the entries that fail the three conditions get
  a real build.** The satisfying set is argued (identical values into `map_parameters` ⇒ identical
  output), not built. Measured feasibility: the AST walk over all 83 entries completes in seconds.
  Rejected: applying Phase 42's `GATE-EVIDENCE-05` two-build byte-invariance method (`git archive`
  an old tree, assert `typsphinx.__file__` resolves into it, plus a positive control) across all of
  `docs/source` and `tests/roots` — the rigor is not worth the build time here, since the argument's
  premise is a value-equality check that the walk itself establishes.
  — **Reversibility:** reversible — widening to real builds later costs only time.

### The fifth element (SC#5)

- **D-10: `entry[4]` is accepted-and-ignored, and `configuration.rst` says so explicitly.** No code
  change. Measured asymmetry that makes this worth stating: **zero** in-repo `conf.py` entries carry
  a fifth element, while **all 10** published examples in `docs/source` do —
  `quickstart.rst:82`, `user_guide/configuration.rst:30`, `user_guide/builders.rst:108`,
  `user_guide/templates.rst:24`, `examples/basic.rst:19` and `:223`, `examples/advanced.rst:126`,
  `:206`, `:355`. So every reader who copied the Quick Start writes a fifth element that nothing
  reads. The only fifth-element producer in the codebase is `_default_typst_documents`
  (`builder.py:39-47`), which hardcodes the literal `"typst"`.

  Noted but deliberately not acted on: the reference implementation puts a **config value** there —
  `default_latex_documents` uses `config.latex_theme` (registered with default `'manual'`), and
  `write_documents()` looks it up via `self.themes.get(themename)`, so LaTeX's fifth element has both
  meaning and validation. Giving typsphinx's fifth element equivalent meaning would mean adding a
  `typst_theme`-style config, which is outside CONF-09.
  — **Reversibility:** reversible — a documentation sentence; giving the element meaning later does
  not conflict with having documented it as ignored.

- **D-11: `configuration.rst` also publishes the precedence rules decided here, and warns that
  `typst_authors` will be removed.** The five-element contract section (`:41-46`) gains the
  accepted-and-ignored note for element 5 plus the resolution order (entry value → `config.project` /
  `config.author`; empty string is a value; `entry[3]` beats `typst_authors`;
  `typst_template_function`'s `params` beat everything). The `typst_authors` sections (`:154`,
  `:276`) gain the new precedence **and** a forward notice that the setting is fully replaceable by
  `typst_template_function`'s `params["authors"]` and is slated for removal in a future major
  release — the byte-identical measurement from D-06 can be shown there. No deprecation warning is
  emitted in code (D-06), so this stays a documentation change and does not add a third breaking
  change to a patch release.

  Rationale for landing this here rather than in Phase 45: `configuration.rst`'s precedence text is
  not assigned to any requirement — DOC-11 covers the README Quick Start and DOC-12 the changelog
  page — so leaving it out would recreate the exact defect this phase exists to fix, documented
  behaviour diverging from actual behaviour.
  — **Reversibility:** reversible — documentation text.

### Claude's Discretion

Deliberately left to research and planning. The owner did not select these; nothing is locked, and
the planner should choose on measured grounds.

- **Which layer performs the entry lookup, and its signature.** D-03 fixes *what* the result must be
  (uniform across A1–A4, achieved by substituting into `sphinx_metadata`), not *where* the helper
  lives. Note `writer.py:55-72`'s `_is_master_document` already walks `typst_documents` for the same
  docname and could be extended to return the entry instead of a bool, at the cost of changing a
  method four call sites rely on.

- **SC#3's multi-master leak evidence — reuse a fixture or build a new one.** Measured starting
  point: `writer.translate()` runs per document and constructs a fresh `TemplateEngine` each time
  (`writer.py:194-201`), so a straightforward implementation does not leak; the risk shape is caching
  the entry lookup on the builder, which is the same failure `effective_elements` was made a fresh
  dict to avoid (`writer.py:250-252`, D-05 of CONF-07). `tests/fixtures/template_named_dir_master/`
  already has two masters with **different** `entry[2]` (`'Template Named Dir Master'` /
  `'Template Named Dir Master (nested)'`), so it detects a title leak as-is — but both entries carry
  `entry[3] == 'Test Author'`, so it cannot detect an **author** leak. A new fixture, or an added
  divergent author in the existing one, is needed for the author half.

- **The rule when two entries name the same docname.** Undefined today for title lookup. Measured
  existing convention: both `_is_master_document` (`writer.py:68`) and `_resolve_output_stem`
  (`builder.py:193-197`) `break` on the first match, so "first wins" is the established shape.
  Whether to match it silently, warn, or leave it alone is open — but see the boundary note in
  `<domain>`: the adjacent `high`-severity duplicate-*target* todo is explicitly out of scope and
  must not be absorbed here.

- **What is measured and handed to Phase 46 as CHANGELOG source text.** REL-06 requires the entry to
  call out both CONF-08's filename rename and CONF-09's title/author change. D-05 arguably adds a
  third user-visible change (the `typst_authors` precedence flip). Phase 44's D-05 set the precedent
  of handing over more than the headline — it recorded that the emitted `.typ`'s *structure* changed,
  not only its name.

- **Where the SC#4 evidence file lives and what it is named.** A `44.2-GATE-EVIDENCE-*.md` in the
  phase directory is the established shape. **Note the reserved-name hazard:** `44.2-VERIFICATION.md`
  is written by the verifier and will clobber any plan-authored file of that name.

## Existing Code Insights

### Reusable Assets
- `writer.py:55-72` `_is_master_document()` — already walks `typst_documents` matching on
  `doc_tuple[0] == docname`, with a malformed-entry guard and a comment explaining why reporting
  malformed entries is `finish()`'s job alone. The title/author lookup needs the same walk.
- `builder.py:186-200` `_resolve_output_stem()` — the established shape for "read element N of the
  matching entry, guard it, fall back with or without a warning". Its `len(entry) >= 2` guard is the
  precedent for D-02's arity tolerance.
- `tests/fixtures/template_named_dir_master/` — two masters with different `entry[2]`, ready-made for
  the SC#3 title-leak check.
- `tests/test_builder_output_stem.py` — 20+ table-driven edge cases over one element of the entry
  (empty, whitespace, non-`str`, `None`, short tuple, non-ASCII, five-element). The same shape covers
  D-01/D-02's matrix; `:77` already pins that a 5-element tuple is accepted.

### Established Patterns
- **Guard-then-fall-back with a warning** for degenerate config values (`builder.py:240`, `:259`,
  `:279`, `:986-999`); **silent pass-through** for the ordinary no-match case (`:201`). D-02 follows
  both.
- **Fresh per-document dicts, never mutation of a live config value** (`writer.py:250-252`) — the
  structural answer to multi-master state leaks, which SC#3 tests for.
- **One routing rule in one place** (`resolve_package_for_engine`, `template_engine.py:152-176`) —
  writer and builder must never re-derive package-vs-template routing independently (WR-04 / BUG-A).
- **Precedence expressed as assignment order, not as branching** — D-07's `typst_authors` override
  and D-08's params merge are both plain "later `update` wins". D-04 and D-05 are implemented the
  same way.

### Integration Points
- `writer.py:212-216` — where `sphinx_metadata` is built; D-03's single substitution point.
- `builder.py:39-47` — the derived default already carries `config.project` / `config.author` in
  `[2]`/`[3]`, so once entries are read, the unset-`typst_documents` path resolves through the entry
  and produces exactly the values it produces today. The fallback in D-02 exists only for explicitly
  configured entries with omitted elements.
