## Summary

This is a re-review of gap-closure plan 04, which repaired the `typst_authors` /
mapped-author precedence documentation flagged as WR-01 in the pre-plan-04
`44.2-REVIEW.md`. Plan 04 touches four files: `docs/source/user_guide/configuration.rst`
(prose, two sites), `typsphinx/template_engine.py` (a comment inside
`map_parameters()`), `tests/test_entry_metadata_precedence.py` (docstring plus four new
test functions), and `tests/test_template_engine.py` (a docstring only, no assertion
change).

**Comment-only constraint verified.** Every added/removed line in the
`typsphinx/template_engine.py` diff begins with `#` (confirmed by filtering the diff for
non-comment `+`/`-` lines: zero results). The module's executable code is byte-for-byte
unchanged from the pre-plan-04 commit; only the D-05 rationale comment inside
`map_parameters()` was reworded. No AST change.

**WR-01 (the original finding) is RESOLVED.** The pre-plan-04 text claimed the
`typst_authors`-survives exception was exclusive to a package-alone build. All three
touched artifacts (`configuration.rst`, the `template_engine.py` comment, and the
`test_entry_metadata_precedence.py` module docstring) now correctly state that the
trigger is the *active parameter mapping*, not `typst_package`, and name two surviving
config shapes instead of the disproven single one. This is now backed by four new,
non-redundant test cells in `tests/test_entry_metadata_precedence.py` Group 2 — verified
by running them directly (`pytest -k map_parameters`, 6 passed): a non-package build with
an explicit mapping omitting `"author"`, a package build with `parameter_mapping` left
unset (`__init__`'s empty-dict branch), a control proving a *custom* mapping that still
maps `"author"` → `"authors"` still gets overwritten (so the trigger really is the
mapping key, not whether it equals `DEFAULT_PARAMETER_MAPPING`), and a cell pinning the
second conjunct (`"author"` absent from `sphinx_metadata`). Each cell tests a genuinely
distinct shape rather than restating one shape multiple times.

**One residual documentation-accuracy gap was found**, introduced by the corrected
wording itself (not present, in this form, before plan 04): the new prose claims
`typst_authors` survives on "*exactly* the two configurations" whose mapping omits
`"author"` — but a third, code-reachable configuration exists (mapping `"author"` to a
target key other than `"authors"`) where `typst_authors` *also* survives, contradicting
the "exactly two" quantifier. See WR-01 (this review) below. It is a narrower version of
the same class of defect plan 04 exists to fix, and carries no test coverage, so nothing
in the suite would catch it if someone tried to fix the prose in the direction this
review suggests.

## Warnings

### WR-01: Corrected precedence rule still overstates exhaustiveness — "exactly the two configurations" omits a third, reachable shape

**File:** `docs/source/user_guide/configuration.rst:186-203` (also `docs/source/user_guide/configuration.rst:49-58`, `typsphinx/template_engine.py:428-463`, `tests/test_entry_metadata_precedence.py:14-20`)

**Issue:** The newly-published precedence rule says `typst_authors` survives "as the sole
source on *exactly* the two configurations whose active mapping carries no `"author"`
key" (`configuration.rst:191-193`), listing (1) `typst_package` set with no
`typst_template_mapping`, and (2) an explicit `typst_template_mapping` that *omits*
`"author"` entirely. The mirrored comment in `template_engine.py:441-447` uses the same
"exactly two config shapes" language, and the `test_entry_metadata_precedence.py` module
docstring (lines 14-20) frames the rule as a clean binary: `"author"` is an active
mapping key AND present in `sphinx_metadata` → overwritten, "otherwise the seed
survives."

This is not what `map_parameters()` implements. Read the mapping loop:

```python
for sphinx_key, template_key in self.parameter_mapping.items():
    if sphinx_key in sphinx_metadata:
        value = sphinx_metadata[sphinx_key]
        if sphinx_key == "author" or template_key in ("authors", "doc_authors"):
            value = self._convert_to_authors_tuple(value)
        params[template_key] = value
```

The `typst_authors` seed lives at the fixed key `params["authors"]`
(`template_engine.py:472`). The loop only overwrites that specific key when
`template_key == "authors"` exactly. If a mapping has `"author"` as an *active key*
mapped to any *other* template key — including `"doc_authors"`, which the loop still
special-cases for tuple-conversion, or an arbitrary name like `"writer"` — `"author"` is
present in the mapping and in `sphinx_metadata`, yet `params["authors"]` (the seed) is
never touched. Measured directly against the shipped code:

```python
engine = TemplateEngine(
    parameter_mapping={"project": "title", "author": "doc_authors"},  # not "authors"
    typst_authors={"Jane Doe": {"organization": "MIT"}},
)
params = engine.map_parameters(
    {"project": "P", "author": "Explicit Entry Author", "release": "1.0"}
)
# params["authors"]     == [{"name": "Jane Doe", "organization": "MIT"}]  <- seed survives
# params["doc_authors"] == ("Explicit Entry Author",)                     <- ALSO present
```

This is not a hypothetical shape: `tests/test_config_template_mapping.py` already
exercises `typst_template_mapping = {"author": "doc_author"}` and
`{"author": "doc_authors"}` as realistic custom-template configurations (Requirement
8.4, "different parameter names") — those tests just never combine that mapping with
`typst_authors` being set, so this combination has zero coverage anywhere in the suite.

Practically: a user with a custom template whose `project()`-equivalent function takes
`writer` (not `authors`) as its author parameter, who also sets `typst_authors` expecting
their entry/`config.author` value to take over per the "exactly the two configurations"
rule, will instead get *both* `authors` (unexpectedly reappearing from the `typst_authors`
seed) and `writer` emitted into `params` — silently contradicting the documented
"exactly two" exhaustiveness claim, and risking an "unexpected argument: authors" Typst
compile abort if their custom template never declared an `authors` parameter at all.

**Fix:** State the precise trigger — the mapped *target* key must be literally
`"authors"`, not merely that `"author"` is present as a mapping *source* key. E.g., in
`configuration.rst`:

```rst
``typst_authors`` survives as the sole source whenever the active mapping does
not send ``"author"`` to the template key ``"authors"`` -- whether because
``"author"`` is absent from the mapping entirely, or because it is present but
routed to a *different* target key (e.g. a custom template whose function
parameter is named something other than ``authors``).
```

Mirror the correction in the `template_engine.py` D-05 comment and the
`test_entry_metadata_precedence.py` module/Group-2 docstrings (drop "exactly two config
shapes" in favor of the general "target key must be `authors`" rule). Add one Group 2
test cell exercising `parameter_mapping={"author": "<non-authors-key>"}` combined with
`typst_authors` set, asserting both that the seed survives at `params["authors"]` *and*
that the separately-mapped key is also present — so the "two outputs land in `params`
simultaneously" behavior this finding describes has direct coverage and the corrected
prose can't silently regress again.
