# Phase 44.2: Code Review Report

**Reviewed:** 2026-08-04T23:07:26Z
**Depth:** standard

## Summary

This phase makes an explicit `typst_documents` entry's title (`entry[2]`) and author
(`entry[3]`) reach the compiled PDF via a new `_resolve_entry_element()` helper in
`typsphinx/writer.py` and a reorder of the `typst_authors` seeding in
`typsphinx/template_engine.py::map_parameters()`.

`_resolve_entry_element()` was traced line by line: it is a pure function (no mutation of
`typst_documents`, no state cached on the builder/writer), its first-match walk is provably
identical to `_is_master_document()`'s own walk (both use `entry and entry[0] == docname`), so
the two can never disagree about which entry a given docname resolves against. `TypstWriter.translate()`
builds a fresh `TemplateEngine` and a fresh `sphinx_metadata` dict on every call, so there is no
cross-document (multi-master) state leak — confirmed both by static reading and by the
`tests/test_multi_master_metadata_no_leak.py` suite, which passes. All `.typ`/template file I/O in
the touched code paths (and in `builder.py`, out of scope but load-bearing) is UTF-8 explicit; no
encoding-assumption defect was found. `mypy typsphinx/` and `ruff check` are clean on every touched
file, and the full targeted test selection (123 tests across the 6 touched/added test modules)
passes.

One documentation/comment-accuracy defect was found: the newly-added precedence text (both the
published docs and two in-code comments/docstrings, all added by this phase) overstates how narrow
the "`typst_authors` survives a mapped author" exception is. It claims the exception is exclusive to
a **package-alone** build; measurement shows the same "survives" behavior also occurs on a
**non-package (custom template) build** whose `typst_template_mapping` happens to omit `"author"`.
This does not corrupt runtime behavior (the underlying `map_parameters()` mechanism is
self-consistent across all four A1-A4 routes and every route-uniformity/precedence test that
exists passes), but it directly contradicts what the phase context asked this review to verify:
"whether the precedence text ... actually matches what the code implements rule for rule." It does
not, in this one respect.

No critical/security findings. No mutation-of-config, cross-document-leak, or encoding defects
were found in the reviewed diff.

## Warnings

### WR-01: Precedence documentation overstates the "package-alone" exception for `typst_authors`

**File:** `docs/source/user_guide/configuration.rst:184-190` (also `typsphinx/template_engine.py:428-439` and `tests/test_template_engine.py:934-947`)

**Issue:** The newly-added "Precedence" paragraph (docs) and the newly-added D-05 reorder comment
(template_engine.py), both introduced by this phase, claim that a mapped author value beats the
`typst_authors` seed "on every route... except a package-alone build (`typst_package` set, no
`typst_template`) using a custom `typst_template_mapping` that specifically omits `"author"`" —
i.e. that `typst_authors` can only "win" on that one, package-specific route.

This is not what `map_parameters()` actually implements. The seed-then-overwrite mechanism keys
purely off whether `"author"` is an *active mapping key* in `self.parameter_mapping` — it has no
special-case branch for `self.typst_package`. Any route (package-based **or** template-based, and
even the bundled-default-template route) whose `typst_template_mapping` is explicitly set and
happens to omit `"author"` exhibits the identical "`typst_authors` survives" behavior, with no
`typst_package` required at all. Measured directly against the shipped code (non-package engine,
custom mapping omitting `"author"`, `typst_authors` set):

```python
engine = TemplateEngine(
    parameter_mapping={"project": "title"},  # omits "author"; NOT a package route
    typst_authors={"Jane Doe": {"organization": "MIT"}},
)
params = engine.map_parameters(
    {"project": "P", "author": "Explicit Entry Author", "release": "1.0"}
)
# params["authors"] == [{"name": "Jane Doe", "organization": "MIT"}]
# -- typst_authors won, on a route with NO typst_package configured at all.
```

The same overstatement appears in three places, all touched by this phase:
- `docs/source/user_guide/configuration.rst:184-190` ("Author Information" > "Precedence")
- `typsphinx/template_engine.py:428-439` (the D-05 reorder rationale comment inside
  `map_parameters()`)
- `tests/test_template_engine.py:934-947` (the updated docstring on
  `test_typst_authors_through_pipeline_produces_native_array_of_dicts`)

No test in the suite exercises the actual boundary condition (non-package route + explicit
mapping omitting `"author"` + `typst_authors` set), so this narrower-than-reality claim was never
caught by the added test matrix (`tests/test_entry_metadata_precedence.py`'s Group 2 only covers
"default mapping, no package" and "package + mapping omitting author" — it does not cover
"non-package custom mapping omitting author").

This directly affects a user who: sets a custom `typst_template` (not a package), sets
`typst_template_mapping` without an `"author"` key (e.g. only mapping `"project"`), and also sets
`typst_authors`. Per the current docs, they'd expect `config.author`/their `typst_documents`
entry's author to be irrelevant here only on the package route — but on their template route,
`typst_authors` silently wins instead of the value they may expect from `entry[3]`/`config.author`
(which was never mapped in the first place, so this is not a behavioral regression — it's that the
docs describe the exception too narrowly for them to predict it).

**Fix:** Broaden the precedence statement to name the real condition (mapping key presence, not
`typst_package` presence). E.g., in `configuration.rst`:

```rst
**Precedence.** An entry's own author element (the fourth position in
`Typst Documents`_ above) takes precedence over this setting whenever the
active ``typst_template_mapping`` (or the default mapping) maps
``"author"`` at all. ``typst_authors`` survives as the sole source
whenever a *custom* ``typst_template_mapping`` is set and specifically
omits ``"author"`` -- on any route, package-based or not.
``typst_template_function``'s dict-form ``params`` take precedence over
both.
```

And mirror the correction in the `typsphinx/template_engine.py` comment and the
`test_typst_authors_through_pipeline_produces_native_array_of_dicts` docstring (drop "the
package-alone route" as if it were the only instance; state the general "author not an active
mapping key" rule as the complete condition). Consider adding one test to
`tests/test_entry_metadata_precedence.py` Group 2 exercising the non-package,
custom-mapping-omits-author, `typst_authors`-set combination, so the general rule (not just the
package-specific special case) has direct coverage.
