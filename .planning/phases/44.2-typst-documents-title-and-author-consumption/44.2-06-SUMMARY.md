## Discrepancy between `<measured_grounding>` §1's stage table and the AST walk

**One deliberate, documented widening of the id scheme was required — not a discrepancy in WHICH sites exist, but in how they must be ADDRESSED.**

`<measured_grounding>` §1 and the action's hand-declared `EXPECTED_STAGE_SITES` both correctly identify that `map_parameters()` writes `params["authors"]` at TWO distinct source sites (the `typst_authors` seed, W1, and the non-package back-fill, W3). Under the literal `<relpath>::<enclosing function>::<assign|update>::<slice>` id format given in the plan, both sites produce the IDENTICAL string `typsphinx/template_engine.py::map_parameters::assign::authors`, because the format has no axis for "which occurrence" — only for file, function, kind, and target-key text. Two AST `Assign` nodes with the same literal target inevitably collide under that scheme.

This collision is structurally provable (not a transcription slip): `assign::authors` appears in `EXPECTED_STAGE_SITES` "twice" per the action's own wording, but `REACHABLE_STAGE_KNOBS` needs to attribute the SEED to `typst_authors` and the BACK-FILL to `typst_package` — two different knobs — which is impossible if both share one dict key.

**Resolution, recorded here per the plan's own escape valve** ("if the source disagrees with that list, the SOURCE wins and the discrepancy is recorded in the SUMMARY"): `_stage_sites()` disambiguates same-function repeats of the same base id with a `#<n>` ordinal suffix on the second and later occurrence (source order), so the seed (`...assign::authors`) and the back-fill (`...assign::authors#2`) remain individually addressable. `EXPECTED_STAGE_SITES`, `REACHABLE_STAGE_KNOBS`, and `UNREACHABLE_STAGE_PROOFS` were all hand-declared with this ordinal scheme baked in from the start (never computed by calling `_stage_sites()` and pasting its output) — verified by reading the module.

All NINE sites `<measured_grounding>` §1 implies (W1's seed, W2's mapping-loop assignment, W3's three back-fill literals, W4's `typst_elements` loop, W5's `toctree_options` update, W6/W7's two `render()` merges) were confirmed present, in the expected enclosing functions, with no additional or missing site — a probe script walking both files independently before freezing the constants confirmed exactly 9 unique disambiguated ids, matching `EXPECTED_STAGE_SITES` one-to-one.

## Decisions Made

- **Ordinal-suffix id disambiguation** (see discrepancy section above) — necessary to make the partition assertion well-defined; documented in the module's own constants and in this SUMMARY rather than silently worked around.
- **`UNREACHABLE_STAGE_PROOFS` for `assign::title`/`assign::date`/`assign::key`** point at `test_pipeline_stage_sites_that_can_determine_authors_are_exactly_these` (the enumeration test itself) rather than a dedicated behavioural test, because their non-reachability is DEFINITIONAL: an id whose literal slice differs from the string `"authors"` cannot, by construction, be the assignment that writes `params["authors"]`. `update::params` and `update::toctree_options` each get their own dedicated proof test (`test_render_applies_template_function_params_after_map_parameters_output` and `test_toctree_options_cannot_reach_authors_or_title` respectively), since their non-reachability is NOT definitional from the id alone — it depends on evaluation order / return-value structure that a dedicated test proves.
