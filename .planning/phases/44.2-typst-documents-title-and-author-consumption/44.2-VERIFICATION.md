### Gaps Summary

**One gap, confined to documentation and code-comment accuracy — no runtime behavior is affected.**

Code review finding WR-01 (`44.2-REVIEW.md`) is still open at verification time. I independently
reproduced it against the shipped `typsphinx/template_engine.py` rather than taking the review's
word for it:

```
engine = TemplateEngine(
    parameter_mapping={"project": "title"},  # omits "author"; NOT a package route
    typst_authors={"Jane Doe": {"organization": "MIT"}},
)
params = engine.map_parameters({"project": "P", "author": "Explicit Entry Author", "release": "1.0"})
# params["authors"] == [{"name": "Jane Doe", "organization": "MIT"}]
```

`typst_authors` wins here even though `typst_package` is `None` — i.e. this is not a package-alone
route at all. Reading `map_parameters()` confirms why: the seed-then-overwrite mechanism (D-05's
reorder) is keyed *only* on `self.parameter_mapping` (`for sphinx_key, template_key in
self.parameter_mapping.items(): ...`); there is no `self.typst_package` conditional anywhere in that
logic. The real rule is "`typst_authors` survives whenever the active `parameter_mapping` does not
map `\"author\"` — on any route, package-based or template-based." The docs, the in-code D-05
rationale comment, and one test docstring all still say the narrower, package-specific version.

**Does this falsify SC#5?** No, not literally — SC#5's own text is specifically about the fifth
tuple element (`entry[4]`, "Document class"), and that half is correctly documented
("accepted and ignored", naming the three real five-element `conf.py` files). **Does it falsify
SC#2?** Partially, in spirit rather than letter: SC#2 requires "each rule has a test," and the rule
as actually implemented (the general "mapping omits author" condition) has no direct test — only
its two narrower sub-cases (default mapping; package+omit-author mapping) are tested, so the
overstated "package-alone-only" documentation was never caught by the added matrix. **It does
falsify plan 03's own explicit backstop must-have** ("the precedence text published in
`configuration.rst` matches the precedence the code actually implements, rule for rule"), which is
why it is recorded as a gap rather than dismissed as cosmetic.

This is a narrow, well-scoped, three-location text fix (per WR-01's own suggested replacement text)
— it does not require touching `typsphinx/writer.py`, does not change any test's pass/fail
disposition, and does not affect SC#1/SC#3/SC#4/SC#6, all of which are cleanly verified with direct,
independently-reproduced evidence.
