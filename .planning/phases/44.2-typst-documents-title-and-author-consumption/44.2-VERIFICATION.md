### Gaps Summary

One gap blocks phase completion: **SC#2 and plan 05's own backstop must-have both fail on the same
root cause** — a single sentence in the just-corrected `configuration.rst` Precedence paragraph
("and nothing else in typsphinx replaces it") makes a false, unscoped claim about the whole
`authors` value's lifecycle, when in fact `typst_template_function`'s `params["authors"]` (applied
later, in `render()`) can and does replace it. This was independently reproduced this session with
a real `sphinx-build`, not taken on the code review's word.

This is a narrower failure than the previous two rounds: the core `iff` rule over the mapping's
target key is now correct and is backed by a mechanically-generated, code-derived test matrix
(`tests/test_params_authors_writers.py`) that cannot be gamed by re-deriving the rule from the
prose being corrected. The render()-level override this false sentence contradicts is itself
correctly stated elsewhere in the same document section and is independently tested (generically,
not in this exact three-knob combination). The remediation scope is therefore narrow and precise:
correct or remove one sentence in `configuration.rst`, add that sentence (or its replacement) as
its own graded row with a named falsification test the next time a gate-evidence enumeration is
produced, and add one test combining `typst_authors` + an authors-omitting mapping +
`typst_template_function`'s `params["authors"]` end-to-end through `render()`.

The `44.2-REVIEW.md` WR-01 finding (unhandled `TypeError` on non-dict `typst_elements`) is
confirmed to predate this phase (introduced in phase 27.1) and is recorded above as a carry-forward
item, not a gap of this phase.
