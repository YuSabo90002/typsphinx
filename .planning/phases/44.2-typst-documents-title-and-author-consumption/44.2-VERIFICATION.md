### Gaps Summary

**Gap closure plan 04 correctly fixed the gap `44.2-VERIFICATION.md`'s first pass recorded, and
introduced a narrower version of the same defect class in the process.**

What plan 04 got right: the "package-alone build" framing — which falsely restricted the
`typst_authors`-survives exception to a single config shape — is gone from all four sites the
previous verification named (`configuration.rst`'s Precedence paragraph, `template_engine.py`'s D-05
comment, `test_template_engine.py`'s docstring) plus the fourth site plan 04 found by its own
measurement (`configuration.rst`'s element-4 bullet). The two previously-untested reachable shapes
(package with `parameter_mapping` left unset; a non-package mapping that omits `"author"`) now have
named, passing tests. The production code was never wrong and remains untouched (comment-only diff,
`ast`-verified). This is genuine, verified progress, not a wasted plan.

What plan 04 got wrong: its replacement rule states the survives-case as "exactly the two
configurations whose active mapping carries no `\"author\"` key." That is itself narrower than the
code. `map_parameters()`'s mapping loop keys the overwrite on the mapped *target* being literally
`"authors"`, not merely on `"author"` being present as a *source* key. A mapping like
`{"author": "doc_authors"}` carries `"author"` as an active key — so by the published rule's own
wording it should NOT survive — yet it demonstrably does (reproduced directly this session; not
merely re-stated from `44.2-REVIEW.md`). This is a real, reachable, currently-undocumented,
currently-untested shape: `tests/test_config_template_mapping.py` already exercises
`typst_template_mapping = {"author": "doc_authors"}` as a realistic custom-template configuration
(Requirement 8.4), it is simply never combined with `typst_authors` being set. A separate, unrelated
fifth site — `.planning/REQUIREMENTS.md`'s `CONF-10` Future Requirement entry — still carries the
*original* "package-alone build" framing verbatim; it sat outside plan 04's four-file scope and its
own occurrence census never checked it.

**Adjudication of the three questions posed for this re-verification:**

1. **Does this defeat plan 04's own must-have truths?** Yes, for the backstop truth specifically
   ("no surface states a condition narrower than the code," and "SC#2 restored ... every clause of
   the corrected rule is pinned by a named, passing test") — both fail on direct measurement. The
   narrower claim ("no surface still restricts the survives-case to a package build") technically
   holds on its literal wording (nothing restricts it to a package build anymore; the new restriction
   is orthogonal — a target-key condition, not a route condition) — that specific narrow truth is not
   what fails. `44.2-GATE-EVIDENCE-04.md`'s own §4 per-sentence enumeration — the artifact plan 04
   built specifically to catch this class of error — rated every sentence `ACCURATE` because its §1
   probe never constructed the falsifying shape; the enumeration inherited the gap instead of
   catching it.

2. **Does this defeat phase-level SC#2?** Yes. SC#2 requires precedence to be "defined and asserted
   for every combination that can occur," with each rule backed by a test. A reachable combination
   (a custom `typst_template_mapping` that maps `"author"` to some other template parameter name,
   combined with `typst_authors` set) produces output the published rule does not correctly predict,
   and has zero test coverage. This is not a hypothetical edge case invented for this review —
   `typst_template_mapping` remapping to differently-named template parameters is an explicitly
   documented, tested use of the feature (`tests/test_config_template_mapping.py`); it is only the
   *combination* with `typst_authors` that has never been exercised.

3. **Does this defeat the phase goal?** No. The phase goal — "an explicit `typst_documents` entry's
   `[2]` title and `[3]` author actually reach the rendered document" — is proven true independent of
   this defect: SC#1 (real-compile PDF metadata gate), SC#3 (no multi-master leak), SC#4 (corpus
   partition), and SC#6 (full gate green) all remain verified and were untouched by plan 04's
   comment/docs-only diff. `typst_authors` is a secondary, already-superseded sugar setting
   (`CONF-10` files its removal as a Future Requirement, measured byte-identical to its replacement)
   whose precedence against a rare mapping shape is the only thing still wrong. The core, headline
   claim of the phase — documented configuration actually taking effect — holds.

**Sizing the remaining work:** small and mechanical, matching plan 04's own shape. Per
`44.2-REVIEW.md`'s suggested fix: restate the trigger as "the mapped TARGET key must be literally
`\"authors\"\`," in the same four sites plan 04 touched, add one Group 2 test cell for the
`{"author": "<non-authors-key>"}` + `typst_authors` shape, and separately correct
`.planning/REQUIREMENTS.md`'s `CONF-10` entry (outside the four-file set, previously unchecked). No
runtime code changes are implicated — `map_parameters()`'s behavior is correct and has been correct
throughout this phase; only its description keeps landing one predicate short.
