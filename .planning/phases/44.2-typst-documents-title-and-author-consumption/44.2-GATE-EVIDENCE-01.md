## 7. User-Visible Changes (source text for Phase 46 / REL-06)

This section is repeated verbatim in `44.2-01-SUMMARY.md`.

1. **A `typst_documents` entry's own title/author now reach the rendered document,
   overriding `config.project`/`config.author`.** Measured this session with
   `tests/fixtures/entry_title_author_render_gate/` (`typst_documents = [("index",
   "index", "My Handbook", "Jane Doe")]`, `project = "Config Project Must Not Win"`,
   `author = "Config Author Must Not Win"`): **before** this phase, the compiled PDF's
   `/Title`/`/Author` were `'Config Project Must Not Win'` / `'Config Author Must Not
   Win'` (§2/§3's recorded RED); **after**, they are `'My Handbook'` / `'Jane Doe'`
   (§4's GREEN). Command: `uv run python -m pytest
   tests/test_document_metadata_render_gate.py::TestEntryTitleAuthorRenderGate::test_entry_title_and_author_reach_the_compiled_pdf
   -v`.

2. **An empty entry title/author is now a VALUE, not a fallback signal, with an
   asymmetric PDF-metadata consequence.** Measured with
   `tests/fixtures/entry_empty_metadata_render_gate/` (`typst_documents = [("index",
   "index", "", "")]`): an empty title produces a PDF with **no `/Title` key at all**
   (`reader.metadata.title is None`); an empty author produces a PDF with a **present,
   empty** `/Author` value (`reader.metadata.author == ""`). Command: `uv run python -m
   pytest
   tests/test_document_metadata_render_gate.py::TestEntryTitleAuthorRenderGate::test_empty_entry_elements_are_values_not_fallback_signals
   -v`.

3. **`typst_authors` is now overridden by the mapped author value on every route where
   `"author"` is an active `parameter_mapping` key, remaining authoritative only on the
   package-alone route whose custom mapping omits `"author"`.** Measured this session
   (§5): `tests/test_config_template_mapping.py`'s
   `test_custom_mapping_applied_to_template` and `test_partial_custom_mapping` both
   confirm the entry's own title/author win on the default-template path.
   `tests/test_template_engine.py::TestTypstAuthorsConfig::test_typst_authors_through_pipeline_produces_native_array_of_dicts`
   confirms `typst_authors` reaches `render()` as a native `list[dict]` ONLY on the
   package-alone/`"author"`-omitting-mapping route; the full
   `tests/test_package_only_config_gate.py` suite (12 tests, control group) and
   `test_typst_authors_unset_or_empty_yields_no_authors_key_on_package_path` pass with
   **zero edits**, proving that route is unaffected.

4. **The `typst_authors` + bundled-template combination, which previously produced no
   PDF at all, now produces one when no `typst_documents` override supersedes it
   either.** MEASURED (not inferred) this session with a standalone probe fixture
   (`project = "Probe Project"`, `author = "Probe Author"`, `typst_authors = {"Jane
   Doe": {...}}`, no `typst_documents` set at all): `uv run python -m sphinx -b
   typstpdf <probe> <build>` now reports `build succeeded.` and generates a PDF (before
   this phase, RESEARCH.md measured the same shape as a hard `TypstError: expected
   string, found dictionary` aggregate build failure). The emitted `.typ` shows
   `authors: ("Probe Author",)` -- the plain `config.author` fallback (via
   `_resolve_entry_element()`'s D-02 silent-fallback path, since no entry names this
   docname) wins over the `typst_authors` dict, matching finding #3 above. This is the
   specific case D-05's own reversibility note names as "unbroken" -- it was measured
   directly, not inferred.
