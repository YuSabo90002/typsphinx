## 3. RED classification

All three failures are metadata/content mismatches — the config-wide fallback values
(`"Config Project Must Not Win"`, `"Config Author Must Not Win"`,
`"Config Fallback Must Not Fire For Empty Title"`, `"Config Fallback Must Not Fire For
Empty Author"`) turned up where the entry's own values (`"My Handbook"`, `"Jane Doe"`,
`""`) belonged. `result.returncode == 0` held in every case (the `sphinx-build -b
typstpdf` subprocess exited cleanly and `typst.compile()` did not raise) — none of the
three failures is a build/compile-failure false-positive. This is the correct RED: the
gate is measuring what it exists to measure.

`git status --porcelain typsphinx/` was empty before this commit — no production source
was touched to produce this RED.
